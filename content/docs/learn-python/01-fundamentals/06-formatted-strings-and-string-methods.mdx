When building real-world programs, you constantly generate dynamic messages from variables — welcome emails, database queries, and terminal logs.

Let's say we want to produce the message: `John [Smith] is a coder`.

---

## The Problem with String Concatenation

Using standard string concatenation (`+`), our code looks like this:

```python
first = "John"
last = "Smith"

message = first + " [" + last + "] is a coder"
print(message)
```

Output:

```text
John [Smith] is a coder
```

It works, but as messages get longer and incorporate numbers or dates, string concatenation quickly becomes unreadable. You have to juggle quotes, plus signs, and manual spaces in your head.

---

## Formatted Strings (`f-strings`)

Python solves this with **formatted strings** (or **f-strings**):

```python
first = "John"
last = "Smith"

msg = f"{first} [{last}] is a coder"
print(msg)
```

Output:

```text
John [Smith] is a coder
```

### How F-Strings Work

- Prefix the string with `f` (or `F`): `f"..."`.
- Inside the quotes, use curly braces `{}` as **placeholders**.
- At runtime, Python evaluates the expressions inside the curly braces and automatically converts them to strings.

### Readability Comparison

| Approach          | Code                                   | Readability                                                                      |
| :---------------- | :------------------------------------- | :------------------------------------------------------------------------------- |
| **Concatenation** | `first + " [" + last + "] is a coder"` | Hard to visualize; fragmented quotes and plus signs.                             |
| **F-String**      | `f"{first} [{last}] is a coder"`       | **Crystal clear**: the finished sentence is visible directly in the source code. |

## Built-In Functions vs. Object Methods

Python distinguishes between **general-purpose functions** and **object methods**:

### 1. General-Purpose Functions (`len()`)

Functions like `print()`, `input()`, and `len()` belong to Python itself. They are not tied to any single type of object:

```python
course = "Python for Beginners"
print(len(course))  # 20 characters
```

Output:

```text
20
```

`len()` counts the characters in a string. Later, it will count elements in a list, keys in a dictionary, and rows in a dataset. A common production use: validating form input lengths (e.g. usernames capped at 30 characters).

### 2. Object Methods (`.upper()`, `.lower()`)

When you type a variable name followed by a dot (`course.`), your code editor displays a list of functions that belong specifically to strings. These are called **methods**.

```python
course = "Python for Beginners"

print(course.upper())  # A NEW string in all uppercase
print(course.lower())  # A NEW string in all lowercase
print(course)          # The original string - untouched!
```

Output:

```text
PYTHON FOR BEGINNERS
python for beginners
Python for Beginners
```

## Searching Text: `.find()`

The `.find()` method returns the index of the first occurrence of a character or substring:

```python
course = "Python for Beginners"

print(course.find("P"))          # 0 (Found at index 0)
print(course.find("o"))          # 4 (Found at index 4)
print(course.find("O"))          # -1 (Not found! Case-sensitive)
print(course.find("Beginners"))  # 11 (Starts at index 11)
```

Output:

```text
0
4
-1
11
```

Two key behaviors to internalize:

1. `.find()` is strictly **case-sensitive**. Searching for `"O"` in `"Python"` yields `-1`.
2. `-1` is Python's way of signalling: _"The requested substring was not found"_.

---

## Replacing Text: `.replace()`

The `.replace()` method swaps an existing character or substring with a new one:

```python
course = "Python for Beginners"

print(course.replace("Beginners", "Absolute Beginners"))
print(course.replace("beginners", "Absolute Beginners"))  # Case-sensitive: no match, unchanged!
print(course.replace("P", "J"))
```

Output:

```text
Python for Absolute Beginners
Python for Beginners
Jython for Beginners
```

---

## The `in` Operator: Boolean Existence

Often, you don't care _where_ a word is located; you only care _whether it exists_. For this, Python provides the elegant `in` operator:

```python
course = "Python for Beginners"

print("Python" in course)
print("python" in course)  # Case-sensitive!
```

Output:

```text
True
False
```

The `in` operator evaluates to a boolean (`True` or `False`). It reads like plain English and is heavily used in conditional statements (`if "admin" in user_roles:`).

### Question 1: Output Prediction (String Immutability & Method Chaining)

Predict what the following code prints to the console:

```python
raw_user = "   dev_sarah_99   "

raw_user.strip()
cleaned = raw_user.upper()

print(f"Original: '{raw_user}'")
print(f"Cleaned:  '{cleaned}'")
```

1. Why does `cleaned` still retain leading and trailing spaces even though `.strip()` was executed?
2. How can this be refactored into a single idiomatic line using method chaining?

<Accordions>
<Accordion title="Reveal Solution & Explanation">

**Output:**

```text
Original: '   dev_sarah_99   '
Cleaned:  '   DEV_SARAH_99   '
```

**Explanation:**

1. Strings in Python are **immutable**. Calling `raw_user.strip()` computes and returns a _new_ string without spaces, but that return value was **discarded** because it was not assigned back to any variable. `raw_user` remains completely unchanged with its original spaces intact.
2. When `raw_user.upper()` runs on line 4, it uppercase-transforms the unchanged string.

**Refactored with Method Chaining:**
Because each string method returns a new string, you can chain methods directly from left to right:

```python
cleaned = raw_user.strip().upper()
print(f"'{cleaned}'")  # 'DEV_SARAH_99'
```

### Question 2: Spot and Fix the Bug (Type Mismatch in F-String Specifiers)

A developer is writing a checkout billing receipt generator:

```python
item_name = "Mechanical Keyboard"
unit_price = "129.50"
quantity = 2

subtotal = unit_price * quantity
print(f"Receipt: {item_name} x {quantity} = ${subtotal:.2f}")
```

1. What unexpected value is computed for `subtotal`?
2. What exception is raised when the f-string attempts to format `subtotal` with `:.2f`?
3. How do you rewrite this safely?

<Accordions>
<Accordion title="Reveal Solution & Explanation">

**1. Unexpected value:**
`unit_price` is a string (`"129.50"`). When multiplied by the integer `2`, Python performs **string repetition**, resulting in:

```text
subtotal = "129.50129.50"
```

**2. The Exception:**

```text
ValueError: Unknown format code 'f' for object of type 'str'
```

The format specifier `:.2f` instructs Python to round a **floating-point number** (`f`) to two decimal places. Passing a string object into a float format specifier causes a runtime `ValueError`.

**3. The Clean Fix:**
Convert `unit_price` to a `float` before doing arithmetic:

```python
item_name = "Mechanical Keyboard"
unit_price = float("129.50")
quantity = 2

subtotal = unit_price * quantity
print(f"Receipt: {item_name} x {quantity} = ${subtotal:.2f}")
# Output: Receipt: Mechanical Keyboard x 2 = $259.00
```

### Question 3: Comparing Substring Checks (`in` vs `.find()` vs `.index()`)

Review the following code looking for the character `"@"` inside an invalid email string:

```python
handle = "johndoe_at_gmail.com"

# Approach A:
has_symbol = "@" in handle

# Approach B:
pos = handle.find("@")

# Approach C:
idx = handle.index("@")
```

What does each approach produce? What are the practical trade-offs, and when should you choose each?

<Accordions>
<Accordion title="Reveal Solution & Explanation">

**Results:**

- **Approach A (`in`)**: Evaluates to `False` (`bool`).
- **Approach B (`.find()`)**: Evaluates to `-1` (`int`).
- **Approach C (`.index()`)**: Crashes with `ValueError: substring not found`.

**Operational Guidance:**

- Use **`in`** when you only need a **boolean existence check** (e.g., `if "@" not in email:`). It is the cleanest and fastest check.
- Use **`.find()`** when you need the **character position** but the substring is optional and its absence should not interrupt execution.
- Use **`.index()`** when the substring **must** exist for the program to continue sensibly, and missing it represents an invalid condition that should be caught by error handling.

</Accordion>
</Accordions>

### Question 4: Practical Data Cleaning Pipeline

Write a small pipeline that cleans raw user input from a signup form:

```python
raw_name = "  eLoN mUsK  "
raw_phone = "+1 (800) 555-0199 "
```

Requirements:

1. Normalize `raw_name` to proper title case (`"Elon Musk"`), removing all outer whitespace.
2. Sanitize `raw_phone` by removing spaces, parentheses, dashes, and the leading `+1 ` prefix so only the 10 digits `"8005550199"` remain.
3. Use an f-string to output: `"User: Elon Musk | Verified Phone: 8005550199"`.

<Accordions>
<Accordion title="Reveal Solution & Code">

```python
raw_name = "  eLoN mUsK  "
raw_phone = "+1 (800) 555-0199 "

# 1. Clean name
clean_name = raw_name.strip().title()

# 2. Clean phone using chained replace calls
clean_phone = (
    raw_phone.replace("+1", "")
    .replace("(", "")
    .replace(")", "")
    .replace("-", "")
    .replace(" ", "")
)

# 3. Formatted output
log_message = f"User: {clean_name} | Verified Phone: {clean_phone}"
print(log_message)
# Output: User: Elon Musk | Verified Phone: 8005550199
```

### Question 5: Production F-String Features (Format Specifiers & Self-Documenting Expressions)

Predict the console output of the following modern Python f-strings:

```python
discount_rate = 0.175
gross_sales = 4589200
status = "ACTIVE"

print(f"Discount: {discount_rate:.1%}")
print(f"Revenue:  ${gross_sales:,}")
print(f"Debug:    {status=}")
```

<Accordions>
<Accordion title="Reveal Solution & Explanation">

**Output:**

```text
Discount: 17.5%
Revenue:  $4,589,200
Debug:    status='ACTIVE'
```

**Under the Hood:**

- **`:.1%`**: Automatically multiplies the decimal by 100, rounds to 1 decimal place, and appends the `%` sign.
- **`:,`**: Automatically adds standard thousands-separator commas to large numbers.
- **`{var=}`**: Self-documenting expression introduced in Python 3.8. It prints both the expression name and its evaluated value—extremely handy for rapid terminal debugging without repetitive typing!

</Accordion>
</Accordions>

## Summary Reference Table

| Syntax            | Operation                               | Result Type | Example                            |
| :---------------- | :-------------------------------------- | :---------- | :--------------------------------- |
| `f"{var}"`        | Interpolate variables into text         | `str`       | `f"Hello, {name}"`                 |
| `len(s)`          | General function to measure length      | `int`       | `len("cat") -> 3`                  |
| `s.upper()`       | Convert all characters to uppercase     | `str` (New) | `"hi".upper() -> "HI"`             |
| `s.lower()`       | Convert all characters to lowercase     | `str` (New) | `"HI".lower() -> "hi"`             |
| `s.title()`       | Capitalize first letter of every word   | `str` (New) | `"py book".title() -> "Py Book"`   |
| `s.find(sub)`     | Return index of first match or `-1`     | `int`       | `"abc".find("b") -> 1`             |
| `s.replace(a, b)` | Replace all occurrences of `a` with `b` | `str` (New) | `"cat".replace("c", "b") -> "bat"` |
| `sub in s`        | Check substring membership              | `bool`      | `"th" in "python" -> True`         |
