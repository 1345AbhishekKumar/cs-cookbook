Welcome to **Stage 4: CPython Runtime Internals & Systems Engineering**.

In this stage, you open the hood of the CPython C codebase itself (`github.com/python/cpython`) to understand how high-level abstractions map down to physical hardware registers, bytecode stacks, and memory arenas.

---

## Stage 4 Core Topics

<Steps>
<Step>
### 01. The CPython Compilation Pipeline
Navigating the source tree: from human code to the PEG Parser (`pegen`), Abstract Syntax Tree (`ast.c`), Symbol Table (`symtable.c`), and Control Flow Graph compiler (`compile.c`).
</Step>

<Step>
### 02. Bytecode & The Evaluation Stack Machine
Deconstructing Python code objects (`PyCodeObject`), examining bytecode instructions with `dis.dis()`, the evaluation loop (`_PyEval_EvalFrameDefault` in `ceval.c`), Tier 1 Specialized Adaptive Interpreter (PEP 659), and the Python 3.13 Copy-and-Patch JIT (PEP 744).
</Step>

<Step>
### 03. PyObject Struct & Memory Allocator
The anatomy of `PyObject` (`ob_refcnt`, `ob_type`), the multi-tiered memory architecture (Arenas → Pools → Blocks in `obmalloc`), and the integration of Microsoft's `mimalloc` allocator in Python 3.13.
</Step>

<Step>
### 04. The GIL, Subinterpreters & Free-Threading (PEP 703)
The mechanics of the Global Interpreter Lock, Per-Interpreter GILs (PEP 684/734), and the free-threaded CPython build (`--disable-gil` in Python 3.13+): Biased Reference Counting, Immortal Objects (PEP 683), and lock-free container access.
</Step>

<Step>
### 05. Native C & Rust Extensions with PyO3
Writing high-speed, thread-safe native extensions using Rust, **PyO3**, and `maturin`. Managing `PyObject` reference ownership and releasing the GIL via `py.allow_threads` for raw parallel CPU performance.
</Step>

<Step>
### Capstone: pytrace-vm Bytecode Evaluator
Build a miniature virtual machine in pure Python that parses Python code objects and simulates the CPython stack machine (`LOAD_CONST`, `STORE_NAME`, `BINARY_OP`, `POP_JUMP_IF_FALSE`, `RETURN_VALUE`).
</Step>
</Steps>
