One of the best qualities of Python is its consistency. When you want the length of a string, a list, a dictionary, or a custom database record, you don't call `.size()`, `.count()`, or `.length()`. You always write:

```python
len(collection)
```

How does Python accomplish this uniform elegance? The answer is **The Python Data Model**.

---

## Mental Model: The Double-Underscore ("Dunder") Protocol

Python's syntax is not hardcoded to built-in objects. Instead, the Python interpreter delegates almost every language feature — addition (`+`), indexing (`[]`), iteration (`for x in`), length (`len()`), and string representation — to special methods whose names begin and end with two underscores: **dunder methods** (double underscore).

```mermaid
flowchart LR
    SYN["Your Code: len(cart)"] --> INT["Interpreter Intercepts"]
    INT --> DUND["Calls: cart.__len__()"]
    DUND --> RES["Returns integer length"]
```

When you write `len(x)`, CPython actually calls `type(x).__len__(x)` under the hood.

## 1. Developer Truth vs. User Beauty: `__repr__` vs. `__str__`

When you print an object or inspect it in a debugger, Python asks the object how it should be rendered:

```python
class Vector2D:
    def __init__(self, x: float, y: float):
        self.x = x
        self.y = y

    def __repr__(self) -> str:
        """Unambiguous developer view: exactly how to recreate the object."""
        return f"Vector2D(x={self.x}, y={self.y})"

    def __str__(self) -> str:
        """Readable user view: clean for end-user UI/logs."""
        return f"({self.x}, {self.y})"

v = Vector2D(3.0, 4.0)

print(str(v))   # Uses __str__
print(repr(v))  # Uses __repr__
```

Output:

```text
(3.0, 4.0)
Vector2D(x=3.0, y=4.0)
```

<Callout type="tip" title="Rule of Thumb: repr vs str">
  - **`__repr__`**: Aimed at the **developer**. It should be unambiguous. If
  possible, it should look like valid Python code that could recreate the exact
  same object: <code>eval(repr(obj)) == obj</code>. - **`__str__`**: Aimed at
  the **end-user**. It should be pretty and readable. - If you only implement
  one, **always implement `__repr__`** — Python will automatically fall back to
  it whenever `__str__` is requested!
</Callout>

## 2. Operator Overloading: Arithmetic Protocols

You can make your custom objects respond to standard arithmetic operators (`+`, `-`, `*`) by implementing numeric dunder methods:

```python
class Vector2D:
    def __init__(self, x: float, y: float):
        self.x = x
        self.y = y

    def __repr__(self) -> str:
        return f"Vector2D(x={self.x}, y={self.y})"

    def __add__(self, other: Vector2D) -> Vector2D:
        """Called for the '+' operator: v1 + v2"""
        if not isinstance(other, Vector2D):
            return NotImplemented
        return Vector2D(self.x + other.x, self.y + other.y)

    def __mul__(self, scalar: float) -> Vector2D:
        """Called for the '*' operator: v * 2"""
        return Vector2D(self.x * scalar, self.y * scalar)

v1 = Vector2D(1, 2)
v2 = Vector2D(3, 4)

print("Addition:", v1 + v2)
print("Scalar Multiplication:", v1 * 3)
```

Output:

```text
Addition: Vector2D(x=4, y=6)
Scalar Multiplication: Vector2D(x=3, y=6)
```

### Reflected (Right-Hand) Operators: `__radd__`, `__rmul__`

In the code above, `v * 3` works, but what happens if you write `3 * v`?

```python
try:
    print(3 * v1)
except TypeError as err:
    print("Caught error:", err)
# Output: TypeError: unsupported operand type(s) for *: 'int' and 'Vector2D'
```

Python integers know how to multiply numbers, but they have no idea what a `Vector2D` is!

To support `3 * v`, Python checks for a **Reflected (Right-Hand) Operator**:

```mermaid
flowchart TD
    EXPR["Expression: 3 * v"] --> S1["1. Try: type(3).__mul__(3, v)"]
    S1 -->|"Returns NotImplemented"| S2["2. Fallback: type(v).__rmul__(v, 3)"]
    S2 -->|"Found __rmul__!"| S3["Executes custom vector scalar math"]
    S2 -->|"Missing or NotImplemented"| ERR["Raises TypeError: unsupported operand"]
```

```python
class Vector2D:
    def __init__(self, x: float, y: float):
        self.x = x
        self.y = y

    def __mul__(self, scalar: float) -> "Vector2D":
        if not isinstance(scalar, (int, float)):
            return NotImplemented
        return Vector2D(self.x * scalar, self.y * scalar)

    def __rmul__(self, scalar: float) -> "Vector2D":
        """Called when left operand doesn't know how to multiply with Vector2D."""
        return self.__mul__(scalar)

v = Vector2D(4, 5)
print("Left multiply (v * 2):", v * 2)
print("Right multiply (2 * v):", 2 * v)
```

Output:

```text
Left multiply (v * 2): Vector2D(x=8, y=10)
Right multiply (2 * v): Vector2D(x=8, y=10)
```

<Callout type="warning" title="Always Return NotImplemented, Never Raise NotImplementedError!">
When an operator dunder cannot handle the type of the `other` argument, **always `return NotImplemented`** (a Python built-in singleton value), do **not** `raise NotImplementedError`!

- If you `return NotImplemented`, Python gracefully falls back to checking the other operand's reflected method (`__radd__`, `__rmul__`).
- If you `raise NotImplementedError`, the exception aborts execution immediately, preventing Python from attempting the fallback method!
  </Callout>

#### The Subclass Precedence Rule

There is an important edge case in operator resolution:

> If the right-hand operand is an instance of a **subclass** of the left-hand operand, Python invokes the subclass's reflected method **first**, even before the base class's normal method!

This allows derived classes to override math operations and customize how they interact with their own parent classes.

### In-Place Operators: `__iadd__`, `__imul__`

In-place operators like `+=` and `*=` are handled by in-place dunder methods:

- **Mutable Objects** (e.g., `list`): `__iadd__` mutates the existing instance in place and returns `self`. The memory identity (`id(obj)`) remains unchanged.
- **Immutable Objects** (e.g., `int`, `str`, `tuple`): Python falls back to `a = a + b`, allocating a completely new object and rebinding the variable name.

```python
# Mutable list in-place:
nums1 = [1, 2]
original_id = id(nums1)
nums1 += [3]
print("List ID preserved?", id(nums1) == original_id)  # True!

# Immutable int:
num = 100
int_id = id(num)
num += 5
print("Int ID preserved?", id(num) == int_id)  # False! Created new int 105
```

#### The Infamous Tuple-List Mutation Trap

Consider this famous Python puzzle that stumps even experienced developers:

```python
t = (1, [10, 20])
try:
    t[1] += [30]
except TypeError as err:
    print("Caught TypeError:", err)

print("Contents of t:", t)
```

Output:

```text
Caught TypeError: 'tuple' object does not support item assignment
Contents of t: (1, [10, 20, 30])
```

Why did `[30]` get added even though Python raised a `TypeError`?

1. The inner object `t[1]` is a `list`. Python called `t[1].__iadd__([30])`, which mutated the list in place successfully!
2. Then Python attempted to assign the result back to `t[1]` (`t[1] = ...`).
3. Because tuples are immutable, the assignment step raised `TypeError`.
4. The mutation already completed before the assignment failed!

## 3. Rich Comparison Protocols & `@functools.total_ordering`

Python defines six comparison dunder methods:

| Operator | Dunder Method         | Fallback Reflection   |
| :------- | :-------------------- | :-------------------- |
| `==`     | `__eq__(self, other)` | `other.__eq__(self)`  |
| `!=`     | `__ne__(self, other)` | `not (self == other)` |
| `<`      | `__lt__(self, other)` | `other.__gt__(self)`  |
| `<=`     | `__le__(self, other)` | `other.__ge__(self)`  |
| `>`      | `__gt__(self, other)` | `other.__lt__(self)`  |
| `>=`     | `__ge__(self, other)` | `other.__le__(self)`  |

### Eliminating Boilerplate with `@total_ordering`

Implementing all six comparison methods manually is tedious. The standard library provides `@functools.total_ordering`:

> Implement `__eq__` and **any one** ordering method (`__lt__`, `__le__`, `__gt__`, or `__ge__`), and Python automatically synthesizes all remaining comparison operators for you!

```python
from functools import total_ordering

@total_ordering
class Task:
    def __init__(self, title: str, priority: int):
        self.title = title
        self.priority = priority

    def __eq__(self, other: object) -> bool:
        if not isinstance(other, Task):
            return NotImplemented
        return self.priority == other.priority

    def __lt__(self, other: object) -> bool:
        if not isinstance(other, Task):
            return NotImplemented
        return self.priority < other.priority

    def __repr__(self) -> str:
        return f"Task({self.title!r}, p={self.priority})"

t1 = Task("Fix critical bug", 1)
t2 = Task("Refactor CSS", 3)
t3 = Task("Deploy update", 1)

print("t1 < t2 :", t1 < t2)    # True (via __lt__)
print("t1 <= t3:", t1 <= t3)   # True (synthesized by total_ordering!)
print("t2 > t1 :", t2 > t1)    # True (synthesized by total_ordering!)
print("t1 == t3:", t1 == t3)   # True (via __eq__)

# Built-in sorting works automatically:
tasks = [t2, t1, t3]
print("Sorted tasks:", sorted(tasks))
```

Output:

```text
t1 < t2 : True
t1 <= t3: True
t2 > t1 : True
t1 == t3: True
Sorted tasks: [Task('Fix critical bug', p=1), Task('Deploy update', p=1), Task('Refactor CSS', p=3)]
```

## 4. The Sequence & Mapping Protocols: Indexing & Slicing

When you use square brackets `container[key]`, Python invokes the sequence/mapping dunder methods:

- `__getitem__(self, key)`: Read `val = container[key]` or slices `container[1:5]`.
- `__setitem__(self, key, value)`: Write `container[key] = value`.
- `__delitem__(self, key)`: Delete `del container[key]`.
- `__contains__(self, item)`: Membership test `item in container`.

### Handling Slices with `slice.indices()`

When someone slices your object (`obj[1:10:2]`), the `key` argument passed to `__getitem__` is not an integer — it is a **`slice` object**!

The standard library provides `slice.indices(length)` to automatically normalize positive/negative bounds, `None`, and stride steps:

```python
class RollingLogBuffer:
    def __init__(self, items: list[str]):
        self._items = list(items)

    def __len__(self) -> int:
        return len(self._items)

    def __getitem__(self, index: int | slice):
        if isinstance(index, slice):
            # Normalizes start, stop, and step against the buffer's length
            start, stop, step = index.indices(len(self._items))
            return [self._items[i] for i in range(start, stop, step)]
        elif isinstance(index, int):
            return self._items[index]
        raise TypeError(f"Invalid index type: {type(index).__name__}")

    def __contains__(self, item: str) -> bool:
        return item in self._items

buffer = RollingLogBuffer(["log1", "log2", "log3", "log4", "log5"])

print("Single item   :", buffer[0])
print("Slice [1:4]   :", buffer[1:4])
print("Negative slice:", buffer[-2:])
print("Membership    :", "log3" in buffer)
```

Output:

```text
Single item   : log1
Slice [1:4]   : ['log2', 'log3', 'log4']
Negative slice: ['log4', 'log5']
Membership    : True
```

## 5. The Boolean Truthiness Protocol: `__bool__` vs. `__len__`

How does Python evaluate `if obj:` or `bool(obj)`?

It checks two dunder methods in strict order:

1. **`__bool__(self)`**: Evaluated first. Must return `True` or `False`.
2. **`__len__(self)` Fallback**: If `__bool__` is not implemented, Python calls `__len__()`. If the length is `0`, the object evaluates to `False`; otherwise `True`.
3. If **neither** method is defined, all instances of the class evaluate to **`True`** by default!

```python
class ShoppingCart:
    def __init__(self):
        self.items = []

    def add(self, item: str):
        self.items.append(item)

    def __len__(self) -> int:
        return len(self.items)

cart = ShoppingCart()
# Since __bool__ is missing, Python falls back to __len__() == 0:
print("Empty cart truthiness:", bool(cart))  # False

cart.add("Mechanical Keyboard")
print("Full cart truthiness :", bool(cart))  # True
```

## 6. The Hashability Invariant: `__eq__` and `__hash__`

Can you put your custom objects into a `set` or use them as keys in a `dict`?

Only if they are **hashable**. An object is hashable if it has a hash value that never changes during its lifetime and can be compared to other objects.

```python
class UserID:
    def __init__(self, raw_id: int):
        self._raw_id = raw_id

    def __eq__(self, other: object) -> bool:
        if not isinstance(other, UserID):
            return False
        return self._raw_id == other._raw_id

    def __hash__(self) -> int:
        return hash(self._raw_id)

    def __repr__(self) -> str:
        return f"UserID({self._raw_id})"

u1 = UserID(101)
u2 = UserID(101)

# A set automatically recognizes they are identical!
active_users = {u1, u2}
print("Set contains:", active_users)
print("Are they equal?", u1 == u2)
```

Output:

```text
Set contains: {UserID(101)}
Are they equal? True
```

<Callout type="error" title="The Cardinal Invariant of Hashability">
If two objects are considered equal according to `__eq__`, they **MUST return the exact same integer from `__hash__`**:

> **If `a == b`, then `hash(a) == hash(b)`**

If you violate this rule, dictionaries and sets will fail silently, storing duplicate "equal" keys or failing to find items that exist!

</Callout>

### Why Mutable Objects Must Never Be Hashable

Why doesn't Python allow `list`, `dict`, or `set` to be hashed?

Consider what a hash table (like a `dict` or `set`) actually does:

1. When you insert `s.add(obj)`, Python calculates `h = hash(obj)`.
2. It uses `h` to decide which memory **bucket** the object should live in.
3. If `obj` is mutable, and its attributes change later, its hash value would change!
4. The next time you check `obj in s`, Python computes the **new** hash value, looks in a completely different bucket, and concludes that the object is not in the set — even though the object is literally sitting right there in memory!

To prevent this catastrophic data loss bug, Python enforces two strict rules:

1. **Mutable built-in collections have no `__hash__`** (they raise `TypeError: unhashable type: 'list'`).
2. **If you define `__eq__` in a custom class, Python automatically sets `__hash__ = None`**:
   - Unless you explicitly implement `__hash__`, Python will refuse to let instances be placed into sets or dictionaries.
   - You should only implement `__hash__` if your object's identifying fields are **immutable** (e.g. stored in read-only properties or a frozen dataclass).

### Question 2: Spot and Fix the Bug (The Unhashable Type Trap)

A backend engineer creates a `UserSession` class to track active logged-in users in a `set`:

```python
class UserSession:
    def __init__(self, user_id: int, ip_address: str):
        self.user_id = user_id
        self.ip_address = ip_address

    def __eq__(self, other):
        if not isinstance(other, UserSession):
            return False
        return self.user_id == other.user_id and self.ip_address == other.ip_address

# In the authentication gateway:
active_sessions = set()
session = UserSession(101, "192.168.1.1")
active_sessions.add(session)
```

Running this code immediately crashes on `active_sessions.add(session)` with:

```text
TypeError: unhashable type: 'UserSession'
```

1. Why does defining `__eq__` automatically make a class unhashable in Python?
2. What invariant must be preserved between `__eq__` and `__hash__`?
3. Rewrite `UserSession` so it can be stored in sets and used as dictionary keys safely.

<Accordions>
<Accordion title="Reveal Solution & Explanation">

**1. Why Python Sets `__hash__ = None`:**
In Python, objects without a custom `__eq__` inherit object identity hashing (`id(self)`). However, if you define a custom `__eq__`, two distinct instances might be considered equal (`s1 == s2`). If they used identity hashing, they would produce different hashes and violate set/dict lookup rules. To prevent silent data corruption, Python automatically sets `__hash__ = None` whenever `__eq__` is overridden.

**2. The Hash Invariant:**
If two objects compare equal (`a == b`), they **must** return the exact same integer from `hash(a) == hash(b)`.

**3. Corrected Class:**

```python
class UserSession:
    def __init__(self, user_id: int, ip_address: str):
        self.user_id = user_id
        self.ip_address = ip_address

    def __eq__(self, other: object) -> bool:
        if not isinstance(other, UserSession):
            return False
        return (self.user_id, self.ip_address) == (other.user_id, other.ip_address)

    def __hash__(self) -> int:
        # Hash a tuple containing the exact same attributes used in __eq__:
        return hash((self.user_id, self.ip_address))
```

### Question 5: Code Challenge (Production Vector2D with Math Dunders)

Implement a 2D mathematical vector class `Vector2D` that feels like a native Python numeric type.

Requirements:

1. `__init__(self, x: float, y: float)`: Accepts $x$ and $y$ coordinates.
2. `__repr__(self)`: Returns `Vector2D(x, y)`.
3. `__add__(self, other)`: Vector addition `Vector2D(self.x + other.x, self.y + other.y)`.
4. `__mul__(self, scalar)`: Scalar multiplication `Vector2D(self.x * scalar, self.y * scalar)`. Support reverse multiplication (`scalar * vector`) via `__rmul__`.
5. `__abs__(self)`: Euclidean magnitude $\sqrt{x^2 + y^2}$.
6. `__bool__(self)`: Returns `False` if magnitude is zero (origin vector), otherwise `True`.
7. `__eq__` and `__hash__`: Support equality comparison and hashability so vectors can be stored in sets.

<Accordions>
<Accordion title="Reveal Solution & Code">

```python
import math

class Vector2D:
    __slots__ = ("_x", "_y")

    def __init__(self, x: float, y: float):
        self._x = float(x)
        self._y = float(y)

    @property
    def x(self) -> float:
        return self._x

    @property
    def y(self) -> float:
        return self._y

    def __repr__(self) -> str:
        return f"Vector2D({self._x}, {self._y})"

    def __add__(self, other: object) -> "Vector2D":
        if not isinstance(other, Vector2D):
            return NotImplemented
        return Vector2D(self._x + other._x, self._y + other._y)

    def __mul__(self, scalar: float | int) -> "Vector2D":
        if not isinstance(scalar, (int, float)):
            return NotImplemented
        return Vector2D(self._x * scalar, self._y * scalar)

    def __rmul__(self, scalar: float | int) -> "Vector2D":
        # Supports: 3 * v
        return self.__mul__(scalar)

    def __abs__(self) -> float:
        # Supports: abs(v)
        return math.hypot(self._x, self._y)

    def __bool__(self) -> bool:
        # Supports: bool(v), if v:
        return bool(self._x or self._y)

    def __eq__(self, other: object) -> bool:
        if not isinstance(other, Vector2D):
            return False
        return math.isclose(self._x, other._x) and math.isclose(self._y, other._y)

    def __hash__(self) -> int:
        return hash((self._x, self._y))

# Verification Test:
if __name__ == "__main__":
    v1 = Vector2D(3, 4)
    v2 = Vector2D(1, 2)

    print("Addition       :", v1 + v2)        # Vector2D(4.0, 6.0)
    print("Scalar Multi   :", v1 * 2)         # Vector2D(6.0, 8.0)
    print("Reverse Multi  :", 2 * v1)         # Vector2D(6.0, 8.0)
    print("Magnitude (hyp):", abs(v1))        # 5.0
    print("Truthiness     :", bool(v1))       # True
    print("Zero vector    :", bool(Vector2D(0, 0))) # False

    vector_set = {v1, Vector2D(3, 4)}
    print("Set deduplication count:", len(vector_set))  # 1 (Successfully deduplicated!)
```

## Summary Reference

| Dunder Method          | Trigger / Syntax         | Purpose                                      |
| :--------------------- | :----------------------- | :------------------------------------------- |
| `__init__(self, ...)`  | `cls(...)`               | Initialize a newly created instance.         |
| `__repr__(self)`       | `repr(obj)`              | Unambiguous developer string representation. |
| `__str__(self)`        | `str(obj)`, `print(obj)` | Readable user string representation.         |
| `__add__(self, other)` | `a + b`                  | Binary addition operator.                    |
| `__eq__(self, other)`  | `a == b`                 | Equality comparison operator.                |
| `__hash__(self)`       | `hash(obj)`              | Integer hash for sets and dict keys.         |
