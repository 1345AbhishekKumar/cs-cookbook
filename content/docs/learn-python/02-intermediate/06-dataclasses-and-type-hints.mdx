Before Python 3.7, writing a clean data transfer object required writing dozens of lines of repetitive boilerplate for `__init__`, `__repr__`, and `__eq__`.

Today, **`dataclasses`** combined with Python 3.12's **PEP 695 native type parameter syntax** provide a concise, high-performance, and type-safe foundation.

---

## 1. The Modern Production Dataclass

```python
from dataclasses import dataclass, field
import uuid

@dataclass(slots=True, frozen=True, kw_only=True)
class CustomerRecord:
    id: uuid.UUID = field(default_factory=uuid.uuid4)
    username: str
    email: str
    roles: tuple[str, ...] = ("user",)

    def __post_init__(self):
        """Validate business invariants upon instantiation."""
        if "@" not in self.email:
            raise ValueError(f"Invalid email address: {self.email}")

user = CustomerRecord(username="alex", email="alex@example.com")
print(user)
print("Role:", user.roles)
```

Output:

```text
CustomerRecord(id=UUID('...'), username='alex', email='alex@example.com', roles=('user',))
Role: ('user',)
```

### Key Dataclass Flags:

- **`slots=True`**: Disables the default instance `__dict__`. Prevents arbitrary attribute assignment and **reduces memory usage by 40–50%**!
- **`frozen=True`**: Makes instances immutable. Automatically generates a `__hash__` method, allowing instances to be used as keys in dictionaries or stored in sets.
- **`kw_only=True`**: Enforces that all attributes must be specified as keyword arguments at call sites, preventing positional mixing bugs.
- **`field(default_factory=...)`**: Safe generation of unique default instances (e.g. `uuid4()`, or factory functions for mutable containers).

## 2. Python 3.12+ Native Generic Syntax (PEP 695)

In Python 3.12, the verbose legacy syntax `T = TypeVar("T")` and `Generic[T]` was replaced by native first-class language keywords:

```python
# Modern Python 3.12+ Generic Class Syntax:
class Stack[T]:
    def __init__(self):
        self._items: list[T] = []

    def push(self, item: T) -> None:
        self._items.append(item)

    def pop(self) -> T:
        return self._items.pop()

    def peek(self) -> T | None:
        return self._items[-1] if self._items else None

# Modern First-Class Type Alias:
type Point3D = tuple[float, float, float]
type JSONValue = str | int | float | bool | None | dict[str, "JSONValue"] | list["JSONValue"]

stack = Stack[int]()
stack.push(10)
stack.push(20)
print("Popped:", stack.pop())
```

Output:

```text
Popped: 20
```

## 3. Structural Subtyping: `typing.Protocol` (PEP 544)

In nominal typing languages (like Java or C#), a class must explicitly state `implements Serializable`. Python supports **static duck typing** via `Protocol`: if an object walks like a duck and quacks like a duck, static type checkers accept it — **no explicit inheritance required**.

```python
from typing import Protocol

# 1. Define the structural protocol
class Renderable(Protocol):
    def render(self) -> str: ...

# 2. Independent classes with NO shared inheritance
class MarkdownDocument:
    def __init__(self, content: str):
        self.content = content

    def render(self) -> str:
        return f"<article>{self.content}</article>"

class SVGGraphic:
    def __init__(self, shape: str):
        self.shape = shape

    def render(self) -> str:
        return f"<svg><{self.shape}/></svg>"

# 3. Type-safe consumer function
def export_html(item: Renderable) -> None:
    print("Exported:", item.render())

export_html(MarkdownDocument("Hello World"))
export_html(SVGGraphic("circle"))
```

Output:

```text
Exported: <article>Hello World</article>
Exported: <svg><circle/></svg>
```

Both `MarkdownDocument` and `SVGGraphic` satisfy the `Renderable` protocol without knowing it exists!

### Question 1: Output Prediction (Dataclass Immutability & Hashability)

Examine this frozen dataclass definition:

```python
from dataclasses import dataclass

@dataclass(frozen=True)
class EndpointConfig:
    host: str
    port: int = 8080

cfg1 = EndpointConfig("127.0.0.1")
cfg2 = EndpointConfig("127.0.0.1", 8080)

print("1. Equality   :", cfg1 == cfg2)
print("2. Set length :", len({cfg1, cfg2}))

try:
    cfg1.port = 9090
except Exception as err:
    print("3. Mutation   :", type(err).__name__)
```

1. What will lines 1, 2, and 3 output?
2. Why is `cfg1` hashable, while a standard non-frozen `@dataclass` cannot be placed in a `set`?
3. What exact exception type does Python raise on `cfg1.port = 9090`?

<Accordions>
<Accordion title="Reveal Solution & Explanation">

**1. Output:**

```text
1. Equality   : True
2. Set length : 1
3. Mutation   : FrozenInstanceError
```

**2. Explanation of Hashability:**

- By default, `@dataclass` generates `__eq__` but sets `__hash__ = None` because attributes are mutable.
- When `frozen=True` is enabled, Python marks instance attributes as read-only and automatically generates an optimal `__hash__` implementation based on the field values. Because `cfg1 == cfg2` and their hashes match, `{cfg1, cfg2}` deduplicates to length `1`.

**3. The Exception:**
Python raises `dataclasses.FrozenInstanceError: cannot assign to field 'port'`.

### Question 2: Spot and Fix the Bug (The Mutable Default & Ordering Traps)

A backend engineer creates this database configuration model:

```python
from dataclasses import dataclass

@dataclass
class DatabaseSettings:
    pool_size: int = 10
    database_url: str
    read_replicas: list[str] = []
```

When Python imports or runs this module, it crashes immediately before instantiating anything:

```text
ValueError: mutable default <class 'list'> for field read_replicas is not allowed: use default_factory
```

Even if you fix that, a `SyntaxError: non-default argument 'database_url' follows default argument 'pool_size'` occurs.

1. Why does Python forbid `read_replicas: list[str] = []` in dataclasses?
2. Why did `database_url: str` trigger an argument ordering error?
3. How does `kw_only=True` and `field(default_factory=...)` resolve both issues elegantly?

<Accordions>
<Accordion title="Reveal Solution & Explanation">

**1. The Mutable Default Trap:**
If Python allowed `read_replicas = []`, that single list instance would be shared across all instances of `DatabaseSettings`, causing mutations on one settings instance to corrupt all others. Python explicitly forbids mutable defaults to protect you.

**2. The Positional Argument Ordering Rule:**
In standard Python functions and generated constructors, parameters with default values cannot precede parameters without defaults (`database_url`).

**3. Corrected Model:**

```python
from dataclasses import dataclass, field

@dataclass(kw_only=True)  # Allows any order of defaults and non-defaults!
class DatabaseSettings:
    pool_size: int = 10
    database_url: str
    read_replicas: list[str] = field(default_factory=list)

# Usage:
settings = DatabaseSettings(database_url="postgresql://localhost/prod")
```

</Accordion>

### Question 3: Architecture Question (Nominal vs Structural Subtyping)

In Python typing:

1. What is the fundamental difference between inheriting from `abc.ABC` (**nominal subtyping**) and inheriting from `typing.Protocol` (**structural subtyping**)?
2. If class `AudioPlayer` defines a `play()` method, does it need to explicitly inherit from `class Playable(Protocol)` in its class header (`class AudioPlayer(Playable)`) to pass static type checking?
3. Why is `Protocol` often called **Static Duck Typing**?

<Accordions>
<Accordion title="Reveal Solution & Explanation">

**1. Nominal vs Structural:**

- **Nominal Subtyping (`ABC`)**: A class is only considered a subtype if it explicitly lists the parent in its inheritance hierarchy (`class Worker(Job):`).
- **Structural Subtyping (`Protocol`)**: A class is considered a subtype if its shape (attributes and methods) matches the protocol, regardless of its declared inheritance tree.

**2. No Inheritance Needed:**
No. `AudioPlayer` does **not** need to inherit from `Playable`. As long as it implements `def play(self) -> None`, type checkers like Pyright, Mypy, and IDEs accept it everywhere `Playable` is required.

**3. Static Duck Typing:**
The classic Python mantra is: _"If it walks like a duck and quacks like a duck, it's a duck."_ `Protocol` brings that dynamic duck typing into static compile-time type verification (PEP 544).

</Accordion>
</Accordions>

from dataclasses import dataclass

### Question 5: Code Challenge (High-Performance Immutable Value Object)

Create a production-grade immutable value object `Money` using modern dataclass features:

Requirements:

1. `@dataclass(slots=True, frozen=True)` with fields `amount: float` and `currency: str = "USD"`.
2. Add a `__add__(self, other)` method that:
   - Validates that `other` is an instance of `Money`.
   - Validates that `self.currency == other.currency`. If currencies differ, raise a `ValueError("Cannot add different currencies: X and Y")`.
   - Returns a new `Money` instance with the combined sum.
3. Add a custom `__str__` returning formatted output: `f"${self.amount:.2f} {self.currency}"`.
4. Ensure instances can be stored and deduplicated inside a `set`.

<Accordions>
<Accordion title="Reveal Solution & Code">

```python
from dataclasses import dataclass

@dataclass(slots=True, frozen=True)
class Money:
    amount: float
    currency: str = "USD"

    def __post_init__(self):
        # Validate non-negative amounts
        if self.amount < 0:
            raise ValueError("Money amount cannot be negative.")
        # Normalize currency code to uppercase
        object.__setattr__(self, "currency", self.currency.upper())

    def __add__(self, other: object) -> "Money":
        if not isinstance(other, Money):
            return NotImplemented
        if self.currency != other.currency:
            raise ValueError(f"Cannot add different currencies: {self.currency} and {other.currency}")
        return Money(round(self.amount + other.amount, 2), self.currency)

    def __str__(self) -> str:
        symbol = "$" if self.currency == "USD" else self.currency + " "
        return f"{symbol}{self.amount:.2f}"

# Verification Test:
if __name__ == "__main__":
    price1 = Money(49.99, "usd")
    price2 = Money(15.50, "USD")

    total = price1 + price2
    print("Total price:", total)  # $65.49
    assert total == Money(65.49, "USD")

    # Test set deduplication
    money_wallet = {price1, Money(49.99, "USD")}
    print("Deduplicated set size:", len(money_wallet))  # 1

    # Test currency mismatch guard
    try:
        price1 + Money(10.0, "EUR")
    except ValueError as err:
        print("Caught currency mismatch:", err)
```

## Summary Reference

- **`@dataclass(slots=True)`**: Eliminates `__dict__`, decreases memory overhead, increases attribute lookup speed.
- **`frozen=True`**: Creates hashable, read-only value objects.
- **PEP 695 Syntax**: `class Container[T]:` and `type Alias = ...` natively integrated into Python grammar.
- **`typing.Protocol`**: Compile-time structural duck typing without inheritance coupling.
