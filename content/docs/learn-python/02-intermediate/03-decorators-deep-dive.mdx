Decorators are one of Python's most elegant design patterns. They allow you to dynamically alter or extend the behavior of a function or class **without modifying its internal source code**.

---

## 1. What is a Decorator? Syntactic Sugar

At its core, a decorator is simply a callable that takes a function as input and returns a modified function as output:

```python
def my_decorator(func):
    def wrapper():
        print("Before execution")
        func()
        print("After execution")
    return wrapper

# The '@' symbol is syntactic sugar:
@my_decorator
def say_hello():
    print("Hello world!")

say_hello()
```

Output:

```text
Before execution
Hello world!
After execution
```

The `@my_decorator` syntax is identical to:

```python
say_hello = my_decorator(say_hello)
```

## 2. Preserving Function Metadata: `functools.wraps`

When you wrap a function, a subtle bug occurs if you are not careful:

```python
def log_call(func):
    def wrapper(*args, **kwargs):
        """Wrapper docstring."""
        return func(*args, **kwargs)
    return wrapper

@log_call
def calculate_tax(amount: float) -> float:
    """Calculates sales tax."""
    return amount * 0.08

print("Name:", calculate_tax.__name__)
print("Doc:", calculate_tax.__doc__)
```

Output:

```text
Name: wrapper
Doc: Wrapper docstring.
```

The original function's name and docstring were completely obliterated by the wrapper! Debuggers, documentation generators, and IDE tooltips will all report `"wrapper"`.

### The Fix: `@functools.wraps`

```python
from functools import wraps

def log_call(func):
    @wraps(func)  # Copies __name__, __doc__, __annotations__, and __module__
    def wrapper(*args, **kwargs):
        return func(*args, **kwargs)
    return wrapper

@log_call
def calculate_tax(amount: float) -> float:
    """Calculates sales tax."""
    return amount * 0.08

print("Name:", calculate_tax.__name__)
print("Doc:", calculate_tax.__doc__)
```

Output:

```text
Name: calculate_tax
Doc: Calculates sales tax.
```

## 3. Parametric Decorators: Decorators that Accept Arguments

What if you want a decorator that accepts configuration arguments, like `@retry(max_attempts=3)`?

This requires **three layers of nested functions**:

1. Outer function: receives the decorator's arguments (`max_attempts`).
2. Middle function: receives the target function (`func`).
3. Inner wrapper: receives the function call arguments (`*args, **kwargs`).

```python
import time
from functools import wraps

def retry(max_attempts: int = 3, delay: float = 0.5):
    def decorator(func):
        @wraps(func)
        def wrapper(*args, **kwargs):
            last_err = None
            for attempt in range(1, max_attempts + 1):
                try:
                    return func(*args, **kwargs)
                except Exception as err:
                    last_err = err
                    print(f"Attempt {attempt} failed: {err}. Retrying in {delay}s...")
                    time.sleep(delay)
            raise RuntimeError(f"All {max_attempts} attempts failed") from last_err
        return wrapper
    return decorator

@retry(max_attempts=3, delay=0.1)
def unstable_network_call(success_on_attempt: int):
    unstable_network_call.counter = getattr(unstable_network_call, "counter", 0) + 1
    if unstable_network_call.counter < success_on_attempt:
        raise ConnectionResetError("Remote server disconnected")
    return "Data payload received successfully!"

print(unstable_network_call(2))
```

Output:

```text
Attempt 1 failed: Remote server disconnected. Retrying in 0.1s...
Data payload received successfully!
```

## 4. Modern Type-Safe Decorators: `ParamSpec` (PEP 612)

Historically, decorating a function wiped out its type hints in IDEs. Python 3.10+ introduced `typing.ParamSpec` and `typing.Concatenate` to allow decorators to preserve the exact parameter signature and return type of the wrapped function:

```python
from collections.abc import Callable
from functools import wraps
import time
from typing import ParamSpec, TypeVar

P = ParamSpec("P")
R = TypeVar("R")

def measure_latency(func: Callable[P, R]) -> Callable[P, R]:
    @wraps(func)
    def wrapper(*args: P.args, **kwargs: P.kwargs) -> R:
        start = time.perf_counter()
        result = func(*args, **kwargs)
        duration = time.perf_counter() - start
        print(f"[{func.__name__}] Executed in {duration * 1000:.3f}ms")
        return result
    return wrapper

@measure_latency
def compute_primes(limit: int) -> int:
    return len([x for x in range(2, limit) if all(x % d != 0 for d in range(2, int(x**0.5) + 1))])

count = compute_primes(10000)
print(f"Primes found: {count}")
```

Output:

```text
[compute_primes] Executed in 12.450ms
Primes found: 1229
```

Because of `Callable[P, R]`, `pyright` and `mypy` know that `compute_primes` accepts an integer and returns an integer — complete with full autocomplete!

### Question 1: Output Prediction (Decorator Stacking Order)

Without executing the code, determine the exact terminal output when `greet()` is called:

```python
def uppercase(func):
    def wrapper(*args, **kwargs):
        print("[uppercase] wrapper entered")
        result = func(*args, **kwargs)
        return result.upper()
    return wrapper

def emphasize(func):
    def wrapper(*args, **kwargs):
        print("[emphasize] wrapper entered")
        result = func(*args, **kwargs)
        return f"*** {result} ***"
    return wrapper

@uppercase
@emphasize
def greet(name: str) -> str:
    print("[greet] core function running")
    return f"hello {name}"

print("Final Output:", greet("alice"))
```

<Accordion title="Reveal Solution & Explanation">

```text
[uppercase] wrapper entered
[emphasize] wrapper entered
[greet] core function running
Final Output: *** HELLO ALICE ***
```

**Why this execution order occurs:**

1. **Definition Time**: Stacking decorators evaluates from bottom to top:
   ```python
   greet = uppercase(emphasize(greet))
   ```
   First, `emphasize` wraps `greet`. Then, `uppercase` wraps the resulting wrapper.
2. **Execution Time**: The outermost wrapper (`uppercase`) executes first, calls the inner wrapper (`emphasize`), which calls the core `greet()` function.
3. The returned string `"*** hello alice ***"` from `emphasize` is passed into `uppercase`, which calls `.upper()` to produce `"*** HELLO ALICE ***"`.

```python
    return wrapper
```

### Question 3: Architecture Question (Why Parametric Decorators Require 3 Levels)

When a decorator takes arguments, such as `@repeat(times=3)`:

1. Why does a standard 2-level decorator pattern (`def decorator(func): def wrapper(): ...`) fail?
2. Trace what Python evaluates when it encounters `@repeat(times=3) def task(): ...`.
3. What does each of the 3 nested functions accept as its parameters?

<Accordions>
<Accordion title="Reveal Solution & Explanation">

**1. The Mechanics of Decorator Arguments:**
In Python, `@expression` evaluates the expression first, and then applies the resulting callable to the decorated function:

```python
# @repeat(times=3)
# def task(): ...
# Expands to:
task = repeat(times=3)(task)
```

**2. The 3-Tier Hierarchy:**
Because `repeat(times=3)` must return a _decorator_, which in turn returns a _wrapper_, three nested levels are required:

- **Tier 1 (Outer Factory)**: `def repeat(times: int)` $\rightarrow$ Accepts the configuration arguments. Returns the decorator function.
- **Tier 2 (Decorator)**: `def decorator(func: Callable)` $\rightarrow$ Accepts the actual function being decorated. Returns the wrapper.
- **Tier 3 (Wrapper)**: `def wrapper(*args, **kwargs)` $\rightarrow$ Replaces `func` at runtime, executing the loop logic and invoking `func(*args, **kwargs)`.

### Question 4: Hands-On Challenge (`@validate_positive` Input Sanitizer)

Implement a `@validate_positive` decorator that inspects all numeric positional and keyword arguments passed to a function and raises a `ValueError` if any argument is $\le 0$.

<Accordions>
<Accordion title="Reveal Solution & Explanation">

```python
from functools import wraps

def validate_positive(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        # Inspect positional arguments
        for arg in args:
            if isinstance(arg, (int, float)) and arg <= 0:
                raise ValueError(f"Positional argument must be strictly positive, got {arg}")
        # Inspect keyword arguments
        for key, val in kwargs.items():
            if isinstance(val, (int, float)) and val <= 0:
                raise ValueError(f"Keyword argument '{key}' must be strictly positive, got {val}")
        return func(*args, **kwargs)
    return wrapper

@validate_positive
def calculate_box_volume(width: float, height: float, depth: float = 1.0) -> float:
    return width * height * depth

# Verification:

try:
    calculate_box_volume(2.0, -1.0)
except ValueError as err:
```

### Question 5: Code Challenge (Production `@retry` with Exponential Backoff)

Write a production-grade parametric decorator `@retry(max_retries=3, backoff_base=0.1, exceptions=(Exception,))`.

Requirements:

1. Wrap the decorated function preserving metadata via `@functools.wraps`.
2. Intercept any exception that is an instance of `exceptions`.
3. If an intercepted exception occurs, wait for `backoff_base * (2 ** attempt)` seconds using `time.sleep()`, and retry.
4. If all retries fail, re-raise the final exception.
5. If the function succeeds, return its result immediately.

<Accordions>
<Accordion title="Reveal Solution & Code">

```python
from functools import wraps
import time
from typing import Callable, Any

def retry(
    max_retries: int = 3,
    backoff_base: float = 0.1,
    exceptions: tuple[type[Exception], ...] = (Exception,)
) -> Callable:
    """
    Parametric decorator that retries a function with exponential backoff on transient failures.
    """
    def decorator(func: Callable) -> Callable:
        @wraps(func)
        def wrapper(*args: Any, **kwargs: Any) -> Any:
            last_err = None
            for attempt in range(max_retries):
                try:
                    return func(*args, **kwargs)
                except exceptions as err:
                    last_err = err
                    delay = backoff_base * (2 ** attempt)
                    print(f"⚠️ [Attempt {attempt + 1}/{max_retries}] {func.__name__} failed ({err}). Retrying in {delay:.2f}s...")
                    time.sleep(delay)
            # Exhausted retries:
            raise last_err  # Re-raise the final caught exception
        return wrapper
    return decorator

# Verification Test:
if __name__ == "__main__":
    calls = 0

    @retry(max_retries=3, backoff_base=0.05, exceptions=(ConnectionError,))
    def unstable_network_call():
        nonlocal calls
        calls += 1
        if calls < 3:
            raise ConnectionError("Temporary connection dropped")
        return "SUCCESS"

    result = unstable_network_call()
    print("Final result:", result)
    assert result == "SUCCESS"
    assert calls == 3
```

</Accordion>
</Accordions>

## Summary Reference

- **`@decorator`**: Equivalent to `func = decorator(func)`.
- **`@wraps(func)`**: Mandatory on all wrappers to preserve `__name__` and docstrings.
- **Parametric decorator**: 3-level function nest: `outer(args) -> middle(func) -> inner(*args, **kwargs)`.
- **`ParamSpec`**: Type hints that preserve parameter lists through wrapper decorators.
