## 1. CPU Profiling with `cProfile`

Python includes a native deterministic profiler: **`cProfile`**. It tracks the total time, number of calls, and cumulative time spent inside every single function:

```python
import cProfile
import pstats
import time

def slow_step():
    time.sleep(0.3)

def fast_step():
    total = sum(i for i in range(100_000))
    return total

def run_pipeline():
    for _ in range(3):
        slow_step()
        fast_step()

# Profile execution:
profiler = cProfile.Profile()
profiler.enable()

run_pipeline()

profiler.disable()
stats = pstats.Stats(profiler).sort_stats("cumulative")
stats.print_stats(5)
```

Output:

```text
         100021 function calls in 0.912 seconds

   Ordered by: cumulative time
   List reduced from 15 to 5 due to restriction <5>

   ncalls  tottime  percall  cumtime  percall filename:lineno(function)
        1    0.000    0.000    0.912    0.912 app.py:12(run_pipeline)
        3    0.000    0.000    0.901    0.300 app.py:5(slow_step)
        3    0.901    0.300    0.901    0.300 {built-in method time.sleep}
        3    0.008    0.003    0.011    0.004 app.py:8(fast_step)
```

The output reveals instantly that `slow_step` accounts for 98.7% of total runtime, pinpointing exactly what needs optimization.

## 2. Memory Optimization: The Power of `__slots__`

By default, Python stores all instance attributes inside a dynamic dictionary (`self.__dict__`). While flexible, a dictionary carries a significant memory footprint (~150+ bytes per instance).

If your system stores **1,000,000 objects in RAM** (such as geographic coordinates or financial quotes), standard instances will consume gigabytes of unnecessary memory!

### The Solution: `__slots__`

`__slots__` tells CPython: _"This class will only ever have these specific attributes."_ CPython eliminates the instance `__dict__` and allocates a **compact, fixed-size C array**:

```python
import sys

# 1. Standard class with dynamic __dict__
class StandardPoint:
    def __init__(self, x: float, y: float):
        self.x = x
        self.y = y

# 2. Optimized class with fixed __slots__
class SlottedPoint:
    __slots__ = ("x", "y")
    def __init__(self, x: float, y: float):
        self.x = x
        self.y = y

p_standard = StandardPoint(1.0, 2.0)
p_slotted = SlottedPoint(1.0, 2.0)

print("Standard Instance Overhead:", sys.getsizeof(p_standard) + sys.getsizeof(p_standard.__dict__), "bytes")
print("Slotted Instance Overhead:", sys.getsizeof(p_slotted), "bytes")
```

Output:

```text
Standard Instance Overhead: 152 bytes
Slotted Instance Overhead: 48 bytes
```

### Scale Benchmark: 1,000,000 Objects

| Object Type                     | 1,000,000 Instances in RAM | Memory Saved           |
| :------------------------------ | :------------------------- | :--------------------- |
| **Standard Class (`__dict__`)** | ~150 MB                    | 0%                     |
| **`__slots__` Class**           | **~48 MB**                 | **68% RAM Reduction!** |

In modern Python, you can apply this automatically using:

```python
@dataclass(slots=True)
class Coordinate:
    lat: float
    lon: float
```

### Question 1: Output Prediction (Attribute Assignment on Slotted Class)

Consider the following slotted class definition:

```python
class Packet:
    __slots__ = ("header", "payload")
    def __init__(self, header: str, payload: bytes):
        self.header = header
        self.payload = payload

pkt = Packet("TCP", b"DATA")
pkt.header = "UDP"
print(pkt.header)

try:
    pkt.timestamp = 1718000000
    print("Timestamp assigned:", pkt.timestamp)
except AttributeError as err:
    print("Caught error:", err)
```

What does this print, and why?

<Accordions>
<Accordion title="Solution & Breakdown">
**Output:**
```text
UDP
Caught error: 'Packet' object has no attribute 'timestamp' and no __dict__ for this attribute
```

**Explanation:**

1. Modifying existing slotted attributes (`pkt.header = "UDP"`) succeeds normally via C-level descriptor offsets.
2. When attempting to assign a new attribute `pkt.timestamp = 1718000000`, Python checks whether `timestamp` is defined in `__slots__`.
3. Finding that it is not in `__slots__`, Python looks for an instance dictionary `pkt.__dict__` to store the dynamic attribute.
4. Because `__slots__` eliminates `__dict__`, Python cannot store dynamic attributes and immediately raises `AttributeError`!

### Question 2: Spot and Fix the Bug (Broken Inheritance with **slots**)

A developer attempts to optimize a base and child class hierarchy with `__slots__`. However, instance profiling reveals that the child class instances are **still consuming 150+ bytes each and have a `__dict__`**:

```python
class BaseEntity:
    __slots__ = ("id", "created_at")
    def __init__(self, id: int, created_at: float):
        self.id = id
        self.created_at = created_at

class UserEntity(BaseEntity):
    # Notice: No __slots__ defined in child class!
    def __init__(self, id: int, created_at: float, email: str):
        super().__init__(id, created_at)
        self.email = email

u = UserEntity(1, 100.0, "user@test.com")
print("Has __dict__:", hasattr(u, "__dict__"))  # True!
```

Explain why `UserEntity` has a `__dict__` despite inheriting from a slotted base, and provide the fix.

<Accordions>
<Accordion title="Solution & Breakdown">
**The Root Cause:**
In Python, `__slots__` is **not automatically inherited**. If a subclass does not define `__slots__ = (...)`, CPython automatically equips the subclass instances with a standard `__dict__` and `__weakref__`! The memory benefits of `__slots__` in the base class are largely lost.

**The Fix:**
Subclasses must explicitly declare `__slots__` containing only their _additional_ attributes:

```python
class BaseEntity:
    __slots__ = ("id", "created_at")
    def __init__(self, id: int, created_at: float):
        self.id = id
        self.created_at = created_at

class UserEntity(BaseEntity):
    # Only declare new attributes not already in base __slots__:
    __slots__ = ("email",)

    def __init__(self, id: int, created_at: float, email: str):
        super().__init__(id, created_at)
        self.email = email

u = UserEntity(1, 100.0, "user@test.com")
print("Has __dict__:", hasattr(u, "__dict__"))  # False!
```

### Question 3: Architecture Deep-Dive (cProfile vs Sampling Profilers like py-spy)

What is the difference between **deterministic profilers** (such as `cProfile`) and **statistical sampling profilers** (such as `py-spy` or `Austen`)? Why should you NEVER run `cProfile` in a latency-critical production environment?

<Accordions>
<Accordion title="Solution & Breakdown">
**Deterministic Profiling (`cProfile`):**
- Hooks into CPython's interpreter execution loop via `PyEval_SetProfile`.
- Intercepts and records **every single function call, return, and exception**.
- **Flaw:** High observer overhead (can slow down code by 30% to 300%). It severely distorts runtime characteristics, especially for code with many small function calls. In production, this can trigger cascading timeouts.

**Sampling Profiling (`py-spy`):**

- Operates out-of-process. It inspects CPython process memory from the outside using OS system calls (`process_vm_readv` on Linux or `ReadProcessMemory` on Windows).
- Periodically samples the instruction pointer / call stack (e.g., 100 times per second).
- **Advantage:** Overhead is near zero (< 1-3%). It can be attached to live production web servers without restarting them or causing latency degradation.
  </Accordion>
</Accordions>

### Question 4: Hands-On Challenge (Restoring Weakref Support to a Slotted Class)

By default, slotted classes do not support weak references (`weakref.ref(instance)` raises `TypeError: cannot create weak reference to 'SlottedItem' object`).

Modify the class below so that it retains all memory benefits of `__slots__` while enabling `weakref` compatibility.

```python
class CacheItem:
    __slots__ = ("key", "val")
    def __init__(self, key: str, val: str):
        self.key = key
        self.val = val
```

<Accordions>
<Accordion title="Solution & Breakdown">
To enable weak reference support without adding a full dynamic `__dict__`, add `"__weakref__"` to the `__slots__` tuple:

```python
import weakref

class CacheItem:
    # Adding "__weakref__" reserves a single C pointer slot for weakref management:
    __slots__ = ("key", "val", "__weakref__")

    def __init__(self, key: str, val: str):
        self.key = key
        self.val = val

item = CacheItem("session_42", "auth_token_xyz")

# Weak reference now works seamlessly!
r = weakref.ref(item)
print("Referenced item:", r().key)  # session_42

# Dynamic attributes are STILL blocked:
try:
    item.extra = "not allowed"
except AttributeError:
    print("Dynamic attributes still safely prevented!")
```

## Summary Reference

- **`cProfile`**: Built-in deterministic profiler tracking function call durations.
- **`py-spy`**: Zero-overhead sampling profiler that attaches to production Python processes without restarting them.
- **`__slots__`**: Replaces the per-instance dictionary with a compact C array.
- **`@dataclass(slots=True)`**: Modern idiomatic way to create slotted classes.
