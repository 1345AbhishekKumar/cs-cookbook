Welcome to **Stage 3: Concurrency, Architecture & Metaprogramming**.

In this stage, you build high-throughput concurrent systems and robust enterprise architectures following domain-driven design (*Cosmic Python*), while mastering low-overhead asynchronous I/O and memory management.

---

## Stage 3 Core Topics

<Steps>
<Step>
### 01. Metaclasses & Class Construction
Understanding `type` as a class factory, `__new__` vs `__init__`, modifying class namespaces via `__prepare__`, and lightweight class registration using `__init_subclass__`.
</Step>

<Step>
### 02. The Concurrency Matrix: Threads vs Processes vs Async
When to use what: OS threads and GIL I/O bottlenecks vs `multiprocessing` CPU-bound scaling (and IPC serialization cost) vs `asyncio` cooperative single-threaded multiplexing.
</Step>

<Step>
### 03. AsyncIO & Event Loop Mechanics
How the Python event loop works under the hood: socket file descriptors (`epoll`/`kqueue`), coroutines as state machines, and non-blocking stream readers and writers.
</Step>

<Step>
### 04. Structured Concurrency (`TaskGroup` & `except*`)
Preventing orphaned background tasks using `asyncio.TaskGroup` (Python 3.11+) and handling concurrent multi-task failures using Exception Groups (PEP 654) and `except*` syntax.
</Step>

<Step>
### 05. Memory Profiling, tracemalloc & Cyclic GC
Reference counting mechanics, cyclic garbage collector internals (`gc` generational sweeps: Gen 0, Gen 1, Gen 2), taking heap snapshots with `tracemalloc`, and hunting memory leaks.
</Step>

<Step>
### 06. Performance Optimization & Slots
Benchmarking `__slots__` vs `__dict__` vs `dataclass(slots=True)`, line-by-line CPU profiling with `line_profiler`, and sampling production services with `py-spy`.
</Step>

<Step>
### Capstone: tiny-redis RESP Server & Crawler
Build an in-memory concurrent key-value database implementing the Redis Serialization Protocol (RESP) from scratch with TTL expiration, pub/sub queues, and non-blocking socket streams.
</Step>
</Steps>
