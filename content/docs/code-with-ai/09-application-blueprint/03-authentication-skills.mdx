Authentication is one of the highest-stakes areas of software engineering. AI models frequently introduce subtle security flaws when implementing auth from scratch: using unhashed tokens, creating insecure session cookies, failing to verify webhook cryptographic signatures, or misconfiguring CSRF protections.

Installing official authentication skills equips your agent with hardened, framework-specific recipes, verified database schemas, and zero-trust patterns.

---

## 1. Better Auth (`better-auth/skills`)

**Better Auth** is the premier TypeScript-first authentication framework for modern fullstack applications. It provides built-in support for multiple database adapters (Drizzle, Prisma, Kysely), two-factor authentication, passkeys (WebAuthn), and organization management.

### Installation

```bash
npx skills add better-auth/skills
```

To install globally for Google Antigravity:
```bash
npx skills add better-auth/skills -g -a antigravity -y
```

### Sub-Skills Catalog

The `better-auth/skills` package bundles **6 specialized sub-skills**:

```
better-auth/skills
├── better-auth-best-practices
├── better-auth-security-best-practices
├── create-auth
├── email-and-password-best-practices
├── organization-best-practices
└── two-factor-authentication-best-practices
```

---

### Detailed Breakdown of Better Auth Sub-Skills

#### 1. `better-auth-best-practices`
* **Trigger Topic**: Project setup, Next.js App Router route handlers, database adapter configuration, client hook initialization.
* **What It Teaches the Agent**:
  - Establishes the canonical server configuration in `lib/auth.ts` using `betterAuth({ ... })`.
  - Configures the Next.js catch-all route handler in `app/api/auth/[...all]/route.ts`.
  - Enforces strict separation between server-only auth instances and client-side hooks (`lib/auth-client.ts` via `createAuthClient`).
  - Implements session caching and edge cookie resolution.

#### 2. `better-auth-security-best-practices`
* **Trigger Topic**: Session token storage, cookie attributes (`SameSite`, `HttpOnly`, `Secure`), CSRF defenses, rate limiting on auth endpoints.
* **What It Teaches the Agent**:
  - Sets up cryptographic session signing and rotating secrets (`BETTER_AUTH_SECRET`).
  - Ensures cookies use `Secure; HttpOnly; SameSite=Lax` (or `Strict` for mutations).
  - Binds sessions to client IP/User-Agent fingerprints to mitigate session hijacking.
  - Automatically wraps `/api/auth/sign-in` and `/api/auth/sign-up` in sliding-window rate limiters.

#### 3. `create-auth`
* **Trigger Topic**: Bootstrapping an authentication layer from scratch in a fresh project or migrating from NextAuth/Auth.js.
* **What It Teaches the Agent**:
  - Generates the exact database schema for user, session, account, and verification tokens.
  - Generates migration scripts compatible with Drizzle ORM (`drizzle-kit generate`), Prisma (`prisma db push`), or SQL migrations.
  - Connects environment variables (`BETTER_AUTH_URL`, `DATABASE_URL`) with type validation.

#### 4. `email-and-password-best-practices`
* **Trigger Topic**: Traditional email/password signup, password hashing, email verification tokens, forgot-password reset flows.
* **What It Teaches the Agent**:
  - Enforces password complexity rules (length, entropy) without frustrating user ergonomics.
  - Dispatches email verification tokens with expiration timestamps.
  - Protects the reset password endpoint against user enumeration attacks (timing-safe responses).

#### 5. `organization-best-practices`
* **Trigger Topic**: B2B multi-tenancy, workspace creation, team invitations, role-based access control (RBAC: Owner, Admin, Member).
* **What It Teaches the Agent**:
  - Configures the Better Auth Organization plugin:
    ```typescript
    import { organization } from "better-auth/plugins";

    export const auth = betterAuth({
      plugins: [organization()]
    });
    ```
  - Guides database table additions (`organization`, `member`, `invitation`).
  - Creates server actions for inviting teammates, validating invite tokens, and switching the active tenant context.

#### 6. `two-factor-authentication-best-practices`
* **Trigger Topic**: Multi-factor authentication, TOTP authenticator apps (Google Authenticator, 1Password), backup recovery codes.
* **What It Teaches the Agent**:
  - Enables the `twoFactor()` plugin.
  - Implements the enrollment flow: generating QR code SVG data, verifying initial TOTP codes, and displaying one-time backup recovery codes.
  - Protects high-value routes with step-up verification challenges.

## 2. Clerk (`clerk/skills`)

**Clerk** is a complete, enterprise-grade user management and authentication platform. Its official skills teach your AI agent how to integrate Clerk across React, Next.js App Router, React Router, mobile apps, and backend APIs.

### Installation

```bash
npx skills add clerk/skills
```

To install globally for Google Antigravity:
```bash
npx skills add clerk/skills -g -a antigravity -y
```

### Sub-Skills Catalog

The `clerk/skills` repository organizes **12 specialized sub-skills** across 4 core domains:

```
clerk/skills
├── Core Engine
│   ├── clerk (Main router & architecture)
│   ├── clerk-setup (Bootstrapping & keys)
│   ├── clerk-cli (Terminal workflows)
│   ├── clerk-custom-ui (Headless components)
│   └── clerk-backend-api (Server SDK & JWT validation)
├── Framework Patterns
│   ├── clerk-nextjs-patterns (App Router, middleware, RSC)
│   ├── clerk-react-patterns (Hooks, providers, UI components)
│   └── clerk-react-router-patterns (Remix / React Router v7)
├── Enterprise Features
│   ├── clerk-orgs (B2B organizations & RBAC)
│   ├── clerk-billing (Pricing tables & Stripe bridge)
│   ├── clerk-webhooks (Svix signature verification)
│   └── clerk-testing (Mock session helpers)
└── Mobile SDKs
    ├── clerk-expo (Universal React Native)
    └── clerk-android (Native Android)
```

---

### Detailed Breakdown of Clerk Sub-Skills

#### 1. Core Engine Skills
* **`clerk`**: The meta-router. Analyzes your question, detects your project stack, and routes to the appropriate sub-skill.
* **`clerk-setup`**: Guides provider installation (`@clerk/nextjs`), environment variable configuration (`NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY`, `CLERK_SECRET_KEY`), and wrapping root layouts in `<ClerkProvider>`.
* **`clerk-cli`**: Automates Clerk dashboard interactions, creating applications, syncing redirect URLs, and listing API credentials from the CLI.
* **`clerk-custom-ui`**: For teams building custom branded forms instead of default prebuilt components. Teaches the agent how to use `useSignIn()` and `useSignUp()` hooks to handle multi-step authentication state machines.
* **`clerk-backend-api`**: Server-side SDK usage. Covers `clerkClient()`, fetching user profiles from backend worker processes, updating private metadata, and validating session JWTs in edge runtimes.

#### 2. Framework Pattern Skills
* **`clerk-nextjs-patterns`**: The most widely used skill. Enforces modern Next.js 14/15/16 App Router standards:
  - Setting up `clerkMiddleware()` in `middleware.ts` with route matchers:
    ```typescript
    import { clerkMiddleware, createRouteMatcher } from '@clerk/nextjs/server';

    const isProtectedRoute = createRouteMatcher(['/dashboard(.*)', '/api/trpc(.*)']);

    export default clerkMiddleware(async (auth, req) => {
      if (isProtectedRoute(req)) await auth.protect();
    });
    ```
  - Using `await auth()` inside React Server Components and Server Actions.
  - Avoiding client-side flashing through server-rendered authentication state.
* **`clerk-react-patterns`**: Client-side component usage: `<SignedIn>`, `<SignedOut>`, `<SignInButton>`, `<UserButton>`, and the `useUser()` hook.
* **`clerk-react-router-patterns`**: Integration patterns for React Router v7 and Remix loaders/actions.

#### 3. Feature & Security Skills
* **`clerk-orgs`**: Building enterprise multi-tenant B2B portals: `<OrganizationSwitcher>`, verifying organization memberships, and scoping database records by `orgId`.
* **`clerk-billing`**: Setting up subscription tiers, gating feature access based on active plan entitlements, and managing billing portals.
* **`clerk-webhooks`**: Writing secure webhook handlers to sync user creation/updates to your primary database (e.g. Supabase or Neon):
  - Uses `svix` to verify incoming headers (`svix-id`, `svix-timestamp`, `svix-signature`).
  - Handles `user.created`, `user.updated`, and `user.deleted` idempotently.
* **`clerk-testing`**: Mocking Clerk authentication states in Vitest, Jest, and Playwright tests so test runners can execute without hitting real API rate limits.

#### 4. Mobile SDK Skills
* **`clerk-expo`**: Universal mobile authentication using Expo SecureStore for native token persistence, OAuth browser redirects via `WebBrowser.warmUpAsync()`, and native biometric sign-in.
* **`clerk-android`**: Native Kotlin/Java SDK patterns for Android applications.
