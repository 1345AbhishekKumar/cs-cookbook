## 1. Core Blueprint Workflow Skills (`E:\intercom`)

These skills define the project workflow engine inside `.agents/skills/` and `.claude/skills/`.

### 1. `/onboard`
* **Trigger Topic**: New project initialization, stack detection.
* **Explanation**: Inspects the real project root, detects runtime, package manager (npm, pnpm, bun), scripts (`dev`, `build`, `lint`), and writes the initial `blueprint/config.json`.

### 2. `/adopt`
* **Trigger Topic**: Integrating Blueprint into an existing brownfield application.
* **Explanation**: Audits already-shipped features and established conventions, producing `build-plan.md` and `project-plan.md` that reflect reality without overwriting code.

### 3. `/discovery`
* **Trigger Topic**: Early-stage product planning, requirements elicitation.
* **Explanation**: Multi-turn planning interview that interrogates user assumptions, identifies personas, defines user journeys, and drafts the initial roadmaps.

### 4. `/overview`
* **Trigger Topic**: Distilling plans into active context.
* **Explanation**: Compiles the planning documents into `blueprint/context/project-overview.md` (the persistent source of truth) and creates an initial baseline git commit.

### 5. `/prototype`
* **Trigger Topic**: UI wireframing, static mockups.
* **Explanation**: Generates static HTML/Tailwind mockup pages to visually lock design and layout before database modeling or API implementation.

### 6. `/feature [id]`
* **Trigger Topic**: Starting a planned feature from `build-plan.md`.
* **Explanation**: Creates a dedicated feature branch (`feature/<id>-<title>`), extracts the scope into `blueprint/context/current-feature.md`, and halts for human review before any code is written.

### 7. `/implement`
* **Trigger Topic**: Building the active approved spec.
* **Explanation**: Executes implementation in small, reviewable steps. Runs real builds and typechecks after each step to prevent syntax drift.

### 8. `/check`
* **Trigger Topic**: Behavior proof, automated test execution.
* **Explanation**: Proves that the implementation satisfies the done-when criteria in `current-feature.md` by executing automated tests and checking running endpoints.

### 9. `/check guide`
* **Trigger Topic**: Manual QA, visual inspection.
* **Explanation**: Generates a read-only human walkthrough: exact local URLs to open, buttons to click, edge-case test values to enter, and expected UI responses.

### 10. `/audit current`
* **Trigger Topic**: Static analysis, security pass, code hygiene.
* **Explanation**: Reviews diff against `coding-standards.md`. Checks for security vulnerabilities, memory leaks, dead code, and unhandled errors; logs findings to `blueprint/context/findings.md`.

### 11. `/audit independent current`
* **Trigger Topic**: Air-gapped review for sensitive changes (auth, payments, data deletion).
* **Explanation**: Freezes the checkpoint and prepares an immutable receipt contract for an isolated reviewer sub-agent.

### 12. `/complete`
* **Trigger Topic**: Closing out a finished work item.
* **Explanation**: Runs final preflight checks, moves the feature spec to `blueprint/history/features/`, updates `build-plan.md`, and squash-merges with explicit user approval.

### 13. `/autopilot`
* **Trigger Topic**: Bounded semi-autonomous feature creation.
* **Explanation**: Chains `/feature` and `/implement` in a single pass through configured quality gates, pausing for human review before `/complete`.

### 14. `/continuous`
* **Trigger Topic**: Autonomous backlog processing.
* **Explanation**: Loops through remaining planned features serially: branching, implementing, verifying, archiving, and merging local commits until the build plan is finished or a gate fails.

### 15. `/fix <issue>`
* **Trigger Topic**: Unplanned bugs, immediate remediation.
* **Explanation**: Documents an ad-hoc bug or UI flaw into `blueprint/context/current-feature.md`, branches immediately, and enters the implementation loop.

### 16. `/debug <issue>`
* **Trigger Topic**: Diagnosing runtime failures without editing code.
* **Explanation**: Gathers error logs, isolates root causes, formulates reproducible tests, and passes the diagnosis to `/fix` or `/implement`.

### 17. `/rollback [id]`
* **Trigger Topic**: Reversing a regression or broken release.
* **Explanation**: Examines the archived feature spec and exact git commit hash in `blueprint/history/`, verifies downstream dependencies, and safely reverses the commit.

### 18. `/doctor`
* **Trigger Topic**: Environment and state integrity check.
* **Explanation**: Audits `blueprint/config.json`, verify commands, git branch cleanliness, adapter health, and resets malformed `run.json` state.

### 19. `/status`
* **Trigger Topic**: Session orientation and progress summary.
* **Explanation**: Read-only display of the current active branch, active feature ID, completed checklist items, and the recommended next step.

### 20. `/brief [id]`
* **Trigger Topic**: Pre-implementation preview.
* **Explanation**: Read-only analysis of an upcoming item in `build-plan.md`: assesses complexity, file dependencies, and risks before generating a spec.

### 21. `/explore <topic>`
* **Trigger Topic**: Architectural investigation.
* **Explanation**: Deep-dives into the codebase to analyze how an idea or library interacts with existing modules without writing files or modifying plans.

### 22. `/tests` & `/tests browser`
* **Trigger Topic**: Test harness setup.
* **Explanation**: Configures a unit testing runner (Vitest/Jest) or initializes a browser test suite (Playwright) without interrupting active feature work.

### 23. `/ci`
* **Trigger Topic**: Continuous integration automation.
* **Explanation**: Establishes a single `Verify` command and creates `.github/workflows/verify.yml` with pull-request checks and opt-in pre-push hooks.

## 2. Better Auth Skills (`better-auth/skills`)

```bash
npx skills add better-auth/skills
```

* **`better-auth-best-practices`**: Establishes `betterAuth({ ... })` in `lib/auth.ts`, configures `app/api/auth/[...all]/route.ts`, enforces server-only isolation, and sets up `lib/auth-client.ts` with `createAuthClient()`.
* **`better-auth-security-best-practices`**: Enforces Argon2id password hashing, rotating secrets via `BETTER_AUTH_SECRET`, strict cookie flags (`HttpOnly; Secure; SameSite=Lax`), and sliding-window rate limiters on auth endpoints.
* **`create-auth`**: Scaffolds database schemas for user, session, account, and verification tokens for Drizzle ORM, Prisma, Kysely, or raw SQL.
* **`email-and-password-best-practices`**: Implements timing-safe password comparisons, expiration-bounded email verification links, and protected password reset flows.
* **`organization-best-practices`**: Configures the Better Auth Organization plugin, manages workspace tables (`organization`, `member`, `invitation`), and handles role-based access control (Owner, Admin, Member).
* **`two-factor-authentication-best-practices`**: Implements the `twoFactor()` plugin: QR code generation, initial verification, backup codes, and step-up auth challenges for sensitive actions.
