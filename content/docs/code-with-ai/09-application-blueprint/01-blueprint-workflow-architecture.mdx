The application building blueprint found in `E:\intercom` solves the primary failure mode of AI coding agents: **context drift and uncontrolled scope creep**.

When you instruct an AI agent to build a large application, it tends to hallucinate architectures, overwrite working code, introduce speculative dependencies, and produce unverified changes. The Blueprint converts the agent into a disciplined, bounded software engineer operating behind strict verification gates.

---

## 1. Directory Structure of `E:\intercom`

The Blueprint resides at the root of your application repository and consists of five core components:

```text
my-app/
├── AGENTS.md                  # Cross-tool instructions (Antigravity, Codex, Copilot, OpenCode)
├── CLAUDE.md                  # Claude Code entry point (imports AGENTS.md)
├── skills-lock.json           # Exact dependency lockfile for 180+ agent skills
├── .agents/skills/            # Portable agent skill definitions (<skill>/SKILL.md)
├── .claude/skills/            # Mirror adapter for Claude Code
└── blueprint/                 # The deterministic project workflow engine
    ├── config.json            # Deterministic project workflow policy
    ├── build-plan.md          # Ordered list of discrete features with done-when criteria
    ├── project-plan.md        # High-level architecture, user personas & system roadmap
    ├── context/               # Persistent "working memory on disk"
    │   ├── project-overview.md# Source of truth: tech stack, conventions & constraints
    │   ├── coding-standards.md# Non-negotiable code rules, trust boundaries & testing
    │   ├── ai-interaction.md  # Output formatting, concise response rules & review steps
    │   ├── current-feature.md # The single active feature/fix specification being built
    │   ├── findings.md        # Recorded audit, security, and quality findings
    │   └── review.md          # Independent review receipts & approvals
    ├── history/               # Permanent archive of shipped work
    │   ├── features/          # Archived specs of completed features
    │   ├── fixes/             # Archived bugfix specifications
    │   └── rollbacks/         # Archived rollback plans
    └── .state/                # Local state machine (Git ignored)
        ├── manifest.json      # File change tracking & integrity checksums
        └── run.json           # Live activity telemetry for dashboards
```

## 2. How to Overlay the Blueprint on Any New App

<Callout type="warn">
**Never run a framework scaffolder inside an existing Blueprint folder.** Tools like `create-next-app` or `create-vite` require an empty directory and will fail if `AGENTS.md` or `blueprint/` are present.
</Callout>

<Steps>
<Step>
### Step 1: Scaffold your application first
Create your app in an empty folder using your preferred framework CLI:

```bash
# Example: Next.js App Router
npx create-next-app@latest my-saas-app --typescript --tailwind --eslint --app

cd my-saas-app
```
</Step>

<Step>
### Step 2: Overlay the Blueprint files
You can overlay the Blueprint using either the official CLI from **[ai-blueprint.dev](https://ai-blueprint.dev/)** or by copying your configured template from `E:\intercom`:

**Method A: Official CLI Installer (Recommended)**
```bash
npx create-ai-blueprint@latest
```

**Method B: Local Template Copy (From `E:\intercom`)**
```powershell
# Copy AGENTS.md, CLAUDE.md, and the blueprint engine
Copy-Item -Path "E:\intercom\AGENTS.md" -Destination "."
Copy-Item -Path "E:\intercom\CLAUDE.md" -Destination "."
Copy-Item -Path "E:\intercom\blueprint" -Destination "." -Recurse
Copy-Item -Path "E:\intercom\.agents" -Destination "." -Recurse
Copy-Item -Path "E:\intercom\.claude" -Destination "." -Recurse
Copy-Item -Path "E:\intercom\skills-lock.json" -Destination "."
```
</Step>

<Step>
### Step 3: Run the Onboarding Handshake
Open your AI coding agent (Google Antigravity, Claude Code, or Codex) and run:

```text
/onboard
```

The agent will inspect your real dependencies, detect package scripts (`npm run dev`, `build`, `lint`), normalize test runners, and configure `blueprint/config.json`.
</Step>
</Steps>

## 3. Deep Dive: `blueprint/config.json`

`blueprint/config.json` is the machine-readable rulebook. It establishes quality gates without requiring you to re-prompt the model on every turn:

```json
{
  "schemaVersion": 1,
  "qualityGates": {
    "regular": {
      "audit": "manual",
      "independentReview": "when-sensitive",
      "check": "manual",
      "tryGuide": "manual"
    },
    "continuous": {
      "audit": "manual",
      "independentReview": "when-sensitive",
      "check": "when-behavioral",
      "tryGuide": "manual"
    }
  },
  "review": {
    "independentExecution": "automatic"
  },
  "workflow": {
    "stepReview": "feature",
    "checkpointCommits": "disabled"
  },
  "git": {
    "branchPrefix": "feature/",
    "landing": "local-merge"
  }
}
```

### Key Configuration Directives:
* **`independentReview` (`when-sensitive` / `always` / `manual`)**: When a feature modifies authentication, payments, data destruction, or shared schema, the agent automatically blocks completion until an independent reviewer checks the diff.
* **`review.independentExecution` (`automatic`)**: Spawns a fresh, isolated child reviewer sub-agent through Antigravity/Claude Code with the review contract before landing.
* **`workflow.stepReview` (`feature` vs `every`)**: By default (`feature`), the agent executes small implementation steps and presents one unified review packet with the diff and proof of completion. Set to `every` during high-risk work or pairing sessions to approve every atomic file edit.
* **`git.landing` (`local-merge` vs `pull-request`)**: Defines whether `/complete` squash-merges locally to `main` or pushes a remote branch and opens a GitHub Pull Request.

## 4. The Complete Lifecycle Commands

All commands are slash commands in AI chat (e.g. `/feature` in Antigravity or `$feature` in Codex), **not shell terminal commands**.

| Phase | Command | What It Does & Behavior |
|---|---|---|
| **Setup** | `/onboard` | Inspects project stack, adapts commands, establishes baseline `config.json`. |
| **Setup** | `/adopt` | Bootstraps the Blueprint into an existing brownfield application with existing code. |
| **Setup** | `/discovery` | Multi-turn planning interview that drafts `project-plan.md` and `build-plan.md`. |
| **Setup** | `/overview` | Distills planning documents into `blueprint/context/project-overview.md` and commits baseline. |
| **Planning** | `/brief [id]` | Read-only briefing on an upcoming build plan item (scope, dependencies, risks) before speccing. |
| **Planning** | `/explore <query>`| Investigates code architecture and dependencies without editing files or requiring plans. |
| **Build Loop** | `/feature [id]` | Turns the next unchecked item in `build-plan.md` into `blueprint/context/current-feature.md` on a new branch. |
| **Build Loop** | `/implement` | Builds the active spec in small, verifiable steps; runs project build & typechecks. |
| **Build Loop** | `/check` | Runs automated verification against the running app or test runner. |
| **Build Loop** | `/check guide` | Generates a manual human testing guide: exact URLs, buttons to click, and expected UI behavior. |
| **Build Loop** | `/audit current` | Static analysis pass checking security, dead code, performance, and standards drift. Logs to `findings.md`. |
| **Build Loop** | `/complete` | Runs safety checks, archives spec to `blueprint/history/features/`, and squash-merges with your approval. |
| **Recovery** | `/fix <issue>` | Documents an ad-hoc bug or UI flaw into `current-feature.md` and branches for immediate remediation. |
| **Recovery** | `/debug <issue>`| Reproduces and isolates failures without modifying code, handing evidence to `/fix`. |
| **Recovery** | `/rollback [id]`| Safely plans and executes a reversal of an archived feature commit with dependency checking. |
| **Automation** | `/autopilot` | Combines `/feature` and `/implement` in a single bounded pass, pausing before `/complete`. |
| **Automation** | `/continuous` | Runs through multiple features serially, running gates, archiving, and merging local commits. |
| **System** | `/doctor` | Health check for adapters, plan freshness, state integrity, and workflow drift. |
| **Release** | `/release` | Readiness check for Vercel/Render deployment, environment variables, and production smoke tests. |

## 5. State Machine & Dashboard Tracking

To prevent agent crashes from corrupting your project, the Blueprint records live state in `blueprint/.state/run.json` using an atomic script helper:

```bash
# Invoked automatically by workflow skills
node .agents/skills/doctor/scripts/run-state.mjs start --command feature --summary "Implementing OAuth Login" --boundary local-only
```

The script manages a deterministic JSON schema:

```json
{
  "schemaVersion": 1,
  "command": "implement",
  "status": "running",
  "summary": "Building Feature 04: Stripe Webhook Processor",
  "detail": "Adding cryptographic signature verification in route handler.",
  "boundary": "local-only",
  "startedAt": "2026-10-06T18:30:00Z",
  "updatedAt": "2026-10-06T18:32:15Z",
  "progress": { "current": 2, "total": 4, "label": "steps" },
  "feature": { "id": "4", "title": "Stripe Webhooks" }
}
```

If an agent disconnects or hits a rate limit mid-feature, you can re-open your session and type `/status` or `/feature resume` to continue exactly where it stopped without repeating completed steps.
