In modern agentic engineering, **Skills** represent portable domain competence. Instead of cramming hundreds of pages of documentation into your system prompt or pasting code snippets into chat, skills package best practices, edge cases, and architectural rules into standardized Markdown units.

The `E:\intercom` environment locks and manages **184 individual skills** across 18 major official packages. Here is how they work and how to manage them.

---

## 1. Anatomy of an Agent Skill (`SKILL.md`)

Every skill follows the open **Agent Skills Specification**. It is anchored by a `SKILL.md` file located inside a dedicated directory:

```markdown
---
name: better-auth-best-practices
description: "Expert guidance for setting up Better Auth in Next.js App Router and Node runtimes with Drizzle/Prisma adapters."
---

## When to Use This Skill
- User asks to implement user authentication, signup, login, or session cookies.
- Creating auth route handlers in `app/api/auth/[...all]/route.ts`.
- Configuring database adapters (Drizzle, Prisma, Kysely, Postgres).

## Core Rules & Architecture
1. Always instantiate `betterAuth` in a dedicated server file (`lib/auth.ts`).
2. Never import `auth` from server files into Client Components (`'use client'`).
3. Export auth client hooks from a distinct client file (`lib/auth-client.ts`).

## Code Pattern: Next.js App Router Route Handler
```typescript
// app/api/auth/[...all]/route.ts
import { auth } from "@/lib/auth";
import { toNextJsHandler } from "better-auth/next-js";

export const { GET, POST } = toNextJsHandler(auth);
```

## Common Mistakes & Anti-Patterns
- ❌ Do NOT store raw passwords; Better Auth hashes passwords with Argon2id by default.
- ❌ Do NOT bypass CSRF protection when calling custom auth mutations.
```

## 2. The Progressive Disclosure Mechanism

A common question is: *“If I install 184 skills, won't that consume my entire LLM context window?”*

The answer is **No**, due to **Progressive Disclosure**:

```
┌──────────────────────────────────────────────────────────┐
│                   AGENT INITIALIZATION                   │
│   Reads ONLY YAML Frontmatter: Name + Short Description  │
│   (Consumes ~15-20 tokens per skill; total < 3,500 toks) │
└────────────────────────────┬─────────────────────────────┘
                             │
                             ▼
┌──────────────────────────────────────────────────────────┐
│                     USER PROMPT                          │
│        "Set up Stripe subscription checkout"             │
└────────────────────────────┬─────────────────────────────┘
                             │
                             ▼
┌──────────────────────────────────────────────────────────┐
│                DYNAMIC SKILL RESOLUTION                  │
│   Agent matches intent -> loads 'stripe-pay/SKILL.md'    │
│   Deep documentation is read ONLY for that task!         │
└──────────────────────────────────────────────────────────┘
```

The agent keeps a compact index of all available skills. Only when a prompt touches a specific domain does the agent fetch and inject that individual `SKILL.md` into active working memory.

## 3. Storage Locations: Global vs. Project Scope

Skills can be installed in two locations depending on whether you want them available across every project on your workstation or locked to a specific codebase:

### Option A: Global Scope (Available to all projects in Antigravity)
- **Path**: `C:\Users\abhi1\.gemini\antigravity\skills\<skill-name>\` (or `~/.gemini/config/skills/`)
- **CLI Flag**: Add `-g` or `--global`
- **Command**:
  ```bash
  npx skills add <package> -g -a antigravity -y
  ```

### Option B: Project-Level Scope (Recommended for Team Repositories)
- **Path**: `.agents/skills/<skill-name>/` and `.claude/skills/<skill-name>/`
- **Lockfile**: Updates `skills-lock.json` in the root of your application.
- **CLI Flag**: Run without `-g`
  ```bash
  npx skills add <package> -y
  ```

## 4. Understanding `skills-lock.json`

Just as `package-lock.json` guarantees deterministic Node packages, `skills-lock.json` ensures that all developers and agents on a team use the exact same versions and hashes of skills:

```json
{
  "version": 1,
  "skills": {
    "better-auth-best-practices": {
      "source": "better-auth/skills",
      "sourceType": "github",
      "skillPath": "better-auth/best-practices/SKILL.md",
      "computedHash": "f35281e7a0c07b3fd3c4e96c7833dafb294a3a8662cb68a8544f4225008d6568"
    },
    "clerk-nextjs-patterns": {
      "source": "clerk/skills",
      "sourceType": "github",
      "skillPath": "skills/clerk-nextjs-patterns/SKILL.md",
      "computedHash": "cdcb9f08d567058fca7563ad8c67a4a2a2f3b9f286294e1caeb1ea5407dfebc6"
    }
  }
}
```

If you clone a project containing `skills-lock.json`, you can restore all skills instantly:

```bash
npx skills experimental_install
```

## 5. Skills CLI Command Reference

The `skills` CLI provides a comprehensive command set for skill lifecycle management:

```bash
# 1. Install an entire repository of skills
npx skills add clerk/skills -y

# 2. Inspect all sub-skills in a repository before installing
npx skills add clerk/skills --list

# 3. Install only a specific sub-skill
npx skills add clerk/skills --skill clerk-setup clerk-orgs -y

# 4. Install globally for Google Antigravity
npx skills add addyosmani/agent-skills -g -a antigravity -y

# 5. List all skills installed in your current project
npx skills list

# 6. List all globally installed skills
npx skills list -g

# 7. Update all skills to the latest upstream versions
npx skills update

# 8. Remove a skill
npx skills remove <skill-name>
```
