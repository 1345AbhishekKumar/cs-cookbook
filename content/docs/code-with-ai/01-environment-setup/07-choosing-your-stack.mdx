## What Makes a Stack AI-Friendly?

Three criteria determine whether a technology is a good fit for AI-assisted development. Notice that "best architecture" is not one of them.

**1. Training Data Saturation**

The more a technology appears in LLM training data — GitHub repos, documentation, Stack Overflow threads, blog posts — the more fluently an agent codes it. Next.js has millions of public repos. Drizzle has a smaller but very high-quality training footprint. An obscure ORM with 200 stars has almost none. Agents hallucinate less with popular tools.

**2. Type Safety**

TypeScript + Zod = self-documenting code. When every function has typed inputs and outputs, and every schema is validated at runtime, your agent can navigate your codebase by reading types alone. It does not need extensive comments because the types *are* the documentation. An untyped JavaScript codebase is a maze without a map — for you and for the agent.

**3. MCP Server Support**

Model Context Protocol (MCP) servers let coding agents directly query your services — your database, your auth provider, your payment processor — without you having to explain the API schema. Supabase has an official MCP server. Stripe has one. GitHub has one. When your stack has MCP coverage, your agent gets live, accurate context from your running services.

<Callout type="info">
**The AI-Friendly Stack Rule of Thumb:** Before adding any new dependency, ask three questions: (1) Does it have TypeScript types? (2) Does it appear in major open-source projects on GitHub? (3) Does it have an MCP server or is one actively developed? If the answer to all three is yes, you are in safe territory.
</Callout>

## The Recommended Stack (Starter)

For solo and small-team AI-native applications, this is the stack you should default to — not because it is perfect in theory, but because it is the most agent-friendly combination available today:

| Layer | Choice | Why |
|---|---|---|
| **Framework** | Next.js 15 (App Router) | Highest LLM training saturation of any full-stack JS framework |
| **Language** | TypeScript (strict mode) | Agent navigates by types; fewer hallucinations |
| **Styling** | Tailwind CSS | Utility classes are in-line, visible to agents reading JSX |
| **Database** | Supabase (PostgreSQL) | Official MCP server, generous free tier, Postgres semantics |
| **ORM** | Drizzle ORM | Type-safe, lightweight, excellent TypeScript inference |
| **Auth** | Supabase Auth or Clerk | Both have excellent agent training data; Clerk for complex flows |
| **Deployment** | Vercel | Zero-config Next.js deploys, GitHub integration |

```bash
npx create-next-app@latest my-app \
  --typescript \
  --tailwind \
  --eslint \
  --app \
  --src-dir \
  --import-alias "@/*"
```

## Platform-Specific Architecture Choices

While Next.js full-stack dominates web apps, your product may require specific platform targets:

### 1. Web with Separate ML / Python Backend: React + FastAPI
When building applications requiring AI model inference, scientific computing, computer vision, or background job workers, pairing a modern React/Next.js frontend with a **FastAPI** backend is the gold standard:
- **Frontend**: Next.js 15 or Vite + React + TypeScript + Tailwind.
- **Backend**: Python 3.12+ with FastAPI + Pydantic v2 + SQLAlchemy 2.0 / SQLModel.
- **Why AI Agents Excel Here**: Both React and FastAPI have massive training dataset saturation. Pydantic v2 schemas give agents typed contracts that mirror TypeScript interfaces with zero ambiguity.
- **Communication**: OpenAPI contracts generated automatically by FastAPI (`/openapi.json`) allow agents to generate client SDKs instantly with `openapi-ts`.

### 2. Desktop Apps (Windows & macOS): Electron vs. Tauri
When your app needs native system tray access, offline local disk storage, or desktop capabilities:

| Dimension | **Electron** | **Tauri (v2.0)** |
|---|---|---|
| **Core Architecture** | Chromium + Node.js runtime bundled | Native OS Webview + Rust core |
| **Installer Size** | ~80MB – 150MB | ~5MB – 15MB (ultra-lightweight) |
| **RAM Usage** | ~150MB – 300MB idle | ~30MB – 60MB idle |
| **LLM Familiarity** | ⭐⭐⭐⭐⭐ (Decade of public code) | ⭐⭐⭐⭐ (Rapidly growing, Rust IPC) |
| **Agent Autonomy** | High (pure JavaScript/TypeScript ecosystem) | Medium-High (requires Rust understanding for plugins) |
| **Best For** | Heavy apps, complex Node.js dependencies, VS Code style | High-performance utilities, small bundle size, Windows/Mac |

### 3. Mobile Apps: Expo (React Native)
For iOS and Android cross-platform delivery:
- **Framework**: **Expo** with Expo Router (file-based navigation mirroring Next.js App Router).
- **Styling**: NativeWind v4 (Tailwind CSS for React Native) or Tamagui.
- **Why Agents Love Expo**: File-based routing (`app/` directory), EAS Build cloud workflows, and unified TypeScript types mean skills and conventions transfer 1-to-1 from Next.js.
- **Official Support**: Expo maintains official agent skills and MCP servers allowing agents to query documentation, trigger EAS builds, and diagnose crash logs directly.

## When to Break the Rules

The recommended stack is a default, not a decree. Deviate intentionally when:

- **React + FastAPI** → your app is ML-heavy, uses PyTorch/HuggingFace, processes high-volume tabular data with Pandas/Polars, or runs LangGraph/LlamaIndex pipelines directly in Python.
- **Electron or Tauri** → you are building a Windows or macOS desktop application with native file system hooks, system tray utilities, or local hardware access.
- **Expo** → you need a universal mobile experience on the iOS App Store and Google Play Store sharing logic with your web codebase.
- **Nuxt 3** → your team is a Vue shop.
- **Go + Chi or Fiber** → you need raw performance for a high-throughput microservice.

The principle: **the best stack for AI-assisted development is the most popular stack your team already knows.** Popularity in training data matters. Your team's existing expertise matters more.

## Initializing the Project

Here is the exact sequence to go from zero to a deployable, auth-connected, database-linked Next.js project:

<Steps>
  <Step>
    **Scaffold the Next.js app**

    ```bash
    npx create-next-app@latest my-app \
      --typescript \
      --tailwind \
      --eslint \
      --app \
      --src-dir \
      --import-alias "@/*"
    cd my-app
    ```
  </Step>
  <Step>
    **Connect to Supabase**

    Create a project at [supabase.com](https://supabase.com), then:

    ```bash
    npm install @supabase/supabase-js @supabase/ssr
    ```

    Add to `.env.local`:

    ```bash
    NEXT_PUBLIC_SUPABASE_URL=https://your-project.supabase.co
    NEXT_PUBLIC_SUPABASE_ANON_KEY=your-anon-key
    SUPABASE_SERVICE_ROLE_KEY=your-service-key
    ```
  </Step>
  <Step>
    **Install and configure Drizzle ORM**

    ```bash
    npm install drizzle-orm postgres
    npm install -D drizzle-kit
    ```

    Create `drizzle.config.ts`:

    ```typescript
    import { defineConfig } from 'drizzle-kit';

    export default defineConfig({
      schema: './src/lib/db/schema.ts',
      out: './drizzle',
      dialect: 'postgresql',
      dbCredentials: {
        url: process.env.DATABASE_URL!,
      },
    });
    ```
  </Step>
  <Step>
    **Configure Clerk for authentication**

    ```bash
    npm install @clerk/nextjs
    ```

    Add to `.env.local`:

    ```bash
    NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY=pk_test_...
    CLERK_SECRET_KEY=sk_test_...
    ```

    Wrap your app in `ClerkProvider` in `src/app/layout.tsx` and add the middleware file — your agent can do both once you tell it the keys are configured.
  </Step>
  <Step>
    **Push to GitHub and deploy to Vercel**

    ```bash
    git init
    git add .
    git commit -m "feat: initial scaffold"
    gh repo create my-app --public --push
    ```

    Then visit [vercel.com/new](https://vercel.com/new), import the GitHub repo, add your environment variables, and deploy. First deploy typically takes under 90 seconds.
  </Step>
</Steps>

<Takeaway>
Choose your stack based on three AI-friendly criteria: training data saturation, TypeScript type safety, and MCP server support. The recommended starter stack — **Next.js 15 + TypeScript + Tailwind + Supabase + Drizzle + Vercel** — hits all three. Deviate only when your workload or team's expertise genuinely demands it. Scaffold the project once, commit it, deploy it to Vercel empty — then have your agent fill it in feature by feature.
