<LessonIntro>
The most common point of failure in AI-assisted development is not a limitation in LLM intelligence; it is abdication of architectural responsibility. Typing "Build me a micro-SaaS with authentication, Stripe billing, and a dashboard" is not a prompt — it is a wish. When you ask an agent to invent your project out of thin air, it makes fifty silent design decisions on your behalf: database schema conventions, auth strategies, state management, and edge-case behaviors. You are not a spectator watching an AI code; you are the chief architect holding the technical deed. You own every decision; the agent executes the syntax.
</LessonIntro>

## The "Vibe Coding" Trap vs. Intentional Engineering

When developers treat coding agents like magic wands, they slide into what the industry calls "vibe coding": accepting whatever code compiles without knowing why or how it works.


## The 4 Laws of Decision Ownership

To maintain mastery over an AI-built codebase, enforce these four principles:

1. **Never delegate scope definition**: You define the exact boundary of what exists and what is omitted. If you don't declare the edge, the LLM will hallucinate unnecessary complexity.
2. **Never accept a library you cannot debug**: If the agent introduces an obscure date picker or state management library you don't understand, reject it and mandate standard tools (e.g. `date-fns`, React standard state).
3. **Decide data contracts before implementation**: You must understand the shape of your database rows and API response payloads before the agent begins rendering UI components.
4. **Assume full legal and production accountability**: The agent will not join the 3 AM incident triage bridge when an unverified query exposes user data. You are the sole accountable party.

## Reusable Artifact: The Decision-Ownership Checklist

Before handing any prompt to an AI agent, verify every item on this checklist:

| Check | Question to Ask Yourself | If Unanswered |
|---|---|---|
| 📋 **Explicit Goal** | Can I state the single user outcome of this task in one sentence? | Stop. Refine the ticket. |
| 🛑 **Explicit Exclusions** | Have I stated what the agent must *not* touch or build in this step? | The agent will over-engineer. |
| 🗄️ **Data Schema** | Do I know which database tables and columns this change touches? | Agent will invent conflicting columns. |
| 🔐 **Auth Policy** | Who is authorized to execute this action, and how is it verified? | Security holes (IDOR) will emerge. |
| 📦 **Tech Dependencies** | Have I explicitly specified which libraries and utilities to use? | Agent may install redundant npm packages. |

<Callout type="info">
Copy this checklist into your notes before every major feature session. When you feel the urge to say "just make it work," pause and fill in the missing decisions first.
</Callout>
