## What a Skill Is

A Skill is a Markdown file — typically named `SKILL.md` — that the agent loads when starting a specific type of task. It's not a prompt; it's documentation. The agent reads it the same way a developer reads an internal wiki page before beginning a PR.

Every good SKILL.md has four parts:

| Section | Purpose |
|---|---|
| **When to use this skill** | Conditions that trigger this skill — e.g., "Use when implementing a new UI component" |
| **Rules and patterns** | Explicit instructions: naming conventions, required imports, structural patterns |
| **Example code snippets** | Concrete before/after examples of what good looks like |
| **Common mistakes** | What NOT to do, so the agent avoids the easy wrong paths |

Here's a minimal SKILL.md structure:

```markdown
# Skill: React Server Components

## When to Use
Use this skill whenever you are creating a new page, layout, or data-fetching component
in the Next.js App Router.

## Rules
- Server Components are the default — opt into Client Components only for interactivity
- Never use `useState` or `useEffect` in Server Components
- Fetch data directly with `await` at the top of the component — no wrappers needed
- Pass data down to Client Components as props — do not fetch in Client Components

## Example

### ✅ Correct
```tsx
// app/dashboard/page.tsx
import { getLinks } from '@/actions/links';

export default async function DashboardPage() {
  const links = await getLinks(); // Direct async fetch in Server Component
  return <LinkTable links={links} />;
}
```

### ❌ Wrong
```tsx
// Client Component fetching data — avoid this
'use client';
import { useEffect, useState } from 'react';

export default function DashboardPage() {
  const [links, setLinks] = useState([]);
  useEffect(() => { fetch('/api/links').then(/* ... */); }, []);
  // ...
}
```

## Common Mistakes
- Adding `'use client'` to a component that only needs to display data
- Fetching data in a Client Component wrapped in `useEffect`
- Forgetting to `await` the data fetch (TypeScript will catch this, but it's still a footgun)
```

## Matt Pocock Skills

Matt Pocock's skills implement a structured workflow for going from a fuzzy idea to shipped code. Install the entire collection with one command:

```bash
npx skills@latest add mattpocock/skills
```

This installs the following slash commands into your agent (Claude Code and compatible agents):

| Command | What It Does | When to Run |
|---|---|---|
| `/grill-with-docs` | Agent interviews you about the feature/project, reads referenced docs, asks clarifying questions until context is complete | Start of a new feature or project |
| `/to-spec` | Compresses the interview + context into a concise, structured technical spec | After `/grill-with-docs` |
| `/to-tickets` | Breaks the spec into ordered, implementable tasks with acceptance criteria | After `/to-spec` |
| `/implement` | Implements one ticket at a time, test-first, with clear checkpoints | Per ticket during implementation |
| `/code-review` | Reviews the current diff against the spec and your conventions | Before every PR |

### The Workflow in Practice

```bash
# 1. Start a new feature session in Claude Code
/grill-with-docs

# Agent: "Tell me about the feature you want to build..."
# You: Describe branded domains. The agent asks 8-10 follow-up questions.
# Agent generates a context document.

# 2. Compress to spec
/to-spec

# Agent: Produces a crisp 1-page spec with: Goal, Constraints, Schema changes, API changes, UI changes.

# 3. Break into tickets
/to-tickets

# Agent: "I've created 7 tickets. Starting with Ticket 1: Database migration for custom_domains table."

# 4. Implement ticket by ticket
/implement
```

<LessonNote variant="myth" title="Myth: You can just describe the feature and let the agent figure it out">
Skipping the grill-and-spec phases and going straight to implementation is the single biggest source of wasted tokens and wrong-direction code. The agent doesn't know what you don't tell it. `/grill-with-docs` forces the agent to surface its assumptions before they become bugs.
</LessonNote>

## Emil Kowalski Design Skills

Emil Kowalski is a design engineer known for UI components that feel genuinely premium — the kind of interfaces where every hover state, every transition, and every spacing decision is deliberate. His skills collection teaches your agent to apply that same sensibility.

```bash
npx skills@latest add emilkowalski/design
```

Emil's skill teaches the agent these core principles:

| Principle | What It Means in Code |
|---|---|
| **Spring animations** | Use `spring` physics for motion (via Framer Motion) — not `ease-in-out` tweens |
| **Hover micro-interactions** | Every interactive element has a visible, intentional hover state — not just cursor change |
| **Precise spacing** | Spacing follows a consistent 4px grid — no arbitrary pixel values |
| **Accessible by default** | Every interactive element has `aria-label`, keyboard focus styles, and correct roles |
| **Invisible details** | Transitions on mount, subtle border-radius changes on press, delightful empty states |

### What It Looks Like

Without the Emil design skill, an agent builds a button like this:

```tsx
<button onClick={onClick} className="bg-blue-500 text-white px-4 py-2 rounded">
  Create Link
</button>
```

With the Emil design skill loaded, the agent produces:

```tsx
<motion.button
  onClick={onClick}
  className="bg-blue-500 text-white px-4 py-2 rounded-md font-medium"
  whileHover={{ scale: 1.02, backgroundColor: '#2563eb' }}
  whileTap={{ scale: 0.98 }}
  transition={{ type: 'spring', stiffness: 400, damping: 30 }}
  aria-label="Create a new short link"
>
  Create Link
</motion.button>
```

The difference is what separates apps that users call "polished" from apps that just work.

## Security Audit Skills (Cloudflare)

Before shipping any significant feature, you should run a security audit. Cloudflare's security skill turns your agent into a systematic OWASP-checklist auditor.

```bash
npx skills@latest add cloudflare/security-audit
```

Once installed, run the `/security-audit` command before every major release:

```bash
/security-audit
```

The agent will systematically check:

- **OWASP Top 10** — SQL injection, XSS, broken auth, IDOR, and more
- **CSP headers** — Content Security Policy configuration in your Next.js middleware
- **Auth misconfigurations** — Routes that should be protected but aren't
- **Exposed secrets** — Patterns that suggest API keys in client-side code
- **RLS policies** — Supabase Row Level Security gaps (if you have a Supabase MCP connected)
- **Dependency vulnerabilities** — Cross-references your `package.json` against known CVEs

<Callout type="info">
The Cloudflare security skill is most powerful when combined with the Supabase MCP server (covered in the next lesson). With MCP connected, the agent can actually read your RLS policies and check them — not just ask you to describe them.
</Callout>

## Official Provider Skills (Expo, FastAPI, Tauri)

Rather than using generic community prompts, top framework maintainers now publish **official, vendor-maintained skills** so agents write idiomatic, up-to-date code.

### 1. Official Expo Mobile Skills (`expo/skills`)
Maintained directly by the Expo team, these skills teach coding agents the nuances of the modern Expo ecosystem (SDK 52+, Expo Router v4, EAS Build):

```bash
# Install all official Expo skills for Cursor, Claude Code, or Codex:
npx skills@latest add expo/skills --skill '*'

# Or for Claude Code via official plugin:
claude plugin install expo@claude-plugins-official
```

What the official Expo skills enforce:
- **Expo Router Conventions**: File-based tabs, stack navigators, typed route parameters, and async Data Loaders.
- **NativeWind & React Native Styling**: Preventing unsupported CSS properties (e.g. `position: fixed`) from breaking mobile layouts.
- **EAS Workflows**: Configuring `eas.json` for development clients and automated App Store / Play Store releases.
- **Asset Optimization**: Using `expo-image` and vector icons properly without memory leaks.

### 2. FastAPI & Python Backend Skills (`fastapi-python`)
For Python and FastAPI backend developers, official and vetted framework skills enforce Pydantic v2 best practices and async concurrency:

```bash
# Install FastAPI development skills:
npx skills@latest add mindrally/skills --skill fastapi-python
```

What the FastAPI skill teaches your agent:
- **Pydantic v2 Standards**: Using `model_validate`, `field_validator(mode='before')`, and `@computed_field` instead of deprecated Pydantic v1 patterns.
- **Dependency Injection**: Structuring database sessions via `Depends(get_db)` and OAuth2 bearer token security schemes.
- **Async DB Sessions**: Using `AsyncSession` with SQLAlchemy 2.0 / SQLModel to prevent blocking event loop execution.
- **Automatic OpenAPI Documentation**: Decorating endpoints with response models and status codes so frontend clients can generate typed SDKs.

### 3. Tauri & Desktop Skills (Windows & macOS)
Building native desktop applications requires understanding the security boundaries between the Webview UI and the native Rust backend:

```bash
# Install Tauri desktop development skills and rules:
npx skills@latest add full-stack-skills/tauri-skills
```

What the Tauri skill instructs your agent on:
- **Tauri 2.0 Architecture**: Using the new multi-platform capabilities and plugin architecture.
- **IPC Commands**: Writing type-safe Rust commands with `#[tauri::command]` and invoking them from TypeScript with `@tauri-apps/api/core`.
- **Desktop Security Boundary**: Enforcing the Principle of Least Privilege in `tauri.conf.json` permissions capabilities instead of granting broad filesystem/shell access.
- **Native Windows & macOS Features**: Implementing system tray menus, global shortcuts, and file drop listeners.

## Writing Your Own Skills

The community skills are great, but the most valuable skills are the ones you write yourself — encoding the specific patterns that are unique to your team and project.

<Steps>
<Step>
**Identify a repeated task**

Find a task you've explained to the agent 3+ times. Common candidates: "how we write Server Actions," "how we handle errors," "how we structure a new feature folder."
</Step>
<Step>
**Write the rules in a SKILL.md**

Create a new file and fill in the four sections: when to use, rules, examples, common mistakes. Be specific — vague rules produce vague code.
</Step>
<Step>
**Store it in `.skills/`**

Create a `.skills/` folder in your project root. Name the file descriptively: `.skills/server-actions.md`, `.skills/error-handling.md`.
</Step>
<Step>
**Reference it in AGENTS.md**

Add a `## Custom Skills` section to your AGENTS.md:
```markdown
## Custom Skills
- `.skills/server-actions.md` — Load when writing any Server Action
- `.skills/error-handling.md` — Load when implementing error boundaries or try/catch
- `.skills/new-feature.md` — Load when scaffolding a new feature module
```
</Step>
</Steps>

Here's a minimal template for a custom SKILL.md:

```markdown
# Skill: [Skill Name]
> Load this skill when: [specific trigger condition]

## Rules
- [Rule 1]
- [Rule 2]
- [Rule 3]

## Pattern

```tsx
// ✅ The correct pattern
```

## What NOT To Do

```tsx
// ❌ Common wrong approach
```

## Checklist Before Finishing
- [ ] [Check 1]
- [ ] [Check 2]
```

<Callout type="info">
**Skills compound in value.** One skill takes 30 minutes to write and saves 10 minutes per session for the rest of the project. On a 6-month project with daily agent sessions, a single custom skill pays back 30× the investment. Write the skill the first time you catch yourself re-explaining something you've already explained.
</Callout>
