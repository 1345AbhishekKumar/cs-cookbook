## Repeat without copying, fail in only three ways

Copying a print line fifteen times is annoying; copying it ten thousand times is not programming. A loop runs a set of instructions repeatedly so you write the logic once. The video introduces the for loop for the "do this N times" case — print something fifteen times, walk every array slot — and the while family for "keep going until something changes" cases. The hosts repeat the opening line five times on purpose: hearing the repetition makes the waste obvious. The discipline is to state the start, the continuation test, and the step so clearly that the loop must end. Forget the step and you get the video's cautionary tale: an infinite loop, likened to telling someone they can leave the couch once a TV character achieves the impossible. The program is not stuck because the computer is slow; it is stuck because your exit can never happen.

That leads directly into errors, which the video narrows to three kinds for scripting-style languages. Syntax errors are small spelling or grammar breaks — a two-word variable name, a misspelled `String` — and they are the friendliest: the IDE underlines them and often refuses to run until they are fixed, like an essay checker that blocks printing. Runtime errors appear only when you run: logically plausible code the machine cannot physically complete in reasonable time or space. The infinite loop is the flagship example. Logic errors are the quiet ones: the program runs and prints, but the answer is wrong because you multiplied where you meant to add. No red underline arrives; you must notice the wrong output and reason backward. Learning to name which of the three you face changes what you do next — fix spelling, fix feasibility, or fix reasoning — and that classification is the bridge to debugging in Module 6.

### Step-by-step breakdown

1. Choose for (known count) vs while (condition-driven).
2. Write start, test, and step explicitly.
3. Keep the body small; print the counter while learning.
4. Check the exit on paper: does the test ever become false?
5. When output surprises you, label the failure: syntax, runtime, or logic.

- **Obvious** — Print "hi" 15 times with a for loop, not 15 pasted lines.
- **Counter-intuitive** — Syntax errors block running — a kindness. The IDE is stopping you from testing code it already knows is malformed.
- **Edge case** — Infinite loop as runtime error: code looks reasonable, but "leave when impossible happens" never ends.

```java
// Java shape from the video:
for (int i = 0; i < 15; i++) { print(i); }
// syntax error:  int my variable = 5;  // space not allowed
// logic error:   total = a * b;        // meant a + b, runs but wrong
```

```python
# Python - loops + the 3 error types, runs as-is:
# for loop: repeat 15 times (no manual i++ needed)
for i in range(15):
    print(i)   # 0..14

# while loop: keep going until something changes
count = 0
while count < 5:
    print(count)
    count += 1   # forget this line = infinite loop (runtime error)

# loop over an array without copying lines:
foods = ["milk", "eggs", "bread"]
for item in foods:
    print(item)

# syntax error:  my variable = 5   # space not allowed - Python refuses to run
# runtime error: print(10 / 0)     # ZeroDivisionError only when run
# logic error:   total = 4 * 5     # runs, gives 20, but you meant 4 + 5 = 9
```

Visual analogy — A washing-machine cycle: start, check "still dirty and time left?", agitate, advance timer. No timer advance = flood.

**✕ What people get wrong:** "Runtime and logic errors are the same because both run." Runtime means cannot finish; logic means finishes wrongly. Different fixes.

**Why this matters:** Loops plus arrays let you handle 100,000 users with the same lines that handle 3. Errors taxonomy tells you where to look when scale breaks.
