## Borrow wisely, build cleanly, store flexibly

You do not need to write everything. A library is a collection of functions someone else proved correct; importing lets you borrow just what you need. The video's example is Python's `math` library: importing the whole thing for one factorial wastes load time and memory, especially as projects grow, so you write `from math import factorial` (or the Java equivalent) to take a single tool rather than the whole workshop. For smaller scripts the cost is negligible, but the habit scales: depend on little, understand what you borrowed, and keep load proportional to need. This is also your first encounter with the ecosystem idea — programming is not solo invention but careful assembly of trusted parts.

Making your own functions mirrors that discipline. The video builds two Java shapes: a void function that takes no arguments and simply runs (much like the early print demo), and a void-with-arguments version where the parentheses declare typed parameters such as `num1` and `num2`. Calling `multiplyNumbers(5, 8)` slides 5 into `num1` and 8 into `num2`, prints 40, and returns nothing — void means no tray comes back. The parameter names are the kitchen's internal labels; the arguments are the specific tickets tonight.

Then storage grows up. Plain arrays have fixed size, which hurts when you do not know how many users, scores, or items will arrive. An ArrayList starts around size 10 and grows itself by allocating more memory as you append beyond capacity — ideal when the count is unknown. Dictionaries solve a different rigidity: instead of linear positions, each value is tied to a key used to reference it, like looking up a definition by word rather than by page number. Together, import discipline, clean function shapes, and flexible containers move you from classroom snippets to programs that survive real input.

### Step-by-step breakdown

1. Need a proven tool? Import the smallest piece that does the job.
2. Need a new tool? Declare void vs returning, then list typed parameters in parentheses.
3. Name parameters for inside the function; pass arguments for this specific call.
4. Unknown count? Prefer ArrayList over fixed array so growth is automatic.
5. Lookup by identity (username, ID)? Prefer dictionary key over numeric index.

- **Obvious** — Need factorial once: `from math import factorial`, not the whole math library.
- **Counter-intuitive** — Void with arguments still returns nothing. `multiplyNumbers(5,8)` prints 40 but gives you no value to store.
- **Edge case** — ArrayList crossing 10 elements triggers reallocation. Slight cost once, freedom always — the right trade when size is unknowable.

```python
# Python - borrow one tool, build your own, store flexibly:
from math import factorial
print(factorial(5))  # 120
# import math        # whole workshop - heavier than needed for one tool
# Java shape from video:
# public void multiplyNumbers(int num1, int num2) {
#   System.out.println(num1 * num2);
# }
```

```python
# Python - your own functions (void vs returning):
# void-like: prints but returns None (no tray back)
def multiply_numbers(num1, num2):
    print(num1 * num2)

multiply_numbers(5, 8)      # prints 40
result = multiply_numbers(5, 8)  # prints 40, but result is None
print(result)               # None - nothing to store

# returning: hands a value back to catch
def multiply_return(num1, num2):
    return num1 * num2

print(multiply_return(5, 8))  # 40, now usable
total = multiply_return(5, 8) + 10
print(total)  # 50

# Python lists grow like ArrayLists (no fixed size pain):
scores = []            # start empty - size unknown is fine
scores.append(95)
scores.append(80)
print(scores)          # [95, 80] - grew itself

# Python dicts = key-value lookup (no slot numbers):
student = {"name": "Ada", "id": 42}
print(student["name"])  # Ada - lookup by key, not position
student["grade"] = "A"  # add a new key
print(student)
```

Visual analogy — Fixed array = egg carton (12 slots, no more). ArrayList = expandable file folder. Dictionary = labeled filing cabinet (ask by name, not by drawer number).

**✕ What people get wrong:** "Bigger import is safer in case I need more later." Extra imports cost load and clarity. Import what you use; add more when proven needed.

**Why this matters:** Real programs are mostly reuse plus a thin layer of your own functions over flexible storage. This module is that layer.
