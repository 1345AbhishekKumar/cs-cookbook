## Named boxes that hold one thing at a time

The video's most durable image is a storage facility full of cardboard boxes. Each box has a label written in marker — that label is the variable name — and inside is a single sheet of paper — the value. To make a variable called `name` holding "no pointer exception", you build a box labeled `name` and slip that paper inside. To read it later, you point at the box and the computer fetches the paper. To change it, you swap the paper: `age` 17 becomes 18 on a birthday by replacing the sheet, not by building a new facility. You can even build an empty labeled box and fill it later, for example when you plan to store what a user will type but do not know it yet. Point at an empty box, though, and you get the famous null pointer exception — reaching for paper that is not there.

Boxes come in types, and the type decides what fits. The video walks through primitives: integers for whole numbers, floats and doubles for decimals (doubles hold about 64-bit precision versus 32 for floats, so more decimal places), strings for text, characters for single symbols, and Booleans for true/false. Manipulation is swapping, combining, and converting those papers: assign with `=`, update by reassigning, do arithmetic, use modulus to test evenness, concatenate strings, and cast or parse when a value must change type.

The "one paper per box" limit is intentional foreshadowing. One string variable cannot comfortably hold six grocery items while staying searchable and deletable — which is exactly why Module 4 introduces arrays. For now, practice the discipline the video models: declare with a type, give a clear name, initialize before you read, and print the box contents often so you can see what the machine actually stored, not what you hoped it stored.

### Step-by-step breakdown

1. Declare: pick a type and a name (`int age`).
2. Initialize: put the first value in (`age = 17`).
3. Read: reference the name wherever the value is needed.
4. Update: reassign (`age = 18`).
5. Guard: never read a box you have not filled; expect null errors if you do.

- **Obvious** — `String name = "Ada";` printing `name` shows `Ada`.
- **Counter-intuitive** — An "empty box" is legal to create but illegal to read meaningfully. The machine does not guess; it throws.
- **Edge case** — float vs double: both hold decimals, but long precise values need the 64-bit box or they lose detail.

```java
# Java shapes from the video:
int age = 17;        // box labeled age, paper says 17
age = 18;            // swap paper on birthday
String name = "Ada";
boolean isEven = (50 % 2 == 0);  // true
```

```python
# Python - same ideas, no type declarations needed:
age = 17          # int box
print(age)        # 17
age = 18          # swap paper on birthday
print(age)        # 18
name = "Ada"      # str box
price = 19.99     # float box (Python has no separate double)
is_student = True # bool box - note capital T
is_even = (50 % 2 == 0)
print(is_even)    # True
print(type(age), type(price), type(name), type(is_student))
# Empty box idea: Python uses None
user_input = None
print(user_input)  # None - Python's version of "empty box"
# Reading None like a value still runs, but logic breaks -
# closest Python cousin of the null-pointer lesson
```

Visual analogy — Labeled moving boxes in a storage unit. The marker is the name, the unit is memory, the paper is the value. Labels do not move; papers do.

**✕ What people get wrong:** "A variable can hold many values if I squeeze them in." One variable holds one value. For many related values you need a list structure, not a bigger box.

**Why this matters:** Every later structure — arrays, lists, dictionaries, function arguments — is just a disciplined arrangement of these boxes.
