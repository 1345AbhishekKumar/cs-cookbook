### Why can't computers just use base-10 like humans?

Because the fundamental hardware element — a transistor — has only two states: on and off. Building a reliable 10-state switch is enormously harder than building a reliable 2-state switch. Binary is the path of least resistance for hardware, and we build abstractions (hex, decimal display, programming languages) on top to make it human-friendly. The hardware stays binary because that is what physics makes reliable.

### Is Python "better" than C because it's easier?

Better for what? Python is far more productive for most application code — you write less, it's more readable, the ecosystem is huge. C is far faster and gives you control over memory, which matters for operating systems, embedded devices, game engines, and anything where microseconds count. "Better" depends on the constraint that matters most: developer time (Python) or machine time (C).

### Do I really need to know Big-O if I'm not doing algorithms interviews?

Yes, but not to recite proofs. You need the intuition: if you nest two loops over the same list, your code will be slow at scale; if you can replace a linear scan with a hash lookup, you should. Big-O is the vocabulary that lets you reason about whether your code will survive growth. Without it, performance problems feel like magic.

### What's the difference between a thread and a process?

A process is an independent running program with its own memory space. A thread is a unit of execution *inside* a process — multiple threads in one process share the same memory. Threads are lighter to create but introduce the risk of race conditions (two threads editing the same data simultaneously). Processes are heavier but safer (isolated memory).

### Why does DNS take time, and why do things still load if DNS is "slow"?

DNS is a distributed database queried over the network. The first lookup for a domain may take tens of milliseconds; subsequent lookups are cached at multiple levels (browser, OS, router, ISP). If DNS feels slow, it's usually the first uncached request. Once cached, subsequent requests to the same domain skip the lookup entirely.
