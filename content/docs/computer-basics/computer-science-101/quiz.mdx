## 1. Hardware, CPU & Execution Cycle

<TryIt

<TryIt
  question="Why is an L1 CPU cache miss roughly 100 times more costly in latency than an L1 cache hit?"
  options={[
    "Cache misses require the CPU to reboot its clock oscillator",
    "Fetching data from main RAM requires traversing the motherboard memory bus (~50-100 ns), whereas L1 cache responds directly on the silicon die in ~1 ns",
    "Cache misses force the operating system into a Ring 0 context switch",
    "RAM requires all binary data to be decrypted before read operations",
  ]}
  answer="B"
  why="L1 cache sits directly inside the core silicon and matches clock cycle frequency (under 1 ns). Main RAM is separated across the physical motherboard traces and memory controllers, costing tens of nanoseconds of idle processor stall time."

## 2. Encodings & Data Representation

<TryIt
  question="Why can the decimal number 0.1 NOT be represented with 100% precision in standard IEEE 754 binary floating-point?"
  options={[
    "The CPU ALU cannot divide numbers smaller than 1",
    "In base 2, 1/10 becomes an infinite repeating binary fraction (0.0001100110011...), just as 1/3 is an infinite repeating decimal (0.3333...) in base 10",
    "Floating-point registers are restricted to integer values only",
    "Unicode characters occupy the fractional bits of floating-point registers",
  ]}
  answer="B"
  why="A fraction can only be expressed cleanly in a base if its denominator's prime factors divide that base. Base 10 has prime factors 2 and 5 (so 1/10 terminates), but base 2 only has factor 2, making 1/10 an infinite repeating binary sequence that must be rounded."
/>

<TryIt
  question="In a UTF-8 encoded text file, how many bytes does the emoji character '💻' consume?"
  options={["1 byte (same as ASCII)", "2 bytes", "4 bytes", "8 bytes"]}
  answer="C"
  why="UTF-8 is variable-width: standard ASCII occupies 1 byte, accented Latin scripts use 2 bytes, most Asian scripts use 3 bytes, and supplementary characters (including modern emoji) use 4 bytes."

<TryIt
  question="What mechanism prevents a buggy user-space program (Ring 3) from directly corrupting another program's memory or executing raw disk controller I/O?"

<TryIt
  question="When chaining commands with a pipe ('cat logs.txt | grep 500 | wc -l'), how is data transferred between the processes?"
  options={[

## 4. Languages, Memory & Garbage Collection

<TryIt
  question="What is the key performance difference between Ahead-of-Time (AOT) compiled languages (Go, Rust, C++) and Just-In-Time (JIT) languages (Java, JavaScript)?"
  options={[
    "AOT languages can only run on 32-bit operating systems",
    "AOT compiles directly into native CPU machine code before distribution, allowing immediate execution without warmup; JIT runtimes start via interpretation or bytecode and compile hot paths during runtime",
    "JIT languages cannot allocate heap memory",
    "AOT code requires an active internet connection to execute",
  ]}
  answer="B"
  why="AOT binaries are already machine code tailored for an OS/architecture. JIT runtimes like V8 and JVM profile code as it runs, compiling frequently executed functions ('hot paths') into optimized machine code on the fly."
/>

<TryIt
  question="Why is allocating memory on the call stack faster than allocating memory on the heap?"
  options={[
    "The stack uses persistent flash memory instead of volatile RAM",
    "Stack allocation only moves the stack pointer register (SP) by a precalculated offset, while heap allocation requires searching free-lists and synchronizing across threads",
    "Heap variables can never be larger than 64 bits",
    "The operating system disables CPU cache for heap addresses",
  ]}
  answer="B"
  why="Stack frames are ordered and deterministic. Allocating a local variable takes a single CPU instruction modifying the stack pointer, whereas the heap must search memory allocators and manage fragmentation."
/>

<TryIt
  question="In a tracing garbage collector (Mark-and-Sweep), how does the engine decide that an object on the heap can be safely freed?"
  options={[
    "When its internal reference counter reaches zero",

    "When the object has been in memory for more than 60 seconds",
    "When the operating system sends a SIGKILL signal",
  ]}
  answer="B"
  why="Tracing collectors start at GC Roots and traverse pointers. Unreachable objects are swept and freed, neatly solving the circular reference problem that breaks pure reference counting."

## 5. Data Structures & Big-O Scaling

<TryIt
  question="Why does retrieving an element from an array by index run in O(1) constant time?"
  options={[
    "Because arrays use binary search trees internally",
    "Because array elements are stored contiguously in memory; the CPU computes the target address with simple arithmetic: base_address + (index * element_size)",
    "Because the CPU keeps all arrays in L1 cache permanently",
    "Because indexing is performed by the operating system kernel",
  ]}
  answer="B"
  why="Contiguous memory layout means direct mathematical addressing. Accessing index 500 costs the exact same single arithmetic calculation as accessing index 0."
/>

<TryIt
  question="If an algorithm has O(n²) quadratic time complexity and processes 1,000 items in 10 milliseconds, approximately how long will it take to process 10,000 items (10x increase)?"
  options={[
    "100 milliseconds (10x slower)",
    "1,000 milliseconds / 1 second (100x slower: 10²)",
    "10 milliseconds (unchanged)",
    "10,000 milliseconds",
  ]}
  answer="B"
  why="In $O(n^2)$ algorithms, multiplying the input size by $k$ multiplies the runtime by $k^2$. Increasing $n$ from 1,000 to 10,000 ($10\times$) results in $10^2 = 100\times$ more operations: $10\text{ ms} \times 100 = 1{,}000\text{ ms}$ (1 second)."

## 6. Networking & Concurrency

<TryIt
  question="What is the fundamental difference between multi-threaded parallelism and event-loop concurrency?"
  options={[
    "Parallelism requires multiple physical CPU cores running instructions at the same instant; event loops manage multiple tasks on a single thread by interleaving non-blocking I/O operations",
    "Parallelism only works on Linux; event loops only work on Windows",
    "Event loops require separate guest operating systems for each task",
    "Parallelism cannot use shared memory",
  ]}
  answer="A"
  why="Parallelism executes simultaneous calculations across multiple hardware cores. Concurrency is about system structure: an event loop handles thousands of concurrent I/O connections on one thread by never waiting synchronously for sockets or disks."
/>

<TryIt
  question="Why does real-time voice and video communication (e.g., Zoom, WebRTC) prefer UDP over TCP?"
  options={[
    "UDP automatically fixes packet corruption with error-correcting codes",
    "UDP drops guaranteed delivery and packet retransmission, eliminating latency spikes from head-of-line blocking when a packet is lost",
    "UDP has stronger cryptographic encryption than TCP",
    "TCP cannot route packets across internet routers",
  ]}
  answer="B"
  why="In live audio or video, a dropped packet 200 ms ago is useless; users notice latency and jitter far more than a tiny dropped frame. TCP pauses all playback while retransmitting lost packets (head-of-line blocking), whereas UDP keeps streaming."
/>
