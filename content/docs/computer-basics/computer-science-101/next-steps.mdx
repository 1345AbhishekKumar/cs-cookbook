You now have the vocabulary. Here is where to take it next:

- **Practice data structures by implementing them from scratch** — a linked list, a hash map, a binary search tree. The act of building reveals the trade-offs no diagram can.
- **Solve algorithm problems on a platform like LeetCode or Exercism** — start with easy problems, focus on identifying which algorithm strategy each one needs.
- **Read the source of a small open-source project** — you'll see classes, functions, and data structures used in anger, not in isolation.
- **Set up a simple server** — write a tiny HTTP API in any language, deploy it to a VM, and curl it. The network stack becomes real the moment you do it yourself.
- **Learn one compiled and one interpreted language deeply** — the contrast reveals what each paradigm makes easy or hard.
- **Study a specific algorithm in depth** — Dijkstra's, quicksort, or dynamic programming on knapsack. One deep dive teaches more than ten shallow overviews.

## Spaced repetition schedule

To retain this material, review the cheat sheet at these intervals:

- Review in 1 minute — skim the cheat sheet now.
- Review in 10 minutes — try to recall each data structure's strength without looking.
- Review in 1 hour — explain Big-O to someone (or out loud).
- Review in 1 day — re-read one module that felt foggiest.
- Review in 3 days — implement one data structure from memory.
- Review in 1 week — take a concept and find a real-world example of it in code you've written or used.
