Welcome to **Stage 2: Querying & Performance** — where PostgreSQL starts to feel powerful.

You can create tables; now you'll ask real questions of them. This stage covers everyday SQL, then the features that make people choose PostgreSQL over other databases, and finally the single most valuable skill: **reading an execution plan and knowing why a query is slow or fast**.

---

## Pedagogical Philosophy

<Callout type="info" title="Performance Is Mostly Physical">
Ninety percent of query performance comes down to one question: **how many pages must the database read?** An index exists to avoid reading pages you don't need. Once you can see, from `EXPLAIN`, whether a query scanned a table or used an index, you can fix almost anything.
</Callout>

By the end of this stage you will be able to:

- Write joins, grouping, subqueries, CTEs, and window functions confidently.
- Reach for `jsonb`, arrays, ranges, full-text search, `ON CONFLICT`, and `RETURNING` when they are the right tool.
- Choose and create the correct index type for a query.
- Read `EXPLAIN (ANALYZE, BUFFERS)` and spot the bottleneck.
