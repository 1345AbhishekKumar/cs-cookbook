## Clause Order vs. Evaluation Order

| Write order | Evaluation order |
| :--- | :--- |
| `SELECT` | `FROM` / `JOIN` |
| `FROM` | `WHERE` |
| `WHERE` | `GROUP BY` |
| `GROUP BY` | `HAVING` |
| `HAVING` | `SELECT` |
| `ORDER BY` | `ORDER BY` |
| `LIMIT` | `LIMIT` |

Aliases from `SELECT` work in `ORDER BY` but not `WHERE`/`HAVING`.

## Operators

| Category | Operators |
| :--- | :--- |
| Arithmetic | `+ - * / % ^ \|/` |
| Comparison | `= <> != < <= > >=` |
| Range / membership | `BETWEEN`, `IN`, `NOT IN` |
| Pattern | `LIKE`, `ILIKE` (`%` any length, `_` single character), `~`, `~*` |
| Null | `IS NULL`, `IS NOT NULL`, `IS DISTINCT FROM` |
| Logic | `AND`, `OR`, `NOT` |
| Array / JSON | `@>`, `<@`, `&&`, `?`, `?|`, `?&`, `->`, `->>`, `#>`, `#>>` |
| Concat | `||` |
| Cast | `x::type`, `CAST(x AS type)` |

### Defensive Math, Expressions & Dates

```sql
COALESCE(num / NULLIF(denom, 0), 0)                 -- safe division (no zero-divide error)
COALESCE(nullable_col, 'fallback')                  -- first non-null
EXTRACT(YEAR FROM departure_at)                     -- extract numeric component
AGE(departure_at, now())                            -- duration as human interval
round(base_price * 0.15, 2)                         -- round to decimal places
```

### Mutating Data Safely

```sql
-- Always use WHERE unless intentionally targeting every record!
UPDATE t SET col1 = 'val', col2 = 100 WHERE id = 1;
DELETE FROM t WHERE status = 'cancelled' AND created_at < now() - interval '30 days';

-- Interactive safety net in psql:
BEGIN;
UPDATE t SET status = 'active' WHERE id = 1;
-- verify with SELECT, then:
COMMIT; -- (or ROLLBACK;)
```

## Joins & Semi/Anti Joins

| Join | Unmatched left | Unmatched right |
| :--- | :--- | :--- |
| `INNER` | dropped | dropped |
| `LEFT` | kept (NULLs) | dropped |
| `RIGHT` | dropped | kept (NULLs) |
| `FULL` | kept | kept |
| `CROSS` | Cartesian product | |

```sql
WHERE EXISTS     (SELECT 1 FROM child c WHERE c.parent_id = p.id)  -- semi
WHERE NOT EXISTS (SELECT 1 FROM child c WHERE c.parent_id = p.id)  -- anti (NULL-safe)
CROSS JOIN LATERAL (SELECT ... FROM t WHERE t.k = o.k LIMIT 3) x    -- top-N per row
```

## Aggregation Cookbook

```sql
count(*)                             -- all rows
count(col)                           -- non-null only
count(DISTINCT col)                  -- distinct
count(*) FILTER (WHERE cond)         -- conditional count
COALESCE(sum(x), 0)                  -- 0 for empty sets
string_agg(col, ',' ORDER BY col)    -- concatenate
array_agg(col ORDER BY col)          -- collect
percentile_cont(0.5) WITHIN GROUP (ORDER BY x)  -- median
```

| Grouping | Produces |
| :--- | :--- |
| `GROUP BY a, b` | `(a,b)` |
| `ROLLUP (a, b)` | `(a,b)`, `(a)`, grand total |
| `CUBE (a, b)` | all combinations |
| `GROUPING SETS ((a),(b),())` | exactly those |
| `GROUPING(col)` | `1` = subtotal row |

## Window Cookbook

```sql
func() OVER (PARTITION BY g ORDER BY o ROWS BETWEEN a AND b)
```

| Goal | Expression |
| :--- | :--- |
| Unique row number | `row_number() OVER (...)` |
| Rank (gaps) / (no gaps) | `rank()` / `dense_rank()` |
| Previous / next | `lag(x)` / `lead(x)` |
| Running total | `sum(x) OVER (PARTITION BY g ORDER BY o)` |
| Moving average | `avg(x) OVER (ORDER BY o ROWS BETWEEN 2 PRECEDING AND CURRENT ROW)` |
| Percent of total | `100.0 * x / sum(x) OVER (...)` |
| Top-N per group | `row_number() ... <= N` inside a CTE |

Frame modes: `ROWS` (physical rows), `RANGE` (value span), `GROUPS` (peer groups).

## PostgreSQL Feature Reference

| Feature | Quick form |
| :--- | :--- |
| JSON extract | `payload ->> 'k'`, `payload #>> '{a,b}'` |
| JSON contain | `payload @> '{"k":"v"}'`, `payload ? 'k'` |
| Arrays | `@>` contains, `&&` overlaps, `unnest(arr)` |
| Full text | `to_tsvector(body) @@ plainto_tsquery($1)` |
| First per group | `DISTINCT ON (k) ... ORDER BY k, sort` |
| Top-N per row | `CROSS JOIN LATERAL (... LIMIT n)` |
| Conditional agg | `count(*) FILTER (WHERE cond)` |
| Upsert | `ON CONFLICT (k) DO UPDATE SET c = EXCLUDED.c` |
| Return values | `INSERT ... RETURNING id` (`OLD`/`NEW` in PG18) |
| Merge | `MERGE INTO t USING s ON ...` |
| Subtotals | `GROUP BY ROLLUP (a, b)` |
| Date spine | `generate_series(start, stop, interval '1 day')` |
| Temporal | `PRIMARY KEY (id, period WITHOUT OVERLAPS)` (PG18) |

## Index Type Atlas

| Type | Best for | Not for |
| :--- | :--- | :--- |
| **B-tree** (default) | Equality, ranges, `ORDER BY`, `LIKE 'x%'` | Containment, geometry |
| **Hash** | Big opaque values, equality only | Ranges, sorting |
| **GIN** | Arrays, `jsonb`, full-text | Simple equality |
| **GiST** | Ranges, geometry, `EXCLUDE` | General equality at scale |
| **SP-GiST** | Quadtrees, IP prefixes | General sorts |
| **BRIN** | Huge, time-ordered tables | Randomly ordered data |
| **Bloom** | Ad-hoc equality combinations | Selective single columns |

```sql
CREATE INDEX i ON t (a, b);                          -- btree
CREATE INDEX i ON t USING gin (tags);                -- arrays / jsonb / FTS
CREATE INDEX i ON t (a) INCLUDE (b, c);              -- covering
CREATE INDEX i ON t (lower(email));                  -- expression
CREATE INDEX i ON t (a) WHERE status = 'pending';    -- partial
CREATE INDEX CONCURRENTLY i ON t (a);                -- no write lock
```

<Callout type="tip" title="Composite Index Prefix Rule">
For `(a, b, c)`: usable by `a`, `a,b`, `a,b,c`. Not by `b` or `c` alone (unless PG18 skip scan applies). Order: equality columns first, then range/sort.
</Callout>

## `EXPLAIN` Node Glossary

| Node | Means |
| :--- | :--- |
| `Seq Scan` | Full table scan |
| `Index Scan` | Index lookup + heap fetch |
| `Index Only Scan` | Answered from the index alone |
| `Bitmap Index Scan` + `Bitmap Heap Scan` | Many matches read in physical order |
| `Nested Loop` / `Hash Join` / `Merge Join` | Join algorithms |
| `HashAggregate` / `GroupAggregate` | `GROUP BY` strategies |
| `Sort` | Explicit sort (watch disk spill) |
| `Materialize` | Cache inner input across loops |
| `Gather` / `Gather Merge` | Parallel worker collection |

| Field | Reading |
| :--- | :--- |
| `cost=a..b` | Estimated units (≈ page reads) |
| `rows=` | Estimated output rows |
| `actual rows=` | Real output rows (compare to `rows=`) |
| `Buffers: shared hit/read` | Pages from cache / disk |
| `Rows Removed by Filter` | Wasted reads — often a missing index |

## Tuning Cheatsheet

```sql
ANALYZE t;                                     -- refresh statistics
SET work_mem = '64MB';                         -- for this session's sorts/hashes
SET max_parallel_workers_per_gather = 0;       -- isolate a plan
```

| Setting | Guidance |
| :--- | :--- |
| `random_page_cost` | ~1.1 on SSD (default 4.0 assumes spinning disks) |
| `effective_cache_size` | Planner's cache estimate (~50–75% of RAM) |
| `work_mem` | Per sort/hash node; raise for analytics |
| `default_statistics_target` | Raise for skewed columns |
