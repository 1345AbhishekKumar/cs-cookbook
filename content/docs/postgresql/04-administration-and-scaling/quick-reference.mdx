## Roles & Privileges

```sql
-- Group roles (permission bundles)
CREATE ROLE app_rw      NOLOGIN;
CREATE ROLE app_ro      NOLOGIN;
CREATE ROLE app_migrate NOLOGIN;

-- A login role that carries a bundle
CREATE ROLE app_service LOGIN PASSWORD '…';
GRANT app_rw TO app_service;

-- Grants (note: schema USAGE is a separate gate from table rights)
GRANT USAGE ON SCHEMA public TO app_rw, app_ro, app_migrate;
GRANT SELECT, INSERT, UPDATE, DELETE ON ALL TABLES IN SCHEMA public TO app_rw;
GRANT SELECT ON ALL TABLES IN SCHEMA public TO app_ro;
GRANT USAGE, SELECT ON ALL SEQUENCES IN SCHEMA public TO app_rw;

-- Future objects
ALTER DEFAULT PRIVILEGES IN SCHEMA public
  GRANT SELECT, INSERT, UPDATE, DELETE ON TABLES TO app_rw;
ALTER DEFAULT PRIVILEGES IN SCHEMA public
  GRANT USAGE, SELECT ON SEQUENCES TO app_rw;

-- Revoke and inspect
REVOKE DELETE ON bookings FROM app_rw;
```

| Idea | Rule |
| :--- | :--- |
| Superuser | Never for the app; admin over a bastion only |
| Built-in roles | `pg_monitor`, `pg_read_all_data`, `pg_write_all_data`, `pg_signal_backend` |
| `search_path` | Pin it (`ALTER ROLE … SET search_path = app, pg_catalog`) |
| `public` schema | `REVOKE CREATE ON SCHEMA public FROM PUBLIC` (default in PG15+) |
| `TRUNCATE` | Grant to nobody who doesn't need it — RLS doesn't stop it |

```sql
-- Audit
SELECT rolname, rolsuper, rolcanlogin FROM pg_roles WHERE rolcanlogin;
SELECT grantee, privilege_type FROM information_schema.role_table_grants WHERE table_name = 'bookings';
```

## Authentication (`pg_hba.conf`)

```conf
# TYPE     DATABASE     USER          ADDRESS        METHOD
local      all          postgres                     peer
hostssl    travelbuddy  app_service   10.0.0.0/8     scram-sha-256
host       all          all           ::/0           reject
```

| Method | Use |
| :--- | :--- |
| `scram-sha-256` | **Preferred** password auth |
| `md5` | Deprecated (PG18); avoid |
| `peer` | Local OS-user match |
| `cert` | TLS client certs |
| `reject` | Final catch-all deny |

```sql
SELECT pg_reload_conf();                       -- apply pg_hba changes
SELECT pid, usename, ssl FROM pg_stat_ssl JOIN pg_stat_activity USING (pid);
```

## Row-Level Security

```sql
ALTER TABLE bookings ENABLE ROW LEVEL SECURITY;
ALTER TABLE bookings FORCE  ROW LEVEL SECURITY;   -- also applies to the owner

CREATE POLICY sel_own ON bookings FOR SELECT TO app_rw
  USING      (tenant_id = current_setting('app.tenant_id')::bigint);
CREATE POLICY ins_own ON bookings FOR INSERT TO app_rw
  WITH CHECK (tenant_id = current_setting('app.tenant_id')::bigint);
CREATE POLICY staff_all ON bookings TO support_staff USING (true);
```

| Clause | Applies to | Meaning |
| :--- | :--- | :--- |
| `USING` | `SELECT`/`UPDATE`/`DELETE` | Which rows are visible |
| `WITH CHECK` | `INSERT`/`UPDATE` | Which new rows are allowed |
| `TO role` | Any | Scope the policy |
| `PERMISSIVE` (default) | Any | Policies OR together |
| `RESTRICTIVE` | Any | Must all pass (AND) |

<Callout type="warn" title="RLS Gotchas">
- Owners and superusers bypass RLS unless you `FORCE` it.
- **`TRUNCATE` ignores RLS** — revoke the privilege.
- With a transaction-mode pooler, set the tenant with `SET LOCAL` **inside** the transaction.
</Callout>

```sql
SELECT * FROM pg_policies;                                  -- what's defined
SELECT relname FROM pg_class c JOIN pg_namespace n ON n.oid = c.relnamespace
WHERE n.nspname = 'public' AND c.relkind = 'r' AND NOT c.relrowsecurity;
```

## Configuration: What to Tune

```conf
shared_buffers              = 4GB      # ~25% RAM
effective_cache_size        = 12GB     # ~75% RAM (planner estimate only)
work_mem                    = 8MB      # PER sort/hash node PER connection
maintenance_work_mem        = 512MB    # VACUUM / CREATE INDEX
max_connections             = 100      # keep low; pool instead
random_page_cost            = 1.1      # SSD
effective_io_concurrency    = 200      # SSD
wal_level                   = replica
max_wal_size                = 4GB
checkpoint_completion_target= 0.9
synchronous_commit          = on       # off = faster, can lose recent commits
```

| Want | Do |
| :--- | :--- |
| Apply now, session-only | `SET x = …` / `SET LOCAL x = …` |
| Persist, cluster-wide | `ALTER SYSTEM SET x = …; SELECT pg_reload_conf();` |
| One database / role | `ALTER DATABASE db SET …` / `ALTER ROLE r SET …` |
| Find non-defaults | `SELECT name, setting, boot_val FROM pg_settings WHERE source <> 'default';` |
| Who needs restart | `SELECT name FROM pg_settings WHERE pending_restart;` |

<Callout type="tip" title="The Two Biggest Wins">
Lower `random_page_cost` to ~`1.1` on SSDs (planner starts using your indexes), and raise `max_wal_size` so checkpoints stop causing latency spikes.
</Callout>

## Connections & Pooling

```sql
SELECT state, count(*) FROM pg_stat_activity WHERE backend_type = 'client backend' GROUP BY state;
SELECT application_name, count(*) FROM pg_stat_activity GROUP BY 1 ORDER BY 2 DESC;
```

```ini
; pgbouncer.ini
[pgbouncer]
listen_port       = 6432
auth_type         = scram-sha-256
pool_mode         = transaction    ; session | transaction | statement
max_client_conn   = 2000
default_pool_size = 25
```

| Pool mode | Server conn held | Preserves session state |
| :--- | :--- | :--- |
| `session` | Whole client session | Yes |
| `transaction` | One transaction | No (use `SET LOCAL`) |
| `statement` | One statement | No |

Sizing: app pools ~5–20/instance → pooler `default_pool_size ≈ 2–4 × cores` → `max_connections` modest (100–200). A Postgres backend is a **process**, so more connections past a small multiple of cores lowers throughput.

## Replication

```conf
# primary
wal_level             = replica
max_wal_senders       = 10
max_replication_slots = 10
hot_standby           = on
```

```bash
# create the standby from a base backup (writes standby.signal + primary_conninfo)
pg_basebackup -h primary -U replicator -D $PGDATA -Fp -Xs -R -P -S standby1
pg_ctl -D $PGDATA start
```

```sql
-- primary: standby connections + byte lag
SELECT client_addr, state, sent_lsn, replay_lsn,
       pg_wal_lsn_diff(pg_current_wal_lsn(), replay_lsn) AS lag_bytes
FROM pg_stat_replication;

-- standby
SELECT pg_is_in_recovery(), pg_last_wal_replay_lsn(), pg_last_wal_receive_lsn();

-- slots
SELECT slot_name, active, restart_lsn FROM pg_replication_slots;
```

| `synchronous_commit` | Commit returns after |
| :--- | :--- |
| `off` | Local write (async) — may lose recent commits |
| `local` | Local flush |
| `remote_write` | Standby received WAL |
| `on` | Standby **flushed** |
| `remote_apply` | Standby **applied** (read-your-writes) |

```conf
synchronous_standby_names = 'FIRST 1 (standby1, standby2)'   # quorum-style
```

<Callout type="error" title="Slot + Disconnected Consumer = Full Disk">
Monitor `restart_lsn` age in `pg_replication_slots`; set `max_slot_wal_keep_size` to bound retention.
</Callout>

## Failover Runbook

```bash
pg_ctl promote -D $PGDATA          # or: SELECT pg_promote();
```

1. Confirm the primary is truly down (no split-brain).
2. Promote the lowest-lag standby.
3. Repoint the app (VIP/DNS/PgBouncer/HAProxy).
4. `pg_rewind` the old primary, then reattach it as a standby.
5. Verify: `SELECT pg_is_in_recovery();` → `false`, and `pg_stat_replication` is healthy again.

| Tool | Role |
| :--- | :--- |
| Patroni | Automated HA on etcd/Consul/K8s |
| repmgr | Lighter replication manager |
| pg_auto_failover | Single-witness automation |
| PgBouncer / HAProxy | Route clients to the current primary |

## Logical Replication

```sql
-- publisher: wal_level = logical (restart)
CREATE PUBLICATION pub FOR TABLE customers, bookings;    -- or FOR ALL TABLES

-- subscriber: tables must already exist
CREATE SUBSCRIPTION sub
  CONNECTION 'host=publisher dbname=travelbuddy user=replicator password=…'
  PUBLICATION pub;
```

Does **not** copy DDL, sequences, or unlisted tables' data.

## Extensions

```sql
SELECT * FROM pg_available_extensions;         -- available
SELECT extname, extversion FROM pg_extension;  -- installed
CREATE EXTENSION IF NOT EXISTS pg_stat_statements;
```

| Extension | Purpose |
| :--- | :--- |
| `pg_stat_statements` | Query stats (needs `shared_preload_libraries`, restart) |
| `pgcrypto` | Hashing/encryption, `gen_random_uuid()` |
| `postgis` | Spatial types & GiST indexes |
| `pgvector` | Vector type + ANN index for embeddings |
| `pg_trgm` | Fuzzy / `LIKE '%…%'` indexes |
| `pg_cron` | In-database scheduling |
| `pg_partman` | Automated partitioning |

```sql
SELECT query, calls, mean_exec_time, rows
FROM pg_stat_statements ORDER BY total_exec_time DESC LIMIT 20;
```

<Callout type="warn" title="Extensions Are Server Code">
Some require `shared_preload_libraries` and a **restart**. Only install trusted ones; keep them patched. Managed services restrict the catalog.
</Callout>

## Upgrades

| Approach | Downtime | Best for |
| :--- | :--- | :--- |
| `pg_upgrade --link` | Minutes | Most in-place upgrades |
| Logical replication | Near-zero | Large / always-on systems |
| Dump & restore | Long | Small databases |

```bash
/usr/lib/postgresql/18/bin/pg_upgrade \
  --old-datadir=…/16/main --new-datadir=…/18/main \
  --old-bindir=…/16/bin  --new-bindir=…/18/bin \
  --check            # run --check first, then without it
```

Always: run `--check`, rehearse on a restored copy, and run `ANALYZE` after the upgrade.

## Admin Decision Table

| Symptom | Likely cause | First move |
| :--- | :--- | :--- |
| `too many clients already` | Pool × instances > `max_connections` | Add PgBouncer, shrink app pools |
| Throughput falls as connections rise | A process per connection | Lower `max_connections`, pool |
| App can write a table it shouldn't | Over-broad grants / superuser app role | Least-privilege roles + RLS |
| Tenant data visible across tenants | RLS off, or missing `FORCE`/`SET LOCAL` | Enable RLS, fix pooling tenant var |
| Index ignored despite low cost | `random_page_cost` too high | Set ~1.1, re-`EXPLAIN` |
| Checkpoint latency spikes | Small `max_wal_size` | Raise it; completion target 0.9 |
| Standby far behind | Long transactions / heavy writes / slot backlog | Investigate on primary; check lag bytes |
| Two nodes accepting writes | Failed/unsafe failover | Fence peers; use an HA manager |
| Upgrade fails | Missing extension / incompatible object | `pg_upgrade --check` output |
