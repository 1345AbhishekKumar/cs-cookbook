## Why GitHub Actions?

Modern high-performing software teams ship code to production multiple times per day. That velocity is only possible when testing, linting, container builds, security scans, and cloud deployments are orchestrated by a robust, deterministic continuous integration engine.

GitHub Actions has quickly become the undisputed industry standard for software automation. Because your automation lives directly alongside your version control repository, developers enjoy zero-friction setup, deep GitHub event hooks, and access to the world's largest marketplace of pre-built workflow actions.

## 9-Part Masterclass Curriculum

<Steps>
  <Step>
    ### [1. Foundations, Evolution & Workflow Architecture](/docs/devops-cicd-performance/github-actions/01-foundations-and-architecture)
    Trace the history of computing from punch cards, floppy discs, Tinderbox, CruiseControl, and Jenkins to modern cloud CI/CD. Master the 5 fundamental architectural pillars: Events, Workflows, Jobs, Runners, and Steps. Author your very first workflow with parallel and dependent jobs.
  </Step>

  <Step>
    ### [2. Events, Triggers & Monorepo Path Filtering](/docs/devops-cicd-performance/github-actions/02-events-triggers-and-filtering)
    Explore every trigger mechanism: `push`, `pull_request`, `workflow_dispatch`, and UTC `schedule` cron strings. Implement glob patterns and path filtering (`paths:` and `paths-ignore:`) to build blazing-fast monorepo pipelines that only execute for modified services.
  </Step>

  <Step>
    ### [3. Variables, Secrets, Environments & Data Passing](/docs/devops-cicd-performance/github-actions/03-variables-secrets-and-environments)
    Demystify variable scoping across workflow, job, and step levels. Master runtime data passing using `$GITHUB_OUTPUT` and `$GITHUB_ENV`, share outputs between jobs across isolated runners, and configure repository and environment-level encrypted secrets with automatic log masking.
  </Step>

  <Step>
    ### [4. Runners, Ephemeral Lifecycles, Artifacts & Caching](/docs/devops-cicd-performance/github-actions/04-runners-artifacts-and-caching)
    Deep dive into compute runners: GitHub-hosted VMs, containerized runners, Kubernetes-based Actions Runner Controller (ARC), and high-performance cloud runners. Master persistent build artifacts (`actions/upload-artifact@v4`) and aggressive layer/dependency caching (`actions/cache@v4`).
  </Step>

  <Step>
    ### [5. Matrix Strategies, Conditionals & Concurrency](/docs/devops-cicd-performance/github-actions/05-matrix-conditionals-and-concurrency)
    Scale testing across OS matrices, runtime versions, and architecture targets. Use `include` and `exclude` filters, `fail-fast` error management, dynamic runtime matrices with `fromJson()`, and cancel outdated pipeline executions with `concurrency` groups.
  </Step>

  <Step>
    ### [6. Enterprise Security, Fine-Grained Permissions & Passwordless OIDC](/docs/devops-cicd-performance/github-actions/06-security-permissions-and-oidc)
    Harden your pipelines against supply-chain attacks. Eliminate long-lived cloud API keys by implementing OpenID Connect (OIDC) token exchange with AWS IAM, Google Cloud, and Azure. Enforce the Principle of Least Privilege with scoped `permissions:` and immutable commit SHA pinning.
  </Step>

  <Step>
    ### [7. Marketplace Actions & Authoring Custom Logic](/docs/devops-cicd-performance/github-actions/07-marketplace-and-custom-actions)
    Navigate the GitHub Actions Marketplace safely. Master the 4 mechanisms for custom reusability: Composite Actions, Reusable Workflows (`workflow_call`), TypeScript Actions with Rollup packaging, and Docker Container Actions for Python, Go, and Rust.
  </Step>

  <Step>
    ### [8. Developer Experience: Local Testing, act & Live Debugging](/docs/devops-cicd-performance/github-actions/08-local-testing-and-debugging)
    End the frustrating "git commit -m 'fix ci' && git push" feedback loop. Decouple pipeline logic into local Taskfiles, execute complete workflows offline using `act` with Docker containers, and SSH directly into failing cloud runners using interactive breakpoints.
  </Step>

  <Step>
    ### [9. Enterprise Patterns, Observability & Capstone Pipeline](/docs/devops-cicd-performance/github-actions/09-enterprise-patterns-and-observability)
    Build an end-to-end multi-service production pipeline: automated linting with Super-Linter, multi-arch container builds with Docker Buildx, GitOps release automation with Release Please, and enterprise distributed tracing via Honeycomb.
  </Step>
</Steps>

## Companion Repository Setup

This course comes with an official open-source companion repository: [`sidpalas/devops-directive-github-actions-course`](https://github.com/sidpalas/devops-directive-github-actions-course).

```bash
# 1. Fork the repository on GitHub to your personal account
# 2. Clone your personal fork locally with submodules
git clone --recurse-submodules https://github.com/<YOUR-USERNAME>/devops-directive-github-actions-course.git

cd devops-directive-github-actions-course

# 3. Enter the hermetic Devbox environment (Nix-backed tooling)
devbox shell
```

<Callout type="info" title="Devbox & WSL2 Compatibility">
If you are developing on Windows, run these exercises inside **WSL2 (Windows Subsystem for Linux)** running Ubuntu. Devbox pins all underlying CLI tools (such as `act`, `task`, `docker`, and language runtimes) to identical versions across macOS and Linux, guaranteeing you will never encounter environment drift.
</Callout>
