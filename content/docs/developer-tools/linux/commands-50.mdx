## Navigation & files (commands 01–13)

      

If you're a complete beginner, work through this section in order.

    

    
### 01. whoami - Who am I logged in as?

      

Prints the username of the currently logged-in user.

      

**Syntax:** `whoami`

      
```bash
$ whoami
colt
```

      

<Callout type="info">

`who am i` with spaces is a *different* command (and it works). But `who am` or any other variation fails with `command not found`. The shell doesn't guess.

</Callout>

    

    
### 02. man - Read the manual

      

Displays the reference documentation for any command.

      

**Syntax:** `man `

      

This is the single most important command to know — it means you never have to memorize everything.

      
```bash
$ man whoami
$ man ls
$ man man     # the manual for the manual
```

      

#### A man page typically contains

      

- **NAME** — what the command is.
- **SYNOPSIS** — the syntax, including which options exist. Brackets `[ ]` mean optional.
- **DESCRIPTION** — what it does in detail.
- **OPTIONS** — every flag explained.
- **AUTHOR / REPORTING BUGS** — credits and where to file issues.

      

#### Navigating a man page

      
        Space — page down
        b — page up
        ↑ / ↓ — line scroll
        h — help
        q — quit
      

      

<Callout type="warn">

While viewing a man page you cannot type commands. Press <kbd>q</kbd> to exit back to your shell.

</Callout>

    

    
### 03. clear - Wipe the screen

      

Clears your terminal display. Purely cosmetic — nothing is deleted.

      

**Syntax:** `clear [-x]`

      
```bash
$ clear
```

      

**The `-x` option:** normally `clear` also wipes your scrollback buffer, so you can't scroll up to see old output. With `-x`, the screen clears but your scrollback history survives.

      
```bash
$ clear -x    # clear screen, keep scrollback
```

      

<Callout type="tip">

<kbd>Ctrl</kbd> + <kbd>L</kbd> does the same thing and is much faster than typing `clear`. Works on Linux, macOS, and WSL.

</Callout>

    

    
### 04. pwd - Print working directory

      

Tells you where you currently are.

      

**Syntax:** `pwd`

      
```bash
$ pwd
/home/colt/Desktop
```

      

"Working directory" means the folder your terminal session is currently sitting inside. Think of it as the terminal equivalent of the address bar in a file manager. You can have several terminal windows open, each sitting in a different directory — `pwd` tells you which one you're in.

      

<Callout type="info">

By default on Ubuntu, your prompt displays your current directory name. But don't rely on it — `pwd` gives you the full absolute path.

</Callout>

    

    
### 05. ls - List directory contents

      

Lists what's inside a folder.

      

**Syntax:** `ls [options] [path]`

      

In a GUI you just see the contents; in a terminal you have to ask.

      
```bash
$ ls                    # contents of current directory
$ ls wildlife           # contents of ./wildlife
$ ls meal-diary/friday  # nested relative path
$ ls /home/colt/Documents  # absolute path
```

      

#### Relative vs. absolute paths

      

- **Relative path** — interpreted from where you currently are. `ls Documents` only works if `Documents` is inside your current folder.
- **Absolute path** — the full, unique location starting with `/`. Works from anywhere.

      

#### Essential options

      

| Option | Meaning |
| --- | --- |
| `-l` | Long listing format: permissions, owner, group, size, modification date, name. |
| `-a` / `--all` | Show hidden entries — anything starting with a dot (e.g. `.bashrc`). |
| `-h` | Human-readable sizes (K, M, G) when combined with `-l`. |

      
```bash
$ ls -l
$ ls -a
$ ls -al      # combine flags: all + long
$ ls -lh      # long + human readable
```

      

<Callout type="tip">

On Unix systems, a leading `.` means "don't show this by default". Configuration files like `.bashrc` and `.zshrc` live this way.

</Callout>

    

    
### 06. cd - Change directory

      

The terminal equivalent of double-clicking into a folder.

      

**Syntax:** `cd [path]`

      

<Callout type="info">

`cd` is built into the shell itself, so `man cd` won't give you a proper page. Use `help cd` instead — it dumps text rather than opening a scrollable viewer, but it works.

</Callout>

      

#### Every form of cd you need

      
```bash
$ cd Desktop              # relative: into ./Desktop
$ cd meal-diary/friday    # jump several levels at once
$ cd ..                   # up one level (.. = parent dir)
$ cd ../../..             # up three levels
$ cd                      # jump to your home directory
$ cd ~                    # same thing, using ~ shorthand
$ cd /                    # the root directory (top of everything)
$ cd /home/colt/Documents # absolute path — works from anywhere
$ cd ~/Desktop            # home-relative absolute path
```

      

<Callout type="tip">

The classic workflow: `ls` to look around → `cd` into something you found → `ls` again. You'll do this thousands of times.

</Callout>

    

    
### 07. mkdir - Make directory

      

Creates folders. There is no "make folder" command — this is it.

      

**Syntax:** `mkdir [-p] name [name2 ...]`

      
```bash
$ mkdir greenhouse              # one folder
$ mkdir winter summer           # multiple at once, space-separated
$ mkdir summer/seeds            # create inside an existing subfolder
$ mkdir ~/blah                 # create somewhere else entirely
```

      

#### The `-p` option — parents

      

Without `-p`, creating a nested path fails if the parent doesn't exist:

      
```bash
$ mkdir winter/seeds/lettuce
mkdir: cannot create directory 'winter/seeds/lettuce': No such file or directory

$ mkdir -p winter/seeds/lettuce
# success — creates winter, seeds, and lettuce as needed
```

      

`-p` (or `--parents`) does two things:

      

- Creates any missing parent directories along the way.
- Does **not** error if the directory already exists.

    

    
### 08. touch - Create files / update timestamps

      

Confusingly named, but it's how you create empty files.

      

**Syntax:** `touch filename [filename2 ...]`

      
```bash
$ touch squash
$ touch melon.txt apple.pdf berry.png
$ touch red.pdf orange.png yellow.xls   # several at once
```

      

<Callout type="warn">

`touch apple.pdf` does *not* create a real PDF. It creates an empty file with that name. On macOS, double-clicking it may open a PDF viewer that then complains it's empty; on Ubuntu it may just open a text editor. The extension is a hint, not a guarantee.

</Callout>

      

#### What if the file already exists?

      

`touch` won't create a duplicate. Instead it updates the file's **access and modification timestamps**. That's the original purpose — hence the name. You can see it with `ls -l`:

      
```bash
$ ls -l berry.png
-rw-r--r-- 1 colt colt 0 Oct 15 13:48 berry.png

$ touch berry.png
$ ls -l berry.png
-rw-r--r-- 1 colt colt 0 Oct 15 13:50 berry.png   # time updated
```

    

    
### 09. rmdir - Remove empty directory

      

Deletes a folder — but only if it's completely empty.

      

**Syntax:** `rmdir dirname [dirname2 ...]`

      
```bash
$ mkdir deleteme
$ rmdir deleteme         # works — it was empty

$ rmdir seeds
rmdir: failed to remove 'seeds': Directory not empty
```

      

Because `rm -r` can also remove empty directories, you could technically never use `rmdir`. Its appeal is that it's *safe* — it physically cannot delete anything with contents inside.

    

    
### 10. rm - Remove files & directories

      

The delete command. Fast, powerful, and completely unforgiving.

      

**Syntax:** `rm [-r] [-i] [-v] target [target2 ...]`

      

<Callout type="warn">

`rm` does not move files to a recycle bin. They are gone immediately and permanently. Be certain before you hit Enter.

</Callout>

      
```bash
$ rm blue.txt                  # delete a file
$ rm carrot cat dog           # delete several at once
$ rm -v carrot cat dog        # verbose: reports each removal
```

      

#### Deleting directories

      

Plain `rm` refuses to touch a directory. You need `-r`:

      
```bash
$ rm seeds
rm: cannot remove 'seeds': Is a directory

$ rm -r seeds                 # recursive: removes dir + everything inside
$ rm -rv seeds                # recursive + verbose
```

      

#### Interactive mode

      

`-i` prompts before each deletion, including before descending into directories:

      
```bash
$ rm -ri zoo
rm: descend into directory 'zoo'? y
rm: remove regular empty file 'zoo/snake'? y
rm: remove regular empty file 'zoo/cat'? y
rm: remove regular empty file 'zoo/jaguar'? n
rm: remove regular empty file 'zoo/dog'? y
rm: remove directory 'zoo'? n
```

      

<Callout type="tip">

A folder tree with thousands of nested files and dozens of levels disappears in a fraction of a second. Always double-check the path before running `rm -r`.

</Callout>

    

    
### 11. open / xdg-open - Open in the GUI

      

Opens a file or folder in the graphical world, using the default application — as if you double-clicked it.

      

**Syntax:** `open         (macOS)
xdg-open     (Linux)`

      
```bash
# macOS
$ open .                  # open current folder in Finder
$ open purple.txt         # opens in default text editor
$ open document.pdf       # opens in default PDF viewer

# Linux equivalent
$ xdg-open .
$ xdg-open tomato.js
```

      

<Callout type="info">

`open` is macOS-only. On Linux use `xdg-open` — you may need to install it first (`sudo apt install xdg-utils`). On WSL it generally isn't available.

</Callout>

    

    
### 12. mv - Move & rename

      

Moves files and folders — and, because moving to the same place with a new name *is* renaming, it's also how you rename things.

      

**Syntax:** `mv source destination`

      

#### Renaming

      
```bash
$ mv jornal.txt journal.txt       # fix a typo
$ mv journal.txt Journal.txt      # change case
```

      

#### Moving

      

If the last argument is a directory, `mv` treats it as the destination:

      
```bash
$ mv journal.txt stuff/           # move into ./stuff
$ mv cake cookie pie stuff/       # move multiple files (dir must be last)
$ mv stuff ../                    # move a folder up one level
$ mv stuff STUFF                  # rename a folder
```

      

Add `-v` for verbose output showing exactly what moved where.

    

    
### 13. cp - Copy

      

Copies files. Unlike `mv`, the original stays put — you end up with two independent files.

      

**Syntax:** `cp [-r] [-v] source destination`

      
```bash
$ cp journal.txt today-journal.txt      # copy with a new name
$ cp handbook.pdf handbook-backup.pdf    # full copy, not a shortcut
```

      

#### Copying directories

      

Like `rm`, `cp` needs `-r` to handle directories:

      
```bash
$ cp stuff stuff-copy
cp: -r not specified; omitting directory 'stuff'

$ cp -r stuff stuff-copy       # copies the folder and everything inside
$ cp -rv stuff stuff-copy      # with verbose output
```

      

#### Copying into a destination

      
```bash
$ cp song-of-myself.txt stuff/psalms.txt
# copies the file AND renames it in the process
```

    
  

  
  
    
## Reading & inspecting content (commands 14–19)

      

Getting text in and out of files.

    

    
### 14. head - First lines of a file

      

Prints the beginning of a file. Default is the first 10 lines.

      

**Syntax:** `head [-n N] file`

      
```bash
$ head song-of-myself.txt          # first 10 lines
$ head -n 100 song-of-myself.txt   # first 100 lines
```

      

Perfect for peeking at a huge log or data file without flooding your terminal.

    

    
### 15. tail - Last lines of a file

      

The mirror image of `head`: prints the last 10 lines by default.

      

**Syntax:** `tail [-n N] [-f] file`

      
```bash
$ tail song-of-myself.txt          # last 10 lines
$ tail -n 20 song-of-myself.txt   # last 20 lines
```

      

#### The `-f` option — follow

      

This is the killer feature. `-f` tells `tail` not to stop at the end of the file, but to **keep watching and print new lines as they're appended**. Ideal for live log monitoring.

      
```bash
$ tail -f /var/log/system.log
```

      

The prompt never returns — you get a live feed. New processes starting, errors appearing, all stream in real time. Press <kbd>Ctrl</kbd>+<kbd>C</kbd> to stop following.

      

<Callout type="tip">

`head` = top of the file. `tail` = bottom. `tail -f` = bottom, and keep watching.

</Callout>

    

    
### 16. date - Current date & time

      

Prints the current date and time. On its own it's not very exciting — but it's the perfect tool for learning redirection.

      

**Syntax:** `date [+format]`

      
```bash
$ date
Fri Oct 15 13:26:41 UTC 2021

$ date > today.txt        # save the output to a file
$ head today.txt
Fri Oct 15 13:26:41 UTC 2021
```

      

It's mainly useful inside scripts when you need to stamp something with the current time. We'll cover the `>` operator properly in the Redirection section.

    

    
### 17. cat - Concatenate & print files

      

Short for *concatenate*. Its simplest use is dumping an entire file to the screen — no pagination, no truncation.

      

**Syntax:** `cat [-n] file [file2 ...]`

      
```bash
$ cat contents.txt              # print the whole file
$ cat -n song-of-myself.txt     # with line numbers
```

      

#### Concatenating multiple files

      

Give it several filenames and it prints them all, one after another:

      
```bash
$ cat letters.txt words.txt
```

      

Combine with redirection and you can merge files into a new one:

      
```bash
$ cat butcher.txt feedstore.txt groceries.txt > everything.txt
# everything.txt now contains all three lists in order
```

      

<Callout type="info">

`cat` dumps everything. `head`/`tail` give you one end. `less` gives you a scrollable viewer. For a very long file, `cat` is the worst choice — use `less`.

</Callout>

    

    
### 18. less - Page through a file

      

Opens a file in an interactive, scrollable viewer. Far better than `cat` for anything long.

      

**Syntax:** `less filename`

      
```bash
$ less song-of-myself.txt
```

      

The screen switches to a paged view. Your prompt disappears — you're inside the `less` program.

      

#### Navigation

      

| Key | Action |
| --- | --- |
| <kbd>Space</kbd> | Page down |
| <kbd>b</kbd> | Page up |
| <kbd>↑</kbd> / <kbd>↓</kbd> | Scroll one line |
| <kbd>g</kbd> | Jump to start of file |
| <kbd>G</kbd> (Shift+g) | Jump to end of file |
| <kbd>/</kbd> then text | Search forward |
| <kbd>q</kbd> | Quit |

      

<Callout type="tip">

Because `less` doesn't print the file into your terminal, your scrollback isn't polluted with thousands of lines. When you quit, you're back exactly where you were.

</Callout>

    

    
### 19. echo - Print text

      

Takes whatever you give it and prints it back. Useless on its own — genuinely useful when combined with redirection.

      

**Syntax:** `echo text`

      
```bash
$ echo hi
hi
```

      

#### The real use: fast file creation

      
```bash
$ echo "username=colt" > config.txt
# config.txt is created containing that line

$ echo "key=value" >> config.txt
# appended as a second line

$ cat config.txt
username=colt
key=value
```

      

Two seconds to make a small config file or add a line to an existing one, without opening an editor. For anything substantial, use `nano` instead.

    
  

  
  
    
## Processing & searching text (commands 20–25)

      

Where the command line starts to feel like a superpower.

    

    
### 20. wc - Word count

      

Counts lines, words, and bytes in whatever you feed it.

      

**Syntax:** `wc [-l] [-w] [-c] file`

      
```bash
$ wc song-of-myself.txt
1757   15767   188743 song-of-myself.txt
#  lines  words   bytes
```

      

| Flag | Counts |
| --- | --- |
| `-l` | Lines only |
| `-w` | Words only |
| `-c` | Bytes only |
| `-m` | Characters only |

      
```bash
$ wc -l song-of-myself.txt
1757 song-of-myself.txt
```

      

<Callout type="tip">

`wc` shines with pipes. Count how many files are in a directory:

        
```bash
$ ls -l | wc -l
```

</Callout>

    

    
### 21. sort - Sort lines

      

Sorts lines of text. By default: alphabetical, case-sensitive.

      

**Syntax:** `sort [-n] [-r] [-u] [-f] [file]`

      
```bash
$ sort everything.txt
butter
chicken feed
chicken scratch
eggs
ground beef
ground pork
```

      

<Callout type="warn">

It sorts the *output*. The original file is untouched. To save the sorted result, redirect it:

        
```bash
$ sort everything.txt > sorted-everything.txt
```

</Callout>

      

#### Key options

      

| Flag | Meaning |
| --- | --- |
| `-n` | Numeric sort (so 9 comes before 10, not after) |
| `-r` | Reverse order |
| `-u` | Unique — drop duplicate lines |
| `-f` | Ignore case |
| `-h` | Human-numeric sort — understands K, M, G suffixes |

      
```bash
$ sort -n nums.txt        # proper numeric order
$ sort -nr nums.txt       # numeric, descending
$ sort -nu nums.txt       # numeric, unique only
```

      

<Callout type="tip">

Plain `sort` on human-readable sizes gets it wrong — it sorts "9.2M" as less than "900K" because it compares characters. `sort -h` understands the units.

</Callout>

    

    
### 22. uniq - Filter repeated lines

      

Removes or reports duplicate lines. Almost always used *after* `sort`.

      

**Syntax:** `uniq [-c] [-d] [-u] [file]`

      

<Callout type="warn">

It only compares **adjacent** lines. If duplicates aren't next to each other, it won't catch them. That's why you sort first:

        
```bash
$ sort flavors.txt | uniq
```

</Callout>

      

| Flag | Meaning |
| --- | --- |
| `-c` | Prefix each line with a count of how many times it appeared |
| `-d` | Show only lines that are duplicated |
| `-u` | Show only lines that appear exactly once |

      
```bash
$ sort flavors.txt | uniq -c
      5 chocolate
      6 vanilla
      1 rainbow sherbet
      1 mint
```

      

#### Chaining it into a ranked list

      
```bash
$ sort flavors.txt | uniq -c | sort -nr
      6 vanilla
      5 chocolate
      1 rainbow sherbet
      1 mint
```

      

That pipeline — sort, count, re-sort numerically — is one of the most useful patterns in day-to-day shell work. It works for log analysis, access counts, anything.

    

    
### 23. diff - Compare two files

      

Shows what's different between two files. Identical files produce no output at all.

      

**Syntax:** `diff [-y] [-u] file1 file2`

      
```bash
$ diff flavors.txt flavors2.txt
3c3
< strawberry
---
> strawberry and cream
24a25
> mint
```

      

#### Reading the output

      

| Code | Meaning |
| --- | --- |
| `a` | Added — line exists in the second file only |
| `d` | Deleted — line exists in the first file only |
| `c` | Changed — line differs between files |

      

So `24a25` reads: "after line 24 of the first file, line 25 was added in the second file."

      

#### Two useful output modes

      
```bash
$ diff -y file1 file2    # side-by-side comparison
$ diff -u file1 file2    # unified format with context
```

      

<Callout type="tip">

Git's `git diff` uses unified diff format under the hood. Once you can read `diff -u` output, git diffs make a lot more sense.

</Callout>

    

    
### 24. find - Locate files by attribute

      

Searches for files and folders by name, size, type, or modification time — recursively, descending into every subdirectory.

      

**Syntax:** `find  [-name pattern] [-type t] [-size n] [-mtime n] [-exec cmd \{\} \;]`

      
```bash
$ find .                    # everything under current dir, recursively
$ find . -name "*.txt"      # exact pattern match
$ find . -name "*7*"        # anything with a 7 in the name
$ find stuff -name "*.js"   # search only inside ./stuff
```

      

<Callout type="info">

`find . -name 7` only finds a file literally named `7`. To match "contains 7", you need wildcards: `-name "*7*"`. Always quote patterns so the shell doesn't expand them first.

</Callout>

      

#### Filtering by type

      
```bash
$ find . -type f            # files only
$ find . -type d            # directories only
$ find . -type l            # symbolic links only
```

      

#### Case-insensitive search

      
```bash
$ find . -iname "*e*"       # -iname ignores case
```

      

#### Combining criteria

      
```bash
$ find . -type d -name "*E*"                # directories with uppercase E
$ find . -name "E*" -or -name "F*"          # starts with E OR F
$ find . -type f -size +100k               # files larger than 100 KB
$ find . -type f -size +100k -size -1M     # between 100 KB and 1 MB
$ find . -mtime +3                         # modified more than 3 days ago
```

      

#### The `-exec` option

      

Runs a command on every result. The syntax is fussy:

      
```bash
$ find . -type f -size +100k -exec ls -lh {} \;
```

      

- `-exec` — "run the following command on each match"
- `\{\}` — placeholder, replaced by each found file
- `\;` — backslash + semicolon terminates the command

      

You can substitute any command — `ls -lh` for details, `cat` for contents, `rm` to delete, and so on.

      

<Callout type="tip">

`find` searches for *files* by their attributes. `grep` searches for *text inside* files. Different tools, different jobs.

</Callout>

    

    
### 25. grep - Search inside files

      

Finds text inside files. Prints every matching line, with the match highlighted.

      

**Syntax:** `grep [options] pattern [file...]`

      
```bash
$ grep green song-of-myself.txt
...the sniff of green leaves and dry leaves...
...green and violet...
...dusky green...
```

      

#### Essential options

      

| Flag | Meaning |
| --- | --- |
| `-n` | Show line numbers |
| `-i` | Case-insensitive |
| `-r` | Recursive — search all files in a directory tree |
| `-c` | Count matching lines |
| `-C N` | Show N lines of context before and after each match |

      
```bash
$ grep -n green song-of-myself.txt
32:...the sniff of green leaves...
1026:...green...

$ grep -C 2 green song-of-myself.txt     # 2 lines of context

$ grep -r chicken .                       # search every file recursively
./gg.txt:...chicken...
./feed-store.txt:chicken feed
./website.html:chicken

$ grep -ri CHICKEN .                      # case-insensitive recursive
```

      

<Callout type="tip">

`grep` is case-sensitive by default. `grep chicken` and `grep Chicken` find different things. Use `-i` when you don't care about case.

</Callout>

      

<Callout type="info">

`grep` accepts regex patterns, which makes it enormously powerful — you can match all email addresses, phone numbers, or IP addresses across an entire machine. Regex is a large topic on its own; know that the capability exists and reach for it when you need it.

</Callout>

    
  

  
  
    
## System, disk & processes (commands 26–36)

      

Inspecting and controlling your machine.

    

    
### 26. du - Disk usage

      

Reports how much space files and directories occupy.

      

**Syntax:** `du [-h] [-m] [-g] [path]`

      
```bash
$ du
32      ./tar-demo
16      ./wildlife
156     ./cleanup
36M     .

$ du pokemon-exercise      # size of one specific folder
24      pokemon-exercise
```

      

| Flag | Meaning |
| --- | --- |
| `-h` | Human-readable (K, M, G) — **use this** |
| `-m` | Report in megabytes |
| `-g` | Report in gigabytes |

      

#### Finding your biggest space hogs

      
```bash
$ du -h | sort -h | tail
# 10 largest items in the current directory

$ du -h | sort -hr | head
# same result, sorted descending, first 10
```

      

<Callout type="warn">

Plain `sort` will mangle human-readable sizes — it'll claim "9.2M" is smaller than "900K". Always pair `du -h` with `sort -h`.

</Callout>

    

    
### 27. df - Disk free / filesystem space

      

Shows mounted filesystems and how much space each has, uses, and has available.

      

**Syntax:** `df [-h] [path]`

      

Different from `du`: `du` measures files, `df` measures filesystems.

      
```bash
$ df -h
Filesystem      Size  Used Avail Use% Mounted on
udev            3.9G     0  3.9G   0% /dev
/dev/sda5       234G   89G  133G  41% /
tmpfs           790M  1.6M  788M   1% /run
```

      

Pass it a path to learn about the filesystem that path lives on:

      
```bash
$ df -h ~/Desktop
```

      

<Callout type="tip">

`du` = *disk usage* of files. `df` = *disk free* on filesystems.

</Callout>

    

    
### 28. history - Your command history

      

Lists every command you've run in this shell, with a number next to each.

      

**Syntax:** `history`

      
```bash
$ history
 2061  man df
 2062  du -m
 2063  clear
 2064  grep -rE "[email pattern]" ~
 2065  history
```

      

#### Rerunning a command by number

      
```bash
$ !2064        # re-executes command number 2064
```

      

#### Searching your history

      

Pipe it through `grep` when the list is too long to scan:

      
```bash
$ history | grep cookie
 1683  touch cake cookie pie
 1686  touch cake cookie

$ !1686        # rerun it
```

      

<Callout type="tip">

<kbd>↑</kbd> arrow cycles through recent commands. <kbd>Ctrl</kbd>+<kbd>R</kbd> opens a reverse search — start typing any part of an old command and it finds it.

</Callout>

    

    
### 29. ps - Process status

      

Lists currently running processes.

      

**Syntax:** `ps [aux] [axww]`

      
```bash
$ ps
  PID TTY          TIME CMD
 1234 pts/0    00:00:00 bash
 5678 pts/0    00:00:03 node
```

      

By default it shows only processes started by *you*. Column one is the **PID** (process ID) — you'll need that for `kill`.

      

#### Seeing everything

      
```bash
$ ps ax          # all processes from all users
$ ps axww        # same, but long lines wrap instead of being cut off
```

      

#### Finding a specific process

      
```bash
$ ps axww | grep "Visual Studio"
  902 ?  S  0:12 /Applications/Visual Studio Code.app/...
```

      

That PID — `902` — is what you'd feed to `kill`.

    

    
### 30. top - Live process dashboard

      

A live, continuously updating view of the top resource-consuming processes.

      

**Syntax:** `top [-o field]`

      

Where `ps` is a snapshot, `top` is a running monitor.

      
```bash
$ top
# live dashboard of processes sorted by CPU%

$ top -o mem      # sort by memory instead of CPU
```

      

Columns include PID, CPU percentage, memory usage, and the command. Sorting by `mem` shows your memory hogs at the top — browsers and video tools usually dominate.

      

<Callout type="tip">

Press <kbd>q</kbd> to quit. <kbd>Ctrl</kbd>+<kbd>C</kbd> also usually works.

</Callout>

    

    
### 31. kill - Terminate a process by PID

      

Sends a signal to a process. Despite the name, it's not just "shut down" — there are dozens of possible signals.

      

**Syntax:** `kill [-SIGNAL] PID`

      

List them all:

      
```bash
$ kill -l
```

      

You'll see a long list: `SIGHUP`, `SIGINT`, `SIGKILL`, `SIGTERM`, `SIGSTOP`, and many more. Most you'll never use.

      

#### The two that matter

      

| Signal | Number | Behaviour |
| --- | --- | --- |
| `SIGTERM` | 15 (default) | **Gentle.** Asks the program to stop. It can save state, clean up, close files properly. |
| `SIGKILL` | 9 | **Brutal.** Force-quits immediately. No cleanup, no saving. The program has no say. |

      

Think of it like quitting a GUI app: normal quit → quit without saving → force quit → pull the plug. `SIGTERM` is the polite version; `SIGKILL` is pulling the plug.

      

#### Usage

      
```bash
$ kill 5678            # default SIGTERM (15) — try this first

$ kill -9 5678         # SIGKILL — when the gentle way fails
$ kill -SIGKILL 5678   # same thing, spelled out
$ kill -s KILL 5678    # another valid spelling
```

      

<Callout type="tip">

Always try the default (`SIGTERM`) first. Give it a few seconds. If the process is still there, escalate to `-9`.

</Callout>

      

<Callout type="info">

Whether a program actually handles a given signal is up to that program's source code. Some ignore signals entirely — which is exactly why `-9` exists.

</Callout>

    

    
### 32. killall - Kill by program name

      

Like `kill`, but you supply the program's *name* instead of a PID.

      

**Syntax:** `killall [-SIGNAL] name`

      
```bash
$ killall node              # gentle: all processes named "node"
$ killall -9 node           # forceful: all node processes
$ killall -SIGKILL node
```

      

<Callout type="tip">

`kill` is *precise* — you target one exact process by PID. `killall` is *broad* — convenient when several instances are running, but you lose precision.

</Callout>

    

    
### 33. jobs - List background / suspended jobs

      

Shows the jobs running in your current shell — what's running, what's suspended, and each job's number.

      

**Syntax:** `jobs`

      
```bash
$ jobs
[1]+  Stopped    find / -mtime -1 > all-changes.txt
[2]-  Running    top
```

      

#### Suspending a job with Ctrl+Z

      

If a long-running command is hogging your terminal, <kbd>Ctrl</kbd>+<kbd>Z</kbd> **suspends** (pauses) it rather than killing it. Then `jobs` shows it as `Stopped`, and you can resume it later in the foreground or background.

      

<Callout type="info">

<kbd>Ctrl</kbd>+<kbd>C</kbd> *cancels* — the process is terminated. <kbd>Ctrl</kbd>+<kbd>Z</kbd> *suspends* — the process is paused and can be resumed.

</Callout>

    

    
### 34. bg - Resume a job in the background

      

Resumes a suspended job — but sends it to the background, so it runs without occupying your terminal.

      

**Syntax:** `bg [%jobnumber]`

      
```bash
$ jobs
[1]+  Stopped    find / -mtime -1 > all-changes.txt

$ bg 1
[1]+ find / -mtime -1 > all-changes.txt &
```

      

The trailing `&` tells you it's now running in the background. You can keep typing commands — the job just hums along invisibly.

      

#### Starting something in the background from the start

      

Append `&` to any command to background it immediately:

      
```bash
$ sleep 50 &
[1] 12345
```

    

    
### 35. fg - Bring a job to the foreground

      

Resumes a background or suspended job and puts it back in your terminal, where you can see its output and interact with it.

      

**Syntax:** `fg [%jobnumber]`

      
```bash
$ fg 2          # resume job number 2
$ fg            # resume the only/current job
```

      

<Callout type="tip">

The full workflow:

        
```bash
long-command          # running in foreground
Ctrl+Z                # suspend it
jobs                  # check its job number
bg 1                  # send it to background
# ...do other things...
fg 1                  # bring it back
```

</Callout>

    

    
### 36. sleep - Pause for N seconds

      

Does nothing for a specified number of seconds, then returns your prompt.

      

**Syntax:** `sleep N`

      

Mostly useful in scripts (waiting for a service to come up, pacing output).

      
```bash
$ sleep 2        # two-second pause
$ sleep 50 &     # 50-second pause, in the background
```

      

Great for experimenting with `jobs`, `bg`, and `fg` since it's a harmless, long-running no-op.

    
  

  
  
    
## Archives, editing & power tools (commands 37–43)

      

Compression, text editing, custom shortcuts, and link magic.

    

    
### 37. gzip - Compress a file

      

Compresses files using the gzip algorithm (LZ77-based). One of the most common compression tools on Linux.

      

**Syntax:** `gzip [-k] [-v] file`

      

<Callout type="warn">

`gzip myfile.txt` produces `myfile.txt.gz` and **deletes the original**. Use `-k` to keep it.

</Callout>

      
```bash
$ gzip -k all-changes.txt
# now you have both all-changes.txt and all-changes.txt.gz

$ ls -lh
-rw-r--r-- 1 colt colt 1.8M all-changes.txt
-rw-r--r-- 1 colt colt 232K all-changes.txt.gz
```

      

Add `-v` for verbose output — it reports the compression ratio:

      
```bash
$ gzip -kv all-changes.txt
all-changes.txt:  87.3% -- replaced with all-changes.txt.gz
```

      

<Callout type="info">

`gzip` compresses individual files. Give it several files and you get several `.gz` files — it does *not* bundle them together. For that, you need `tar`.

</Callout>

    

    
### 38. gunzip - Decompress

      

Reverses `gzip`. Both forms do the same thing.

      

**Syntax:** `gunzip file.gz
gzip -d file.gz`

      
```bash
$ gunzip all-changes.txt.gz
# or equivalently:
$ gzip -d all-changes.txt.gz
```

      

If a file with the target name already exists, it will ask before overwriting.

    

    
### 39. tar - Tape archive

      

Bundles many files into a single archive. Add gzip and you get a compressed "tarball" — the standard way software is distributed on Unix systems.

      

**Syntax:** `tar -cf archive.tar files…
tar -xf archive.tar
tar -czf archive.tar.gz files…
tar -tf archive.tar`

      

#### The flags you need

      

| Flag | Meaning |
| --- | --- |
| `-c` | **Create** a new archive |
| `-x` | **Extract** from an archive |
| `-t` | **List** the contents without extracting |
| `-f` | Specify the archive **file** name (must come last in the flag group) |
| `-z` | Compress/decompress with **gzip** in the same step |
| `-v` | Verbose |
| `-C` | Extract into a specific directory |

      

#### Create an archive (no compression)

      
```bash
$ tar -cf archive.tar song-of-myself.txt lots-of-text.txt more-text.txt
```

      

#### Look inside without extracting

      
```bash
$ tar -tf archive.tar
song-of-myself.txt
lots-of-text.txt
more-text.txt
```

      

#### Extract

      
```bash
$ tar -xf archive.tar              # into current directory
$ tar -xf archive.tar -C somewhere/ # into a specific directory
```

      

#### Create + compress in one step

      
```bash
$ tar -czf bundle.tar.gz song-of-myself.txt lots-of-text.txt more-text.txt
```

      

Extracting a gzipped tarball needs no extra flag — `tar` detects the compression automatically:

      
```bash
$ tar -xf bundle.tar.gz
```

      

#### The two-step alternative

      
```bash
# Archive first, then compress
$ tar -cf archive.tar file1 file2
$ gzip -k archive.tar

# Reverse: decompress, then extract
$ gzip -d archive.tar.gz
$ tar -xf archive.tar
```

      

<Callout type="tip">

Always name compressed tarballs `something.tar.gz`. Others need to know how to unpack it — `gunzip` or plain `tar -xf`.

</Callout>

    

    
### 40. nano - Terminal text editor

      

A simple, beginner-friendly text editor that runs right in your terminal. Unlike `vim`, you can start typing immediately — no modal confusion.

      

**Syntax:** `nano filename`

      
```bash
$ nano song-of-myself.txt
$ nano newfile.txt      # creates the file if it doesn't exist
```

      

#### Essential shortcuts

      

| Shortcut | Action |
| --- | --- |
| <kbd>Ctrl</kbd>+<kbd>X</kbd> | Exit (prompts to save) |
| <kbd>Ctrl</kbd>+<kbd>S</kbd> | Save to current filename |
| <kbd>Ctrl</kbd>+<kbd>O</kbd> | Write Out — save under a different name |
| <kbd>Ctrl</kbd>+<kbd>W</kbd> | Search (press Enter again to find next match) |
| <kbd>Ctrl</kbd>+<kbd>K</kbd> | Cut the current line |
| <kbd>Ctrl</kbd>+<kbd>U</kbd> | Paste (uncut) the line |
| <kbd>Ctrl</kbd>+<kbd>G</kbd> | Help — full manual of every shortcut |

      

<Callout type="info">

<kbd>Ctrl</kbd>+<kbd>C</kbd> and <kbd>Ctrl</kbd>+<kbd>V</kbd> don't copy/paste here. Those shortcuts mean something else in a terminal. Inside `nano`, use <kbd>Ctrl</kbd>+<kbd>K</kbd> to cut and <kbd>Ctrl</kbd>+<kbd>U</kbd> to paste.

</Callout>

      

<Callout type="tip">

Sometimes you need to tweak a config file on a remote server with no GUI, or make a one-line change without opening a whole IDE. `nano` is the friendly entry point; `vim` and `emacs` are more powerful but have much steeper learning curves.

</Callout>

    

    
### 41. alias - Create your own shortcuts

      

Define custom short names for commands you type often.

      

**Syntax:** `alias name='command'`

      
```bash
$ alias la='ls -la'
$ la                # now equivalent to ls -la

$ alias pscpu10="ps ax | sort -k3 -nr | head -10"
```

      

Running `alias` with no arguments lists all currently defined aliases.

      

<Callout type="warn">

Aliases defined this way are temporary. They exist only in the current shell session. Open a new window and they're gone.

</Callout>

      

#### Making aliases permanent

      

Add them to your shell's configuration file, which runs automatically every time a new shell starts:

      

| Shell | Config file |
| --- | --- |
| bash (Linux default) | `~/.bashrc` |
| bash (macOS) | `~/.bash_profile` |
| zsh (macOS default) | `~/.zshrc` |

      

On some Ubuntu systems there's also a dedicated `~/.bash_aliases` file, but it doesn't exist on every distro — `~/.bashrc` is the safe choice.

      
```bash
$ nano ~/.bashrc

# add at the bottom:
alias ll='ls -l'
alias la='ls -la'
alias rm='rm -v'
```

      

Then either open a new terminal window, or reload the file in your current one:

      
```bash
$ source ~/.bashrc
```

      

#### Single quotes vs. double quotes — this matters

      

Variables inside **double quotes** are expanded *once*, at definition time. Inside **single quotes**, they're expanded *every time* you run the alias.

      
```bash
# Double quotes: $PWD is baked in at definition time
$ alias ls-here="ls $PWD"
$ cd ~/Desktop && ls-here
# still lists your OLD directory — the value was frozen

# Single quotes: $PWD is re-evaluated on every run
$ alias ls-current='ls $PWD'
$ cd ~/Desktop && ls-current
# correctly lists Desktop
```

      

<Callout type="tip">

Use **single quotes** for aliases unless you specifically want a value frozen at definition time.

</Callout>

    

    
### 42. xargs - Turn output into arguments

      

The adapter between pipes and commands that don't accept piped input.

      

**Syntax:** `command | xargs [options] target-command`

      

#### The problem it solves

      

Some commands (`sort`, `wc`, `grep`) read from **standard input** — so pipes work with them. Others (`rm`, `ls`, `touch`, `mkdir`) expect a **list of arguments** on the command line — so pipes fail:

      
```bash
$ cat dead-players.txt | rm
rm: missing operand
# rm got nothing it could use — the pipe isn't arguments

$ cat dead-players.txt | xargs rm
# works! xargs converts the input into arguments for rm
```

      

#### Practical example: delete a dynamic list of files

      

Suppose `dead-players.txt` contains:

      
```bash
player1.txt
player4.txt
player7.txt
player9.txt
player11.txt
```

      
```bash
$ cat dead-players.txt | xargs rm
# all five files are removed
```

      

This scales — a list of thousands of names works just as well as five.

      

#### Practical example: enrich find output

      
```bash
$ find . -type f -size +1M | xargs ls -lh
# find gives filenames; xargs feeds them to ls -lh
```

      

Without `xargs`, piping `find` into `ls` fails — `ls` won't read from a pipe. With it, you get detailed listings of exactly the files `find` discovered.

      

<Callout type="info">

`xargs` can control how many arguments go to each invocation, split on custom delimiters, and substitute placeholders. Check `man xargs` when you need more.

</Callout>

    

    
### 43. ln - Create links

      

Creates a reference to another file — conceptually similar to a desktop shortcut, but with important differences between the two types.

      

**Syntax:** `ln target linkname        (hard link)
ln -s target linkname    (soft / symbolic link)`

      

#### Hard links

      
```bash
$ echo "I am original" > original.txt
$ ln original.txt hardlink.txt
```

      

A hard link is **not a copy**. Both names point to the same data in memory. Edit one and the other changes instantly — in both directions.

      
```bash
$ echo "more stuff" >> original.txt
$ cat hardlink.txt
I am original
more stuff

$ echo "from the link" >> hardlink.txt
$ cat original.txt
I am original
more stuff
from the link
```

      

**The key property:** delete the original, and the hard link survives with its data intact. It was never pointing *at the name*, it was pointing at the shared data.

      

#### Soft / symbolic links

      
```bash
$ ln -s original.txt symlink.txt
```

      

A symbolic link points to the *path*, not the shared data. `ls -l` reveals it with an arrow and an `l` as the first permission character:

      
```bash
$ ls -l
-rw-r--r-- 1 colt colt 45 original.txt
lrwxrwxrwx 1 colt colt 12 symlink.txt -> original.txt
```

      

**The key property:** delete the original and the symlink becomes a *dangling* link — it still exists but points at nothing. Attempting to read it gives `No such file or directory`.

      

#### Comparison

      

| - | Hard link | Soft (symbolic) link |
| --- | --- | --- |
| Created with | `ln target link` | `ln -s target link` |
| Points to | Shared data | The path/name |
| Survives original deletion? | Yes | No — becomes dangling |
| Can link across filesystems? | No | Yes |
| Shown in `ls -l` as | Regular file | `l` + arrow to target |

      

#### Why symbolic links matter: version management

      

Look at how Python is installed on Linux:

      
```bash
$ ls -l /usr/bin/python*
lrwxrwxrwx 1 root root   9 ... /usr/bin/python3 -> python3.8
-rwxr-xr-x 1 root root ... /usr/bin/python3.8
```

      

You can have `python3.5`, `python3.8`, `python3.9` all installed simultaneously. The symlink `python3` determines which one actually runs when you type `python3`. Point the symlink at a different version and you've switched interpreters — without touching a single script.

    
  

  
  
    
## Users & permissions (commands 44–50)

      

Who can do what, and how to change it.

    

    
### 44. who - Who is logged in

      

Lists users currently logged into the machine.

      

**Syntax:** `who`

      
```bash
$ who
colt     console  Oct 15 09:12
colt     ttys000  Oct 15 10:04
colt     ttys003  Oct 15 13:20
```

      

On a personal machine you'll see the same username repeated — one line per terminal session. On a shared server, this shows you everyone currently connected.

      

<Callout type="info">

`whoami` = "which user am I?" `who` = "who else is logged in right now?"

</Callout>

    

    
### 45. su - Switch user

      

Log in as another user within your current terminal session.

      

**Syntax:** `su username
su - username`

      
```bash
$ su elvis
Password: *****
# you're now elvis in this window
```

      

You need the target user's password — unless you're root.

      

#### The `-` flag: a true login shell

      

Plain `su elvis` keeps you in your current directory and inherits your environment variables. `su - elvis` behaves like a genuine login: it changes to the target user's home directory and resets the environment.

      
```bash
$ su elvis         # stay in current dir
$ su - elvis       # full login, lands in /home/elvis
$ su -l elvis      # long form of the same thing
```

      

Exit the switched session with `exit` or <kbd>Ctrl</kbd>+<kbd>D</kbd>.

      

<Callout type="info">

Becoming elvis doesn't give you elvis's files in a magical way — it means you *are* elvis, with all of elvis's restrictions. If elvis can't write to a directory, neither can you.

</Callout>

    

    
### 46. sudo - Super user do

      

Runs a single command with root (elevated) privileges.

      

**Syntax:** `sudo command`

      

#### The root account

      

`root` is the superuser — it can do anything: create users, change passwords, modify system files, delete anything. On Ubuntu and many distributions, **the root account is locked**. You can't log in as root; there's no root password to type.

      

Instead, individual users are granted the ability to run specific commands as root via `sudo`. This is safer than a single shared root password: each person uses their own password, and privileges can be granted or revoked individually.

      

#### How it works

      
```bash
$ nano /etc/hosts
[ File '/etc/hosts' is unwritable ]

$ sudo nano /etc/hosts
[sudo] password for colt: *****
# now editable
```

      

Notice: you enter **your own password**, not root's. Then `sudo` checks whether your account is permitted to run that command as root. It remembers your password for a few minutes, so you don't retype it constantly.

      

#### It's not unlimited

      

`sudo` doesn't turn you into root. If your account isn't authorized, it fails:

      
```bash
$ su - elvis
$ sudo nano /etc/hosts
elvis is not in the sudoers file. This incident will be reported.
```

      

Authorization lives in a configuration file called the *sudoers* file. Which users get which privileges is fully configurable — a deep admin topic.

      

#### The most common real-world use: installing software

      
```bash
$ apt install tldr
E: Could not open lock file - open (13: Permission denied)

$ sudo apt install tldr
# works — installing software is a system-wide change
```

      

<Callout type="tip">

Whenever you hit "Permission denied" on something that affects the whole system, try the same command prefixed with `sudo`.

</Callout>

    

    
### 47. passwd - Change a password

      

Changes passwords. Two modes.

      

**Syntax:** `passwd
sudo passwd username`

      

#### Change your own password

      
```bash
$ passwd
Changing password for colt.
Current password: *****
New password: *****
Retype new password: *****
passwd: password updated successfully
```

      

You must know your current password. You won't see anything as you type — that's normal.

      

#### Change someone else's password (admin)

      
```bash
$ passwd elvis
passwd: You may not view or modify password information for elvis.

$ sudo passwd elvis
[sudo] password for colt: *****
New password: *****
Retype new password: *****
passwd: password updated successfully
```

      

As an admin you enter *your* password to authorize, then set *their* new password. You don't need to know their old one — useful when someone forgets theirs.

      

#### Other things passwd can do

      

- **Lock** an account's password so no one can log in with it.
- **Expire** a password, forcing the user to set a new one at next login.
- **Delete** a password entirely (empty password — generally a bad idea).

      

See `man passwd` for the full option list.

    

    
### 48. chown - Change owner

      

Changes which user (and optionally which group) owns a file or directory.

      

**Syntax:** `chown [-R] user[:group] target`

      

Recall the third column of `ls -l` is the owner, and the fourth is the group owner. `chown` changes both.

      
```bash
$ ls -l
drwxr-xr-x 2 kitty kitty 4096 Oct 15 12:00 music

$ sudo chown colt music
$ ls -l
drwxr-xr-x 2 colt kitty 4096 Oct 15 12:00 music
```

      

<Callout type="warn">

Counter-intuitively, you cannot change the owner of a file you own. Linux requires root for this. You'll need `sudo`.

</Callout>

      

#### Recursive: `-R`

      

By default `chown` changes only the top-level item. Use `-R` to apply it to everything nested inside.

      
```bash
$ ls -l cat-stuff
drwxr-xr-x 3 kitty kitty 4096 toys
-rw-r--r-- 1 colt  colt     0 notes.txt

$ sudo chown -R kitty cat-stuff
$ ls -l cat-stuff
drwxr-xr-x 3 kitty kitty 4096 toys
-rw-r--r-- 1 kitty kitty    0 notes.txt
```

      

#### Changing owner and group together

      
```bash
$ sudo chown colt:pals-forever music
#     └ owner └ group

$ sudo chown :pals-forever music    # change group only
$ sudo chown colt: music            # owner + their default group
```

      

<Callout type="info">

Every file has one owner *and* one group. The group lets you grant a set of permissions to many users at once — say, everyone in `movie-club` can read a file but only the owner can edit it. Managing group membership is an admin task beyond this lesson's scope, but the concept explains why `ls -l` shows two names.

</Callout>

    

    
### 49. groups - See your group memberships

      

Lists every group the current user (or a specified user) belongs to.

      

**Syntax:** `groups [username]`

      
```bash
$ groups
colt adm cdrom sudo dip plugdev lpadmin sambashare pals-forever movie-club
```

      

Useful when you're wondering why you can or can't access something — permissions are often granted via group membership rather than to individuals.

    

    
### 50. chmod - Change mode (permissions)

      

Changes the read/write/execute permissions on a file or directory. The last and most involved command in the course.

      

**Syntax:** `chmod [who][+|-|=][permissions] target`

      

#### The symbolic syntax

      

| Part | Values | Meaning |
| --- | --- | --- |
| **Who** | `u` | User — the file's owner |
| `g` | Group — members of the owning group | - |
| `o` | Others — everyone else | - |
| `a` | All of the above | - |
| **Operator** | `+` | Add the permission |
| `-` | Remove the permission | - |
| `=` | Set exactly this, removing everything else | - |
| **Permission** | `r` | Read |
| `w` | Write | - |
| `x` | Execute | - |

      

#### Examples

      
```bash
# Let everyone read a file
$ chmod a+r only-colt-can-read.txt

# Give the group write access
$ chmod g+w notes.txt

# Let others list a directory again
$ chmod o+r permissions/

# Remove execute from everyone
$ chmod a-x script.sh

# Make a script executable by its owner
$ chmod u+x myscript.sh

# Multiple who values at once
$ chmod ug+w shared.txt

# Multiple permissions at once
$ chmod a+rwx everything.txt

# Reset to exactly read-only for all
$ chmod a=r file.txt
```

      

#### What `=` does differently

      

`+` and `-` modify one permission at a time. `=` wipes the slate and sets exactly what you specify:

      
```bash
$ ls -l file.txt
-rwxrwxrwx 1 colt colt 0 file.txt

$ chmod a=r file.txt
$ ls -l file.txt
-r--r--r-- 1 colt colt 0 file.txt
# read-only for everyone — write and execute removed
```

      

#### Octal (numeric) notation

      

You'll encounter this constantly in the wild. Each permission set is a 3-bit binary value, expressed as a single octal digit:

      

| Octal | Binary | Symbolic | Meaning |
| --- | --- | --- | --- |
| 0 | 000 | `---` | No permissions |
| 1 | 001 | `--x` | Execute only |
| 2 | 010 | `-w-` | Write only |
| 3 | 011 | `-wx` | Write + execute |
| 4 | 100 | `r--` | Read only |
| 5 | 101 | `r-x` | Read + execute |
| 6 | 110 | `rw-` | Read + write |
| 7 | 111 | `rwx` | Full permissions |

      

So `chmod 755 file` means:

      
```bash
7 → rwx   for the owner
5 → r-x   for the group
5 → r-x   for everyone else

Result: -rwxr-xr-x
```

      

And `chmod 777` gives full permissions to everyone — often seen in tutorials, rarely a good idea in production.

      

<Callout type="tip">

The symbolic form (`chmod u+x script.sh`) is easier to read and reason about. Octal is worth recognizing, but you can always use letters instead.

</Callout>

      

<Callout type="info">

For a directory, `x` means "you may `cd` into it". For a file, `x` means "this is a runnable program". Removing `x` from a directory locks people out of it entirely — even if they have read permission.

</Callout>

## Redirection

      

Sending command output somewhere other than your screen.

    

    

Every command that produces output sends it to **standard output** — which normally means your terminal. Redirection lets you send it to a file instead.

    

### `>` — Overwrite

    
```bash
$ date > today.txt
```

    

Runs `date`, captures its output, and writes it to `today.txt`. If the file doesn't exist, it's created. If it *does* exist...

    

<Callout type="warn">

Run `date > today.txt` twice and you don't get two dates — you get one. The file is completely replaced each time. This has bitten every developer at least once.

</Callout>

    

### `>>` — Append

    
```bash
$ date >> log.txt
$ whoami >> log.txt
$ pwd >> log.txt
$ cat log.txt
Fri Oct 15 13:26:41 UTC 2021
colt
/home/colt
```

    

Two greater-than signs add to the end of the file instead of replacing it. This is how you build up log files.

    

### Redirection works with anything that produces output

    
```bash
$ ls -l > contents.txt
$ find . -type f > filelist.txt
$ echo "hello" > greeting.txt
$ history > my-history.txt
```

    

<Callout type="tip">

Redirection + pipes combine beautifully:

      
```bash
$ cat groceries.txt butcher.txt | wc -l > count.txt
```

      

Concatenate two files → count the lines → save the number to a file. Three operations, one line.

</Callout>

## Piping

      

Feeding one command's output directly into another.

    

    

The pipe character `|` (usually above the Return key, typed with Shift) takes the output of the command on the left and passes it as input to the command on the right.

    
```bash
command1 | command2
```

    

### Redirection vs. piping

    

- **Redirection (`>`)** — output goes to a *file*.
- **Pipe (`|`)** — output goes to another *command*.

    

### Examples

    
```bash
# Count files in the current directory
$ ls -l | wc -l

# Sort directory listings
$ ls | sort

# Count shopping items across two files
$ cat groceries.txt butcher.txt | wc -l
9

# Find how many unique numbers exist
$ sort -nu nums.txt | wc -l
5

# Find the 10 largest items in a directory
$ du -h | sort -h | tail

# Search your command history
$ history | grep cookie
```

    

<Callout type="tip">

Pipes can be stacked indefinitely. The output flows left to right, each command transforming it in turn. This is the real superpower of the Unix command line — small tools, composed into something greater.

</Callout>

## Expansions

      

Special syntax the shell replaces with something bigger before your command ever runs.

    

    

Expansions happen *before* the command executes. The shell rewrites your input into its expanded form, then runs the result. `echo` is the perfect tool for seeing this in action.

    

### 1. Tilde expansion `~`

    

`~` is shorthand for your home directory.

    
```bash
$ echo ~
/home/colt

$ cd ~/Desktop        # same as cd /home/colt/Desktop

$ echo "~"            # quotes prevent expansion
~
```

    

### 2. Variable (environment) expansion `$`

    
```bash
$ echo $USER
colt

$ echo $PATH
/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:...

$ echo $HOME
/home/colt
```

    

The shell substitutes the variable's current value before running the command.

    

### 3. Pathname (glob) expansion `*` and `?`

    

Wildcards match filenames.

    

| Pattern | Matches |
| --- | --- |
| `*` | Any number of characters (including none) |
| `?` | Exactly one character |

    
```bash
$ echo *
cleanup copies notes.txt pokemon.txt words.txt

$ echo *.txt
notes.txt pokemon.txt words.txt

$ echo "*.txt"          # quoted = literal, no expansion
*.txt

$ ls -l *.txt           # long listing of just the text files

$ echo *??              # anything ending in exactly 2 characters
app.js app.py main.js

$ rm *.??               # delete all files with 2-char extensions
```

    

<Callout type="warn">

`rm *.txt` deletes every matching file with no confirmation and no undo. `rm -i *.txt` prompts for each one. Test your pattern with `echo` or `ls` first.

</Callout>

    

### 4. Brace expansion `\{ \}`

    

Generates combinations from a comma-separated list, or a range.

    
```bash
$ echo {a,b,c}.txt
a.txt b.txt c.txt

$ echo app.{js,html,css,py}
app.js app.html app.css app.py

$ touch app.{js,html,css,py}
# creates all four files at once

$ echo day{1..365}
day1 day2 day3 ... day365

$ mkdir day{1..365}
# creates 365 directories in a single command
```

    

<Callout type="tip">

Run the pattern through `echo` first to see exactly what the shell will expand it into. Then swap `echo` for `touch`, `mkdir`, `rm`, or whatever you actually want to do.

</Callout>

## Reading permissions

      

Decoding that cryptic string at the start of `ls -l`.

    

    

Run `ls -l` and you get something like:

    
```bash
-rwxr-xr-- 1 colt pals-forever 4096 Oct 15 13:48 script.sh
```

    

Let's break it down:

    

| Segment | Example | Meaning |
| --- | --- | --- |
| 1st character | `-` | Entry type: `-` file, `d` directory, `l` symlink |
| Characters 2–4 | `rwx` | Owner's permissions |
| Characters 5–7 | `r-x` | Group's permissions |
| Characters 8–10 | `r--` | Everyone else's permissions |

    

### What each permission actually does

    

| Letter | On a file | On a directory |
| --- | --- | --- |
| `r` (read) | You can view the contents | You can list the contents with `ls` |
| `w` (write) | You can modify the file | You can create, rename, or delete files inside |
| `x` (execute) | You can run it as a program | You can `cd` into it |
| `-` | That permission is not granted | - |

    

### Worked example

    
```bash
Owner: rwx  → can read, write, and execute
Group: r-x  → can read and execute, but not write
Other: r--  → can only read
```

    

### Real consequences

    

- **No `r` on a directory** → `ls` fails with "Permission denied", even though you might be able to `cd` into it if `x` is present.
- **No `x` on a directory** → `cd` fails, even if you have read permission. You can see the names but not enter.
- **No `x` on a program** → running it gives "Permission denied". The file exists, it's just not executable.
- **No `w` on a file** → any attempt to redirect into it or edit it fails, even if you can read it fine.

    

<Callout type="tip">

`rwx` for owner, `r-x` for group, `r--` for others is the classic pattern for scripts — full control for you, read-and-run for your team, read-only for the world. In octal that's `754`.

</Callout>

## You made it — now what?

      

The point was never memorization.

    

    

This was a lot of material, and nobody expects you to recall all fifty commands tomorrow. What actually matters:

    

- **Know what's possible.** The biggest win is knowing a tool exists. When you hit a problem, you'll think "there's probably a command for that."
- **Read man pages.** Every command has one, and it's authoritative. Getting comfortable with `man` is more valuable than memorizing flags.
- **Compose.** The real power is combining commands with pipes, redirection, and expansions — not any single command in isolation.
- **Expect fluency on a handful.** `ls`, `cd`, `pwd`, `mkdir`, `touch`, `rm`, `cat`, `grep`, `cp`, `mv` — these become muscle memory within weeks. The rest you look up when needed.
- **Look things up without shame.** Even people who teach this stuff check the man pages. Constantly.

    

### Suggested practice path

    

1. Create a scratch directory and practice `mkdir`, `touch`, `ls`, `cd`, `mv`, `cp`, `rm` until they feel natural.
2. Make a few text files and practice `cat`, `head`, `tail`, `less`, `wc`.
3. Build pipelines: `ls | sort`, `cat a b | wc -l`, `du -h | sort -h | tail`.
4. Practice redirection with `echo` and `date`, using both `>` and `>>`.
5. Set up two or three aliases in `~/.bashrc` for things you type often.
6. Experiment with `chmod` on files you create yourself — add and remove permissions and observe the effects.
