## Why Bun? The ecosystem problem

      

Outside of AI, there haven't been many new web-development technologies that really get
         people excited. Bun is one of the exceptions — an emerging, lightweight JavaScript runtime
         and toolkit that's gaining traction fast. It had been around about a year before
         **1.0 was released**, and that's when it started turning heads.

      

Before going further, it's worth naming the problem Bun is trying to solve. The JavaScript
         ecosystem has been *all over the place* for years:

      

- You need Node.js to run your server.
- You need Webpack or Vite to bundle your front end.
- You need Jest or Vitest for testing.
- You need ts-node or a build step to run TypeScript.
- You need dotenv for environment variables, nodemon for restarts…

      

Every language has its issues, but C#, Python and Rust all feel relatively *put together*
         in terms of their ecosystems. JavaScript just seems scattered — and it's very difficult for
         beginners to know where to start.

      

<Callout type="info">
**The big idea**
        Bun is not *just* a runtime. It's a single tool that does everything you need to build
        full-stack JavaScript and TypeScript applications — which is exactly what the ecosystem needs
        to feel organized and respectable.
</Callout>

    

    
    
      

## What is Bun?

      

**Bun** is a JavaScript runtime *and* an all-in-one toolkit built to serve
         the modern JavaScript ecosystem.

      

When we say "JavaScript runtime," that's the same category as **Node.js** and
         **Deno** — the thing that actually executes your JavaScript on the server.
         In fact, Bun is designed as a **drop-in replacement for Node**.

      

But it's not only a runtime. Bun also includes:

      

| Component | What it replaces |
| --- | --- |
| **Runtime** | Node.js / Deno |
| **Native bundler** | Webpack, Parcel, Vite (for bundling) |
| **Transpiler** | Babel, ts-node, SWC |
| **Task runner** | npm scripts + nodemon |
| **npm client** | npm, yarn, pnpm |
| **Test runner** | Jest, Vitest |
| **SQLite client** | better-sqlite3 and friends |

      

In the past you had to glue all those separate technologies together to build a full-stack
         JavaScript application. Bun has all of it **baked in** — one tool, one install,
         one command line.

      
```bash
bun --version
# 1.0.2  (at the time of recording)
```

    

    
    
      

## Under the hood: Zig & JavaScriptCore

      

Two technical details explain a lot about why Bun behaves the way it does.

      

### 1. It's written in Zig

      

Bun is written in **Zig**, a newer low-level language designed to be fast, safe
         and simple. Zig is generally understood as a modern replacement for C and C++ — fast and
         powerful, yet smaller and less complicated than those languages.

      

### 2. It uses JavaScriptCore, not V8

      

Bun is **not a fork of Node.js**, and it is **not built on the V8
         engine** like Node is. It's built on **JavaScriptCore** — the
         performance-minded JavaScript engine built for Safari and WebKit.

      

Because it isn't dependent on Node or npm, Bun is a very minimal stack. Fewer layers means
         more performance, which is one of its main goals.

      
```bash
Node.js   →  V8 engine   + npm  + separate tooling
Deno      →  V8 engine   + its own tooling
Bun       →  JavaScriptCore engine (WebKit)  +  everything built in
```

    

    
    
      

## The three design goals

      

Bun has three major design goals, and almost every feature you'll see later traces back to
         one of them.

      

### Goal 1 — Speed

      

Bun aims to be faster than both Node.js and Deno. It achieves this with few dependencies,
         by extending the JavaScriptCore engine, and by rewriting JavaScript-implemented APIs in a
         lower-level language.

      

### Goal 2 — An elegant API

      

Bun provides a minimal set of *highly optimized* APIs for common tasks: starting an
         HTTP server, writing files, and so on. Instead of learning five different libraries, you
         learn one small, consistent surface.

      

### Goal 3 — A cohesive developer experience

      

Bun is a complete toolkit for building JavaScript apps — package manager, test runner and
         bundler included — so you don't need to assemble a pile of separate tools just to get
         started.

      

<Callout type="tip">
**Why this matters**
        Those three goals are the reason Bun feels less like "another runtime" and more like an
        opinionated, batteries-included platform.
</Callout>

    

    
    
      

## Speed & performance

      

Bun uses the JavaScriptCore engine and native-speed functionality implemented in Zig. The
         project publishes benchmark comparisons for common workloads against Node.js and Deno.

      

| Workload | Bun | Node.js |
| --- | --- | --- |
| Server-side rendering React (requests/sec) | ~66,000+ | ~13,000 |
| WebSocket chat server (messages/sec) | 1,000,000+ | ~179,000 |
| Loading a huge table (SQLite) | Far ahead | Baseline |

      

The npm client is also much faster — Bun claims installs up to **30× faster**
         than npm.

      

<Callout type="warn">
**Take benchmarks with a grain of salt**
        These are the project's own claims, measured on their own terms. That said, using Bun in
        practice, the speed difference is very noticeable — especially package installation.
</Callout>

    

    
    
      

## A drop-in replacement for Node

      

Bun is described as a **drop-in replacement for Node.js**. In practice that
         means:

      

- It's completely **compatible with Node APIs**.
- It has all the **built-in modules** — `fs`,
            `path`, and the rest.
- It implements the **globals** like `process` and
            `Buffer`.
- It works with **node_modules** — you still have a
            `package.json` and a
            `node_modules` folder.
- It's compatible with the **npm ecosystem**, so you can install and run npm
            packages with it.

      

So you can take an existing Node application and run it with Bun. But you also get
         additional optimized APIs and tools that you simply don't get with Node.

      
```bash
bun install            # like npm install
bun run dev           # like npm run dev
bun add axios          # like npm install axios
```

      

Same concepts you already know from npm — just faster.

    

    
    
      

## No more module madness

      

This one is big. With Node.js, the community has been trying for years to implement ES
         modules without breaking things. You can do it — you edit
         `package.json`, add `"type": "module"`,
         rename files, and hope your dependencies cooperate.

      

With Bun, **you can use either syntax**:

      

- ES module syntax — `import` / `export`
- CommonJS syntax — `require()` / `module.exports`

      

You can even use **both in the same file** with no problem. That alone removes
         a huge amount of friction.

      
```javascript
// ES module syntax — works fine
import path from "path";

// CommonJS syntax — also works fine, even in the same file
const path = require("path");

// And no "type": "module" dance required in package.json
```

    

    
    
      

## TypeScript & JSX out of the box

      

### TypeScript is a first-class citizen

      

You don't need a build step, a loader, or ts-node. Just use a
         `.ts` or `.tsx` extension and execute
         the file directly.

      
```bash
bun run index.ts
```

      

### JSX is built in too

      

Bun supports JSX out of the box — it transpiles JSX syntax to vanilla JavaScript. By default
         it assumes **React**, but you can change that in your
         `tsconfig.json` (for example, to use Preact or another runtime).

      

### Web-standard APIs

      

Bun implements standard web APIs such as `fetch`,
         `WebSocket`, `FormData` and more — so the
         same APIs you use in the browser work on the server.

      

<Callout type="tip">
**Fewer moving parts**
        TypeScript, JSX, and web APIs all work with zero configuration. That's a large chunk of the
        modern JavaScript toolchain gone in one step.
</Callout>

    

    
    
      

## Installing Bun

      

Bun is still very new — 1.0 was just released — so platform support has one caveat:

      

- **macOS & Linux** — use it directly.
- **Windows** — use the **Windows Subsystem for Linux (WSL)** to
            get the full experience.

      

The official site is `bun.sh`, where you'll find all the
         documentation and the install command. At the bottom of the page it notes:
         *supported on macOS, Linux and WSL*.

      

### Install with curl (the recommended way)

      
```bash
curl -fsSL https://bun.sh/install | bash
```

      

On the first run, the installer also asks you to run a command to add Bun to your shell
         path:

      
```bash
exec /bin/zsh
```

      

After that, verify the installation:

      
```bash
bun --version
# 1.0.2
```

      

### Other installation methods

      

Under *Docs → Installation* you'll find several alternatives:

      

| Method | Command |
| --- | --- |
| curl | `curl -fsSL https://bun.sh/install \| bash` |
| npm (global) | `npm install -g bun` |
| Homebrew (macOS) | `brew install oven-sh/bun/bun` |
| Docker | Official Bun image |
| Proto | Via the Proto version manager |

    

    
    
      

## bun init & project structure

      

Create an empty folder, open it in VS Code, open the integrated terminal, and run:

      
```bash
bun init
```

      

Just like `npm init`, it asks for a package name and an entry
         point — `index.ts` is fine.

      

What you get back is **a little more than Node gives you**. With Node you'd get
         a `package.json` and a lock file. Bun also scaffolds:

      

| File / folder | Purpose |
| --- | --- |
| `package.json` | Project metadata, scripts, dependencies |
| `bun.lock` | Bun's lock file (equivalent of package-lock.json) |
| `tsconfig.json` | TypeScript config — customize if you want |
| `index.ts` | Entry point with a starter `console.log` |
| `node_modules/` | Already installed — no `npm install` needed |
| `.gitignore` | Pre-configured to ignore node_modules |
| `README.md` | Starter readme |

      

The generated `package.json` includes a peer dependency on
         **TypeScript** and a dev dependency on **@types/bun** — and they're
         installed for you immediately.

      
```json
{
  "name": "bun-crash",
  "module": "index.ts",
  "type": "module",
  "devDependencies": {
    "@types/bun": "latest"
  },
  "peerDependencies": {
    "typescript": "^5.0.0"
  }
}
```

    

    
    
      

## Running files & scripts

      

To run a file, use `bun run` followed by the filename —
         **including the extension**:

      
```bash
bun run index.ts
# Hello via Bun!
```

      

<Callout type="warn">
**Don't forget the extension**
        If you run `bun run index` without the
        `.ts`, Bun will say *"missing script: index"* — it thinks
        you're referring to an npm script. Always include the extension when running a file.
</Callout>

      

### Adding scripts to package.json

      

Just like npm, Bun reads the `scripts` block from your
         `package.json`:

      
```json
{
  "scripts": {
    "start": "bun run index.ts",
    "dev": "bun --watch index.ts"
  }
}
```

      

Then run them with:

      
```bash
bun start          # normal start
bun run dev        # development / watch mode
```

    

    
    
      

## Watch mode & hot reload

      

With Node.js, if you change something on the server you have to restart it — unless you
         install something like **nodemon**. Bun has this built in.

      

### Watch mode

      

Add `--watch` and Bun restarts automatically every time a file
         changes:

      
```bash
bun --watch index.ts
```

      

Change `"Hello world"` to `"Hello bun!"`,
         save, reload the browser — the new text is there.

      

### Hot reload

      

Hot reload is a step beyond watch mode. If you're building something like a React app and
         you have state, you don't want an extra full reload to wipe that state out. Bun gives you
         hot reloading with a single flag:

      
```bash
bun --hot index.ts
```

      

<Callout type="info">
**--watch vs --hot**
        `--watch` restarts the whole process. `--hot`
        reloads code in place while preserving application state. There are examples in the Bun docs
        if you want to see the difference in action.
</Callout>

    

    
    
      

## Environment variables

      

With Node.js you'd install a package called `dotenv`, then call
         its `config()` method, and so on. In Bun, a
         `.env` file **just works** — no package required.

      

Create a file called `.env`:

      
```bash
PORT=5000
```

      

Then read it in two different ways. The classic Node approach:

      
```typescript
const port = process.env.PORT || 8000;
```

      

Or the Bun-specific shortcut:

      
```typescript
const port = Bun.env.PORT || 8000;
```

      

<Callout type="tip">
**Restart required**
        Bun reads the `.env` file at startup, so if you add the file while
        the server is already running you'll need to restart once. After that, changes picked up by
        watch mode work normally.
</Callout>

    

    
    
      

## Your first server with Bun.serve

      

Bun ships a built-in server API, `Bun.serve`. It's similar in
         spirit to Node's `http` module, but much faster and more
         optimized.

      

To be clear: this is the *basics*, the same way you wouldn't use raw
         `http` in production with Node. In real projects you'd reach for a
         framework. But it's important to know how the foundation works.

      

Notice that **you don't import Bun** — it's a global object.

      
```javascript
const server = Bun.serve({
  port: 5000,
  fetch(request) {
    return new Response("Hello world");
  },
});

console.log(`Listening on port ${server.port}`);
```

      

Run it and visit `localhost:5000`:

      
```bash
bun run index.ts
# Listening on port 5000
```

      

### Adding routes

      

You can inspect the request URL with `new URL(request.url)` and
         branch on `url.pathname`:

      
```typescript
const server = Bun.serve({
  port: 5000,
  fetch(request) {
    const url = new URL(request.url);

    if (url.pathname === "/")     return new Response("Home page");
    if (url.pathname === "/blog") return new Response("Blog");

    return new Response("404!");
  },
});
```

      

Now `/` shows "Home page", `/blog` shows
         "Blog", and anything else shows the 404.

      

### Using a framework instead

      

Of course you can still use **Express**, **Koa**, and the rest with
         Bun. There's also **ElysiaJS** — a framework built specifically to be used with
         Bun, reported to be around *20× faster* than Express. (Again: take framework
         comparisons with a grain of salt.)

    

    
    
      

## bunx — run packages without installing

      

Bun ships its own npm client, and it includes `bunx` — the
         equivalent of `npx`. It lets you run a package without installing
         it first.

      
```bash
# Both forms work — "bun x" or the shortcut "bunx"
bunx cowsay "hello bun"
bun x cowsay "hello bun"
```

      

That prints a little ASCII cow saying "hello bun". Anywhere you'd reach for
         `npx` — scaffolding a project, running a one-off CLI — you can use
         `bunx` instead.

    

    
    
      

## Node modules & the Bun file API

      

### Node core modules still work

      

All the default Node modules — `path`,
         `fs`, and so on — are available. And remember, you can import them
         with either syntax:

      
```javascript
// ES module syntax
import path from "path";

// …or CommonJS syntax — both work in Bun
// const path = require("path");

const filePath = path.join("foo", "bar", "image.png");
const fileName = path.basename(filePath);

console.log(fileName);  // image.png
```

      
```bash
bun run modules.ts
# image.png
```

      

### The optimized Bun file API

      

Instead of `fs`, Bun offers a new, optimized API for dealing with
         files. Writing a file is two lines — and top-level `await` works,
         so you don't need to wrap it in an async function:

      
```typescript
const data = "I love JavaScript";

await Bun.write("output.txt", data);
```

      
```bash
bun run file.ts
# creates output.txt containing: I love JavaScript
```

      

Reading is just as clean. `Bun.file()` gives you a lazy file
         reference you can pull data out of in several forms:

      
```javascript
const file = Bun.file("output.txt");

// As a string
console.log(await file.text());        // I love JavaScript

// Size in bytes — a property, not a method
console.log(file.size);               // 18

// As a readable stream
const stream = await file.stream();

// As an ArrayBuffer
const buffer = await file.arrayBuffer();
```

      

<Callout type="tip">
**Note the capital B**
        The file APIs live on the global `Bun` object:
        `Bun.serve`, `Bun.file`,
        `Bun.write`, `Bun.env`.
</Callout>

      

### Bonus: a built-in SQLite database

      

Bun also ships with a built-in SQLite client, which is very convenient for development —
         you can query a database without installing any dependency at all.

    

    
    
      

## Testing with bun:test

      

Bun has a built-in test runner. Create a file whose name ends in
         `.test.ts` — the `.test` part is what
         tells Bun to pick it up.

      

The API is deliberately Jest-like, so if you've used Jest it'll feel familiar. You import
         the test primitives from `bun:test`:

      
```typescript
import { describe, expect, test, beforeAll } from "bun:test";

beforeAll(() => {
  // set up tests
});

describe("math", () => {
  test("addition", () => {
    expect(2 + 2).toBe(4);
  });
});
```

      

Then run the whole suite with a single command — no config file, no reporters to install:

      
```bash
bun test

# math
#   ✓ addition
# 1 pass, 0 fail
```

      

Bun automatically finds files with `.test` in the name. Hooks like
         `beforeAll` are supported, just like Jest.

      

<Callout type="info">
**Nothing installed**
        At this point, the only thing in `package.json` that isn't Bun
        itself is TypeScript. No Jest, no ts-node, no nodemon, no dotenv.
</Callout>

    

    
    
      

## Bundling for the front end

      

Bun has a built-in bundler that's faster than Webpack, Parcel and others. It takes your
         source files and bundles them into a single file that can be loaded in the browser.

      

Start by installing a third-party module the normal way — and notice how fast it is:

      
```bash
bun install axios
```

      

### Create the source files

      

Make a `src` folder. In `github-api.ts`,
         export a function that fetches a user:

      
```typescript
import axios from "axios";

async function fetchUser(user) {
  const res = await axios.get(
    `https://api.github.com/users/${user}`
  );
  return res.data;
}

export default fetchUser;
```

      

Then use it in `src/index.ts`:

      
```typescript
import fetchUser from "./github-api";

(async () => {
  const userData = await fetchUser("bradtraversy");

  document.querySelector("h1").innerHTML =
    JSON.stringify(userData);
})();
```

      

<Callout type="warn">
**No top-level await here**
        Because this is bundled for the *browser*, you can't use top-level
        `await` — wrap it in an async IIFE, as above.
</Callout>

      

### Bundle it

      
```bash
bun build ./src/index.ts --outfile ./dist/bundle.js
```

      

That creates `dist/bundle.js` containing everything from
         `src` — the entry file *and* the GitHub API function, plus
         axios — in one file.

      

### Wire it into an HTML page

      
```html
<!DOCTYPE html>
<html>
<head>
  <title>GitHub User Data</title>
</head>
<body>
  <h1></h1>
  <script src="./bundle.js"></script>
</body>
</html>
```

      

Open it with a live server and the GitHub API data appears in the browser.

      

### Watch mode for the bundler

      

Add `--watch` to the build command and your bundle rebuilds
         automatically on save — even the HTML file reloads itself:

      
```bash
bun build ./src/index.ts --outfile ./dist/bundle.js --watch
```

    

    
    
      

## React & JSX in Bun

      

Let's go one step deeper into the front end and see Bun transpile JSX with React.

      

### Install React

      
```bash
bun install react react-dom
```

      

### Rename the entry point to .tsx

      

Rename `src/index.ts` to
         `src/index.tsx` — the `x` is what tells
         Bun there's JSX in the file. Then replace the contents:

      
```typescript
import React from "react";
import { createRoot } from "react-dom/client";

const root = createRoot(document.getElementById("root"));

function App() {
  const [count, setCount] = React.useState(0);

  return (
    <div>
      <h1>Hello world</h1>
      <h2>Count: {count}</h2>
      <button onClick={() => setCount(count + 1)}>
        Increment
      </button>
    </div>
  );
}

root.render(<App />);
```

      

### Update the HTML

      

React needs a mount point — a div with an id of `root`:

      
```html
<!DOCTYPE html>
<html>
<head>
  <title>Bun + React</title>
</head>
<body>
  <div id="root"></div>
  <script src="./bundle.js"></script>
</body>
</html>
```

      

### Rebuild

      

Update the build command to point at the new `.tsx` entry and run
         it:

      
```bash
bun build ./src/index.tsx --outfile ./dist/bundle.js --watch
```

      

<Callout type="warn">
**Common gotcha**
        If you forget to change the entry from `.ts` to
        `.tsx`, the build fails with a module resolution error. Bun assumes
        React for JSX by default, but you can change that in
        `tsconfig.json`.
</Callout>

      

Reload the page and you have a working React counter app — click Increment and the count
         goes up. All transpiled and bundled by Bun, with no Babel and no Webpack.

    

    
    
      

## Cheat sheet

      
```bash
bun --version              # check version
bun init                   # scaffold a project
bun run index.ts           # run a file (extension required)
bun start                  # run a package.json script
```

      
```bash
bun install                # install everything from package.json
bun install axios          # install a package
bun add react react-dom    # add dependencies
bunx cowsay "hi"          # run without installing (like npx)
```

      
```bash
bun --watch index.ts       # restart on change (like nodemon)
bun --hot index.ts         # hot reload, preserves state
bun test                    # run *.test.ts files
bun build ./src/index.tsx --outfile ./dist/bundle.js --watch
```

      
```bash
Bun.serve({ port, fetch })   # built-in HTTP server
Bun.file("path.txt")          # lazy file reference
Bun.write("out.txt", data)     # write a file
Bun.env.PORT                # env vars (reads .env automatically)
import { test, expect } from "bun:test"
```

      

### Key takeaways

      

- Bun is a runtime **and** an all-in-one toolkit: bundler, transpiler, task runner, npm client, test runner, SQLite.
- It's written in **Zig** and runs on **JavaScriptCore** — not a Node fork, not V8.
- It's a **drop-in replacement for Node**: Node APIs, built-in modules, globals and node_modules all work.
- **ESM and CommonJS** both work — even in the same file. No `"type": "module"` gymnastics.
- **TypeScript and JSX** run with zero configuration.
- **Watch and hot reload** are built in — no nodemon.
- **.env files** work natively — no dotenv package.
- Built-in **test runner** and **bundler** mean fewer dependencies in your package.json.
- It's still very new (1.0 just released) — expect bigger and better things.

      

<Callout type="info">
**The bigger picture**
        The real value of Bun isn't any single feature — it's that the scattered JavaScript
        ecosystem finally has a tool that puts everything in one place. That's a big step in the
        right direction, especially for beginners who don't know where to start.
</Callout>
