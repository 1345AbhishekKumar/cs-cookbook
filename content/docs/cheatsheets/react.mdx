React is a declarative, component-based UI library. In React 19, actions, async transitions, optimistic UI, the `use()` hook, and native `ref` props make components simpler and eliminate historical boilerplate like `forwardRef`.

- **Official Website:** [https://react.dev](https://react.dev)
- **Documentation:** [https://react.dev/reference/react](https://react.dev/reference/react)
- **GitHub Repository:** [https://github.com/facebook/react](https://github.com/facebook/react)

Use this page as a quick reference: hook cheat-tables, React 19 patterns, and copy-paste snippets.

## Component Basics & JSX

```tsx
interface ButtonProps {
  label: string;
  variant?: "primary" | "secondary";
  onClick?: () => void;
  children?: React.ReactNode;
}

export function Button({ label, variant = "primary", onClick, children }: ButtonProps) {
  return (
    <button className={`btn btn-${variant}`} onClick={onClick}>
      {label}
      {children}
    </button>
  );
}
```

## React 19 Modern Features

React 19 streamlines async workflows, removes `forwardRef`, and treats forms and promises as first-class primitives.

| React 19 Feature | Syntax | What it replaces / improves |
| --- | --- | --- |
| **`ref` as a Prop** | `function Input({ ref, ...props })` | Replaces `forwardRef(...)` wrapper completely. |
| **`use(Promise)`** | `const data = use(fetchPromise)` | Reads promises in render; pauses in `<Suspense>`. |
| **`use(Context)`** | `const theme = use(ThemeContext)` | Flexible `useContext` callable conditionally and in loops. |
| **`useActionState`** | `const [state, formAction, isPending] = useActionState(fn, init)` | Automates form mutation state, pending flags, and error handling. |
| **`useOptimistic`** | `const [opt, setOpt] = useOptimistic(state, updateFn)` | Instant UI updates rolled back if action fails. |
| **`useFormStatus`** | `const { pending } = useFormStatus()` | Reads parent `<form>` submission status in child buttons. |
| **Native Metadata** | `<title>Page Title</title>` directly in JSX | Replaces `react-helmet` without third-party head packages. |

### 1. `ref` as a Normal Prop (No `forwardRef`)

```tsx
// React 19: ref is just another prop!
interface InputProps extends React.ComponentProps<"input"> {
  label: string;
}

export function TextInput({ label, ref, ...props }: InputProps) {
  return (
    <label>
      {label}
      <input ref={ref} {...props} />
    </label>
  );
}
```

### 2. The `use()` API for Promises & Context

Unlike standard hooks, `use()` can be called **inside `if` statements and loops**:

```tsx
import { use, Suspense } from "react";

function UserProfile({ userPromise }: { userPromise: Promise<{ name: string }> }) {
  // Suspends component until userPromise resolves
  const user = use(userPromise);
  return <h2>Hello, {user.name}</h2>;
}

export function Page({ userPromise }: { userPromise: Promise<{ name: string }> }) {
  return (
    <Suspense fallback={<div>Loading profile...</div>}>
      <UserProfile userPromise={userPromise} />
    </Suspense>
  );
}
```

### 3. Forms with `useActionState` & `useFormStatus`

```tsx
"use client";

import { useActionState } from "react";
import { useFormStatus } from "react-dom";

async function updateNameAction(previousState: { error?: string }, formData: FormData) {
  const name = formData.get("name") as string;
  if (!name) return { error: "Name is required" };
  await saveNameToDatabase(name);
  return { error: undefined };
}

function SubmitButton() {
  const { pending } = useFormStatus();
  return <button disabled={pending}>{pending ? "Saving..." : "Save"}</button>;
}

export function NameForm() {
  const [state, formAction, isPending] = useActionState(updateNameAction, {});

  return (
    <form action={formAction}>
      <input name="name" placeholder="Enter name" />
      <SubmitButton />
      {state.error && <p className="error">{state.error}</p>}
    </form>
  );
}
```

### 4. `useOptimistic` for Instant UI

```tsx
import { useOptimistic, useTransition } from "react";

export function MessageList({ messages, sendMessage }: { messages: string[]; sendMessage: (msg: string) => Promise<void> }) {
  const [optimisticMessages, setOptimistic] = useOptimistic(
    messages,
    (state, newMsg: string) => [...state, `${newMsg} (sending...)`]
  );
  const [isPending, startTransition] = useTransition();

  const handleSend = async (formData: FormData) => {
    const text = formData.get("text") as string;
    startTransition(async () => {
      setOptimistic(text);
      await sendMessage(text);
    });
  };

  return (
    <div>
      <ul>
        {optimisticMessages.map((m, i) => (
          <li key={i}>{m}</li>
        ))}
      </ul>
      <form action={handleSend}>
        <input name="text" required />
        <button type="submit">Send</button>
      </form>
    </div>
  );
}
```

## Core Hooks Cheat Table

| Hook | Purpose | Common Signature |
| --- | --- | --- |
| `useState` | Local reactive component state. | `const [val, setVal] = useState(init);` |
| `useReducer` | Complex state transitions / state machines. | `const [state, dispatch] = useReducer(reducer, init);` |
| `useEffect` | External system synchronization (DOM, timers, subscriptions). | `useEffect(() => { ... return cleanup; }, [deps]);` |
| `useLayoutEffect` | Synchronous DOM mutations before browser paint (measurements). | `useLayoutEffect(() => { ... }, [deps]);` |
| `useRef` | Mutable reference that doesn't trigger re-renders; DOM node handle. | `const ref = useRef<HTMLDivElement>(null);` |
| `useMemo` | Cache result of expensive synchronous calculation. | `const val = useMemo(() => compute(a, b), [a, b]);` |
| `useCallback` | Cache function instance across re-renders for memoized children. | `const fn = useCallback(() => doWork(id), [id]);` |
| `useContext` / `use` | Read from a React Context provider without prop drilling. | `const val = use(MyContext);` |
| `useTransition` | Mark state update as non-blocking transition. | `const [isPending, startTransition] = useTransition();` |
| `useDeferredValue` | Defer re-rendering a slow part of UI while keeping inputs responsive. | `const deferredVal = useDeferredValue(val);` |
| `useId` | Generate unique accessible IDs for forms (`aria-describedby`). | `const id = useId();` |

## State Updates: Patterns & Recipes

### 1. Functional State Updaters

Always use the updater function `(prev) => next` when the new state depends on current state to avoid stale closure races:

```tsx
// ❌ Stale if clicked quickly in succession
setCount(count + 1);

// ✅ Always accurate
setCount((prev) => prev + 1);
```

### 2. Updating Objects & Arrays Immutably

```tsx
// Object update
setUser((prev) => ({ ...prev, name: "Alice" }));

// Nested object update
setUser((prev) => ({
  ...prev,
  address: { ...prev.address, city: "London" },
}));

// Array append
setItems((prev) => [...prev, newItem]);

// Array remove
setItems((prev) => prev.filter((item) => item.id !== targetId));

// Array item update
setItems((prev) =>
  prev.map((item) => (item.id === targetId ? { ...item, completed: true } : item))
);
```

## Performance & Re-render Optimization

1. **Keep state close to where it's used:** Move state down into the specific child that needs it.
2. **Component composition over memoization:** Pass children as props (`{children}`) so parent re-renders don't re-render children.
3. **`React.memo`:** Only wrap pure presentation components whose props change infrequently while their parents re-render frequently.
4. **Keys in Lists:** Never use array index as a key for dynamic lists. Always use stable unique IDs (`item.id`).

```tsx
// ❌ Dangerous: index as key breaks input focus and re-ordering
{items.map((item, index) => <TodoItem key={index} item={item} />)}

// ✅ Correct: stable unique key
{items.map((item) => <TodoItem key={item.id} item={item} />)}
```

## Anti-patterns vs Best practices

| Anti-pattern | Why it harms | Best practice |
| --- | --- | --- |
| Storing calculated/derived state in `useState` | Redundant sync, stale state bugs, extra re-render cycles. | Calculate inline during render: `const count = items.length;` |
| Using `useEffect` to fetch data | Race conditions, no caching, waterfall cascades, flicker. | Use TanStack Query, Next.js Server Components, or `use(promise)`. |
| Mutating state directly (`arr.push()`) | React skips re-render because object reference didn't change. | Always return fresh copies with `[...arr, item]`. |
| Missing cleanup functions in `useEffect` | Memory leaks, zombie event listeners, hanging timers. | Always return a teardown function: `return () => window.removeEventListener(...)`. |
| Wrapping every function in `useCallback` | Unnecessary memory allocations and noise without performance benefit. | Only memoize callbacks passed to `React.memo` components or deps arrays. |

## Memory anchors

- **State is a snapshot:** Calling `setCount(count + 1)` doesn't change `count` in the current function tick; it queues a render.
- **Pure rendering:** Components must be pure functions of props and state — no side effects during the render body.
- **React 19 `ref`:** No more `forwardRef`; access `ref` directly as a prop in function components.
- **`use(promise)` suspends:** Suspends until resolved; must be surrounded by a `<Suspense fallback={...}>`.
- **`useActionState` replaces form boilerplate:** Bundles payload mutation, action execution, and `isPending` state into one hook.
- **`useOptimistic` for instantaneous feedback:** Immediately paints predicted state; reverts if action throws an error.
- **Effects are for synchronization:** Don't use `useEffect` for state transformations or user click handlers; use pure calculations or event handlers.
