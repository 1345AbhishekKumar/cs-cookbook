Git is a distributed version control system tracking file snapshots over time. GitHub hosts remote repositories and provides collaboration primitives (PRs, issues, actions).

- **Git Official Documentation:** [https://git-scm.com/doc](https://git-scm.com/doc)
- **GitHub CLI (`gh`) Manual:** [https://cli.github.com/manual](https://cli.github.com/manual)
- **GitHub Documentation:** [https://docs.github.com](https://docs.github.com)

Use this page as a quick reference: daily commands, undo recipes, plumbing workflows, and GitHub CLI (`gh`) automation.

## The Git 4-Area Architecture

```text
Working Directory    Staging Area (Index)    Local Repo (HEAD)    Remote (Origin)
    [Local Files]   ──git add──>   [Staged]   ──git commit──>   [Commits]   ──git push──>   [Cloud]
          │                              │                             │
          │<──────────git restore────────│                             │
          │<──────────────────────────git restore --source=HEAD────────│
          │<────────────────────────────────git fetch / git pull────────────────────────│
```

## Configuration & First Steps

```bash
# Identity (stored in ~/.gitconfig)
git config --global user.name "Your Name"
git config --global user.email "you@example.com"

# Sensible defaults
git config --global init.defaultBranch main
git config --global pull.rebase true              # Rebase by default on pull
git config --global push.autoSetupRemote true      # Auto-set upstream on new branch
git config --global core.editor "code --wait"

# Verify configuration
git config --global --list
```

## Everyday Workflow: Staging & Commits

| Command | Action |
| --- | --- |
| `git status -s` | Compact status overview (`M` modified, `A` added, `??` untracked). |
| `git add <file>` | Stage specific file for the next commit. |
| `git add -p` | Interactive staging: review and stage hunk by hunk. |
| `git diff` | Show unstaged changes in working directory vs stage. |
| `git diff --staged` | Show staged changes vs latest commit (`HEAD`). |
| `git commit -m "feat: message"` | Record staged changes as a new commit snapshot. |
| `git commit --amend` | Modify previous commit message or include newly staged files. |
| `git log --oneline --graph --all` | ASCII commit graph showing branches and history. |

## Branching & Switching

Git 2.23+ introduced `switch` and `restore` to replace overloaded `checkout`.

| Action | Modern Command (Recommended) | Legacy Equivalent |
| --- | --- | --- |
| Create & switch to branch | `git switch -c feature/auth` | `git checkout -b feature/auth` |
| Switch existing branch | `git switch main` | `git checkout main` |
| Switch to previous branch | `git switch -` | `git checkout -` |
| List local branches | `git branch` | `git branch` |
| List all (local + remote) | `git branch -a` | `git branch -a` |
| Delete merged branch | `git branch -d feature/auth` | `git branch -d feature/auth` |
| Force delete unmerged branch| `git branch -D feature/auth` | `git branch -D feature/auth` |
| Rename current branch | `git branch -m new-name` | `git branch -m new-name` |

## Merging vs Rebasing

| Strategy | When to use | Command | Outcome |
| --- | --- | --- | --- |
| **Fast-Forward Merge** | Target branch has no new commits. | `git merge feature` | HEAD pointer simply advances. |
| **3-Way Merge** | Keep explicit branch history and bubble graph. | `git merge --no-ff feature` | Creates an explicit merge commit. |
| **Rebase** | Linear, clean commit history before opening PR. | `git rebase main` | Re-plays your commits on top of main. |
| **Interactive Rebase** | Clean up, squash, reorder, or edit commits. | `git rebase -i HEAD~3` | Opens interactive editor sheet. |

### Interactive Rebase Commands

In `git rebase -i HEAD~N`:

- `pick`: Use commit as-is.
- `reword`: Change commit message.
- `edit`: Stop and allow editing of files or splits.
- `squash`: Melt commit into previous commit and combine messages.
- `fixup`: Melt commit into previous commit and discard this commit message.
- `drop`: Delete commit completely.

```bash
# Conflict resolution during rebase
git status                     # Find conflicting files (marked with <<<<<<<)
# edit files, resolve conflict markers
git add <resolved-file>
git rebase --continue
# or cancel entirely:
git rebase --abort
```

## Undoing Mistakes & Time Travel

### The Undo Decision Matrix

| Situation | Safe / Destructive | Recommended Command |
| --- | --- | --- |
| Discard unstaged file edits | Destructive | `git restore <file>` |
| Unstage a staged file | Safe | `git restore --staged <file>` |
| Discard all local changes | Destructive | `git restore .` |
| Fix message of last commit | Safe | `git commit --amend -m "new message"` |
| Undo last commit, keep changes staged | Safe | `git reset --soft HEAD~1` |
| Undo last commit, keep changes unstaged | Safe | `git reset HEAD~1` (mixed) |
| Destroy last commit & all changes | **Destructive** | `git reset --hard HEAD~1` |
| Revert a public commit already pushed | Safe for teams | `git revert <commit-hash>` |

### Rescuing "Lost" Commits with Reflog

Git almost never deletes committed data immediately. If you made a catastrophic `reset --hard`:

```bash
# 1. View reflog history of all HEAD movements
git reflog

# Output:
# 3a1b2c4 HEAD@{0}: reset: moving to HEAD~1
# 8f9e0d1 HEAD@{1}: commit: important work was here!

# 2. Recover lost commit state
git switch -c recovery-branch 8f9e0d1
```

## Stash: Shelving Work Temporarily

```bash
# Stash modified & staged files
git stash

# Stash including untracked new files
git stash -u -m "wip: authentication form"

# List all stashed entries
git stash list
# stash@{0}: wip: authentication form
# stash@{1}: WIP on main...

# Restore latest stash and delete it from stack
git stash pop

# Restore stash without deleting from stack
git stash apply stash@{0}

# Discard specific stash
git stash drop stash@{0}

# Discard all stashes
git stash clear
```

## Git Worktrees: Multi-Branch Parallelism

Worktrees allow checking out multiple branches into different folders simultaneously without cloning twice.

```bash
# Create a parallel folder for hotfix while keeping feature work open
git worktree add ../hotfix-folder main

# Create and checkout a new branch in a dedicated folder
git worktree add -b bugfix/login ../bugfix-login-dir main

# List active worktrees
git worktree list

# Remove worktree when done
git worktree remove ../hotfix-folder
```

## Git Bisect: Binary Search Bug Hunter

Find the exact commit that introduced a bug via automated binary search.

```bash
git bisect start
git bisect bad                 # Current commit is broken
git bisect good v1.2.0         # Last known good release/commit

# Git checks out intermediate commits automatically
# Test your app:
git bisect bad                 # If bug is present
# or:
git bisect good                # If bug is absent

# End bisect and return to original branch
git bisect reset
```

## Remote Operations & Collaboration

```bash
# Add remote
git remote add origin git@github.com:username/repo.git

# Fetch remote branches without merging
git fetch origin --prune

# Pull with rebase (linear history)
git pull --rebase origin main

# Push new branch and link upstream tracking
git push -u origin feature/login

# Push rebased branch safely (NEVER use plain --force on shared branches)
git push --force-with-lease origin feature/login
```

## GitHub CLI (`gh`) Quick Reference

The official CLI tool connects directly to GitHub APIs from your terminal.

```bash
# Authentication
gh auth login
gh auth status

# Repositories
gh repo clone owner/repo
gh repo create my-app --public --source=. --push
gh repo view --web             # Open current repo in browser

# Pull Requests
gh pr create --title "feat: payment gateway" --body "Closes #42"
gh pr list --state open
gh pr checkout 123             # Check out PR branch locally
gh pr diff 123                 # View diff of PR
gh pr review --approve -b "LGTM!"
gh pr merge 123 --squash --delete-branch

# Issues
gh issue create --title "Bug: token expired" --body "Steps to reproduce..."
gh issue list --assignee "@me"
gh issue close 42

# GitHub Actions
gh run list --limit 5
gh run watch                   # Live stream ongoing workflow run
gh run view --log-failed
```

## Anti-patterns vs Best practices

| Anti-pattern | Why it harms | Best practice |
| --- | --- | --- |
| `git push --force` | Overwrites teammates' pushed commits irreversibly. | Always use `git push --force-with-lease`. |
| Committing secrets (`.env`, private keys) | Permanent in Git history even if deleted in next commit. | Use `.gitignore` before first commit; use BFG / `git filter-repo` to scrub. |
| Giant multi-thousand line commits | Impossible to review, cherry-pick, or revert safely. | Small, atomic commits following Conventional Commits (`feat:`, `fix:`). |
| Merging main into your branch repeatedly | Pollutes graph with endless "Merge branch 'main' into..." noise. | Rebase your branch onto `main` before opening PR. |
| Blind `git add .` | Accidentally stages node_modules, build artifacts, or secret keys. | Inspect with `git status -s` or stage interactively with `git add -p`. |

## Memory anchors

- **4 Areas:** Working Tree (disk) → Index / Staging (`git add`) → Local HEAD (`git commit`) → Remote (`git push`).
- **`switch` vs `restore`:** Use `git switch` for branches; use `git restore` for files. Leave `checkout` for legacy tutorials.
- **`--force-with-lease`:** Replaces dangerous `--force`; refuses push if remote moved ahead unexpectedly.
- **`git reset --soft`:** The undo button for commits: unpacks commit back into your staging area so you can re-commit cleanly.
- **`git reflog` is your safety net:** As long as a commit was created, its SHA lives in reflog for at least 30–90 days.
- **`git worktree` beats multiple clones:** Switch tasks or hotfix production instantly without stashing or context-switching overhead.
- **`gh` eliminates context switching:** Create PRs, review code, and inspect Actions runs straight from the command line.
