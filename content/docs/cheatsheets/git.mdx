Git is a distributed version control system engineered for speed, data integrity, and non-linear workflows. It tracks content snapshots across a directed acyclic graph (DAG) of cryptographic commit objects.

- **Official Website:** [https://git-scm.com](https://git-scm.com)
- **Documentation & Pro Git Book:** [https://git-scm.com/doc](https://git-scm.com/doc)
- **Reference Manual:** [https://git-scm.com/docs](https://git-scm.com/docs)

Use this page as an exhaustive reference: daily commands, plumbing mental models, interactive rebasing, undo matrices, and disaster recovery.

## The Git 4-Area Architecture

```text
Working Directory        Staging (Index)          Local Repo (HEAD)        Remote (Origin)
 [Uncommitted Files]  ──git add──>  [Staged Index]  ──git commit──>  [Commit Objects]  ──git push──>  [Remote Cloud]
         │                                │                                │
         │<──────────git restore──────────│                                │
         │<──────────────────────────git restore --source=HEAD─────────────│
         │<────────────────────────────────git fetch / git pull───────────────────────────────│
```

| Area                        | Purpose                                                                 | Location on Disk         |
| --------------------------- | ----------------------------------------------------------------------- | ------------------------ |
| **Working Directory**       | Your active sandbox containing untracked and modified files.            | Files on filesystem      |
| **Staging Area (Index)**    | A binary index file staging exact changes slated for the next commit.   | `.git/index`             |
| **Local Repository (HEAD)** | Permanent history of compressed snapshot objects and branch references. | `.git/objects/`          |
| **Remote Repository**       | Upstream shared central repository (GitHub, GitLab, Bitbucket).         | Remote server (`origin`) |

## Setup & Global Configuration

```bash
# Identity configuration (saved in ~/.gitconfig)
git config --global user.name "Your Name"
git config --global user.email "you@example.com"

# Sensible production defaults
git config --global init.defaultBranch main
git config --global pull.rebase true              # Linear history on pull
git config --global push.autoSetupRemote true      # Auto-set upstream on new branch
git config --global core.editor "code --wait"
git config --global core.autocrlf input           # Linux/macOS line endings (use 'true' for Windows)
git config --global rerere.enabled true           # Reuse Recorded Resolution for recurring merge conflicts

# Inspect configuration
git config --global --list --show-origin
```

### Useful Aliases

```bash
git config --global alias.st "status -s"
git config --global alias.co "switch"
git config --global alias.br "branch"
git config --global alias.lg "log --graph --oneline --decorate --all"
```

## Daily Workflow: Staging & Commits

| Command                           | Action                                                                                 |
| --------------------------------- | -------------------------------------------------------------------------------------- |
| `git status -s`                   | Short-format status (`M` modified, `A` added, `D` deleted, `??` untracked).            |
| `git add <file>`                  | Stage specific file modifications.                                                     |
| `git add -p`                      | **Patch mode:** Interactively review and stage code hunk by hunk (`y`, `n`, `s`, `e`). |
| `git diff`                        | Diff of unstaged working tree changes vs Staging Area.                                 |
| `git diff --staged`               | Diff of staged changes vs current commit (`HEAD`).                                     |
| `git diff HEAD~1 HEAD`            | Diff between the last two commits.                                                     |
| `git commit -m "feat: summary"`   | Commit staged files with message following Conventional Commits.                       |
| `git commit --amend`              | Edit previous commit message or incorporate newly staged files into it.                |
| `git commit --amend --no-edit`    | Add staged changes into the latest commit without changing the message.                |
| `git log --oneline --graph -n 15` | Compact graphical commit tree of recent commits.                                       |

## Branching & Switching

Git 2.23+ introduced `git switch` to replace the overloaded `git checkout` for branch handling.

| Action                             | Modern Command (Recommended)     | Legacy Command                             |
| ---------------------------------- | -------------------------------- | ------------------------------------------ |
| Create and switch to new branch    | `git switch -c feature/auth`     | `git checkout -b feature/auth`             |
| Switch to existing branch          | `git switch main`                | `git checkout main`                        |
| Switch back to previous branch     | `git switch -`                   | `git checkout -`                           |
| List local branches                | `git branch`                     | `git branch`                               |
| List all branches (local + remote) | `git branch -a`                  | `git branch -a`                            |
| Rename current branch              | `git branch -m new-feature-name` | `git branch -m new-feature-name`           |
| Safe delete merged branch          | `git branch -d feature/auth`     | `git branch -d feature/auth`               |
| Force delete unmerged branch       | `git branch -D feature/auth`     | `git branch -D feature/auth`               |
| Set upstream tracking              | `git branch -u origin/main`      | `git branch --set-upstream-to=origin/main` |

## Merging vs Rebasing

| Strategy                    | When to Use                                    | Command                     | Resulting Graph                                      |
| --------------------------- | ---------------------------------------------- | --------------------------- | ---------------------------------------------------- |
| **Fast-Forward Merge**      | Upstream branch hasn't diverged.               | `git merge feature`         | Pointer moves forward linearly without extra commit. |
| **3-Way Merge (`--no-ff`)** | Feature PR landing; preserves branch topology. | `git merge --no-ff feature` | Creates an explicit merge commit with two parents.   |
| **Rebase**                  | Clean linear history before PR submission.     | `git rebase main`           | Replays local commits on top of current main.        |
| **Interactive Rebase**      | Clean up, squash, reorder, or edit commits.    | `git rebase -i HEAD~4`      | Opens interactive rebase sheet.                      |

### Interactive Rebase Commands (`git rebase -i HEAD~N`)

Inside the interactive rebase editor:

- `pick`: Use commit as-is.
- `reword`: Keep commit contents, but edit commit message.
- `edit`: Stop execution to allow modifying code, splitting commits, or adding files.
- `squash`: Combine commit into the previous commit and concatenate commit messages.
- `fixup`: Combine commit into the previous commit while discarding this commit's message.
- `drop`: Delete the commit completely.

```bash
# Conflict resolution during rebase:
git status                     # Identifies conflicting files
# (manually resolve <<<<<<< HEAD ... >>>>>>> markers)
git add <resolved-file>
git rebase --continue

# Abort rebase safely at any time:
git rebase --abort
```

## Undoing Mistakes & Time Travel

### The Undo Decision Matrix

| Problem Scenario                                  | Safety Level    | Recommended Command                |
| ------------------------------------------------- | --------------- | ---------------------------------- |
| Discard unstaged edits in a file                  | **Destructive** | `git restore <file>`               |
| Unstage a staged file (keep disk edits)           | Safe            | `git restore --staged <file>`      |
| Discard all local unstaged edits across project   | **Destructive** | `git restore .`                    |
| Discard all untracked files and directories       | **Destructive** | `git clean -fd` (`-n` for dry run) |
| Undo last commit, keep changes staged in index    | Safe            | `git reset --soft HEAD~1`          |
| Undo last commit, keep changes unstaged on disk   | Safe            | `git reset HEAD~1` _(mixed)_       |
| Erase last commit and all associated file changes | **Destructive** | `git reset --hard HEAD~1`          |
| Safely revert a public commit already pushed      | Safe for teams  | `git revert <commit-hash>`         |

### Reflog: Rescuing "Destroyed" Commits

If you accidentally executed `git reset --hard` or deleted a branch, Git retains commit objects in `.git/` for 30–90 days:

```bash
# 1. View history of all HEAD pointer movements
git reflog

# Output example:
# 4f8a12b HEAD@{0}: reset: moving to HEAD~1
# 9a7e321 HEAD@{1}: commit: crucial architectural refactor!

# 2. Resurrect the lost commit onto a new branch
git switch -c rescue-branch 9a7e321
```

## Stashing: Shelving Unfinished Work

```bash
# Stash tracked modifications
git stash

# Stash including untracked files with a descriptive message
git stash push -u -m "wip: stripe checkout modal"

# View all stashed snapshots
git stash list
# stash@{0}: On main: wip: stripe checkout modal
# stash@{1}: WIP on feature: auth changes

# Apply latest stash and remove it from stash stack
git stash pop

# Apply specific stash without removing it from stack
git stash apply stash@{0}

# View changes inside a stash without applying
git stash show -p stash@{0}

# Discard a specific stash
git stash drop stash@{0}

# Clear all stashes
git stash clear
```

## Git Worktrees: Multi-Branch Parallelism

Worktrees allow having multiple branches checked out simultaneously in separate directories without cloning the repository twice.

```bash
# 1. Add a worktree for a urgent hotfix while keeping your feature directory open
git worktree add ../my-app-hotfix main

# 2. Add a worktree with a newly created branch
git worktree add -b bugfix/login-csrf ../my-app-bugfix main

# 3. List active worktree paths
git worktree list

# 4. Remove worktree when hotfix is completed and merged
git worktree remove ../my-app-hotfix
```

## Git Bisect: Automated Binary Search Debugger

Find the exact commit that introduced a bug in $O(\log n)$ steps:

```bash
# 1. Start bisect mode
git bisect start

# 2. Tell Git the current commit has the bug
git bisect bad

# 3. Tell Git the last known working release or tag
git bisect good v2.1.0

# 4. Git checks out intermediate commits automatically. Test each step:
git bisect bad   # if bug exists in checked out commit
# or:
git bisect good  # if bug is absent

# Automated testing with a test script (runs fully unattended!):
git bisect run npm test

# 5. When Git announces the culprit commit, exit bisect mode:
git bisect reset
```

## Git Submodules

Manage external repositories nested within your repository:

```bash
# Add submodule
git submodule add https://github.com/vendor/library.git vendor/library

# Clone repo containing submodules recursively
git clone --recurse-submodules https://github.com/org/project.git

# Pull upstream changes for all initialized submodules
git submodule update --remote --recursive
```

## Remote Collaboration & Safe Push

```bash
# Add remote
git remote add origin git@github.com:username/repository.git

# Prune remote branch references that no longer exist on remote
git fetch origin --prune

# Pull with rebase (prevents unsightly merge bubbles)
git pull --rebase origin main

# Push and configure upstream tracking
git push -u origin feature/login

# Push rebased branch safely (NEVER use plain --force on shared branches)
git push --force-with-lease origin feature/login
```

## Anti-patterns vs Best practices

| Anti-pattern                                    | Why it harms                                                         | Best practice                                                               |
| ----------------------------------------------- | -------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| `git push --force`                              | Overwrites teammate commits without warning if remote updated.       | Always use `git push --force-with-lease`.                                   |
| Committing secrets (`.env`, `.pem`)             | Permanently preserved in Git history even if deleted in next commit. | Place in `.gitignore` before first commit; use `git-filter-repo` to scrub.  |
| Giant, unfocused commits                        | Impossible to review, cherry-pick, or bisect cleanly.                | Make small atomic commits following Conventional Commits (`feat:`, `fix:`). |
| Indiscriminate `git add .`                      | Accidental staging of logs, build files, and temporary artifacts.    | Use `git add -p` or review with `git status -s` first.                      |
| Resolving conflicts by deleting markers blindly | Introduces silent syntax errors and compilation bugs.                | Test resolution locally (`npm test` / `cargo test`) before committing.      |

## Memory anchors

- **4 Areas:** Working Tree $\rightarrow$ Staging (`git add`) $\rightarrow$ Local HEAD (`git commit`) $\rightarrow$ Remote (`git push`).
- **`switch` & `restore`:** Modern replacements for `checkout`. `switch` handles branches; `restore` handles files.
- **`--force-with-lease`:** The safe force push. It aborts if someone else pushed commits to the remote branch while you were rebasing.
- **`git reset --soft HEAD~1`:** The commit undo button. Keeps all changes staged in the index so you can re-commit.
- **`git reflog`:** Nothing committed is truly lost for 30–90 days. Retrieve lost commits via `git switch -c recovery <hash>`.
- **`git worktree`:** Work on multiple branches in parallel directories without re-cloning or stashing.
- **`git bisect run`:** Automatically tests commits via script until the regression is located.
