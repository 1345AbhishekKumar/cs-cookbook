A **computer network** is a group of connected devices (laptops, phones, servers, printers) that exchange data and share resources using agreed rules called **protocols** over wired or wireless paths.

Why do we even need networks? Alone, your laptop can only use its own files. Connected, it can open Google, print to an office printer, save to the cloud, or play games with friends. Modern companies run almost everything — email, meetings, payments, backups — on networks, so understanding them helps in web dev, DevOps, and interviews.

**Beginner mental model:** think of it like a postal system:

- **Devices** = houses
- **IP address** = house address — every device needs a unique one to receive letters
- **Packets** = letters / parcels. Big data (a video, a website) is cut into small numbered packets, each sent separately, then joined back. If one is lost, only that piece is resent.
- **Protocols** = postal rules — where to write the address, which language to use, what to do if a letter is lost. Without rules, a Dell laptop could not talk to an Apple server.
- **Cables / Wi-Fi** = roads — how letters physically travel
- **Router / Switch** = post office / sorting center — reads the address and decides where letters go next

Use this page as a quick reference: plain-English definitions first, exact terms and tables second. If you are totally new, read the intro lines of each section; if revising, just scan the tables.

## Networking in 30 seconds

These 8 words appear everywhere. Learn them once and every other section makes sense.

| Term | Beginner meaning | Example |
| --- | --- | --- |
| `Network` | Two or more devices talking to each other. | Laptop + printer on home Wi-Fi |
| `Protocol` | Agreed rules so different devices understand each other. | HTTP for web pages, IP for addressing |
| `Packet` | Small chunk of a big message. Sent separately, joined back later. | A video split into thousands of packets |
| `Bandwidth` | How much data can pass per second. Width of the road. | 100 Mbps connection |
| `Latency` | How long one trip takes. Speed of the road. | 20 ms ping |
| `IP address` | Unique address of a device on a network. | `192.168.1.10` |
| `MAC address` | Permanent hardware address burned into the network card. | `AA:BB:CC:11:22:33` |
| `Port` | Door number on a device for a specific service. IP gets you to the building, port gets you to the flat. | `80` = HTTP, `443` = HTTPS |

Why packets? Imagine sending a 1 GB movie as one piece — one error means resending 1 GB. Split into 10,000 packets, you only resend the lost ones, and different packets can even take different roads to avoid traffic. TCP numbers them so the receiver can reorder them.

Bandwidth vs latency: bandwidth is how many trucks per second, latency is how fast one truck drives. Watching YouTube needs high bandwidth; playing online games needs low latency. A road can be wide but slow, or narrow but fast.

## Network Topologies — how devices are wired

Topology = shape / layout of connections. It decides what happens when one cable or device fails, how much cable you must buy, and how fast problems can be found.

| Topology | What it looks like | Beginner analogy | Pros / Cons + When used |
| --- | --- | --- | --- |
| `Bus` | All devices share one central cable with terminators at both ends. | One long hallway everyone shares. | Cheap and easy for few PCs, but one cable break kills all and finding faults is hard. Only historic labs now. |
| `Ring` | Each device connects to two neighbors in a circle. Data travels one way (or both in dual ring). | Passing notes around a circle. | Equal access, no central box needed, but one failure can break the whole ring. Old Token Ring networks. |
| `Star` | Every device connects to a central hub / switch. All traffic goes via center. | Bicycle wheel with hub in middle. | Most common today (home Wi-Fi, office). Easy to add/remove devices and find faults — one cable fails, rest work. Downside: if the central switch dies, all die. |
| `Mesh` | Every device connects to many others (full mesh = everyone to everyone). | Spider web. | Very reliable — many backup paths — but needs lots of cables and money. Used in data centers, military, mesh Wi-Fi where routers talk to each other. |
| `Tree` | Stars connected together in a hierarchy (bus backbone + star branches). | Tree branches / company org chart. | Scalable for campuses: departments have their own star, joined by a backbone. A backbone failure hurts many users. |
| `Hybrid` | Mix of two or more topologies. | Combo of above. | Real-world large networks are almost always hybrid — e.g. office uses star inside, mesh between offices, ring for ISP backup. Best balance of cost + reliability. |

## Types of Network — by size

Bigger network = bigger area + slower control + more owners. Speed usually drops as size grows.

| Type | Full form | Covers | Beginner example |
| --- | --- | --- | --- |
| `PAN` | Personal Area Network | ~10 meters, one person | Phone + earbuds + smartwatch over Bluetooth |
| `LAN` | Local Area Network | One home, office, building | Home Wi-Fi, school lab — fast (100 Mbps–10 Gbps), you own the router |
| `MAN` | Metropolitan Area Network | One city (10–100 km) | City fiber linking university campuses or government offices |
| `WAN` | Wide Area Network | Country / world | The Internet, or a company linking offices in Delhi + Mumbai + London via ISP/leaseline |

> LAN is fast and you control it. WAN is huge and usually rented from an ISP. When your office Wi-Fi is fast but Google is slow, LAN is fine — WAN/Internet is the bottleneck.

## Internet vs Intranet vs Extranet

Same technology (TCP/IP, browsers), different doors.

| Type | Who can access? | Beginner meaning + example |
| --- | --- | --- |
| `Internet` | Everyone (public) | Millions of connected networks worldwide. You browse it. e.g. `google.com`. No single owner. |
| `Intranet` | Only inside one company (private) | Company's internal portal, e.g. `hr.mycompany.local` or attendance system that only opens on office Wi-Fi. Uses Internet tech but closed by firewall. |
| `Extranet` | Company + trusted outsiders | Intranet opened partly to partners/vendors via login + VPN. e.g. supplier logs in to check stock but cannot see salaries. |

## OSI vs TCP/IP — the layered models

Devices don't send data in one jump. Data passes down layers on the sender (adding headers like envelopes) and up layers on the receiver (removing them). This is called **encapsulation**. Each layer only talks to the same layer on the other side and doesn't need to know how lower layers work — that's why a browser works the same on Wi-Fi or fiber.

**Beginner trick:** OSI has 7 layers, TCP/IP merges them into 4. You mostly use TCP/IP in real work, OSI in exams/interviews. If someone says "L2 issue" they mean switch/MAC, "L3 issue" means IP/routing, "L7 issue" means app (HTTP/DNS).

| TCP/IP Layer | OSI Layers inside | Job in plain English | Example protocols |
| --- | --- | --- | --- |
| `Application` | Application + Presentation + Session | What the user sees. Formatting, encryption, login sessions. | DNS, HTTP, HTTPS, FTP, SMTP, IMAP, DHCP, SSH |
| `Transport` | Transport | Reliable vs fast delivery. Splits data, port numbers, checks errors. | TCP, UDP |
| `Internet` | Network | Addressing + best path (routing). Which road to take? | IPv4, IPv6, ICMP, IPsec |
| `Link` | Data Link + Physical | Physical transfer over cable / Wi-Fi, MAC addressing. How to push bits? | Ethernet, Wi-Fi (802.11), ARP, PPP |

OSI 7 layers top-to-bottom with memory hook — **A**ll **P**eople **S**eem **T**o **N**eed **D**ata **P**rocessing:

1. **Application (7)** — apps talk here. Browser, email, WhatsApp. The data itself. e.g. HTTP says "GET this page", DNS says "what is IP of google.com?"
2. **Presentation (6)** — translation, encryption, compression. Converts text → JPEG/MP3, encrypts with SSL/TLS so Wi-Fi hackers see gibberish.
3. **Session (5)** — start / keep / end conversations. Remembers "this login stays for 30 min". e.g. NetBIOS, SIP starts a call session.
4. **Transport (4)** — TCP = reliable + ordered (numbers packets, calls to confirm, resends lost). Slower but safe — use for web, files, email. UDP = fast + no guarantee (shouts and hopes). Use for live video, games, DNS where speed matters more than one lost packet.
5. **Network (3)** — logical addressing + routing. Adds source/destination IP. Routers read it and pick the best path like Google Maps.
6. **Data Link (2)** — MAC addressing inside one LAN, error check on one hop. Switches live here — they learn which MAC is on which port.
7. **Physical (1)** — raw bits on wire / air. Cables, voltage, radio waves, hubs. No addresses here, just 0s and 1s.

## What happens when you open google.com? — full journey

This ties everything together. Type `https://google.com` and press Enter:

1. **DNS lookup:** Browser asks "what is IP of google.com?" Goes to DNS server (usually `8.8.8.8`) on UDP 53. Gets back e.g. `142.250.190.14`.
2. **TCP handshake:** Your PC opens a reliable connection to that IP on TCP 443 (HTTPS). SYN → SYN-ACK → ACK — like "hello? — hi, I hear you — great, let's talk".
3. **TLS handshake:** They agree on encryption keys so no one in the middle can read.
4. **HTTP request:** Browser sends `GET /` inside encrypted packets. Each packet has IP (where to go) + TCP (which order, which port).
5. **Routing:** Home router (NAT) changes your private `192.168.1.5` to public ISP IP, sends to ISP, ISP routers forward via OSPF/BGP until Google's network.
6. **Response:** Google server replies with packets. Switches forward by MAC inside Google LAN, routers forward by IP across Internet.
7. **Reassembly:** Your PC reorders TCP packets, decrypts TLS, browser renders HTML.

If the page fails: can't resolve name = DNS issue (L7), can't ping IP = network/routing issue (L3), Wi-Fi connected but no Internet = DHCP/NAT/gateway issue.

## Core Protocols & Ports — what beginners must know

A **port** is a number 0–65535 that picks the service on a device. IP gets you to the building, port gets you to the flat: `192.168.1.10:443` = that PC's HTTPS service. Ports 0–1023 are **well-known** (reserved for HTTP, DNS, etc.), 1024–49151 registered, 49152–65535 private/ephemeral (browser picks a random one for itself when browsing).

> TCP = reliable (web, email, files — resends lost packets). UDP = fast (video, DNS, games — no resend). Some services can use both.

| Protocol | Beginner meaning — what it does for you + how it works | Transport + Standard port |
| --- | --- | --- |
| `TCP` | Reliable delivery. Numbers every packet, waits for ACK, resends lost ones, delivers in order. Three-way handshake to start: SYN → SYN-ACK → ACK. Use when nothing may be lost. | Transport protocol — no single port |
| `UDP` | Fast delivery. Just sends, no ACK, no reorder. If a packet is lost in a Zoom call, you see a glitch but call continues — better than waiting. | Transport protocol — no single port |
| `IP` | Addressing. Every packet carries source + destination IP. Routers read it to forward. IPv4 = `192.168.1.10`, IPv6 = longer. No guarantee of delivery — TCP adds that on top. | Network protocol — no port |
| `HTTP *` | Loads web pages (not encrypted). Browser sends `GET /index.html`, server returns HTML. Anyone on the path can read. Learn it, but always use HTTPS in real sites. | TCP 80 |
| `HTTPS *` | Loads web pages securely (HTTP + TLS encryption). Padlock in browser. Passwords/cards safe from Wi-Fi snoopers. | TCP 443 |
| `DNS *` | Phonebook of Internet. Steps: browser → OS cache → router → ISP DNS → root → .com → google's DNS → IP. Then browser connects to that IP. `nslookup google.com` to try. | UDP/TCP 53 |
| `DHCP *` | Auto-gives IP when you join Wi-Fi so you don't type manually. DORA: Discover (who is DHCP?) → Offer (take 192.168.1.5?) → Request (yes!) → ACK (done). Also gives gateway + DNS. No DHCP = self IP `169.254.x.x` and no Internet. | UDP 67 (server) / 68 (client) |
| `SSH *` | Secure remote login to servers. `ssh user@server` gives terminal. Replaces Telnet. Also used by GitHub, SFTP, port-forwarding. | TCP 22 |
| `FTP` | Old file upload / download with two channels: 21 for commands, 20 for data. Passwords go in plain text — avoid on Internet. | TCP 20 (data) / 21 (control) |
| `FTPS / SFTP` | Secure file transfer. FTPS = FTP + SSL (port 990/21), SFTP = files over SSH (port 22, totally different protocol despite similar name). Use SFTP for servers. | TCP 990/21 (FTPS), TCP 22 (SFTP) |
| `SMTP *` | Sends email out (push). You → Gmail SMTP → receiver's server. Only sending, not reading. Needs auth so spammers can't abuse. | TCP 25 (server-to-server), 587 (submission), 465 (SMTPS) |
| `IMAP *` | Reads email, keeps it on server — phone + laptop stay in sync. Delete on phone = deletes everywhere. Best for multi-device. | TCP 143, 993 (secure) |
| `POP3` | Downloads email and usually deletes from server — good for one PC with offline reading, bad for phones. Old style. | TCP 110, 995 (secure) |
| `ARP` | Finds MAC from IP inside LAN. PC shouts "Who has 192.168.1.1? Tell 192.168.1.5" and router replies with MAC. Switches then know where to send. `arp -a` to see table. | No port (Layer 2/3) |
| `RARP` | Reverse of ARP — finds IP from MAC (old diskless PCs). Mostly replaced by DHCP/BOOTP today. Know the name for exams. | No port |
| `ICMP` | Error + ping messages. `ping google.com` sends ICMP echo, measures reply time = latency. `tracert/traceroute` maps each router hop. Blocked by some firewalls so "ping fails" doesn't always mean down. | No port (uses IP protocol 1) |
| `SNMP` | Monitors network devices — router CPU, printer ink, link down alerts. Manager polls agents. v1/v2 insecure, v3 encrypted. | UDP 161 (query) / 162 (trap) |
| `NTP` | Keeps all clocks in sync (important for logs, OTPs, bank transactions). PCs sync to `time.google.com`. Off by minutes = login failures. | UDP 123 |
| `Telnet` | Old insecure remote login — everything plain text. Only for labs/old hardware in isolated LAN. Real life: use SSH. | TCP 23 |
| `SMB` | Windows file / printer sharing — `\\PC\SharedFolder`. Also how ransomware like WannaCry spread, so keep patched and don't expose to Internet. | TCP 445 (modern), 139 (legacy NetBIOS) |
| `LDAP` | Looks up users in a company directory (Active Directory). When you log in to office laptop, LDAP checks password + group. | TCP 389, 636 (secure) |
| `NFS` | Linux/Unix file sharing — mount remote folder as if local (`/mnt/server`). No encryption by itself, use inside trusted LAN or with VPN. | TCP/UDP 2049 |
| `RDP` | Windows Remote Desktop — full graphical control of distant PC. Very targeted by hackers, so use VPN + strong password + change default port if exposed. | TCP 3389 |
| `VNC` | Remote screen sharing (cross-platform). Simpler than RDP, less secure by default — tunnel over SSH/VPN. | TCP 5900+ (5900 = display :0) |
| `SIP` | Starts voice/video calls (VoIP) — dial, ring, hang up. Only signaling; actual voice goes via RTP. Used by IP phones, Jio/Zoom backends. | TCP/UDP 5060, 5061 (secure) |
| `RTP` | Carries actual voice/video after SIP sets up call. Runs over UDP for speed — small loss is okay. | UDP 5004+ (dynamic) |
| `NAT` | Translates many private IPs to one public IP so whole home shares one Internet connection. Home router: `192.168.1.5:1234` → `ISP-IP:5678` and remembers mapping to send replies back. Reason IPv4 still survives. Types: Static, Dynamic, PAT/overload (home). | No fixed port |
| `IPsec / IKE` | Encrypts IP packets for VPNs. Two modes: Transport (PC-to-PC) and Tunnel (office-to-office). IKE negotiates keys on UDP 500/4500, data via ESP (protocol 50) / AH (51). | UDP 500, 4500; protocols ESP (50), AH (51) |

Email flow in one line to remember: **You send via SMTP → stored on server → you read via IMAP (sync) or POP3 (download).** DNS is the phonebook, DHCP is the receptionist giving room numbers, ARP is asking "which face matches this room number?" inside the building.

Advanced routing protocols (for CCNA level — just know the idea). Routing = routers gossiping to learn the best road:

| Protocol | Idea in one line + when used | Identifier |
| --- | --- | --- |
| `RIP` | Old, counts hops. Max 15 hops, slow to learn. Only tiny labs now. Think "how many crossings?" | UDP 520 |
| `OSPF` | Link-state, every router knows full map and runs Dijkstra for shortest path. Fast inside one company/ISP. Areas divide big networks. | IP protocol 89 (not a TCP port) |
| `EIGRP` | Cisco's fast hybrid protocol, easy config, quick convergence. Cisco shops mostly. | IP protocol 88 |
| `BGP` | Glues the whole Internet — ISPs exchange routes between autonomous systems. Path-vector, policy-based, very slow but global. | TCP 179 |
| `STP` | Stops loops in switches by blocking extra paths but keeping them as backup. Without it, one loop = broadcast storm killing LAN. RSTP is faster version. | No IP port |
| `PPP` | Carries data over direct serial/dial links with auth + framing. Old WAN links, still in PPPoE for broadband. | No IP port |

## IP Addressing — beginner guide

An **IPv4 address** is 32 bits written as 4 numbers 0–255: `192.168.1.10`. It has Network part + Host part. Think street + house number.

- **Network ID** = street name (which network). All devices on same LAN share it.
- **Host ID** = house number (which device on that street). Must be unique in that LAN.
- **Subnet mask** = tells where street ends and house starts. e.g. `255.255.255.0` means first 3 numbers are network, last is host.
- **CIDR** = short way to write mask. `/24` means first 24 bits are network. So `192.168.1.0/24` = mask `255.255.255.0` = 256 addresses.
- **Network address** = first address (identifies network, not given to PCs). **Broadcast** = last address (message to all, not given to PCs). **Gateway** = router's address to leave LAN (usually `.1`). Usable hosts = `2^(host bits) - 2`.
- **Loopback** = `127.0.0.1` means "myself". `ping 127.0.0.1` tests your own network card without going out.
- **APIPA** = `169.254.x.x` means "DHCP failed, I gave myself a random address". If you see it, Wi-Fi is connected but no IP — restart router/DHCP.

IPv6 is the long new version: 128-bit hex like `2001:db8::1`. IPv4 has only ~4 billion addresses (over long ago), so IPv6 gives trillions. You will see it in `ipconfig` alongside IPv4 — both run together (dual-stack).

### IPv4 Classes (old system, still asked in exams)

Classful addressing is retired (now we use CIDR), but exams still ask. Rule: look at first number.

| Class | Starts with bits | Range | Use + hosts |
| --- | --- | --- | --- |
| `A` | `0` | `0.0.0.0 – 127.255.255.255` (1–126 usable, 127 = loopback) | Huge networks (16M hosts each). e.g. `10.x` giants, `127.x` = yourself. |
| `B` | `10` | `128.0.0.0 – 191.255.255.255` | Medium networks (65k hosts). Old universities/companies. |
| `C` | `110` | `192.0.0.0 – 223.255.255.255` | Small networks (254 hosts). Most home/office LANs. |
| `D` | `1110` | `224.0.0.0 – 239.255.255.255` | Multicast (one → many, e.g. live streaming, OSPF hellos). Not for normal PCs. |
| `E` | `1111` | `240.0.0.0 – 255.255.255.255` | Reserved / research. Don't use. |

### Private vs Public IPs

- **Public** = reachable on Internet, given and paid to ISP, globally unique. e.g. `8.8.8.8` (Google DNS). Check yours via "what is my ip".
- **Private** = only inside LAN, reused in every home/office, translated by NAT to one public IP. Never routed on Internet. Free to use.

| Private block | Range | CIDR | Typical use |
| --- | --- | --- | --- |
| `10.0.0.0/8` | `10.0.0.0 – 10.255.255.255` | /8 | Big companies |
| `172.16.0.0/12` | `172.16.0.0 – 172.31.255.255` | /12 | Medium networks |
| `192.168.0.0/16` | `192.168.0.0 – 192.168.255.255` | /16 | Home / small office (`192.168.1.1` = your router) |

### Subnetting & CIDR quick table

Why subnet? A company with `10.0.0.0/8` (16M IPs) doesn't want all PCs in one broadcast storm. Split into HR `/24`, Dev `/24`, Guest `/24` — smaller fault zones, better security, easier management.

| CIDR | Subnet mask | Total IPs | Usable hosts |
| --- | --- | --- | --- |
| /32 | 255.255.255.255 | 1 | 1 (one device route) |
| /31 | 255.255.255.254 | 2 | 2* (point-to-point link, no broadcast needed) |
| /30 | 255.255.255.252 | 4 | 2 (WAN link between 2 routers — most common) |
| /29 | 255.255.255.248 | 8 | 6 |
| /28 | 255.255.255.240 | 16 | 14 |
| /27 | 255.255.255.224 | 32 | 30 |
| /26 | 255.255.255.192 | 64 | 62 |
| /25 | 255.255.255.128 | 128 | 126 |
| /24 | 255.255.255.0 | 256 | 254 (one office floor) |
| /23 | 255.255.254.0 | 512 | 510 |
| /22 | 255.255.252.0 | 1,024 | 1,022 |
| /21 | 255.255.248.0 | 2,048 | 2,046 |
| /20 | 255.255.240.0 | 4,096 | 4,094 |
| /16 | 255.255.0.0 | 65,536 | 65,534 |
| /8 | 255.0.0.0 | 16,777,216 | 16,777,214 |

Formula: usable = `2^(32 - CIDR) - 2` (except /31 and /32 special cases). Host bits = 32 − CIDR. /24 → 8 host bits → 2⁸−2 = 254.

Worked example: `192.168.1.0/24` → network `192.168.1.0` (street name), first usable `192.168.1.1` (usually router/gateway), last usable `192.168.1.254`, broadcast `192.168.1.255` (shout to all). Give PCs `.2` to `.254`.

Need 4 subnets for 4 departments from `192.168.1.0/24`? Borrow 2 bits → /26. Each /26 gives 62 hosts: `192.168.1.0/26`, `.64/26`, `.128/26`, `.192/26`. That's subnetting in one line.

## Transmission Media — how bits travel

Media decides speed, distance, and cost. Rule of thumb: wired = fast + stable + needs cable; wireless = mobile + convenient + shared and noisy.

### Guided (wired — signal follows a path)

| Media | Beginner meaning + details |
| --- | --- |
| `Twisted Pair` | Two copper wires twisted to cancel noise. Phone + Ethernet (Cat5e up to 1 Gbps, Cat6/6a up to 10 Gbps). Cheapest, max ~100 m, then need switch. What you plug into laptop. |
| `Coaxial` | Copper core + insulator + metal shield + cover. Old TV cable and first Ethernet (10Base2). Better noise resistance than twisted pair but bulky — now mostly cable-TV/broadband incoming line. |
| `Fiber Optic` | Light pulses through glass (total internal reflection). Immune to electrical noise, very fast (Gbps–Tbps), very long (km). Two types: multimode (cheap, short, LED) and single-mode (costly, long, laser). Backbone of Internet and ISP-to-home (FTTH). Fragile — don't bend sharply. |

### Unguided (wireless — signal floats in air)

Lower frequency = longer range + slower + passes walls. Higher frequency = faster + shorter + blocked easily. That's why 2.4 GHz Wi-Fi reaches far but slow, 5 GHz fast but short.

| Media | Range | Beginner note + example |
| --- | --- | --- |
| `Radio waves` (3 kHz – 1 GHz) | Long, passes through walls | AM/FM, cordless phones, 4G low-band. No antenna alignment needed — tower broadcasts all around. |
| `Microwaves` (1 – 300 GHz) | Line-of-sight, few km to satellites | Mobile, satellite, Wi-Fi (2.4/5 GHz), Bluetooth. Antennas should roughly face each other; rain/buildings weaken. Higher bands = more data but more blockage. |
| `Infrared` (300 GHz – 400 THz) | Very short (meters), blocked by walls | TV remote, wireless mouse, printer, short data beaming. Must point directly. Secure because it doesn't go through walls — neighbor can't snoop. |

## Modes of Communication

Who talks when? This decides if you need one road or two.

| Mode | Direction | Analogy | Example |
| --- | --- | --- | --- |
| `Simplex` | One-way only, full capacity one direction | Radio broadcast / megaphone / CCTV | Keyboard → CPU (you never type back), TV station → you, sensor → server |
| `Half-Duplex` | Both ways, one at a time — must take turns | Walkie-talkie ("over!") | Old hubs, walkie-talkies, old Wi-Fi with collisions. If both talk, collision. |
| `Full-Duplex` | Both ways at same time, capacity split or two paths | Phone call — both can speak and hear | Modern switches, phones, fiber with separate TX/RX strands. Fastest. |

Most modern wired LANs are full-duplex — that's why a switch (full) is far faster than an old hub (half).

## Multiplexing — sharing one road

Laying one cable per user is costly. Multiplexing lets many conversations share one cable/air, demultiplexing splits them back. Your phone call + YouTube + neighbor's Netflix share the same fiber via multiplexing.

| Type | Idea in one line + example |
| --- | --- |
| `FDM` (Frequency Division) | Split frequency into channels. Each user gets own band forever. e.g. radio stations (91.1 vs 93.5 MHz), cable TV channels on one coax. Guard bands prevent mixing. |
| `TDM` (Time Division) | Split time into tiny slots. Each user gets full bandwidth for a short turn, round-robin. e.g. 4 phone calls take turns every millisecond — feels simultaneous. Needs sync. |
| `WDM` (Wavelength Division) | FDM for fiber — many light colors (wavelengths) at once on same glass. One fiber carries 80+ channels = Tbps. Backbone of ISPs. |

## Collision Handling — when two talk at once

On shared media (old hubs, Wi-Fi), if two shout together, signals garble. These rules manage turns.

| Method | Full form | Beginner meaning + where used |
| --- | --- | --- |
| `CSMA/CD` | Carrier Sense + Collision Detection | Listen first, talk if free; while talking keep listening — if crash (voltage doubles), stop, wait random time, retry. Used in old wired Ethernet hubs. Modern switches give each PC its own wire, so collisions almost gone. |
| `CSMA/CA` | Carrier Sense + Collision Avoidance | On Wi-Fi you can't listen while talking (radio can't send+receive same frequency), so avoid instead: wait random backoff + optionally ask "can I send? (RTS/CTS)". Slower but needed for wireless. That's why Wi-Fi slows with many users. |
| `ALOHA` | — | Just talk whenever; if no ACK, wait random and retry. Very simple, many collisions at load. Pure ALOHA = 18% efficiency, Slotted ALOHA = 37%. Ancestor of all shared wireless — historic but exam-favorite. |

## Networking Devices

Home example: Laptop (client) → Wi-Fi → Home Router (router + switch + AP + firewall + modem in one box) → ISP → Internet → Google Server. In big offices each box is separate and powerful.

| Device | Layer | Beginner job + how to remember |
| --- | --- | --- |
| `Client` | — | Your device asking for stuff. Laptop, phone, smart TV. Sends requests, shows results. |
| `Server` | — | Powerful always-on PC giving stuff to many clients. Web server (sites), mail server, file server, DNS server. Has public IP + open ports. |
| `Hub` | L1 | Dumb repeater — copies every packet to all ports. All PCs hear all traffic (insecure + slow + collisions). Cheap historic box. Almost never used now — replaced by switch. |
| `Switch` | L2 | Smart hub — learns MAC → port table by watching source MACs, then forwards only to the right port. Full-duplex, no collisions. Office LAN core. Managed switches add VLANs/QoS. |
| `Router` | L3 | Joins different networks using IP + routing table. Picks best path, connects LAN to Internet, does NAT/firewall. Home router joins `192.168.1.0/24` to ISP. |
| `Multilayer / L3 Switch` | L2+L3 | Switch + router in one for speed. Routes between VLANs inside big buildings at wire speed without going to a slow router. |
| `Access Point` | L2 | Gives Wi-Fi to wired network — bridges wireless to Ethernet. Home router has one built in. Offices mount many on ceilings with same SSID for roaming. |
| `Modem` | L1/L2 | Translates ISP signal (phone DSL / cable / fiber / 4G) to digital Ethernet. Modulator + Demodulator. Fiber homes: ONT box is the modem. |
| `Firewall` | L3–L7 | Security guard — allow/deny by rules: IP, port, app, state. "Block all incoming except reply traffic, allow 80/443 out". Home routers have basic one; companies use Next-Gen with intrusion prevention. |
| `Repeater / Extender` | L1 | Boosts weak signal to go farther (amplifies Wi-Fi or Ethernet beyond 100 m). Halves Wi-Fi speed in cheap models — mesh system is better. |

Quick ladder: Hub (shouts to all) → Switch (whispers to one in LAN by MAC) → Router (forwards between LANs by IP).

## Ethernet, Cables & Speeds

Ethernet = wired LAN standard (IEEE 802.3). Name code: speed + BASE (baseband) + medium. `1000BASE-T` = 1000 Mbps, baseband, twisted-pair. `1000BASE-LX` = fiber long.

| Common name | Speed | Cable, max length | Standard + use |
| --- | --- | --- | --- |
| Ethernet | 10 Mbps | Copper Cat3, 100 m | 802.3 — legacy printers/old gear |
| Fast Ethernet | 100 Mbps | Copper Cat5, 100 m | 802.3u — old offices, cheap IoT |
| Gigabit Ethernet | 1000 Mbps | Copper Cat5e/6 100 m / Fiber 550 m–5 km | 802.3ab (copper) / 802.3z (fiber) — today's default for PCs |
| 10 Gig Ethernet | 10 Gbps | Copper Cat6a 100 m / Fiber longer | 802.3an — servers, backbone, creators |

Fiber cheat: `SX` = short (multimode LED, ~550 m, cheap), `LX/LH` = long (single-mode laser, 5–70 km, costly). Color hint: orange/aqua = multimode, yellow = single-mode. Copper plug = RJ45, fiber plugs = LC/SC.

## Network Security Basics

Think in layers: even with all, stay updated and backup. One lock is never enough.

| Method | Beginner meaning + real example |
| --- | --- |
| `Authentication` | Prove who you are before entry. Password + OTP (2FA), fingerprint, certificates. e.g. Wi-Fi WPA2 password, office login via LDAP/RADIUS. Without it, anyone joins. |
| `Encryption` | Scramble data so thieves see gibberish without the key. HTTPS/TLS encrypts web, WPA2/3 encrypts Wi-Fi, IPsec encrypts VPN. Same key (symmetric) is fast, public/private keys (asymmetric) exchange that key safely. |
| `Firewall` | Filter gate — allow good traffic, block bad by rules (IP/port/direction/state). Home: "allow all out, block unsolicited in". Office: "block Facebook for staff VLAN, allow mail server 25/587". |
| `MAC Filtering` | Allow/block devices by hardware (MAC) address list on router/AP. Easy to bypass by spoofing MAC, so weak alone — use as extra layer with WPA2 password, not replacement. |
| `VPN (IPsec/SSL)` | Encrypted tunnel over public Internet back to office/home. Work from café safely — ISP sees only tunnel, not sites. Site-to-site VPN joins two offices permanently. |

Small checklist for home/small office: change default router password, use WPA2/WPA3 long password, update firmware, disable remote admin + WPS, use HTTPS + 2FA, backup data.

## Beginner FAQs — quick doubts

- **Why do I have two IPs?** `192.168.1.5` is private (your LAN), visible via `ipconfig`. The ISP IP on whatismyip.com is public (router's). NAT maps between them.
- **Why can't others open `192.168.1.5` from Internet?** Private IPs aren't routed on Internet. To expose a server you need port-forwarding or a public IP + firewall rule.
- **TCP or UDP for gaming/calls?** UDP — a lost frame causes a tiny glitch, but waiting for resend would freeze the game. TCP for downloads/web where every byte must be perfect.
- **Why is Wi-Fi slow in crowds?** Shared air + CSMA/CA waiting + interference. Fewer users per AP, use 5 GHz, place AP high and central.
- **What to ping first when Internet dies?** 1. `ping 127.0.0.1` (your card?) → 2. `ping 192.168.1.1` (router?) → 3. `ping 8.8.8.8` (Internet?) → 4. `ping google.com` (DNS?). Where it stops = faulty zone.

## Memory anchors

- **Postal model:** IP = building address, Port = flat number, Router = sorting office, Protocol = postal rules.
- **Sizes:** PAN (you) → LAN (room) → MAN (city) → WAN (world).
- **Internet/Intranet/Extranet:** everyone / employees only / employees + partners.
- **Star wins:** most LANs are Star — one cable fails, rest survive.
- **TCP vs UDP:** TCP calls back to confirm (web/files), UDP shouts and runs (live video/DNS).
- **Star ports:** 80 HTTP, 443 HTTPS, 53 DNS, 22 SSH, 25/587 SMTP, 143/993 IMAP, 67/68 DHCP.
- **Private IPs:** `10.x`, `172.16-31.x`, `192.168.x` — home is almost always `192.168.1.x`.
- **CIDR math:** usable = `2^(32-CIDR) - 2`. /24 = 254 hosts.
- **Layers:** Application (what) → Transport (reliable?) → Internet (where?) → Link (how?).
- **Devices:** Hub shouts, Switch whispers, Router forwards between networks.
