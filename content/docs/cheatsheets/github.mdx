## GitHub CLI (`gh`) Command Reference

The official `gh` command-line tool connects your terminal directly to GitHub features.

```bash
# Installation
# macOS: brew install gh
# Windows: winget install --id GitHub.cli
# Linux: sudo apt install gh
```

### 1. Authentication & Configuration

```bash
gh auth login            # Interactive login (web browser or token)
gh auth status           # Verify logged in account and active scopes
gh auth refresh -s write:packages # Request additional OAuth scopes
gh config set editor "code --wait" # Set default editor
```

### 2. Repositories (`gh repo`)

```bash
gh repo clone owner/repo          # Clone remote repository
gh repo create my-project --public --source=. --push # Initialize & push new repo
gh repo fork owner/repo --clone   # Fork repo and clone locally
gh repo view --web                # Open current repository in default browser
gh repo sync owner/repo           # Sync local fork with upstream parent
```

### 3. Pull Requests (`gh pr`)

```bash
# Create a pull request interactively
gh pr create --title "feat: oauth login" --body "Resolves #42"

# Create PR targeting specific base branch
gh pr create --base main --head feature/oauth

# List open PRs
gh pr list --state open --limit 10

# Checkout a teammate's PR locally for testing
gh pr checkout 128

# View changes and diff
gh pr diff 128

# Review and approve PR
gh pr review 128 --approve -b "LGTM! Verified locally."
gh pr review 128 --request-changes -b "Please add error boundary."

# Merge PR and delete local/remote feature branch
gh pr merge 128 --squash --delete-branch --auto
```

### 4. Issues (`gh issue`)

```bash
gh issue create --title "Bug: session timeout" --label "bug,priority:high"
gh issue list --assignee "@me"
gh issue view 42 --web
gh issue close 42 --comment "Resolved in commit abc1234"
```

### 5. Managing GitHub Actions via CLI (`gh run` & `gh workflow`)

```bash
gh run list --limit 5             # View recent workflow runs
gh run watch                      # Live-stream progress of active workflow run
gh run view --log-failed          # Inspect failure logs directly in terminal
gh run rerun <run-id> --failed    # Rerun only failed jobs

# Trigger manual workflow dispatch from CLI
gh workflow run deploy.yml -f environment=staging -f debug_mode=true
```

## GitHub Actions: Workflow Architecture

Workflows reside in `.github/workflows/*.yml` and automate building, testing, and deploying.

```text
Event Trigger (push / PR / schedule)
      ↓
Workflow (.github/workflows/ci.yml)
      ↓
Jobs (run in parallel by default on fresh virtual machines)
├── Job 1: Lint & Typecheck (ubuntu-latest)
│     ├── Step 1: actions/checkout@v4
│     ├── Step 2: actions/setup-node@v4
│     └── Step 3: run: npm run lint
└── Job 2: Test Suite (runs after Job 1 if 'needs: [lint]')
      └── Matrix: Node [18, 20, 22]
```

## Complete Workflow Syntax Reference

```yaml
name: CI & Deployment Pipeline

# 1. Triggers
on:
  push:
    branches: [main]
    paths-ignore:
      - "**.md"
      - "docs/**"
  pull_request:
    branches: [main]
    types: [opened, synchronize, reopened]
  schedule:
    - cron: "0 2 * * *" # Daily at 02:00 UTC
  workflow_dispatch: # Manual trigger with UI inputs
    inputs:
      environment:
        description: "Target environment"
        required: true
        default: "staging"
        type: choice
        options: [staging, production]
      run_integration_tests:
        description: "Execute end-to-end integration suite"
        type: boolean
        default: false

# 2. Principle of Least Privilege Permissions
permissions:
  contents: read # Read repository source code
  issues: write # Can label/comment on issues
  pull-requests: write# Can post PR review comments
  id-token: write # Required for OIDC AWS/GCP/Azure keyless authentication

# 3. Global Environment Variables
env:
  NODE_ENV: production
  CI: true

jobs:
  # Job 1: Test & Build with Matrix
  test:
    runs-on: ${{ matrix.os }}
    strategy:
      fail-fast: false # Continue other matrix jobs even if one fails
      matrix:
        os: [ubuntu-latest]
        node-version: [18.x, 20.x, 22.x]
        include:
          - os: ubuntu-latest
            node-version: 22.x
            is_canary: true

    steps:
      - name: Checkout Code
        uses: actions/checkout@v4
        with:
          fetch-depth: 0 # Full git history for changelogs/analysis

      - name: Setup Node.js ${{ matrix.node-version }}
        uses: actions/setup-node@v4
        with:
          node-version: ${{ matrix.node-version }}
          cache: "npm" # Automatic dependency caching

      - name: Install Dependencies
        run: npm ci

      - name: Run Test Suite
        run: npm test

      - name: Build Application
        run: npm run build

      - name: Upload Build Artifacts
        if: matrix.node-version == '20.x'
        uses: actions/upload-artifact@v4
        with:
          name: production-build
          path: dist/
          retention-days: 7

  # Job 2: Deploy (runs only on push to main after test job passes)
  deploy:
    needs: [test]
    if: github.event_name == 'push' && github.ref == 'refs/heads/main'
    runs-on: ubuntu-latest
    environment:
      name: production
      url: https://my-app.com

    steps:
      - name: Download Build Artifact
        uses: actions/download-artifact@v4
        with:
          name: production-build
          path: dist/

      - name: Deploy to Cloud Provider
        env:
          DEPLOY_TOKEN: ${{ secrets.PROD_DEPLOY_TOKEN }}
        run: |
          echo "Deploying dist/ to production servers..."
          # Pass secrets securely via env, never plain CLI arguments
```

## Dynamic Variables & Step Outputs

Communicate between steps and set runtime environment variables:

```yaml
steps:
  - name: Generate Dynamic Version
    id: versioning
    run: |
      # 1. Export environment variable to subsequent steps
      echo "RELEASE_TAG=v$(date +'%Y.%m.%d')" >> $GITHUB_ENV

      # 2. Set step output for conditional steps
      echo "sha_short=$(git rev-parse --short HEAD)" >> $GITHUB_OUTPUT

      # 3. Write rich Markdown to GitHub Actions Job Summary page
      echo "### Build Summary :rocket:" >> $GITHUB_STEP_SUMMARY
      echo "- Commit: \`$(git rev-parse --short HEAD)\`" >> $GITHUB_STEP_SUMMARY
      echo "- Built on: $(date)" >> $GITHUB_STEP_SUMMARY

  - name: Consume Outputs
    run: |
      echo "Release Tag: $RELEASE_TAG"
      echo "Short SHA: ${{ steps.versioning.outputs.sha_short }}"
```

## Built-in Contexts & Conditions

| Context                | Content                                            | Example                       |
| ---------------------- | -------------------------------------------------- | ----------------------------- |
| `github.actor`         | Username of user who triggered the event.          | `echo ${{ github.actor }}`    |
| `github.sha`           | Full commit SHA.                                   | `${{ github.sha }}`           |
| `github.ref`           | Branch or tag ref.                                 | `'refs/heads/main'`           |
| `github.event_name`    | Name of event triggering workflow.                 | `'push'`, `'pull_request'`    |
| `secrets.GITHUB_TOKEN` | Auto-generated short-lived token for current repo. | `${{ secrets.GITHUB_TOKEN }}` |

### Status Check Functions

- `if: success()`: Executes only if all previous steps succeeded (default).
- `if: failure()`: Executes only if any previous step failed (used for alerting).
- `if: always()`: Always executes regardless of previous step failures (used for teardown/logs).
- `if: cancelled()`: Executes if workflow was manually cancelled.

## Secrets & Environments

1. **Repository Secrets:** Configured in `Settings > Secrets and variables > Actions`. Never checked into git.
2. **Environment Protection Rules:** Set required reviewers, delay timers, and branch restrictions for sensitive environments (e.g., `production`).
3. **OpenID Connect (OIDC):** Connect directly to AWS IAM, Google Cloud, or Azure without storing permanent long-lived secret keys in GitHub:

```yaml
permissions:
  id-token: write
  contents: read

steps:
  - name: Authenticate to AWS via OIDC
    uses: aws-actions/configure-aws-credentials@v4
    with:
      role-to-assume: arn:aws:iam::123456789012:role/GitHubActionsRole
      aws-region: us-east-1
```

## Dependabot Configuration (`.github/dependabot.yml`)

Automatically keep npm, docker, and pip packages updated:

```yaml
version: 2
updates:
  - package-ecosystem: "npm"
    directory: "/"
    schedule:
      interval: "weekly"
    open-pull-requests-limit: 10
    groups:
      dependencies:
        patterns:
          - "*"

  - package-ecosystem: "github-actions"
    directory: "/"
    schedule:
      interval: "monthly"
```

## Anti-patterns vs Best practices

| Anti-pattern                            | Why it harms                                                         | Best practice                                                                   |
| --------------------------------------- | -------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| Granting `permissions: write-all`       | Breached workflows can compromise repository and packages.           | Follow Principle of Least Privilege: set `permissions` explicitly per job.      |
| Hardcoding long-lived cloud secret keys | Exposed to credential stuffing if leaks occur.                       | Use OpenID Connect (OIDC) roles (`id-token: write`).                            |
| Printing secrets via `echo $SECRET`     | Can expose credentials in plain text in CI logs.                     | GitHub automatically masks secrets, but pass secrets via `env:` to avoid leaks. |
| Missing `timeout-minutes` on jobs       | Hanging tests or frozen servers burn through monthly billing quotas. | Always specify `timeout-minutes: 15` on jobs.                                   |
| Manually merging PRs on main branch     | Breaks git linear history and bypasses status checks.                | Enforce Branch Protection Rules with required status checks and squash-merge.   |

## Memory anchors

- **Official URLs:** [github.com](https://github.com) and [docs.github.com](https://docs.github.com).
- **`gh pr checkout 42`:** Test pull requests locally in one second without manual refspec fetching.
- **Workflow location:** `.github/workflows/*.yml`.
- **Workflow Triggers:** `on: [push, pull_request, workflow_dispatch, schedule]`.
- **`fail-fast: false` in Matrix:** Keeps all OS and node version builds running even if one fails.
- **Least-Privilege Security:** Start workflows with `permissions: {}` and grant only needed scopes (`contents: read`).
- **OIDC over static keys:** Authenticate to AWS/GCP directly using GitHub's signed OIDC identity token.
- **Dynamic environment variables:** Export to next steps with `echo "KEY=VAL" >> $GITHUB_ENV`.
