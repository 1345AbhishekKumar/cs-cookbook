Zod is a TypeScript-first schema declaration and validation library. You declare a schema once, and Zod automatically infers static TypeScript types while validating, coercing, and sanitizing untrusted inputs at runtime.

- **Official Documentation:** [https://zod.dev](https://zod.dev)
- **GitHub Repository:** [https://github.com/colinhacks/zod](https://github.com/colinhacks/zod)
- **Comprehensive Masterclass:** [Input Validation & Schema Architecture with Zod](/docs/full-stack-development/api-design/02-input-validation-zod)
- **Environment Validation Guide:** [Environment Variable Validation with @t3-oss/env-core & Zod](/docs/full-stack-development/api-design/03-environment-configuration)

Use this page as a quick reference: type tables, validator methods, and copy-paste snippets. For architectural deep dives and production patterns, explore the [full Zod lesson](/docs/full-stack-development/api-design/02-input-validation-zod).

## Setup & First Schema

```bash
npm install zod
```

```ts
import { z } from "zod";

// 1. Declare schema
export const UserSchema = z.object({
  id: z.string().uuid(),
  username: z.string().min(3).max(20),
  email: z.string().email(),
  age: z.number().int().min(18).optional(),
});

// 2. Infer static TypeScript type automatically
export type User = z.infer<typeof UserSchema>;

// 3. Validate data safely
const result = UserSchema.safeParse(incomingData);

if (result.success) {
  console.log("Validated user:", result.data.username);
} else {
  console.error("Validation errors:", result.error.flatten().fieldErrors);
}
```

## Primitives & Coercion

| Type | Zod Method | Coerced Equivalent | Examples / Notes |
| --- | --- | --- | --- |
| `string` | `z.string()` | `z.coerce.string()` | Text data. |
| `number` | `z.number()` | `z.coerce.number()` | Float or int. `"42"` → `42`. |
| `boolean` | `z.boolean()` | `z.coerce.boolean()` | True/false. `"true"` / `1` → `true`. |
| `bigint` | `z.bigint()` | `z.coerce.bigint()` | Large integers (`10n`). |
| `date` | `z.date()` | `z.coerce.date()` | `Date` instance. `"2026-01-01"` → `Date`. |
| `literal` | `z.literal("admin")` | — | Exact single value match. |
| `undefined`| `z.undefined()` | — | Exact `undefined`. |
| `null` | `z.null()` | — | Exact `null`. |
| `any` | `z.any()` | — | Disables typecheck. Avoid when possible. |
| `unknown` | `z.unknown()` | — | Safe top type. Requires refinement. |
| `never` | `z.never()` | — | Bottom type. Disallows values. |
| `void` | `z.void()` | — | Matches `undefined` return. |

> **Coercion Tip:** `z.coerce.number()` and `z.coerce.date()` are essential when parsing `FormData`, URL search query strings, or environment variables where all incoming values start as raw strings.

## Validation Modifiers & Constraints

### String Constraints

```ts
z.string()
  .min(5, "Must be at least 5 chars")
  .max(100)
  .length(10)               // Exact length
  .email("Invalid email")
  .url("Invalid URL")
  .uuid("Must be a UUID")
  .cuid()
  .cuid2()
  .ulid()
  .regex(/^[a-z]+$/, "Only lowercase letters")
  .startsWith("https://")
  .endsWith(".png")
  .datetime()               // ISO 8601 string
  .ip({ version: "v4" })
  .trim()                   // Trims whitespace on parse
  .toLowerCase()            // Converts to lowercase
  .toUpperCase();
```

### Number Constraints

```ts
z.number()
  .gt(0)                    // Greater than
  .gte(0)                   // min(0)
  .lt(100)                  // Less than
  .lte(100)                 // max(100)
  .int("Must be an integer")
  .positive("Must be > 0")
  .nonnegative("Must be >= 0")
  .negative("Must be < 0")
  .nonpositive("Must be <= 0")
  .multipleOf(5)            // Divisible by 5
  .finite()
  .safe();                  // Number.MIN_SAFE_INTEGER to Number.MAX_SAFE_INTEGER
```

### Optionality & Nullability

```ts
const s = z.string();

s.optional();  // string | undefined
s.nullable();  // string | null
s.nullish();   // string | null | undefined
s.default("fallback"); // string (falls back if undefined)
```

## Objects & Composition

```ts
const BaseUser = z.object({
  id: z.string(),
  name: z.string(),
  email: z.string().email(),
  role: z.enum(["user", "admin"]),
});

// Extend: add new properties
const StaffUser = BaseUser.extend({
  department: z.string(),
});

// Merge: combine two object schemas
const Combined = BaseUser.merge(z.object({ token: z.string() }));

// Pick: keep specific keys
const UserCredentials = BaseUser.pick({ email: true });

// Omit: strip specific keys
const PublicProfile = BaseUser.omit({ id: true });

// Partial: make every property optional
const UserPatch = BaseUser.partial(); // { id?: string; name?: string; ... }

// Deep Partial
const DeepConfig = z.object({ server: z.object({ port: z.number() }) }).deepPartial();

// Required: make all properties required
const FullUser = UserPatch.required();
```

### Unknown Keys Handling

By default, Zod **strips** unrecognized keys from objects during `parse()`.

| Method | Behavior on Unexpected Keys |
| --- | --- |
| `z.object({...})` (default) | Strips unknown keys silently. |
| `schema.passthrough()` | Retains unknown keys in the output object. |
| `schema.strict()` | Fails validation with an error if unknown keys exist. |

## Arrays, Tuples, Records & Sets

```ts
// Array
const Tags = z.array(z.string()).min(1).max(5);
const NonEmptyTags = z.string().array().nonempty("At least 1 tag required");

// Tuple (fixed length and ordered types)
const Coordinate = z.tuple([z.number(), z.number()]);
const VariadicTuple = z.tuple([z.string()]).rest(z.number()); // [string, ...number[]]

// Record (dynamic key-value map)
const Translations = z.record(z.string(), z.string()); // Record<string, string>
const Scores = z.record(z.enum(["math", "science"]), z.number());

// Set
const UniqueIds = z.set(z.number()).min(1);

// Map
const UserMap = z.map(z.string(), UserSchema);
```

## Unions, Enums & Discriminated Unions

### Enums

```ts
// Zod Enum (creates array & literal union)
const StatusEnum = z.enum(["Draft", "Published", "Archived"]);
type Status = z.infer<typeof StatusEnum>; // "Draft" | "Published" | "Archived"
StatusEnum.enum.Draft; // "Draft"

// Native TypeScript Enum
enum Role {
  Admin = "ADMIN",
  User = "USER",
}
const RoleSchema = z.nativeEnum(Role);
```

### Discriminated Unions (High Performance)

Always prefer `z.discriminatedUnion` over `z.union` for object variants sharing a common tag key:

```ts
const ActionSchema = z.discriminatedUnion("type", [
  z.object({
    type: z.literal("create"),
    payload: z.object({ title: string }),
  }),
  z.object({
    type: z.literal("delete"),
    targetId: z.string().uuid(),
  }),
  z.object({
    type: z.literal("ping"),
  }),
]);

type Action = z.infer<typeof ActionSchema>;
```

## Refinements & Custom Validation

Use `.refine()` for custom predicates, or `.superRefine()` for multiple error paths.

### Cross-Field Validation (`.refine`)

```ts
const PasswordResetSchema = z
  .object({
    password: z.string().min(8),
    confirmPassword: z.string(),
  })
  .refine((data) => data.password === data.confirmPassword, {
    message: "Passwords do not match",
    path: ["confirmPassword"], // Attaches error directly to the confirmPassword field
  });
```

### Granular Issues (`.superRefine`)

```ts
const FormSchema = z.object({ code: z.string() }).superRefine((val, ctx) => {
  if (val.code.length < 4) {
    ctx.addIssue({
      code: z.ZodIssueCode.too_small,
      minimum: 4,
      type: "string",
      inclusive: true,
      message: "Code is too short",
    });
  }
  if (!val.code.startsWith("CS_")) {
    ctx.addIssue({
      code: z.ZodIssueCode.custom,
      message: "Code must begin with 'CS_'",
      path: ["code"],
    });
  }
});
```

## Transformations & Pipelines

Transform input data or chain multi-step parse pipelines.

```ts
// 1. Transform: modify data after validation
const TrimmedString = z.string().transform((val) => val.trim());
const StringToNumber = z.string().transform((val) => parseInt(val, 10));

// 2. Preprocess: run function BEFORE schema validation
const NumericString = z.preprocess((val) => Number(val), z.number().int());

// 3. Pipeline: chain validation -> transformation -> secondary validation
const TimestampPipeline = z
  .string()
  .transform((val) => new Date(val))
  .pipe(z.date().min(new Date("2026-01-01")));
```

### `z.input` vs `z.output`

When a schema contains a `.transform()`, the input type differs from the output type:

```ts
const Schema = z.string().transform((val) => val.length);

type Input = z.input<typeof Schema>;   // string (what caller passes in)
type Output = z.output<typeof Schema>; // number (what parse returns)
type Inferred = z.infer<typeof Schema>; // number (alias for z.output)
```

## Parsing & Error Formatting

```ts
const schema = z.object({
  email: z.string().email(),
  count: z.number().positive(),
});

// Safe parse (does not throw)
const res = schema.safeParse({ email: "invalid", count: -1 });

if (!res.success) {
  // 1. Flattened error format (ideal for UI forms)
  const flattened = res.error.flatten();
  /*
  {
    formErrors: [],
    fieldErrors: {
      email: ['Invalid email'],
      count: ['Number must be greater than 0']
    }
  }
  */

  // 2. Hierarchical error format (ideal for nested trees)
  const formatted = res.error.format();

  // 3. Raw issues array
  console.log(res.error.issues);
}
```

## Practical Ecosystem Recipes

### Next.js Server Action Validation

```ts
"use server";

import { z } from "zod";

const FormSchema = z.object({
  title: z.string().min(1, "Title is required"),
  priority: z.coerce.number().min(1).max(5),
});

export async function createItemAction(formData: FormData) {
  const parsed = FormSchema.safeParse({
    title: formData.get("title"),
    priority: formData.get("priority"),
  });

  if (!parsed.success) {
    return { success: false, errors: parsed.error.flatten().fieldErrors };
  }

  // parsed.data is fully typed and sanitized
  await db.item.create({ data: parsed.data });
  return { success: true };
}
```

### Type-Safe Environment Variables

```ts
import { z } from "zod";

const EnvSchema = z.object({
  NODE_ENV: z.enum(["development", "test", "production"]).default("development"),
  PORT: z.coerce.number().default(3000),
  DATABASE_URL: z.string().url(),
  API_SECRET: z.string().min(16),
});

export const env = EnvSchema.parse(process.env);
```

## Anti-patterns vs Best practices

| Anti-pattern | Why it harms | Best practice |
| --- | --- | --- |
| Duplicating TypeScript `interface` and Zod schema | Type drift and desynchronization bugs. | Define Zod schema once; use `z.infer<typeof Schema>`. |
| Using `schema.parse()` in standard web handlers | Uncaught exceptions crash endpoints or unhandled promise rejections. | Always use `schema.safeParse()` and handle failure branches cleanly. |
| Using `z.union` for large variant objects | Checks every schema one by one, degrading parsing performance. | Use `z.discriminatedUnion("tagKey", [...])`. |
| Forgetting `path` in `.refine` | Root form receives error instead of specific offending input field. | Always provide `path: ["fieldName"]`. |
| Casting untrusted `JSON.parse` with `as MyType` | Zero runtime protection against malformed payloads. | Validate with `MySchema.parse(JSON.parse(raw))`. |

## Memory anchors

- **Single source of truth:** Declare schemas with Zod; derive static types with `z.infer<typeof Schema>`.
- **`safeParse` over `parse`:** `parse` throws `ZodError`; `safeParse` returns `{ success, data }` or `{ success, error }`.
- **Coercion handles strings:** Use `z.coerce.number()` or `z.coerce.date()` for URL search params, `FormData`, and `process.env`.
- **Objects strip by default:** Unrecognized keys are omitted. Use `.strict()` to reject them or `.passthrough()` to preserve them.
- **Discriminated unions win:** Always use `z.discriminatedUnion('type', [...])` instead of `z.union` when schemas share a discriminant property.
- **Path attaches errors:** In `.refine()`, specify `path: ['field']` so error messages appear beside the relevant UI input.
- **Flatten for forms:** `error.flatten().fieldErrors` maps errors directly to `Record<fieldName, string[]>`.
- **`z.input` vs `z.output`:** If using `.transform()`, `z.input` is the pre-transformation type; `z.output` is the post-transformation type.
