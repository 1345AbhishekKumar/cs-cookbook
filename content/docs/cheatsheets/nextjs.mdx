Next.js is a full-stack React framework featuring the App Router, React Server Components (RSC), streaming HTML, Server Actions, and integrated asset optimization.

- **Official Website:** [https://nextjs.org](https://nextjs.org)
- **Documentation:** [https://nextjs.org/docs](https://nextjs.org/docs)
- **GitHub Repository:** [https://github.com/vercel/next.js](https://github.com/vercel/next.js)

Use this page as a quick reference: routing conventions, async request APIs, data patterns, and copy-paste snippets for Next.js 15/16+.

## App Router Special Files

Every folder inside `app/` defines a route segment. These filename conventions are reserved:

| File | Purpose | Execution Environment |
| --- | --- | --- |
| `page.tsx` | Unique UI for the route segment; makes route publicly accessible. | Server (default) or Client (`"use client"`) |
| `layout.tsx` | Shared UI across sub-routes; preserves state on navigation. | Server (default) or Client |
| `loading.tsx` | Instant loading skeleton wrapped in `<Suspense>`. | Server |
| `error.tsx` | Error boundary for child segments; must be a Client Component. | Client (`"use client"` required) |
| `not-found.tsx` | 404 UI rendered when `notFound()` is thrown. | Server (default) |
| `route.ts` | Custom HTTP endpoint (REST API replacing `/api` pages). | Server |
| `template.tsx` | Similar to layout, but remounts and re-creates state on navigation. | Server or Client |
| `default.tsx` | Fallback view for parallel routes (`@slots`). | Server |

## Dynamic & Advanced Route Patterns

| Pattern | Folder Structure | Example URL | Param Type |
| --- | --- | --- | --- |
| **Dynamic segment** | `app/blog/[id]/page.tsx` | `/blog/123` | `{ id: "123" }` |
| **Catch-all** | `app/docs/[...slug]/page.tsx` | `/docs/a/b/c` | `{ slug: ["a", "b", "c"] }` |
| **Optional catch-all**| `app/shop/[[...slug]]/page.tsx`| `/shop` or `/shop/a` | `{ slug?: string[] }` |
| **Route group** | `app/(marketing)/about/page.tsx` | `/about` (skips url segment) | None |
| **Parallel route** | `app/@modal/(.)login/page.tsx` | Slot mounted in parent layout | Intercepted slot |

## Breaking in v15/v16: Async Request APIs

Starting in Next.js 15, request-specific data (`params`, `searchParams`, `cookies()`, `headers()`) are **asynchronous Promises** to enable partial pre-rendering (PPR).

```tsx
// app/blog/[id]/page.tsx (Server Component)

interface PageProps {
  params: Promise<{ id: string }>;
  searchParams: Promise<{ query?: string }>;
}

export default async function BlogPostPage({ params, searchParams }: PageProps) {
  // MUST await params and searchParams in Next.js 15/16+
  const { id } = await params;
  const { query } = await searchParams;

  return (
    <div>
      <h1>Post ID: {id}</h1>
      <p>Search Query: {query ?? "none"}</p>
    </div>
  );
}
```

### Unwrapping Params in Client Components

In `"use client"` components, use React 19's `use()` hook to unwrap params:

```tsx
"use client";

import { use } from "react";

export default function ClientPage({ params }: { params: Promise<{ id: string }> }) {
  const { id } = use(params);
  return <div>Client Post ID: {id}</div>;
}
```

### Async Cookies & Headers

```tsx
import { cookies, headers } from "next/headers";

export async function ProfileWidget() {
  // Await the function call
  const cookieStore = await cookies();
  const token = cookieStore.get("auth-token")?.value;

  const headerList = await headers();
  const userAgent = headerList.get("user-agent");

  return <div>Authenticated: {token ? "Yes" : "No"}</div>;
}
```

## Server Components vs Client Components

| Feature | Server Component (Default) | Client Component (`"use client"`) |
| --- | --- | --- |
| Access database / backend secrets | ✅ Direct access (`fs`, DB, `process.env.SECRET`) | ❌ Cannot access private secrets |
| Bundle size impact | ✅ 0 KB JavaScript sent to browser | ⚠️ Ships JavaScript to browser |
| Event handlers (`onClick`, `onChange`) | ❌ Not supported | ✅ Supported |
| React hooks (`useState`, `useEffect`) | ❌ Not supported | ✅ Supported |
| Browser APIs (`window`, `localStorage`) | ❌ Not supported | ✅ Supported |

### Interleaving Pattern: Passing Server to Client

Pass Server Components into Client Components as `children` to keep them running on the server:

```tsx
// components/ClientModal.tsx
"use client";

export function ClientModal({ children }: { children: React.ReactNode }) {
  const [open, setOpen] = useState(false);
  return <div>{open && children}</div>;
}

// app/page.tsx (Server Component)
export default function Page() {
  return (
    <ClientModal>
      {/* ServerPost remains rendered on the server! */}
      <ServerPostDetails />
    </ClientModal>
  );
}
```

## Data Fetching & Caching

> **Default in v15+:** `fetch` requests are **un-cached** (`no-store`) by default.

```tsx
// 1. Un-cached dynamic fetch (default in Next.js 15+)
const res = await fetch("https://api.example.com/data");

// 2. Opt-in cached fetch (static)
const cached = await fetch("https://api.example.com/data", {
  cache: "force-cache",
});

// 3. Time-based revalidation (ISR)
const isr = await fetch("https://api.example.com/data", {
  next: { revalidate: 3600 }, // revalidate every 1 hour
});

// 4. On-demand cache tag
const tagged = await fetch("https://api.example.com/data", {
  next: { tags: ["products"] },
});
```

### Cache Invalidation

```ts
"use server";

import { revalidatePath, revalidateTag } from "next/cache";

export async function updateProductAction() {
  // Invalidate specific URL path
  revalidatePath("/products");

  // Invalidate all fetches tagged with 'products'
  revalidateTag("products");
}
```

## Server Actions (`"use server"`)

Server Actions are asynchronous functions that run securely on the server and can be invoked directly from Client Components and HTML forms.

```tsx
// app/actions.ts
"use server";

import { revalidatePath } from "next/cache";
import { redirect } from "next/navigation";

export async function createPost(previousState: any, formData: FormData) {
  const title = formData.get("title") as string;

  if (!title) {
    return { error: "Title is required" };
  }

  await db.post.create({ data: { title } });

  revalidatePath("/blog");
  redirect("/blog");
}
```

Component consumption with React 19 `useActionState`:

```tsx
"use client";

import { useActionState } from "react";
import { createPost } from "./actions";

export function PostForm() {
  const [state, formAction, isPending] = useActionState(createPost, null);

  return (
    <form action={formAction}>
      <input name="title" placeholder="Post title" />
      <button disabled={isPending}>{isPending ? "Publishing..." : "Publish"}</button>
      {state?.error && <p className="error">{state.error}</p>}
    </form>
  );
}
```

## Route Handlers (`route.ts`)

Export standard HTTP method functions (`GET`, `POST`, `PUT`, `PATCH`, `DELETE`):

```ts
// app/api/users/[id]/route.ts
import { NextResponse } from "next/server";

interface RouteContext {
  params: Promise<{ id: string }>;
}

export async function GET(request: Request, { params }: RouteContext) {
  const { id } = await params; // Await params in Next.js 15+

  return NextResponse.json({ id, name: "Alice" });
}

export async function POST(request: Request) {
  const body = await request.json();

  if (!body.title) {
    return NextResponse.json({ error: "Missing title" }, { status: 400 });
  }

  return NextResponse.json({ success: true }, { status: 201 });
}
```

## Navigation & Redirects

| API | Environment | Purpose |
| --- | --- | --- |
| `<Link href="/dashboard">` | Client / Server | Declarative client-side navigation with auto prefetching. |
| `useRouter().push('/path')` | Client only | Programmatic navigation within event handlers. |
| `redirect('/login')` | Server | Interrupts render/action and issues an HTTP redirect. |
| `notFound()` | Server | Immediately throws and renders nearest `not-found.tsx`. |

## Anti-patterns vs Best practices

| Anti-pattern | Why it harms | Best practice |
| --- | --- | --- |
| Adding `"use client"` at page level | Converts entire sub-tree to client JS bundle. | Keep page as Server Component; push `"use client"` down to interactive leaves. |
| Synchronous `params.id` in Next.js 15+ | Runtime deprecation error or build failure. | Always `await params` or use `use(params)` in client components. |
| Synchronous `cookies().get()` | Runtime error in modern App Router. | Always `await cookies()`. |
| Exposing secrets in Client Components | Client JS bundles are publicly inspectable. | Query sensitive databases in Server Components or Server Actions only. |
| Plain `<a>` tags for internal links | Triggers full browser page reload, wiping client cache. | Use `<Link href="...">` from `next/link`. |

## Memory anchors

- **Default is Server Component:** You only need `"use client"` when using browser events, state, or hooks.
- **Async request params (v15+):** `params` and `searchParams` props are Promises; always `await` them.
- **Async request headers (v15+):** `await cookies()` and `await headers()`.
- **`fetch` is uncached by default:** Add `{ cache: 'force-cache' }` or `{ next: { revalidate: 60 } }` to enable caching.
- **Error boundaries need `"use client"`:** `error.tsx` must always have `"use client"` at the top.
- **Server Actions for mutations:** Use `"use server"` functions directly with forms; pair with `revalidatePath` and `revalidateTag`.
- **`next/image` requires width + height:** Prevents Cumulative Layout Shift (CLS) automatically.
