## The Iterative DAG Topological Order

**Bottom-Up Tabulation** turns recursion inside out. Instead of starting at the target problem and asking "what subproblems do I need?", tabulation identifies the **base cases** and iteratively fills an array or matrix following the **topological order of the subproblem DAG**.

```mermaid
flowchart LR
    Base["Base Cases: dp[0], dp[1]"] --> Step1["dp[2] = dp[1] + dp[0]"]
    Step1 --> Step2["dp[3] = dp[2] + dp[1]"]
    Step2 --> Target["dp[N] = Target Solution"]
```

## Tabulation vs. Memoization Engineering Showdown

| Dimension               | Top-Down (Memoization)                  | Bottom-Up (Tabulation)                                  |
| :---------------------- | :-------------------------------------- | :------------------------------------------------------ |
| **Execution Flow**      | Target $\to$ Base cases (Demand-driven) | Base cases $\to$ Target (Supply-driven)                 |
| **Call Stack Memory**   | $\mathcal{O}(\text{depth})$ frames      | **$\mathcal{O}(1)$ stack** (iterative loops)            |
| **Cache Locality**      | Random access across memo hash buckets  | **Sequential array scans** (L1/L2 hardware prefetching) |
| **Subproblem Coverage** | Only visits reachable subproblems       | Systematically computes all subproblems in table        |
| **Space Optimization**  | Difficult to reduce space               | Easily compressed via rolling variables/arrays          |

```python
def fib_tabulation(n: int) -> int:
    """Bottom-up tabulation for Fibonacci sequence."""
    if n <= 1:
        return n
        
    dp = [0] * (n + 1)
    dp[0] = 0
    dp[1] = 1

    for i in range(2, n + 1):
        dp[i] = dp[i - 1] + dp[i - 2]

    return dp[n]

````

```typescript
export function fibTabulation(n: number): number {
  if (n <= 1) return n;

  const dp: number[] = new Array(n + 1).fill(0);
  dp[0] = 0;
  dp[1] = 1;

  for (let i = 2; i <= n; i++) {
    dp[i] = dp[i - 1] + dp[i - 2];
  }

  return dp[n];
}
````
