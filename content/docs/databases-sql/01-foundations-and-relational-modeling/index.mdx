Welcome to **Stage 1: Foundations & Relational Modeling** — the mental model everything else is built on.

Before you can shard a cluster or tune an index, you must be able to answer a deceptively simple question: *what is a row, really?* This stage builds that foundation from first principles: why a naive file-backed store collapses under concurrency, what a relational database actually promises, how to model a domain as relations, and how to express precise questions in SQL.

---

## Pedagogical Philosophy

<Callout type="info" title="Model First, Optimize Second">
A surprising share of production database pain is not a performance problem — it is a **modeling** problem. A redundant column that drifts out of sync, a `NULL` that silently changes a `NOT IN` into zero rows, a many-to-many relationship crammed into a comma-separated string. Get the model right and the optimizer has something good to work with; get it wrong and no amount of index tuning will save you.
</Callout>

By the end of this stage you will be able to:

- Explain, in terms of failure modes, **why databases exist** instead of files.
- Distinguish the relational model's theory (relations, keys, domains) from SQL's syntax.
- Reason correctly about `NULL` using **three-valued logic**.
- Read and write joins, aggregation, subqueries, CTEs, and window functions with intent — not cargo-culting.
