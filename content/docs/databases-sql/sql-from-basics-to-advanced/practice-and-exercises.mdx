Reading SQL is not learning SQL. This page gives you a **complete, self-contained practice database** and **graded drills** that exercise every lesson in the track. Copy the seed script, then work through the drills with a real `psql` prompt.

<Callout type="info" title="How the Drills Are Graded">
Each drill is tagged by the kind of thinking it requires:

| | Level | What it tests |
| :--- | :--- | :--- |
| ⭐ | Warm-up | Recall single clauses — `SELECT`, `WHERE`, `ORDER BY` |
| ⭐⭐ | Applied | Combine clauses — joins, grouping, writes |
| ⭐⭐⭐ | Analytical | Window functions, multi-step CTEs, patterns |
| ⭐⭐⭐⭐ | Challenge | Synthesis — edge cases, dense reports, set logic |

Solutions are hidden behind a **Reveal solution** toggle so you attempt the query before checking. Most drills have **more than one correct answer** — matching row counts matter more than matching text.
</Callout>

## Part 0 — Seed the Dataset

Run this once against a fresh database. It creates the TravelBuddy practice schema, loads deterministic data, and resets the identity sequences so later `INSERT`s work.

<Callout type="tip" title="About the Keys">
For readability this dataset uses **integer surrogate keys** (`GENERATED BY DEFAULT AS IDENTITY`) rather than UUIDs. The lesson schemas use `uuidv7()` for realism; **the SQL you write is identical** — only the column type differs. Assigning explicit ids here is what lets the drills reference specific rows.
</Callout>

```sql
-- ============================================================
-- TravelBuddy practice dataset
-- ============================================================

DROP TABLE IF EXISTS
    booking_items, bookings, flight_seats, flights,
    page_events, events, articles, customers, airlines, airports
CASCADE;

    id      integer PRIMARY KEY,
    name    text NOT NULL,
    country text NOT NULL
);

CREATE TABLE airports (
    code    text PRIMARY KEY,
    city    text NOT NULL,
    country text NOT NULL
);

CREATE TABLE customers (
    id         integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    email      text NOT NULL UNIQUE,
    full_name  text NOT NULL,
    phone      text,
    created_at timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE flights (
    id               integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    flight_no        text NOT NULL,
    airline_id       integer NOT NULL REFERENCES airlines(id),
    origin           text NOT NULL REFERENCES airports(code),
    destination      text NOT NULL REFERENCES airports(code),
    departure_at     timestamptz NOT NULL,
    seats_available  integer NOT NULL CHECK (seats_available >= 0),
    base_price_cents bigint NOT NULL,
    tags             text[] NOT NULL DEFAULT '{}',
    UNIQUE (flight_no, departure_at)
);

CREATE TABLE bookings (
    id          integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    customer_id integer NOT NULL REFERENCES customers(id),
    status      text NOT NULL CHECK (status IN ('pending','paid','cancelled')),
    total_cents bigint NOT NULL CHECK (total_cents >= 0),
    version     integer NOT NULL DEFAULT 0,
    created_at  timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE booking_items (
    id          integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    booking_id  integer NOT NULL REFERENCES bookings(id) ON DELETE CASCADE,
    flight_id   integer NOT NULL REFERENCES flights(id),
    price_cents bigint NOT NULL
);

CREATE TABLE flight_seats (
    flight_id integer NOT NULL REFERENCES flights(id) ON DELETE CASCADE,
    seat_no   text NOT NULL,
    status    text NOT NULL CHECK (status IN ('free','held','booked')),
    PRIMARY KEY (flight_id, seat_no)
);

CREATE TABLE page_events (
    id          integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    customer_id integer NOT NULL REFERENCES customers(id),
    event       text NOT NULL,
    occurred_at timestamptz NOT NULL
);

CREATE TABLE events (
    id      integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    payload jsonb NOT NULL
);

CREATE TABLE articles (
    id    integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    title text NOT NULL,
    body  text NOT NULL
);
```

## Part 1 — Warm-Up ⭐

### 1. Distinct origins

List every distinct airport that appears as a flight **origin**, alphabetically.

<details>
<summary>Reveal solution</summary>

```sql
SELECT DISTINCT origin FROM flights ORDER BY origin;
```

</details>

### 2. The five cheapest flights

Show `flight_no`, `origin`, `destination`, and `base_price_cents` for the 5 cheapest flights.

<details>
<summary>Reveal solution</summary>

```sql
SELECT flight_no, origin, destination, base_price_cents
FROM flights
ORDER BY base_price_cents ASC
LIMIT 5;
```

</details>

### 3. Customers with no phone

Full name and email of customers who have no phone number on file.

<details>
<summary>Reveal solution</summary>

```sql
SELECT full_name, email FROM customers WHERE phone IS NULL;
```

</details>

### 4. Availability labels

Label each flight `'sold out'` (0 seats), `'low'` (fewer than 20), or `'ok'`, and sort by seats ascending.

<details>
<summary>Reveal solution</summary>

```sql
SELECT flight_no, seats_available,
       CASE WHEN seats_available = 0  THEN 'sold out'
            WHEN seats_available < 20 THEN 'low'
            ELSE 'ok'
       END AS availability
FROM flights
ORDER BY seats_available ASC;
```

</details>

### 5. June 2026 departures

All flights departing in June 2026, earliest first, using a half-open range.

<details>
<summary>Reveal solution</summary>

```sql
SELECT flight_no, departure_at
FROM flights
WHERE departure_at >= '2026-06-01' AND departure_at < '2026-07-01'
ORDER BY departure_at;
```

</details>

### 6. Example-domain customers

Customers whose email is on the `example.com` domain only.

<details>
<summary>Reveal solution</summary>

```sql
SELECT email FROM customers WHERE email LIKE '%@example.com';
```

</details>

### 7. Uppercased names and signup dates

For each customer: the full name in uppercase and the date they signed up (no time).

<details>
<summary>Reveal solution</summary>

```sql
SELECT upper(full_name) AS name, created_at::date AS signup_date
FROM customers
ORDER BY signup_date;
```

</details>

### 8. Mid-availability flights, priced in dollars

Flights with 10–50 seats available (most first), showing the price as dollars to 2 decimals.

<details>
<summary>Reveal solution</summary>

```sql
SELECT flight_no, seats_available,
       round(base_price_cents / 100.0, 2) AS price_dollars
FROM flights
WHERE seats_available BETWEEN 10 AND 50
ORDER BY seats_available DESC;
```

<Callout type="info" title="Spot the trap">
`base_price_cents / 100` (both integers) would truncate. Dividing by `100.0` forces numeric division.
</Callout>

</details>

## Part 2 — Joins & Set Operations ⭐⭐

### 9. Bookings with customer names

Every booking with the customer's full name, ordered by booking id.

<details>
<summary>Reveal solution</summary>

```sql
SELECT b.id, c.full_name, b.status, b.total_cents
FROM bookings b
JOIN customers c ON c.id = b.customer_id
ORDER BY b.id;
```

</details>

### 10. Booking counts including zero

Every customer with their number of bookings — including customers with none.

<details>
<summary>Reveal solution</summary>

```sql
SELECT c.full_name, count(b.id) AS bookings
FROM customers c
LEFT JOIN bookings b ON b.customer_id = c.id
GROUP BY c.id, c.full_name
ORDER BY bookings DESC, c.full_name;
```

<Callout type="info" title="Why count(b.id), not count(*)">
With a `LEFT JOIN`, a customer with no bookings still produces one row of all-`NULL` booking columns. `count(*)` would count that row as 1; `count(b.id)` ignores the `NULL` and correctly returns 0.
</Callout>

</details>

### 11. Customers who never booked

Customers with **no** bookings at all.

<details>
<summary>Reveal solution</summary>

```sql
SELECT c.full_name
FROM customers c
WHERE NOT EXISTS (SELECT 1 FROM bookings b WHERE b.customer_id = c.id);
```

</details>

### 12. Bookings with their flights

Each booking id with the flight number, origin, and destination it contains (a booking may have several).

<details>
<summary>Reveal solution</summary>

```sql
SELECT b.id AS booking_id, f.flight_no, f.origin, f.destination
FROM bookings b
JOIN booking_items bi ON bi.booking_id = b.id
JOIN flights f ON f.id = bi.flight_id
ORDER BY b.id;
```

</details>

### 13. Origins that are never destinations

Airports that appear as an origin but **never** as a destination.

<details>
<summary>Reveal solution</summary>

```sql
SELECT origin FROM flights
EXCEPT
SELECT destination FROM flights
ORDER BY origin;
```

</details>

### 14. Same-origin, same-day flight pairs

Pairs of flights departing from the same origin on the same day — no duplicate pairs.

<details>
<summary>Reveal solution</summary>

```sql
SELECT a.flight_no AS flight_a, b.flight_no AS flight_b,
       a.origin, a.departure_at::date AS day
FROM flights a
JOIN flights b
  ON b.origin = a.origin
 AND b.departure_at::date = a.departure_at::date
 AND b.id > a.id              -- avoids (x,y) and (y,x)
ORDER BY day, a.origin;
```

</details>

### 15. Flights and destinations per airline

For each airline: its name, total flights, and count of distinct destinations served.

<details>
<summary>Reveal solution</summary>

```sql
SELECT a.name, count(*) AS flights, count(DISTINCT f.destination) AS destinations
FROM airlines a
JOIN flights f ON f.airline_id = a.id
GROUP BY a.name
ORDER BY flights DESC;
```

</details>

### 16. A combined airport list

All origins and destinations as a single de-duplicated, alphabetized list.

<details>
<summary>Reveal solution</summary>

```sql
SELECT origin AS airport FROM flights
UNION
SELECT destination FROM flights
ORDER BY airport;
```

</details>

### 17. Each customer's most recent booking

Each customer's name and the date of their latest booking (blank if none).

<details>
<summary>Reveal solution</summary>

```sql
SELECT c.full_name,
       (SELECT max(b.created_at) FROM bookings b WHERE b.customer_id = c.id) AS last_booking
FROM customers c
ORDER BY last_booking DESC NULLS LAST;
```

</details>

## Part 3 — Aggregation ⭐⭐

### 18. Bookings and revenue per status

Count and total revenue for each booking status, revenue descending.

<details>
<summary>Reveal solution</summary>

```sql
SELECT status, count(*) AS bookings, sum(total_cents) AS revenue_cents
FROM bookings
GROUP BY status
ORDER BY revenue_cents DESC;
```

</details>

### 19. High-value customers

Customers whose **paid** spend exceeds 40,000 cents, highest first.

<details>
<summary>Reveal solution</summary>

```sql
SELECT c.full_name, sum(b.total_cents) AS paid_cents
FROM bookings b
JOIN customers c ON c.id = b.customer_id
WHERE b.status = 'paid'
GROUP BY c.id, c.full_name
HAVING sum(b.total_cents) > 40000
ORDER BY paid_cents DESC;
```

</details>

### 20. Paid vs. cancelled per airline

One row per airline with paid and cancelled booking counts as separate columns.

<details>
<summary>Reveal solution</summary>

```sql
SELECT a.name,
       count(*) FILTER (WHERE b.status = 'paid')      AS paid,
       count(*) FILTER (WHERE b.status = 'cancelled') AS cancelled
FROM bookings b
JOIN booking_items bi ON bi.booking_id = b.id
JOIN flights f  ON f.id = bi.flight_id
JOIN airlines a ON a.id = f.airline_id
GROUP BY a.name
ORDER BY paid DESC;
```

</details>

### 21. Distinct customers per origin

How many distinct customers have booked a flight departing from each origin.

<details>
<summary>Reveal solution</summary>

```sql
SELECT f.origin, count(DISTINCT b.customer_id) AS customers
FROM flights f
JOIN booking_items bi ON bi.flight_id = f.id
JOIN bookings b ON b.id = bi.booking_id
GROUP BY f.origin
ORDER BY customers DESC;
```

</details>

### 22. Monthly booking statistics

Per month: count, average (rounded), minimum, and maximum booking total.

<details>
<summary>Reveal solution</summary>

```sql
SELECT date_trunc('month', created_at)::date AS month,
       count(*)            AS bookings,
       round(avg(total_cents)) AS avg_cents,
       min(total_cents)    AS min_cents,
       max(total_cents)    AS max_cents
FROM bookings
GROUP BY month
ORDER BY month;
```

</details>

### 23. Revenue by origin with a grand total

Paid revenue per origin, plus a grand-total row, using `ROLLUP`.

<details>
<summary>Reveal solution</summary>

```sql
SELECT COALESCE(f.origin, 'ALL') AS origin, sum(b.total_cents) AS revenue_cents
FROM booking_items bi
JOIN bookings b ON b.id = bi.booking_id AND b.status = 'paid'
JOIN flights  f ON f.id = bi.flight_id
GROUP BY ROLLUP (f.origin)
ORDER BY f.origin NULLS LAST;
```

</details>

### 24. Median and 95th-percentile booking value

The median and p95 of all booking totals.

<details>
<summary>Reveal solution</summary>

```sql
SELECT percentile_cont(0.5)  WITHIN GROUP (ORDER BY total_cents) AS median_cents,
       percentile_cont(0.95) WITHIN GROUP (ORDER BY total_cents) AS p95_cents
FROM bookings;
```

</details>

### 26. Atomic booking + seat decrement

In one transaction, create a paid booking for `hana@example.com` (flight 14, price `11900`) and decrement flight 14's available seats — but never below zero.

<details>
<summary>Reveal solution</summary>

```sql
BEGIN;

INSERT INTO bookings (customer_id, status, total_cents)
SELECT id, 'paid', 11900 FROM customers WHERE email = 'hana@example.com';

UPDATE flights
SET seats_available = seats_available - 1
WHERE id = 14 AND seats_available > 0;

COMMIT;
```

<Callout type="info" title="Why the guard matters">
`... AND seats_available > 0` makes the decrement safe against overselling: if the flight is full, the `UPDATE` affects 0 rows instead of going negative (the `CHECK` would abort it).
</Callout>

</details>

### 27. Idempotent seat hold

Hold seat `12A` on flight 1 — but if the seed already booked it, **do not** override the booking.

<details>
<summary>Reveal solution</summary>

```sql
INSERT INTO flight_seats (flight_id, seat_no, status)
VALUES (1, '12A', 'held')
ON CONFLICT (flight_id, seat_no) DO UPDATE
SET status = EXCLUDED.status
WHERE flight_seats.status <> 'booked';
-- 0 rows affected when the seat is already booked
```

</details>

### 28. Expire stale pending bookings

Mark all `pending` bookings older than 7 days as `cancelled`, and report how many changed.

<details>
<summary>Reveal solution</summary>

```sql
WITH expired AS (
    UPDATE bookings
    SET status = 'cancelled'
    WHERE status = 'pending' AND created_at < now() - interval '7 days'
    RETURNING id
)
SELECT count(*) AS cancelled FROM expired;
```

</details>

### 29. Optimistic payment

Pay booking 7 only if nobody else has modified it (its `version` is still 0).

<details>
<summary>Reveal solution</summary>

```sql
UPDATE bookings
SET status = 'paid', version = version + 1
WHERE id = 7 AND version = 0;
-- 0 rows affected ⇒ it changed since you read it; re-read and retry
```

</details>

## Part 5 — Window Functions ⭐⭐⭐

### 30. Rank bookings within each customer

Each booking with its rank by value *within its customer* (largest first).

<details>
<summary>Reveal solution</summary>

```sql
SELECT customer_id, id, total_cents,
       rank() OVER (PARTITION BY customer_id ORDER BY total_cents DESC) AS rnk
FROM bookings
ORDER BY customer_id, rnk;
```

</details>

### 31. Each customer's largest booking

One row per customer: their single biggest booking.

<details>
<summary>Reveal solution</summary>

```sql
WITH ranked AS (
    SELECT *, row_number() OVER (PARTITION BY customer_id ORDER BY total_cents DESC) AS rn
    FROM bookings
)
SELECT * FROM ranked WHERE rn = 1 ORDER BY customer_id;
```

</details>

### 32. Running paid revenue per customer

A running total of each customer's paid spend over time.

<details>
<summary>Reveal solution</summary>

```sql
SELECT customer_id, created_at, total_cents,
       sum(total_cents) OVER (PARTITION BY customer_id ORDER BY created_at) AS running_total
FROM bookings
WHERE status = 'paid'
ORDER BY customer_id, created_at;
```

</details>

### 33. Change from the previous booking

Each booking's value, the customer's previous booking value, and the difference.

<details>
<summary>Reveal solution</summary>

```sql
SELECT customer_id, created_at, total_cents,
       lag(total_cents) OVER (PARTITION BY customer_id ORDER BY created_at) AS prev_cents,
       total_cents - lag(total_cents) OVER (PARTITION BY customer_id ORDER BY created_at) AS delta
FROM bookings
ORDER BY customer_id, created_at;
```

</details>

### 34. Share of a customer's spend

Each booking as a percentage of that customer's total spend (1 decimal).

<details>
<summary>Reveal solution</summary>

```sql
SELECT customer_id, id, total_cents,
       round(100.0 * total_cents / sum(total_cents) OVER (PARTITION BY customer_id), 1) AS pct_of_customer
FROM bookings
ORDER BY customer_id, id;
```

</details>

### 35. Top 2 destinations per origin

The two most-booked destinations for each origin airport.

<details>
<summary>Reveal solution</summary>

```sql
WITH ranked AS (
    SELECT f.origin, f.destination, count(*) AS bookings,
           row_number() OVER (PARTITION BY f.origin ORDER BY count(*) DESC) AS rn
    FROM flights f
    JOIN booking_items bi ON bi.flight_id = f.id
    GROUP BY f.origin, f.destination
)
SELECT origin, destination, bookings
FROM ranked
WHERE rn <= 2
ORDER BY origin, bookings DESC;
```

</details>

## Part 6 — Advanced Patterns ⭐⭐⭐

### 36. Sessionize page events

Group `page_events` into sessions with a 30-minute inactivity timeout; show each session's start, end, and event count.

<details>
<summary>Reveal solution</summary>

```sql
WITH flagged AS (
    SELECT customer_id, occurred_at,
           CASE WHEN occurred_at
                     - lag(occurred_at) OVER (PARTITION BY customer_id ORDER BY occurred_at)
                     > interval '30 minutes'
                 OR lag(occurred_at) OVER (PARTITION BY customer_id ORDER BY occurred_at) IS NULL
                THEN 1 ELSE 0
           END AS new_session
    FROM page_events
),
sessioned AS (
    SELECT customer_id, occurred_at,
           sum(new_session) OVER (PARTITION BY customer_id ORDER BY occurred_at) AS session_id
    FROM flagged
)
SELECT customer_id, session_id,
       min(occurred_at) AS started,
       max(occurred_at) AS ended,
       count(*)         AS events
FROM sessioned
GROUP BY customer_id, session_id
ORDER BY customer_id, session_id;
```

</details>

### 37. Consecutive booking-day streaks

Find each customer's runs of consecutive calendar days on which they booked.

<details>
<summary>Reveal solution</summary>

```sql
WITH days AS (
    SELECT DISTINCT customer_id, created_at::date AS d FROM bookings
),
marked AS (
    SELECT customer_id, d,
           d - (row_number() OVER (PARTITION BY customer_id ORDER BY d))::int AS grp
    FROM days
)
SELECT customer_id, min(d) AS streak_start, max(d) AS streak_end, count(*) AS streak_days
FROM marked
GROUP BY customer_id, grp
ORDER BY customer_id, streak_start;
```

</details>

### 38. Deduplicate customers by email

Keep only the most recent row for each (case-insensitive) email — without deleting anything.

<details>
<summary>Reveal solution</summary>

```sql
WITH ranked AS (
    SELECT *, row_number() OVER (PARTITION BY lower(email) ORDER BY created_at DESC) AS rn
    FROM customers
)
SELECT * FROM ranked WHERE rn = 1 ORDER BY id;
```

<Callout type="info" title="PostgreSQL shortcut">
`SELECT DISTINCT ON (lower(email)) * FROM customers ORDER BY lower(email), created_at DESC;` does the same thing more tersely.
</Callout>

</details>

### 39. Pivot bookings by status

One row per customer with `paid`, `pending`, and `cancelled` counts as columns.

<details>
<summary>Reveal solution</summary>

```sql
SELECT c.full_name,
       count(*) FILTER (WHERE b.status = 'paid')      AS paid,
       count(*) FILTER (WHERE b.status = 'pending')   AS pending,
       count(*) FILTER (WHERE b.status = 'cancelled') AS cancelled
FROM customers c
LEFT JOIN bookings b ON b.customer_id = c.id
GROUP BY c.id, c.full_name
ORDER BY c.full_name;
```

</details>

### 40. Conversion funnel

From `page_events`, count customers at each ordered funnel step: view → add_cart → checkout → pay.

<details>
<summary>Reveal solution</summary>

```sql
WITH steps AS (
    SELECT customer_id,
           min(occurred_at) FILTER (WHERE event = 'view')     AS viewed,
           min(occurred_at) FILTER (WHERE event = 'add_cart') AS added,
           min(occurred_at) FILTER (WHERE event = 'checkout') AS checked_out,
           min(occurred_at) FILTER (WHERE event = 'pay')      AS paid
    FROM page_events
    GROUP BY customer_id
)
SELECT count(*) FILTER (WHERE viewed IS NOT NULL)  AS step1_view,
       count(*) FILTER (WHERE viewed < added)      AS step2_add_cart,
       count(*) FILTER (WHERE added  < checked_out) AS step3_checkout,
       count(*) FILTER (WHERE checked_out < paid)  AS step4_pay
FROM steps;
```

<Callout type="warn" title="Order, not just presence">
Comparing timestamps (`viewed < added`) enforces that each step happened *after* the previous one. Counting presence alone would credit impossible orderings.
</Callout>

</details>

### 41. Month-over-month revenue growth

Paid revenue per month with the previous month's revenue and the percentage change.

<details>
<summary>Reveal solution</summary>

```sql
WITH monthly AS (
    SELECT date_trunc('month', created_at) AS month, sum(total_cents) AS revenue
    FROM bookings WHERE status = 'paid'
    GROUP BY month
)
SELECT month::date AS month,
       revenue,
       lag(revenue) OVER (ORDER BY month) AS prev_revenue,
       round(100.0 * (revenue - lag(revenue) OVER (ORDER BY month))
             / NULLIF(lag(revenue) OVER (ORDER BY month), 0), 1) AS mom_pct
FROM monthly
ORDER BY month;
```

</details>

### 44. Array-tagged flights

Flights tagged `international`, and separately those tagged `red-eye`.

<details>
<summary>Reveal solution</summary>

```sql
-- International
SELECT flight_no, origin, destination, tags
FROM flights
WHERE tags @> ARRAY['international']
ORDER BY flight_no;

FROM flights
```

### 45. Full-text search

Find articles relevant to **"barcelona flight"**, ranked by relevance.

<details>
<summary>Reveal solution</summary>

```sql
SELECT id, title,
       ts_rank(to_tsvector('english', body), q) AS rank
FROM articles, plainto_tsquery('english', 'barcelona flight') q
WHERE to_tsvector('english', body) @@ q
ORDER BY rank DESC;
```

</details>

### 46. Build JSON per customer

One row per customer listing their bookings as a JSON array of objects.

<details>
<summary>Reveal solution</summary>

```sql
SELECT c.full_name,
       jsonb_agg(
           jsonb_build_object('status', b.status, 'total', b.total_cents)
           ORDER BY b.created_at
       ) AS bookings
FROM bookings b
JOIN customers c ON c.id = b.customer_id
GROUP BY c.id, c.full_name
ORDER BY c.full_name;
```

## Part 8 — Challenge ⭐⭐⭐⭐

### 47. Reconcile booking totals

Find bookings whose `total_cents` does **not** equal the sum of their `booking_items` prices.

<details>
<summary>Reveal solution</summary>

```sql
SELECT b.id, b.total_cents, COALESCE(sum(bi.price_cents), 0) AS items_total
FROM bookings b
LEFT JOIN booking_items bi ON bi.booking_id = b.id
GROUP BY b.id, b.total_cents
HAVING b.total_cents <> COALESCE(sum(bi.price_cents), 0)
ORDER BY b.id;
```

</details>

### 48. Best-selling route per airline

For each airline, its single route (origin → destination) with the most bookings.

<details>
<summary>Reveal solution</summary>

```sql
WITH ranked AS (
    SELECT a.name AS airline, f.origin, f.destination, count(*) AS bookings,
           row_number() OVER (PARTITION BY a.name ORDER BY count(*) DESC) AS rn
    FROM airlines a
    JOIN flights f        ON f.airline_id = a.id
    JOIN booking_items bi ON bi.flight_id = f.id
    GROUP BY a.name, f.origin, f.destination
)
SELECT airline, origin, destination, bookings
FROM ranked
WHERE rn = 1
ORDER BY bookings DESC;
```

</details>

### 49. Customers with only cancelled bookings

Every customer who has bookings, and **all** of them are cancelled.

<details>
<summary>Reveal solution</summary>

```sql
SELECT c.full_name
FROM customers c
WHERE EXISTS (SELECT 1 FROM bookings b WHERE b.customer_id = c.id)
  AND NOT EXISTS (
        SELECT 1 FROM bookings b
        WHERE b.customer_id = c.id AND b.status <> 'cancelled'
      );
```

<Callout type="info" title="Universal quantification in SQL">
"All X are Y" is expressed as "there does not exist an X that is not Y" — a `NOT EXISTS` over the negation. This is the standard trick for `FOR ALL` conditions.
</Callout>

</details>

### 50. Dense monthly revenue report

A row for **every** month from January to July 2026, with paid revenue (zero for months with no bookings).

<details>
<summary>Reveal solution</summary>

```sql
WITH months AS (
    SELECT generate_series(
        date_trunc('month', '2026-01-01'::timestamptz),
        date_trunc('month', '2026-07-01'::timestamptz),
        interval '1 month'
    ) AS month
)
SELECT m.month::date AS month,
       COALESCE(sum(b.total_cents), 0) AS revenue_cents
FROM months m
LEFT JOIN bookings b
  ON date_trunc('month', b.created_at) = m.month
 AND b.status = 'paid'
GROUP BY m.month
ORDER BY m.month;
```

</details>

### 51. Fastest conversion

Which customer converted fastest from signup to their first **paid** booking? Report the hours.

<details>
<summary>Reveal solution</summary>

```sql
SELECT c.full_name,
       round(extract(epoch FROM min(b.created_at) - c.created_at) / 3600.0, 1) AS hours_to_first_paid
FROM customers c
JOIN bookings b ON b.customer_id = c.id AND b.status = 'paid'
GROUP BY c.id, c.full_name
ORDER BY hours_to_first_paid ASC
LIMIT 1;
```

</details>

### 52. Most-booked flights

Flights that appear in more than one distinct booking, most-booked first.

<details>
<summary>Reveal solution</summary>

```sql
SELECT f.flight_no, f.origin, f.destination,
       count(DISTINCT bi.booking_id) AS bookings
FROM flights f
JOIN booking_items bi ON bi.flight_id = f.id
GROUP BY f.id, f.flight_no, f.origin, f.destination
HAVING count(DISTINCT bi.booking_id) > 1
ORDER BY bookings DESC, f.flight_no;
```

</details>

### 53. Longest daily paid-booking streak

The longest run of consecutive calendar days that had at least one paid booking (a single number).

<details>
<summary>Reveal solution</summary>

```sql
WITH days AS (
    SELECT DISTINCT created_at::date AS d FROM bookings WHERE status = 'paid'
),
marked AS (
    SELECT d, d - (row_number() OVER (ORDER BY d))::int AS grp FROM days
)
SELECT max(streak) AS longest_streak
FROM (SELECT count(*) AS streak FROM marked GROUP BY grp) s;
```

</details>
