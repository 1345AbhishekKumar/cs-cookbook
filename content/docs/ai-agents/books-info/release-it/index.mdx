**Michael T. Nygard · 2nd ed. 2018**

<Callout type="info" title="For humans">
The book that turns "it works locally" into a design flaw. Nygard catalogues the ways production actually
kills systems — latency, overload, cascading failure, bad data, hostile traffic — and gives each a named
pattern. It is the difference between code that passes tests and code that survives Tuesday. Read it before
your service is the one that takes down the ones depending on it.
</Callout>

## What it argues

Production is a hostile environment, and the failure modes are structural rather than exceptional. A
resource that never times out becomes a thread pool that never drains. A retry without backoff becomes a
self-inflicted denial of service. A queue without a bound becomes an out-of-memory error. Design for
survivability: isolate failure with bulkheads, fail fast instead of hanging, shed load rather than
collapsing, degrade gracefully rather than failing entirely, and make the system's state observable enough
that operators can act. Stability is a property you design in, not something you bolt on after an incident.

## Core ideas

- **Always set timeouts** — every remote call, connection, and lock has a bound.
- **Circuit breakers** — stop calling a failing dependency so you can recover and it can recover.
- **Bulkheads** — partition resources so one overloaded path cannot starve the rest.
- **Back pressure and bounded queues** — refuse or shed work instead of accumulating it.
- **Retries with backoff and jitter** — and only where the operation is safe to repeat.
- **Transparency and steady state** — logs, metrics, and health endpoints; no unbounded growth in any resource.
