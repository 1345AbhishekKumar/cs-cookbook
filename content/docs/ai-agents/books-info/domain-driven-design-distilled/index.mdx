**Vaughn Vernon · 2016**

<Callout type="info" title="For humans">
The right first DDD book. Evans is the source of the ideas; Vernon Distilled is the version you can finish
on a flight and apply on Monday. Its thesis is anti-ceremony: use the *smallest* effective set of DDD
practices, put modelling effort where the business actually differentiates, and skip the patterns that are
not earning their keep. Read this before *Domain-Driven Design* if the big blue book has been sitting
unread.
</Callout>

## What it argues

Not every system has a domain worth modelling deeply. Invest in the **core domain** — the part that is
strategically differentiating — and keep supporting subdomains deliberately plain. Split the system into
**bounded contexts**, each with its own consistent model and language, and make the relationships between
them explicit through context mapping instead of letting a single shared model rot into incoherence. Reach
for tactical patterns (entities, value objects, aggregates, domain events) only where the domain complexity
justifies them.

## Core ideas

- **Subdomains first** — separate core, supporting, and generic work, and spend accordingly.
- **Bounded contexts early** — a context is the boundary inside which one model and one language stay consistent.
- **Context maps over shared models** — name the relationships (partnership, customer/supplier, anti-corruption layer) explicitly.
- **Ubiquitous language** — if the domain experts and the code use different words, the model is already drifting.
- **Minimal tactics** — aggregates, entities, and value objects earn their place; do not decorate.
- **Collaboration is the method** — modelling happens with domain experts, not in isolation before coding.
