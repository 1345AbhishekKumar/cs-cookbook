**Michael Feathers · 2004**

<Callout type="info" title="For humans">
The most practically liberating book on this shelf. Feathers defines legacy code bluntly as **code without
tests**, which turns a vague dread into a work queue. The techniques — find a seam, write a characterization
test, change one thing — are unglamorous and extremely effective. Read it the first time you are asked to
change something nobody understands.
</Callout>

## What the book argues

The hardest part of changing existing code is not the edit; it is the missing feedback. Without tests you
cannot tell whether your change preserved behaviour, so fear and delay dominate. The fix is methodical:
understand the code's current behaviour, capture it in characterization tests, introduce **seams** where
behaviour can be substituted or observed without editing the surrounding system, and only then make the
change. Redesign is something you earn after the code is under test — not something you attempt under
uncertainty.

## Core ideas

- **Legacy code means untested code** — the diagnosis is missing feedback, not age or ugliness.
- **Characterization tests** — document what the code *does*, including its bugs, before changing it.
- **Find seams** — identify the places where you can substitute behaviour without editing everywhere.
- **Break dependencies to enable tests** — narrow interfaces, parameterize constructors, extract and override.
- **Prefer surgical change** — sprout and wrap methods before restructuring anything larger.
- **Earn the redesign** — get it under test first; incremental improvement beats the big rewrite.
