**Robert C. Martin · 2008**

<Callout type="info" title="For humans">
The book that made "code is read far more often than it is written" a mainstream expectation. It is
opinionated and prescriptive in a way modern readers sometimes push back on, but its core claim is hard
to argue with: readability is the property that makes every other property reachable. Best used as a
day-to-day reminder for implementation and review, not as a rulebook to quote at people.
</Callout>

## What the book argues

Clean code is code that someone else can understand, change, and extend without fear. Most of that comes
from small, honest decisions rather than architecture: names that reveal intent, functions that do one
thing at one level of abstraction, no duplicated knowledge, errors handled explicitly instead of leaking
as nulls, and tests treated as first-class code that must be as clean as production. The **Boy Scout Rule**
— leave touched code cleaner than you found it — turns that into a habit rather than a project.

## Core ideas

- **Names carry the design** — intention-revealing, searchable, pronounceable; no encodings, no mental mapping.
- **Small functions, one thing each** — one level of abstraction per function, few arguments, no flag arguments.
- **Readability over cleverness** — never trade clarity for brevity, and never preserve bad structure because it exists.
- **Errors are part of the interface** — handle them explicitly; do not return sentinel values or stack exceptions on failure paths.
- **Comments explain why** — delete comments that narrate code or compensate for a bad name.
- **Tests stay clean too** — test code is read and changed; readability rules apply with equal force.
