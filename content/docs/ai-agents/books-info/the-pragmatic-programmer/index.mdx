**Andrew Hunt & David Thomas · 1999 (2nd ed. 2019)**

<Callout type="info" title="For humans">
The best general-purpose engineering operating style in one book. Where *Clean Code* is about the code,
this is about the person: taking responsibility, avoiding duplicated knowledge, keeping components
independent, delivering in tracer-bullet slices, and automating the boring parts. It is the closest thing
to a default rule set for "how a professional behaves on a codebase", which is exactly why it makes a good
always-on agent bias.
</Callout>

## What the book argues

Software rots not from bad algorithms but from duplicated knowledge and tangled dependencies. Keep
components orthogonal so a change in one place does not surprise you in another. Deliver something real
early (a tracer bullet) so you get feedback while the design is still cheap to change. Fix broken windows
before they invite more decay. Automate everything repetitive, because human diligence does not scale.
And own the outcome: "it works on my machine" is not a verdict.

## Core ideas

- **DRY is about knowledge, not text** — two places encoding one fact is a defect waiting to diverge.
- **Orthogonality** — independent components mean fewer surprises and smaller blast radius.
- **Tracer bullets over big bangs** — thin end-to-end slices give feedback fast.
- **Design for change** — reversibility, no premature lock-in, prototype to learn and then throw the prototype away.
- **Ruthless feedback** — treat warnings, tests, and reviews as information, not ceremony.
- **Automate** — builds, tests, and repeatable chores belong in tooling.
