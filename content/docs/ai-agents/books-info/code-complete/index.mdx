**Steve McConnell · 2004**

<Callout type="info" title="For humans">
A dense construction-phase reference — less quotable than *Clean Code*, more useful when you actually want
evidence. Its central observation is economic: defects are cheapest to prevent during construction, and
construction discipline is what separates code someone can inspect from code that merely passes. Read the
routines-and-classes chapters if you write code all day; skim the rest.
</Callout>

## What the book argues

Most defects are introduced where code is written, so that is where quality control pays. Disciplined
construction — deliberate routine design, clear class interfaces, correct control structures, deliberate
data handling, and defensive programming where it is warranted — reduces defects far more reliably than
hoping for heroic debugging. McConnell is explicit that this is judgement work, not style theatre: pick
practical techniques that hold up under real constraints, and prefer correctness and inspectability over
cleverness.

## Core ideas

- **Design routines deliberately** — high cohesion, cohesive names, few parameters, clear contracts.
- **Abstract data types over exposed representation** — callers should not depend on internal layout.
- **Control the complexity of control flow** — readable nesting, no deep decision trees, no boolean-flag puzzles.
- **Defensive programming in proportion** — validate at trust boundaries; do not paper over impossible states everywhere.
- **Verify what you build** — inspection, tests, and assertions as part of construction, not a later phase.
- **Practical over fashionable** — adopt a technique because it reduces defects here, not because it is current.
