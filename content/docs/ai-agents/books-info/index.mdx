Fourteen books shaped how good software gets written. This sub-module turns each one into an **operational full rulebook** an agent can load, because "have you read Clean Code?" is not something you can put in a system prompt. Each rulebook provides imperative decision rules, trigger rules, and checklists.

## Load them into an agent

Point your agent at the path for the book rulebook you want. For example:

```md
## Engineering rules

Before changing code, read and follow:

- Construction standards: /docs/ai-agents/books-info/code-complete
- Refactoring discipline: /docs/ai-agents/books-info/refactoring
- Architecture boundaries: /docs/ai-agents/books-info/clean-architecture
- Distributed data systems: /docs/ai-agents/books-info/designing-data-intensive-applications
```

## How these are written

Every rule page uses the same grammar, so an agent can scan it predictably:

- **When to use** — the situation that makes this book relevant.
- **Primary bias to correct** — the instinct that is usually wrong without this book.
- **Decision rules** — what to do, stated as `MUST` / `SHOULD` / `MUST NOT`.
- **Trigger rules** — the moments the rules must be recalled.
- **Final checklist** — what to verify before declaring the work done.
