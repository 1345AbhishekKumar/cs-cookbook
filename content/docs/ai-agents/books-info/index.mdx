Fourteen books shaped how good software gets written. This sub-module turns each one into a
**rule set an agent can load**, because "have you read Clean Code?" is not something you can put
in a system prompt. Each book ships in three depths so you can spend exactly as much context as
the task deserves — and each book's overview page is written for the human who wants to
understand the idea before handing the rules to a machine.

<Callout type="info" title="Two audiences, one source">
The overview pages (this one and every book's landing page) are written for **humans** — what the
book argues, when to reach for it, which depth to load. The `nano`, `mini`, and `full` pages are
written for **agents** — imperative decision rules, trigger rules, and checklists, each keeping
the source's `OBEY <book>` preamble.
</Callout>

## Pick a depth

Every book is available at three levels of commitment. They are strict expansions of each other:
nano is a bias correction, mini is the working rule set, full is the complete policy.

| Depth | Size | Reach for it when |
| --- | --- | --- |
| **Nano rules** — e.g. [Clean Code nano](/docs/ai-agents/books-info/clean-code/nano) | ≈0.3–0.8k tokens | You want an always-on bias check. Cheap enough to keep in every prompt. |
| **Mini rules** — e.g. [Clean Code mini](/docs/ai-agents/books-info/clean-code/mini) | ≈1.0–2.1k tokens | The book's concerns are actually relevant to this task. The usual choice. |
| **Full rulebook** — e.g. [Clean Code full](/docs/ai-agents/books-info/clean-code/full) | ≈2.9–15.7k tokens | You are doing deep work in this book's territory and want no gaps. |

## Load them into an agent

Point your agent at the URL for the depth you want. The docs ship a machine-readable index at
`/llms.txt`, so an agent that can fetch pages can pull a rulebook by path:

```md
## Engineering rules

Before changing code, read and follow:
- Nano bias: /docs/ai-agents/books-info/the-pragmatic-programmer/nano
- Working rules: /docs/ai-agents/books-info/clean-code/mini
- For persistence boundaries: /docs/ai-agents/books-info/designing-data-intensive-applications/full
```

A practical default is **one or two `mini` rule sets plus a couple of `nano` bias checks** — enough
discipline to change behaviour, small enough to leave room for the actual task. Escalate a single
book to `full` only when that book governs the whole job, and drop the rest.

## How these are written

Every rule page uses the same grammar, so an agent can scan it predictably:

- **When to use** — the situation that makes this book relevant.
- **Primary bias to correct** — the instinct that is usually wrong without this book.
- **Decision rules** — what to do, stated as `MUST` / `SHOULD` / `MUST NOT`.
- **Trigger rules** — the moments the rules must be recalled.
- **Final checklist** — what to verify before declaring the work done.

## Keeping the rulebooks in sync

The rule pages are generated from the upstream rule set, so they can be refreshed rather than
hand-edited. The per-book overview pages are hand-written and are never overwritten:

```bash
node scripts/generate-agent-rules-books.mjs <path-to-agent-rules-books-main>
```
