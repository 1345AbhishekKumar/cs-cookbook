In JavaScript, values often change types or represent multiple potential states. TypeScript's **Control Flow Analysis** tracks your code as it executes, narrowing wide union types into specific subtypes.

---

## 1. Union Types & Literal Types

A union type (`A | B`) models a value that can be any one of several types:

```typescript
// Literal union type
type HttpMethod = "GET" | "POST" | "PUT" | "DELETE";
type PortNumber = 3000 | 8080 | 443;

function sendRequest(url: string, method: HttpMethod) {
  // TypeScript guarantees 'method' is strictly one of the 4 valid HTTP verbs
}
```

---

## 2. Type Narrowing Mechanisms

TypeScript automatically narrows types inside conditional branches:

```typescript
function processValue(val: string | number | Date) {
  // 1. typeof narrowing (primitives)
  if (typeof val === "string") {
    return val.toUpperCase(); // Inferred as 'string'
  }

  // 2. instanceof narrowing (class instances)
  if (val instanceof Date) {
    return val.toISOString(); // Inferred as 'Date'
  }

  // 3. Remaining type after elimination
  return val.toFixed(2); // Inferred as 'number'
}
```

### The `in` Operator Narrowing
Use the `in` operator to test if an object possesses a specific property:

```typescript
type AdminUser = { id: string; permissions: string[] };
type RegularUser = { id: string; email: string };

function checkAccess(user: AdminUser | RegularUser) {
  if ("permissions" in user) {
    // Inferred as AdminUser
    console.log(user.permissions);
  } else {
    // Inferred as RegularUser
    console.log(user.email);
  }
}
```

## 3. Custom Type Guards (`val is Type`)

When type-checking logic is complex, write a custom type predicate function:

```typescript
interface NetworkError {
  isNetworkError: true;
  statusCode: number;
}

// Custom type guard returning 'error is NetworkError'
function isNetworkError(error: unknown): error is NetworkError {
  return (
    typeof error === "object" &&
    error !== null &&
    "isNetworkError" in error &&
    (error as NetworkError).isNetworkError === true
  );
}

// Usage in catch block
try {
  // network call
} catch (err) {
  if (isNetworkError(err)) {
    console.log("HTTP status:", err.statusCode); // Fully typed!
  }
}
```

## 4. Discriminated Unions (Tagged Unions)

The most important architectural pattern in TypeScript. A discriminated union is a union of object types that all share a single literal property (the **discriminant**):

```typescript
type PaymentMethod =
  | { type: "credit_card"; cardNumber: string; cvv: string }
  | { type: "paypal"; email: string }
  | { type: "crypto"; walletAddress: string };

function processPayment(payment: PaymentMethod) {
  switch (payment.type) {
    case "credit_card":
      // Automatically narrowed to credit_card
      return chargeCard(payment.cardNumber, payment.cvv);

    case "paypal":
      // Automatically narrowed to paypal
      return redirectPayPal(payment.email);

    case "crypto":
      // Automatically narrowed to crypto
      return transferCrypto(payment.walletAddress);
  }
}
```

## 5. Exhaustiveness Checking with `never`

What happens if someone adds a new payment method `{ type: "apple_pay" }` to `PaymentMethod` later? Without exhaustiveness checking, the switch statement silently skips it.

Use the `never` type to turn missed cases into compile-time errors:

```typescript
function assertNever(x: never): never {
  throw new Error(`Unhandled union case: ${JSON.stringify(x)}`);
}

function processPaymentExhaustive(payment: PaymentMethod) {
  switch (payment.type) {
    case "credit_card":
      return chargeCard(payment.cardNumber, payment.cvv);
    case "paypal":
      return redirectPayPal(payment.email);
    case "crypto":
      return transferCrypto(payment.walletAddress);
    default:
      // If any case is unhandled, 'payment' is NOT 'never', triggering a COMPILE ERROR!
      return assertNever(payment);
  }
}
```

<Callout type="tip" title="Why Exhaustiveness Checking Matters">
Exhaustiveness checking guarantees 100% test coverage for state unions at build time. When you add a new feature or state to your application, the TypeScript compiler instantly highlights every switch statement in your project that needs to be updated.
</Callout>
