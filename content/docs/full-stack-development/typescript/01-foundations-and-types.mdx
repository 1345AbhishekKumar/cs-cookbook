TypeScript adds static typing to JavaScript. All types exist solely at compile time; once compiled by `tsc` or transpiled by modern bundlers (Next.js, Vite, esbuild), the annotations are erased, leaving pure JavaScript.

---

## 1. Type Annotations & Type Inference

TypeScript has a sophisticated inference engine. You do not need to annotate every variable explicitly:

```typescript
// Explicit Type Annotations
const appName: string = "CS Cookbook";
const serverPort: number = 8080;
const isProduction: boolean = true;

// Type Inference: TypeScript automatically infers 'role' as 'string'
let role = "admin";
// role = 100; // Type Error: Type 'number' is not assignable to type 'string'.
```

<Callout type="tip" title="When to Annotate vs When to Infer">
- **Rely on inference**: Variable declarations with immediate values, array literals, and return values of simple functions.
- **Explicitly annotate**: Function parameters, object interfaces, uninitialized variables, and complex return values to enforce contracts.
</Callout>

## 2. Top and Bottom Types

The TypeScript type hierarchy has a single top and a single bottom:

```
          ┌───────────────────────────────────┐
          │   unknown (Safe Top Type)         │
          │   any     (Unsafe Escape Hatch)   │
          └─────────────────┬─────────────────┘
                            │
                            ▼
          ┌───────────────────────────────────┐
          │   string, number, boolean, ...    │
          │   Objects, Functions, Arrays      │
          └─────────────────┬─────────────────┘
                            │
                            ▼
          ┌───────────────────────────────────┐
          │   never   (Bottom / Uninhabited)  │
          └───────────────────────────────────┘
```

### 1. `unknown` (The Safe Top Type)
Represents any possible value, but prevents you from calling methods or accessing properties until you prove its type through narrowing:

```typescript
function parseApiResponse(rawJson: string): unknown {
  return JSON.parse(rawJson);
}

const payload = parseApiResponse('{"userId": 10}');
// payload.userId; // Error: 'payload' is of type 'unknown'.

// Narrow before access:
if (typeof payload === "object" && payload !== null && "userId" in payload) {
  console.log((payload as { userId: number }).userId); // Safe!
}
```

### 2. `any` (The Unchecked Escape Hatch)
Turns off all static checking for that variable. Using `any` spreads viral un-typed code through your codebase:

```typescript
const badData: any = "hello";
badData.nonExistentMethod(); // Compiles without error, but crashes at runtime!
```

### 3. `never` (The Bottom Type)
Represents a type that can never contain any value. It is returned by functions that never return (e.g. infinite loops or functions that always throw):

```typescript
function fail(errorMessage: string): never {
  throw new Error(errorMessage);
}
```

### 4. `void` (No Return Value)
Represents the return value of a function that does not return anything meaningful:

```typescript
function logNotice(message: string): void {
  console.log(`[NOTICE]: ${message}`);
}
```

## 3. Arrays and Tuples

```typescript
// Standard array syntax
const tags: string[] = ["react", "typescript", "nextjs"];
const scores: Array<number> = [98, 85, 92]; // Generic syntax alternative

// Tuples: Fixed-length arrays with specific types at each index
type GeoCoordinate = [latitude: number, longitude: number];
const officeLocation: GeoCoordinate = [37.7749, -122.4194];

// Tuples with Optional and Rest elements
type StringNumberPair = [string, number?];
type ResponseHeader = [key: string, ...values: string[]];

// Readonly Tuples with 'as const'
const httpStatuses = [200, 404, 500] as const;
// httpStatuses.push(201); // Error: Property 'push' does not exist on type 'readonly [200, 404, 500]'.
```

## 4. Enums (`enum`) vs. Const Objects

TypeScript introduced `enum` early in its history to allow developers to declare a collection of named constants.

### 1. Numeric Enums
By default, enums are numeric and auto-increment from `0`:

```typescript
enum Direction {
  Up,    // 0
  Down,  // 1
  Left,  // 2
  Right  // 3
}

const move = Direction.Up; // 0
```

<Callout type="warning" title="Numeric Enum Reverse Mapping">
Numeric enums generate a bidirectional (reverse) lookup table in JavaScript:
```typescript
console.log(Direction[0]); // "Up"
console.log(Direction["Up"]); // 0
```
However, this allows arbitrary numbers to be assigned to numeric enums, which can weaken type safety in strict codebases.
</Callout>

### 2. String Enums
String enums require explicit string initializers and do **not** support reverse mapping:

```typescript
enum ApprovalStatus {
  Draft = "DRAFT",
  Submitted = "SUBMITTED",
  Approved = "APPROVED",
  Rejected = "REJECTED"
}

function processApplication(status: ApprovalStatus): void {
  if (status === ApprovalStatus.Approved) {
    console.log("Application granted.");
  }
}
```

### 3. What Does `enum` Emit in JavaScript?
Unlike almost all other TypeScript constructs which are completely erased during compilation, `enum` generates runtime JavaScript code (an Immediately Invoked Function Expression - IIFE):

```javascript
// Compiled JavaScript Output:
var ApprovalStatus;
(function (ApprovalStatus) {
    ApprovalStatus["Draft"] = "DRAFT";
    ApprovalStatus["Submitted"] = "SUBMITTED";
    ApprovalStatus["Approved"] = "APPROVED";
    ApprovalStatus["Rejected"] = "REJECTED";
})(ApprovalStatus || (ApprovalStatus = {}));
```

### 4. The Modern Idiom: `as const` Objects
Because enums generate extra JavaScript runtime overhead and do not tree-shake cleanly in older bundlers, modern TypeScript codebases frequently favor POJO (Plain Old JavaScript Objects) with `as const`:

```typescript
// Define object as const
export const OrderStatus = {
  Pending: "pending",
  Shipped: "shipped",
  Delivered: "delivered"
} as const;

// Derive type automatically
export type OrderStatus = (typeof OrderStatus)[keyof typeof OrderStatus];
// 'pending' | 'shipped' | 'delivered'
```

<Callout type="tip" title="Production Guidance">
- Use **String Enums** when working in legacy codebases, Angular, or frameworks that rely on enum metadata at runtime.
- Use **`as const` objects or Union Literals** (`type OrderStatus = 'pending' | 'shipped' | 'delivered'`) in modern full-stack TypeScript (Next.js, Node.js, Vite) for zero runtime overhead and optimal tree-shaking.
</Callout>
