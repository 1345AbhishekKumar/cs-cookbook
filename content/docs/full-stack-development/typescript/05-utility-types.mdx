TypeScript provides a rich standard library of built-in utility types that transform existing types without manual duplication.

---

## 1. Property Modifiers: `Partial`, `Required`, `Readonly`

```typescript
interface DatabaseUser {
  id: string;
  name: string;
  email: string;
  bio?: string;
}

// 1. Partial<T>: Makes ALL properties optional (?)
type UpdateUserDto = Partial<DatabaseUser>;
// { id?: string; name?: string; email?: string; bio?: string }

// 2. Required<T>: Strips all optionality (all fields mandatory)
type StrictUser = Required<DatabaseUser>;
// { id: string; name: string; email: string; bio: string }

// 3. Readonly<T>: Prevents property reassignment
type ImmutableUser = Readonly<DatabaseUser>;
```

---

## 2. Shape Projections: `Pick`, `Omit`, `Record`

```typescript
// 1. Pick<T, Keys>: Selects a subset of properties
type UserContactInfo = Pick<DatabaseUser, "name" | "email">;
// { name: string; email: string }

// 2. Omit<T, Keys>: Drops specified properties
type CreateUserPayload = Omit<DatabaseUser, "id">;
// { name: string; email: string; bio?: string }

// 3. Record<Keys, ValueType>: Type-safe dictionary / map
type UserRole = "admin" | "editor" | "viewer";
type RolePermissions = Record<UserRole, string[]>;

const permissions: RolePermissions = {
  admin: ["read", "write", "delete"],
  editor: ["read", "write"],
  viewer: ["read"]
};
```

---

## 3. Union Manipulation: `Exclude`, `Extract`, `NonNullable`

Operates across union members:

```typescript
type ActionEvent = "click" | "hover" | "focus" | "scroll" | "resize";

// 1. Exclude<T, U>: Removes matching types from union
type MouseEvent = Exclude<ActionEvent, "scroll" | "resize">;
// "click" | "hover" | "focus"

// 2. Extract<T, U>: Keeps only matching types from union
type WindowEvent = Extract<ActionEvent, "scroll" | "resize" | "unload">;
// "scroll" | "resize"

// 3. NonNullable<T>: Removes null and undefined from type
type NullableString = string | null | undefined;
type DefiniteString = NonNullable<NullableString>; // strictly 'string'
```

## 4. Function & Promise Introspection

Introspect types directly from functions and promises:

```typescript
async function fetchUserProfile(userId: string) {
  return {
    id: userId,
    displayName: "Alex",
    roles: ["admin"]
  };
}

// 1. ReturnType<T>: Extracts function return type
type FetchReturn = ReturnType<typeof fetchUserProfile>; 
// Promise<{ id: string; displayName: string; roles: string[] }>

// 2. Awaited<T>: Recursively unwraps Promise return values
type UserProfile = Awaited<ReturnType<typeof fetchUserProfile>>;
// { id: string; displayName: string; roles: string[] }

// 3. Parameters<T>: Extracts function arguments as a tuple
type FetchParams = Parameters<typeof fetchUserProfile>; // [userId: string]
```

## 5. Production Pattern: End-to-End DTO Modeling

Never redefine database entity shapes manually across your API routes:

```typescript
// Single Source of Truth: Database Model
export interface UserEntity {
  id: string;
  email: string;
  passwordHash: string;
  name: string;
  role: "admin" | "member";
  createdAt: Date;
  updatedAt: Date;
}

// DTO for User Creation (Strip system generated fields)
export type CreateUserDTO = Omit<UserEntity, "id" | "createdAt" | "updatedAt">;

// DTO for Profile Patch (All fields optional, never edit passwordHash directly)
export type UpdateUserDTO = Partial<Omit<CreateUserDTO, "passwordHash">>;

// Public Safe Profile for Client responses (Never leak passwordHash)
export type PublicUserDTO = Omit<UserEntity, "passwordHash">;
```

## 6. The `Prettify<T>` Tooltip Helper

When combining types using intersections (`&`), TypeScript's language server often renders unreadable tooltips in IDEs:

```typescript
type A = { id: string; name: string };
type B = { role: "admin" | "user"; permissions: string[] };

type CombinedUser = A & B;
// Hover in VS Code displays:
// type CombinedUser = A & B
```

This makes debugging deep object shapes and DTOs frustrating because the developer cannot see the resolved properties at a glance.

### The Solution: `Prettify<T>`
By using a mapped type, you force the TypeScript compiler to evaluate and flatten the intersection into a single, clean object shape:

```typescript
export type Prettify<T> = {
  [K in keyof T]: T[K];
} & {};

type ReadableUser = Prettify<CombinedUser>;
// Hover in VS Code now displays cleanly:
// type ReadableUser = {
//   id: string;
//   name: string;
//   role: "admin" | "user";
//   permissions: string[];
// }
```

<Callout type="tip" title="Use Cases in Production">
Use `Prettify<T>` on complex return types, library exports, or whenever constructing compound types with `Pick`, `Omit`, or `&` so consumers of your API get clear, readable intellisense without nested intersection artifacts.
</Callout>
