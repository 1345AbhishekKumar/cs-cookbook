## 1. The `satisfies` Operator (TS 4.9+)

Before `satisfies`, annotating an object forced TypeScript to **widen** property types to the declared type, losing specific literal knowledge:

```typescript
type Palette = Record<string, string | [number, number, number]>;

// The Problem with traditional type annotation:
const themeWidened: Palette = {
  primary: "#3b82f6",
  secondary: [255, 0, 0]
};
// themeWidened.primary.toUpperCase(); 
// Error: Property 'toUpperCase' does not exist on type 'string | [number, number, number]'.

// The Solution: 'satisfies' validates the contract WITHOUT widening!
const theme = {
  primary: "#3b82f6",
  secondary: [255, 0, 0]
} satisfies Palette;

theme.primary.toUpperCase(); // OK! TypeScript remembers 'primary' is specifically a string!
theme.secondary.map(n => n * 2); // OK! Known to be a number array!
```

## 2. Template Literal Types

Template literal types mirror JavaScript template strings, allowing you to construct string pattern types:

```typescript
type HttpMethod = "get" | "post" | "delete";
type ApiRoute = "/users" | "/orders" | "/auth";

// Automatically generates every valid permutation:
// "GET /users" | "GET /orders" | "POST /users" ...
type Endpoint = `${Uppercase<HttpMethod>} ${ApiRoute}`;

// Type-safe Event Emitters
type EventName = "userLoggedIn" | "cartUpdated" | "orderPlaced";
type HandlerName = `on${Capitalize<EventName>}`;
// "onUserLoggedIn" | "onCartUpdated" | "onOrderPlaced"
```

## 3. Mapped Types with Key Remapping (`as`)

Iterate over keys and re-map their names and values dynamically:

```typescript
interface ServiceConfig {
  databaseUrl: string;
  cachePort: number;
}

// Transform all properties into getter functions with capitalized names
type ConfigGetters<T> = {
  [K in keyof T as `get${Capitalize<string & K>}`]: () => T[K];
};

type GeneratedGetters = ConfigGetters<ServiceConfig>;
/* Inferred Type:
{
  getDatabaseUrl: () => string;
  getCachePort: () => number;
}
*/
```

## 4. Conditional Types & The `infer` Keyword

Conditional types introduce `if/else` logic into the type system:

```typescript
type IsArray<T> = T extends unknown[] ? true : false;

type T1 = IsArray<string[]>; // true
type T2 = IsArray<number>;   // false
```

### Unpacking Types with `infer`
The `infer` keyword lets you extract and capture an internal type from within another type:

```typescript
// Unpack the element type inside an Array
type ElementOf<T> = T extends (infer U)[] ? U : T;

type Str = ElementOf<string[]>; // string
type Num = ElementOf<number>;   // number (unchanged)

// Extract the resolved value from a Promise (Re-implementing Awaited)
type UnwrapPromise<T> = T extends Promise<infer R> ? UnwrapPromise<R> : T;

type Resolved = UnwrapPromise<Promise<Promise<string>>>; // string
```

## 5. Branded (Nominal) Types

TypeScript is structurally typed. This means an `orderId: string` and a `userId: string` are interchangeable, leading to subtle runtime bugs:

```typescript
// Define nominal brands
type Brand<K, T> = K & { readonly __brand: T };

type UserId = Brand<string, "UserId">;
type OrderId = Brand<string, "OrderId">;

// Constructor helper functions
function makeUserId(id: string): UserId {
  return id as UserId;
}

function makeOrderId(id: string): OrderId {
  return id as OrderId;
}

function cancelOrder(userId: UserId, orderId: OrderId) {
  // Logic
}

const user = makeUserId("usr_1");
const order = makeOrderId("ord_9");

cancelOrder(user, order); // OK!
// cancelOrder(order, user); // Compile Error! Argument of type 'OrderId' is not assignable to 'UserId'.
```
