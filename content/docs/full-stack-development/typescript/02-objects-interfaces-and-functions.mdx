TypeScript models the shapes of JavaScript objects through structural typing. If two types have the same properties with compatible types, they are interchangeable.

---

## 1. Object Types & Modifiers

```typescript
type UserAccount = {
  readonly id: string;       // Cannot be reassigned after creation
  username: string;
  email: string;
  avatarUrl?: string;        // Optional property (string | undefined)
};

const user: UserAccount = {
  id: "usr_981",
  username: "alex",
  email: "alex@example.com"
};

// user.id = "new_id"; // Error: Cannot assign to 'id' because it is a read-only property.
```

## 2. `interface` vs `type` Aliases

Both `interface` and `type` can describe object shapes, but they have distinct features:

<Tabs items={['Interface (Declaration Merging & Extends)', 'Type Alias (Unions & Mappings)']}>
  <Tab value="Interface (Declaration Merging & Extends)">
    Interfaces are designed for open, extensible object models and support **Declaration Merging**:

    ```typescript
    interface DatabaseEntity {
      id: string;
      createdAt: Date;
    }

    // Extends another interface
    interface Customer extends DatabaseEntity {
      name: string;
      loyaltyPoints: number;
    }

    // Declaration Merging: Redefining merges properties together
    interface Customer {
      tier: "gold" | "silver";
    }
    ```
  </Tab>
  <Tab value="Type Alias (Unions & Mappings)">
    Type aliases can represent unions, primitives, tuples, and mapped types:

    ```typescript
    // Union types
    type HttpStatus = 200 | 404 | 500;

    // Intersection
    type WithTimestamps = { createdAt: Date; updatedAt: Date };
    type Post = { id: string; title: string } & WithTimestamps;

    // Tuples and primitives
    type Coordinates = [x: number, y: number];
    ```
  </Tab>
</Tabs>

<Callout type="tip" title="Industry Best Practice">
Default to `type` for internal application development (React props, state unions, transformations). Use `interface` when authoring public libraries or building object-oriented domain models that require extension.
</Callout>

## 3. Dynamic Keys: Index Signatures vs `Record`

When an object has arbitrary dynamic keys:

```typescript
// 1. Index Signature
interface UserRatings {
  [productId: string]: number;
}

// 2. Built-in Record Utility (Cleaner alternative)
type UserScores = Record<string, number>;

const scores: UserScores = {
  "math": 95,
  "science": 92
};
```

## 4. Function Signatures & Typing

```typescript
// Typing function parameters and return type
type MathOperation = (a: number, b: number) => number;

const add: MathOperation = (x, y) => x + y;
const multiply: MathOperation = (x, y) => x * y;

// Async function signatures
type FetchDataFn = (url: string) => Promise<unknown>;
```

## 5. Function Overloads

Sometimes a function can return different types based on the types of its input arguments. Use function overload signatures:

```typescript
// Overload signatures (declaring the contracts)
function parseDate(timestamp: number): Date;
function parseDate(dateString: string): Date;
function parseDate(year: number, month: number, day: number): Date;

// Implementation signature (compatible with all overloads)
function parseDate(a: number | string, b?: number, c?: number): Date {
  if (typeof a === "string") return new Date(a);
  if (typeof b === "number" && typeof c === "number") return new Date(a, b, c);
  return new Date(a);
}

const d1 = parseDate("2026-10-04");     // Date
const d2 = parseDate(1728000000000);    // Date
const d3 = parseDate(2026, 9, 4);       // Date
```
