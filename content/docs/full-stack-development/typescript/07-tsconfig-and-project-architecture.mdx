Configuring the TypeScript compiler (`tsconfig.json`) properly ensures maximum type safety, optimal build performance, and seamless compatibility with modern build tools (Vite, Next.js, tsx, esbuild).

---

## 1. Essential Compiler Flags for Production

Every modern production TypeScript application should enable the following flags:

```json
{
  "compilerOptions": {
    /* 1. Maximum Type Safety */
    "strict": true,
    "noUncheckedIndexedAccess": true,
    "noImplicitOverride": true,
    "exactOptionalPropertyTypes": true,

    /* 2. Modern Module Resolution */
    "target": "ES2024",
    "module": "NodeNext",
    "moduleResolution": "NodeNext",
    "verbatimModuleSyntax": true,
    "isolatedModules": true,

    /* 3. Build & Performance Optimization */
    "skipLibCheck": true,
    "forceConsistentCasingInFileNames": true
  }
}
```

### The Critical Safety Flag: `noUncheckedIndexedAccess`
By default, accessing an array element (`const first = items[0]`) is typed as `T`, even if the array is completely empty!

With `"noUncheckedIndexedAccess": true`, TypeScript types any index or dynamic key access as `T | undefined`, forcing you to check for existence and eliminating index out-of-bounds runtime crashes:

```typescript
const names: string[] = [];
const firstName = names[0]; 
// Without flag: 'string' (Crashing bug!)
// With flag:    'string | undefined' (Forces if (firstName) check!)
```

## 2. Modern Module Syntax: `verbatimModuleSyntax`

Introduced in TypeScript 5.0, `verbatimModuleSyntax` simplifies how TypeScript handles imports and type erasure:

```typescript
// Any import marked with 'type' is guaranteed to be erased from compiled JavaScript:
import type { UserProfile } from "./models.js";

// Standard value import (emitted in compiled output)
import { renderUser } from "./renderer.js";

// Inline type specifier
import { renderUser, type UserProfile } from "./user.js";
```

## 3. Ambient Declarations & `.d.ts` Files

Declaration files contain only type information (no runtime code). They inform the compiler about global variables or untyped JavaScript libraries.

### Declaring Non-Code Assets (CSS Modules & SVGs)
Create a `globals.d.ts` file in your `src/` directory:

```typescript
// globals.d.ts
declare module "*.svg" {
  const content: string;
  export default content;
}

declare module "*.module.css" {
  const classes: { readonly [key: string]: string };
  export default classes;
}

// Typing process.env environment variables
declare namespace NodeJS {
  interface ProcessEnv {
    readonly DATABASE_URL: string;
    readonly PORT?: string;
  }
}
```

## 5. Practical Node.js + TypeScript Project Bootstrap

Setting up a standalone Node.js service with TypeScript requires configuring the source layout, compiler, and development reload workflow.

### Step 1: Initialize Project & Layout
Create your workspace with separate directories for TypeScript source code (`src/`) and compiled JavaScript output (`dist/` or `build/`):

```bash
mkdir node-ts-service && cd node-ts-service
npm init -y
mkdir src
touch src/index.ts
```

Install TypeScript and Node types as developer dependencies:

```bash
npm install -D typescript @types/node
```

### Step 2: Initialize & Configure `tsconfig.json`
Generate a fresh `tsconfig.json`:

```bash
npx tsc --init
```

Ensure your `tsconfig.json` sets the root and output paths correctly:

```json
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "NodeNext",
    "moduleResolution": "NodeNext",
    "rootDir": "./src",
    "outDir": "./dist",
    "strict": true,
    "skipLibCheck": true
  },
  "include": ["src/**/*"]
}
```

### Step 3: Configure Development Scripts

<Tabs items={['Modern Approach: tsx (Recommended)', 'Classic Approach: tsc -w + nodemon']}>
  <Tab value="Modern Approach: tsx (Recommended)">
    `tsx` is an ultra-fast esbuild-powered runtime that executes TypeScript directly with automatic hot-reloading:

    ```bash
    npm install -D tsx
    ```

    In `package.json`:
    ```json
    {
      "type": "module",
      "scripts": {
        "dev": "tsx watch src/index.ts",
        "build": "tsc",
        "start": "node dist/index.js"
      }
    }
    ```
  </Tab>

  <Tab value="Classic Approach: tsc -w + nodemon">
    The traditional pipeline compiles TypeScript to disk with `tsc -w` while `nodemon` monitors the compiled `dist/` directory, coordinated concurrently:

    ```bash
    npm install -D nodemon concurrently
    ```

    In `package.json`:
    ```json
    {
      "scripts": {
        "build:watch": "tsc -w",
        "start:watch": "nodemon dist/index.js",
        "dev": "concurrently \"npm:build:watch\" \"npm:start:watch\"",
        "build": "tsc",
        "start": "node dist/index.js"
      }
    }
    ```
  </Tab>
</Tabs>

<Callout type="tip" title="Build & Deployment">
For production deployment, run `npm run build` to output type-checked, compiled JavaScript to `./dist`, then deploy only the `./dist` folder with production dependencies and run `node dist/index.js`.
</Callout>
