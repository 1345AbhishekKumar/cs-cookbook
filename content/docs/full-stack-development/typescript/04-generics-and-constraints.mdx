Generics allow you to write reusable functions, interfaces, and classes that work with a variety of data types while strictly **preserving type identity** between inputs and outputs.

---

## 1. Why Generics?

Consider an identity function:

```typescript
// BAD: Using 'any' destroys type safety
function badIdentity(arg: any): any {
  return arg;
}
const res1 = badIdentity("hello"); // Type is 'any' (Lost information!)

// GOOD: Generic parameter <T> captures the exact argument type
function identity<T>(arg: T): T {
  return arg;
}
const res2 = identity("hello"); // Type is strictly 'hello' or 'string'!
const res3 = identity(42);      // Type is strictly 'number'!
```

## 2. Generic Interfaces & Production Response Wrappers

In full-stack applications, API responses usually share a common envelope with varying payload data:

```typescript
interface ApiResponse<TData> {
  status: 200 | 400 | 500;
  success: boolean;
  data: TData;
  timestamp: string;
}

interface User {
  id: string;
  name: string;
}

interface Order {
  orderId: string;
  total: number;
}

// Concrete instantiated types
type UserResponse = ApiResponse<User>;
type OrderListResponse = ApiResponse<Order[]>;
```

## 3. Generic Constraints (`extends`)

Sometimes a function shouldn't accept *any* type, but only types that fulfill a certain minimal contract. Use `extends` to enforce a constraint:

```typescript
interface HasId {
  id: string | number;
}

// T must be an object with an 'id' property
function findById<T extends HasId>(items: T[], targetId: string | number): T | undefined {
  return items.find(item => item.id === targetId);
}

const users = [
  { id: "1", name: "Alice", email: "a@test.com" },
  { id: "2", name: "Bob", email: "b@test.com" }
];

const found = findById(users, "1"); // Inferred type is { id: string; name: string; email: string }
```

### Keyof Constraints (`K extends keyof T`)
Ensure that a second argument is guaranteed to be a valid property key on the first object:

```typescript
function getProperty<T, K extends keyof T>(obj: T, key: K): T[K] {
  return obj[key];
}

const developer = { name: "Sarah", seniority: "Staff", salary: 180000 };

const salary = getProperty(developer, "salary"); // Type: number
const seniority = getProperty(developer, "seniority"); // Type: string
// getProperty(developer, "invalidKey"); // Error: Argument of type '"invalidKey"' is not assignable to keyof...
```

## 4. Modern Const Type Parameters (`<const T>`)

Introduced in TypeScript 5.0, `<const T>` automatically infers narrow literal types at the call site without requiring developers to append `as const`:

```typescript
// Without <const T>: Types are widened to string[]
function setRoutesLegacy<T extends readonly string[]>(routes: T): T {
  return routes;
}
const r1 = setRoutesLegacy(["/home", "/about"]); // Type: string[]

// With modern <const T>: Preserves exact string literal tuple!
function setRoutesModern<const T extends readonly string[]>(routes: T): T {
  return routes;
}
const r2 = setRoutesModern(["/home", "/about"]); 
// Type: readonly ["/home", "/about"]!
```

## 5. Default Generic Parameters

Just like function default arguments, generics can provide sensible default types:

```typescript
interface RequestConfig<TPayload = Record<string, unknown>> {
  endpoint: string;
  method: "GET" | "POST";
  payload?: TPayload;
}

// Uses default Record<string, unknown>
const getReq: RequestConfig = { endpoint: "/users", method: "GET" };

// Overrides with custom typed payload
const postReq: RequestConfig<{ email: string }> = {
  endpoint: "/users",
  method: "POST",
  payload: { email: "alex@example.com" }
};
```
