CSS positioning dictates how elements are placed relative to their natural document flow, their parent containers, or the browser viewport.

---

## 1. The Five Positioning Schemes

| Position | Removed from Flow? | Coordinates Relative To | Common Use Cases |
| :--- | :--- | :--- | :--- |
| `static` | No (Default) | Normal document flow order | Standard text, paragraphs, buttons |
| `relative` | No | Itself (leaves original space reserved) | Anchor container for `absolute` children |
| `absolute` | Yes | Nearest positioned ancestor (`relative`, `absolute`, `fixed`) | Badges, tooltips, dropdown menus |
| `fixed` | Yes | The browser viewport | Floating action buttons, cookie consent bars |
| `sticky` | Hybrid | Normal flow until scroll threshold, then sticks | Sticky table headers, navigation bars |

---

## 2. Practical Positioning Examples

### Relative Parent with Absolute Child (Badge / Tooltip Pattern)

```css
.card {
  position: relative; /* 1. Establishes the coordinate origin */
  padding: 1.5rem;
  border-radius: 8px;
}

.notification-badge {
  position: absolute; /* 2. Positioned relative to .card */
  top: -8px;
  right: -8px;
  background-color: red;
  color: white;
  border-radius: 9999px;
  padding: 2px 8px;
}
```

### Modern Inset Shorthand (`inset: 0`)
Instead of typing `top: 0; right: 0; bottom: 0; left: 0;` to stretch an overlay across its parent, use the modern `inset` property:

```css
.modal-backdrop {
  position: fixed;
  inset: 0; /* Stretches 100% of viewport width and height */
  background-color: oklch(0 0 0 / 0.6);
  backdrop-filter: blur(4px);
}
```

### Sticky Headers (`position: sticky`)

A sticky element scrolls naturally with the page until it touches the specified offset, where it stays pinned:

```css
.table-header th {
  position: sticky;
  top: 0; /* Pins to top of scroll container */
  background-color: #ffffff;
  z-index: 10;
}
```

<Callout type="warn" title="Why Sticky Sometimes Fails to Stick">
If any parent ancestor has `overflow: hidden`, `overflow: auto`, or `overflow: scroll` declared without adequate height, `position: sticky` will fail to stick because its scrolling context is captured by that parent.
</Callout>

## 3. Demystifying the Stacking Context & Z-Index

A common source of developer frustration is setting `z-index: 999999` and having an element still appear behind another element.

### The Mental Model: Stacking Context Trees
Elements are not stacked in a single global list. Instead, they exist in **Stacking Context Trees**. An element in a lower parent stacking context can **never** appear in front of an element in a higher parent stacking context, regardless of how high its `z-index` is!

```
Root Stacking Context
├── Header (Stacking Context 1, z-index: 1)
│    └── Modal Child (z-index: 999999) <── Still locked inside Context 1!
└── Sidebar (Stacking Context 2, z-index: 2) <── Renders ABOVE Header & Modal!
```

### What Creates a Stacking Context?
1. The root element (`<html>`).
2. An element with `position: relative | absolute | fixed | sticky` AND a numeric `z-index` other than `auto`.
3. An element with `opacity` less than `1`.
4. An element with `transform`, `filter`, `perspective`, or `clip-path`.
5. An element with `isolation: isolate`.

---

## 4. The Modern Solution: `isolation: isolate`

To prevent child components from accidentally leaking z-indexes or getting trapped under sibling components, use `isolation: isolate`:

```css
.card-widget {
  position: relative;
  isolation: isolate; /* Creates a clean, isolated local stacking context */
}

.card-widget .internal-popover {
  z-index: 10; /* Only competes locally within .card-widget */
}
```

<Callout type="tip" title="Rule of Thumb for Z-Index">
Adopt an architectural scale for `z-index` tokens in your CSS variables:
```css
:root {
  --z-dropdown: 100;
  --z-sticky: 200;
  --z-fixed: 300;
  --z-modal-backdrop: 400;
  --z-modal: 500;
  --z-toast: 600;
}
```
</Callout>
