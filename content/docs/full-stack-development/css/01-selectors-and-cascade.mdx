CSS applies styles to HTML nodes by evaluating selectors against the DOM tree. When multiple conflicting rules match the same element, the browser's **Cascade Engine** determines the winning declaration.

---

## 1. Anatomy of a CSS Rule

```css
selector {
  property: value; /* Declaration */
}
```

```
.card-title {
  color: oklch(0.2 0.02 260);
  font-size: 1.5rem;
}
```

## 2. Modern Selectors & Combinators

### Basic & Attribute Selectors

```css
/* 1. Universal Selector */
* { margin: 0; }

/* 2. Type (Tag) Selector */
p { line-height: 1.6; }

/* 3. Class Selector */
.button-primary { background: blue; }

/* 4. ID Selector (Avoid for styling; creates high specificity) */
#main-navigation { position: sticky; }

/* 5. Attribute Selectors */
input[disabled] { opacity: 0.5; }
input[type="email"] { border-color: gray; }
a[href^="https"] { color: green; }      /* Starts with https */
a[href$=".pdf"] { padding-right: 20px; } /* Ends with .pdf */
a[href*="github"] { font-weight: bold; } /* Contains github */
```

### Combinators (Relational Targeting)

| Combinator | Syntax | Matches | Example |
| :--- | :--- | :--- | :--- |
| **Descendant** | `A B` | Any `B` nested anywhere inside `A` | `nav a` |
| **Direct Child** | `A > B` | Any `B` that is an immediate direct child of `A` | `ul > li` |
| **Adjacent Sibling** | `A + B` | The very next sibling `B` immediately after `A` | `h2 + p` (first paragraph after heading) |
| **General Sibling** | `A ~ B` | Any sibling `B` that appears anywhere after `A` | `h2 ~ p` |

## 3. Pseudo-classes & Pseudo-elements

### Useful Pseudo-classes

```css
/* User State */
button:hover { filter: brightness(1.1); }
button:active { transform: scale(0.98); }
input:focus-visible { outline: 2px solid blue; } /* Shows outline only for keyboard navigation */
input:disabled { cursor: not-allowed; }

/* Structural Position */
li:first-child { border-top: none; }
li:last-child { border-bottom: none; }
tr:nth-child(even) { background-color: #f8fafc; } /* Zebra striping */
tr:nth-child(3n + 1) { font-weight: bold; }

/* Logical Modern Pseudo-classes: :is() and :where() */
/* :is() adopts the highest specificity of its argument list */
:is(header, main, footer) h1 { font-size: 2rem; }

/* :where() ALWAYS has 0 specificity (Ideal for resets and libraries) */
:where(h1, h2, h3) { margin-top: 0; }

/* Negation */
button:not(.btn-disabled) { cursor: pointer; }
```

### Pseudo-elements (Creating Virtual DOM Nodes)

Pseudo-elements use a double colon `::` and generate styling anchors without modifying HTML markup:

```css
/* Adding visual icons or decorative accents */
.badge::before {
  content: "•";
  margin-right: 0.5rem;
  color: green;
}

/* Customizing input placeholder text */
input::placeholder {
  color: #94a3b8;
  font-style: italic;
}

/* Customizing user text selection highlight */
::selection {
  background-color: #3b82f6;
  color: white;
}
```

## 4. The Specificity Calculation Engine

When two rules target the exact same element with conflicting properties, the browser calculates a specificity tuple `(Inline, ID, Class, Element)`:

```
┌───────────────────────────────────────┬───────────────┐
│ Selector Level                        │ Weight Score  │
├───────────────────────────────────────┼───────────────┤
│ 1. Inline Styles (style="...")        │ (1, 0, 0, 0)  │
│ 2. IDs (#header)                      │ (0, 1, 0, 0)  │
│ 3. Classes, Attributes, Pseudo-classes│ (0, 0, 1, 0)  │
│ 4. Elements & Pseudo-elements (p, div)│ (0, 0, 0, 1)  │
└───────────────────────────────────────┴───────────────┘
```

### Specificity Comparison Example:
```css
/* Score: (0, 0, 0, 1) */
p { color: black; }

/* Score: (0, 0, 1, 1) -> 1 class + 1 element (WINS over p alone) */
article .lead { color: blue; }

/* Score: (0, 1, 0, 1) -> 1 ID + 1 element (WINS over classes) */
#hero p { color: purple; }

/* Score: (0, 0, 0, 0) -> :where() has ZERO specificity! */
:where(#hero) p { color: gray; }
```

<Callout type="warn" title="The !important Trap">
Adding `!important` overrides the normal cascade and specificity calculation. Using `!important` makes future debugging and overrides extremely painful. Keep specificity as flat as possible, using classes rather than IDs or `!important`.
</Callout>

## 5. Modern Cascade Layers (`@layer`)

Cascade Layers enable developers to structure CSS into explicit layers of precedence, solving the "specificity war" across third-party libraries, base styles, and utility classes:

```css
/* 1. Declare the explicit priority hierarchy from lowest to highest */
@layer reset, base, components, utilities;

/* Rules inside a higher layer ALWAYS defeat rules in a lower layer, regardless of specificity! */

@layer reset {
  * { box-sizing: border-box; margin: 0; }
}

@layer base {
  button {
    background-color: gray;
    padding: 0.5rem 1rem;
    font-size: 1rem;
  }
}

@layer components {
  /* This component style wins over the base button, even if base used an ID! */
  .btn-primary {
    background-color: #3b82f6;
    color: white;
  }
}

@layer utilities {
  /* Utilities have the highest priority */
  .hidden {
    display: none;
  }
}
```
