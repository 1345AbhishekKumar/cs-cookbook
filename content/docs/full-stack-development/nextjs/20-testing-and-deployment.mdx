## 1. Testing Next.js Applications

### 1. Unit Testing with Vitest
Use **Vitest** for fast, in-memory testing of utility functions, business logic, and isolated Client Components:

```typescript
// __tests__/utils.test.ts
import { describe, it, expect } from 'vitest';
import { formatCurrency } from '@/lib/utils';

describe('formatCurrency', () => {
  it('formats USD cents correctly', () => {
    expect(formatCurrency(1999)).toBe('$19.99');
  });
});
```

### 2. E2E Testing with Playwright (Recommended for RSC)

<Callout type="info" title="Why Playwright for Server Components?">
Asynchronous React Server Components rely on internal Next.js request contexts (`cookies()`, `headers()`, fetch cache stores) that standard JSDOM unit test runners cannot simulate. **Playwright End-to-End tests** run against real compiled production builds (`next build && next start`), providing true validation of server mutations, streaming, and cookies.
</Callout>

```typescript
// tests/checkout.spec.ts
import { test, expect } from '@playwright/test';

test('completes checkout flow with Server Action', async ({ page }) => {
  await page.goto('/cart');

  // Fill shipping form
  await page.fill('input[name="address"]', '742 Evergreen Terrace');
  await page.click('button[type="submit"]');

  // Verify server action redirected to order confirmation
  await expect(page).toHaveURL(/\/orders\/\d+/);
  await expect(page.locator('h1')).toContainText('Order Confirmed');
});
```

## 2. Docker Containerization (`output: 'standalone'`)

Next.js includes an `output: 'standalone'` option that automatically copies only the required `node_modules` into a minimal production bundle, shrinking Docker image sizes from ~1GB down to under ~120MB.

### 1. Configure `next.config.ts`

```typescript
// next.config.ts
import type { NextConfig } from 'next';

const nextConfig: NextConfig = {
  output: 'standalone', // Creates minimal server bundle in .next/standalone
};

export default nextConfig;
```

### 2. Multi-Stage Dockerfile

```dockerfile
# Stage 1: Dependencies
FROM node:20-alpine AS deps
WORKDIR /app
COPY package*.json ./
RUN npm ci

# Stage 2: Builder
FROM node:20-alpine AS builder
WORKDIR /app
COPY --from=deps /app/node_modules ./node_modules
COPY . .
RUN npm run build

# Stage 3: Runner
FROM node:20-alpine AS runner
WORKDIR /app
ENV NODE_ENV=production
ENV PORT=3000

# Copy standalone build output
COPY --from=builder /app/public ./public
COPY --from=builder /app/.next/standalone ./
COPY --from=builder /app/.next/static ./.next/static

EXPOSE 3000
CMD ["node", "server.js"]
```

## 3. Static Site Exports (`output: 'export'`)

If your application has no server runtime dependencies (no server actions, cookies, or dynamic routes), you can export a 100% static HTML/JS/CSS site for hosting on GitHub Pages, AWS S3, or Cloudflare Pages:

```typescript
// next.config.ts
import type { NextConfig } from 'next';

const nextConfig: NextConfig = {
  output: 'export',
  images: { unoptimized: true }, // Static hosting requires unoptimized images
};

export default nextConfig;
```

Running `next build` will output static static HTML files into the `out/` directory.
