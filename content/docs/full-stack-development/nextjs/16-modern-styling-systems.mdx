Styling full-stack applications in the Next.js App Router requires understanding the constraints of React Server Components: styles should generate zero client-side JavaScript runtime overhead.

---

## 1. Tailwind CSS v4 (CSS-First Architecture)

Tailwind CSS v4 is the modern standard for Next.js applications, adopting a CSS-first configuration that removes the legacy `tailwind.config.js` in favor of native CSS custom properties.

### Setup

```bash
npm install tailwindcss @tailwindcss/postcss postcss
```

```javascript
// postcss.config.mjs
export default {
  plugins: {
    '@tailwindcss/postcss': {},
  },
};
```

### Global Styles with `@theme`

```css
/* app/globals.css */
@import "tailwindcss";

@theme {
  --color-brand-primary: #3b82f6;
  --color-brand-accent: #10b981;
  --font-sans: var(--font-inter), sans-serif;
}
```

```tsx
// Using utility classes in a Server Component
export function HeroCard() {
  return (
    <div className="p-6 rounded-2xl bg-brand-primary text-white shadow-xl hover:scale-105 transition-transform">
      <h2 className="text-2xl font-bold font-sans">Next-Gen Full Stack</h2>
      <p className="mt-2 text-white/80">Tailwind CSS v4 with zero JavaScript overhead.</p>
    </div>
  );
}
```

## 2. CSS Modules (`*.module.css`)

CSS Modules are supported out of the box without extra build configuration. They scope class names locally to prevent naming collisions:

```css
/* components/Button.module.css */
.btnPrimary {
  background-color: #2563eb;
  color: #ffffff;
  padding: 0.75rem 1.5rem;
  border-radius: 0.5rem;
  font-weight: 600;
  transition: opacity 0.2s ease;
}

.btnPrimary:hover {
  opacity: 0.9;
}
```

```tsx
// components/Button.tsx
import styles from './Button.module.css';

export function Button({ children }: { children: React.ReactNode }) {
  return <button className={styles.btnPrimary}>{children}</button>;
}
```

## 3. CSS-in-JS Constraints with Server Components

<Callout type="warning" title="Runtime CSS-in-JS Limitations in RSC">
Legacy CSS-in-JS libraries (such as `styled-components` or `emotion`) rely on runtime style tag injection into the DOM via React Context and Hooks. Because Server Components have no client DOM access, using these libraries requires placing `'use client'` at the top of every styled file!
</Callout>

### Recommended Zero-Runtime Alternatives
- **Tailwind CSS**: Generates static CSS classes at build time.
- **shadcn/ui**: Copy-paste accessible components built on Tailwind and Radix UI primitives.
- **Vanilla Extract / StyleX**: Type-safe CSS-in-JS that compiles entirely to static `.css` stylesheets at build time.
