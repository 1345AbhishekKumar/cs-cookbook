Next.js features a powerful file-system based router built from the ground up to support React Server Components, nested UI trees, and streaming.

---

## 1. Core Terminology

- **Tree**: A convention for visualizing a hierarchical structure. For example, a component tree with parent and children components, or a directory folder structure.
- **Subtree**: Part of a tree, starting at a new root and ending at the leaves.
- **Root**: The first node in a tree or subtree, such as the root layout (`app/layout.tsx`).
- **Leaf**: Nodes in a subtree that have no children, such as the final `page.tsx` file in a URL path.
- **URL Segment**: Part of the URL path delimited by forward slashes `/`.
- **URL Path**: Part of the URL that comes after the domain host (composed of individual segments).

---

## 2. The App Router

The App Router lives inside the `app` directory. It works alongside the legacy `pages` directory to allow for incremental adoption.

<Callout type="info" title="Router Precedence">
The App Router takes priority over the Pages Router. Routes across directories must not resolve to the same URL path, as doing so will trigger a build-time conflict error.
</Callout>

By default, components inside `app` are **React Server Components (RSC)**. This improves initial load performance, reduces client JavaScript bundle sizes, and enables direct server-side data access.

## 3. Roles of Folders and Files

Next.js uses a strict file-system convention:

- **Folders**: Define the URL routes. A route is a single path of nested folders, following the file-system hierarchy from the root down to a final leaf folder.
- **Files**: Define the UI rendered for a specific route segment.

### Route Segments & Nested Routes

Each folder in a route represents a **route segment**, mapped directly to a segment in the URL:

```plaintext
app/
├── dashboard/                 # /dashboard (Segment)
│   ├── settings/              # /dashboard/settings (Leaf Segment)
│   │   └── page.tsx
│   └── page.tsx
└── layout.tsx                 # / (Root Segment)
```

---

## 4. Special File Conventions

Next.js provides a set of reserved filenames to create UI with specialized behavior in nested routes:

| File | Purpose | Description |
| :--- | :--- | :--- |
| `layout.tsx` | Layout | Shared UI for a segment and all its child segments. Preserves state across navigations. |
| `page.tsx` | Page | Unique UI for a route; makes route segments publicly accessible. |
| `loading.tsx` | Loading UI | Automatic Suspense boundary fallback for a segment and its children. |
| `not-found.tsx` | Not Found UI | Rendered when `notFound()` is triggered for a segment. |
| `error.tsx` | Error Boundary | React Error Boundary fallback for catching client and rendering errors (must be `'use client'`). |
| `global-error.tsx` | Global Error | Catches errors occurring within the Root Layout (`app/layout.tsx`). |
| `route.ts` | Route Handler | Server-side API endpoint handling HTTP verbs (`GET`, `POST`, `PUT`, etc.). |
| `template.tsx` | Template | Similar to layout, but remounts and re-creates state on every route change. |
| `default.tsx` | Parallel Fallback | Fallback UI for unmatched Parallel Route slots. |

> Supported extensions: `.js`, `.jsx`, `.ts`, or `.tsx`.

## 5. Component Hierarchy

React components defined in special files are nested automatically in a defined hierarchy:

```plaintext
<Layout>
  <Template>
    <ErrorBoundary (error.tsx)>
      <Suspense (loading.tsx)>
        <NotFoundBoundary (not-found.tsx)>
          <Page />
        </NotFoundBoundary>
      </Suspense>
    </ErrorBoundary>
  </Template>
</Layout>
```

In nested route folders, the inner segment's hierarchy is nested **inside** the children prop of its parent segment.

## 6. Next.js 15+ Async Page Props

In Next.js 15 and 16, page `params` and `searchParams` are asynchronous `Promise` objects. You must `await` them before reading:

```tsx
// app/blog/[slug]/page.tsx
type PageProps = {
  params: Promise<{ slug: string }>;
  searchParams: Promise<{ query?: string }>;
};

export default async function BlogPostPage({ params, searchParams }: PageProps) {
  const { slug } = await params;
  const { query } = await searchParams;

  return (
    <article>
      <h1>Post: {slug}</h1>
      {query && <p>Filtered by: {query}</p>}
    </article>
  );
}
```

## 7. Dynamic Route Segment Types

1. **Standard Dynamic Segment**: `app/shop/[category]/page.tsx` matches `/shop/shoes` (`params.category = 'shoes'`).
2. **Catch-All Segment**: `app/shop/[...slug]/page.tsx` matches `/shop/shoes/nike/air` (`params.slug = ['shoes', 'nike', 'air']`).
3. **Optional Catch-All Segment**: `app/shop/[[...slug]]/page.tsx` matches `/shop` as well as all nested sub-paths (`params.slug = undefined` at root).

### Pre-generating Static Routes with `generateStaticParams`

```tsx
// app/blog/[slug]/page.tsx
export async function generateStaticParams() {
  const posts = await fetch('https://api.example.com/posts').then((res) => res.json());
  return posts.map((post: { slug: string }) => ({ slug: post.slug }));
}
```

## 8. Route Groups `(folder)`

Wrap folder names in parentheses `(groupName)` to organize files logically without modifying the URL path:

```plaintext
app/
├── (marketing)/
│   ├── about/page.tsx         # Resolves to /about
│   └── layout.tsx             # Marketing Layout
├── (shop)/
│   ├── cart/page.tsx          # Resolves to /cart
│   └── layout.tsx             # Shop Layout
└── layout.tsx
```

### Multiple Root Layouts
You can delete the root `app/layout.tsx` and place distinct root layouts inside separate Route Groups (e.g. `(marketing)/layout.tsx` and `(app)/layout.tsx`), each defining independent `<html>` and `<body>` tags.

## 9. Linking & Client Navigation

### `<Link>` Component

```tsx
import Link from 'next/link';

export function Navigation() {
  return (
    <nav>
      <Link href="/dashboard">Dashboard</Link>
      <Link href="/dashboard/settings" prefetch={true}>Settings</Link>
    </nav>
  );
}
```

### Programmatic Navigation with `useRouter()`

In Client Components (`'use client'`), use `useRouter()` from `next/navigation`:

```tsx
'use client';

import { useRouter } from 'next/navigation';

export function LogoutButton() {
  const router = useRouter();

  return (
    <button type="button" onClick={() => router.push('/login')}>
      Log Out
    </button>
  );
}
```
