The directive system (`'use client'`, `'use server'`, and Next.js 16's `'use cache'`) establishes explicit contracts between server and client execution environments. Misunderstanding these directives is one of the most common pitfalls for full-stack React developers.

---

## 1. Directive Comparison Matrix

| Directive | Specification | Role & True Meaning | Where Placed |
| :--- | :--- | :--- | :--- |
| `'use client'` | React Directive | **Boundary Marker**: Declares the entry boundary to the client component tree. Components **still render on the server during SSR** for initial HTML, then hydrate in the browser. | Top of a file before imports. |
| `'use server'` | React Directive | **RPC Action Declaration**: Marks an asynchronous function as a **Server Action** callable from the client across the network. It does **not** create a Server Component. | Top of an action file or top of an `async` function body. |
| `'use cache'` | Next.js 16 Directive | **Cache Boundary**: Instructs Next.js to cache the component, function, or file output across requests using Cache Components. | Top of a file or top of an `async` function. |

---

## 2. Debunking the Top 3 Directive Myths

### Myth 1: "'use client' means the component runs only in the browser."
**Reality**: Client Components still execute on the server during the initial page request to generate the initial HTML shell. This ensures fast First Contentful Paint (FCP) and SEO indexing. The directive simply indicates that the component will **hydrate** and become interactive in the browser.

### Myth 2: "'use server' marks a component as a Server Component."
**Reality**: Server Components have **no directive**. All components in the Next.js `app` directory are Server Components by default. `'use server'` designates an asynchronous function as a **Server Action** (a public RPC endpoint).

### Myth 3: "I must add 'use server' to every page.tsx file."
**Reality**: Adding `'use server'` to the top of a component file does not make it a Server Component; it causes an error because React components cannot be Server Actions. Omit directives entirely for standard Server Components.

## 3. The Leaf-Node Interactivity Rule

To maintain optimal performance and keep client JavaScript bundle sizes minimal, follow the **Leaf-Node Principle**:

```plaintext
                    [ app/layout.tsx ] (Server Component)
                            │
                    [ app/page.tsx ] (Server Component)
                            │
               ┌────────────┴────────────┐
               ▼                         ▼
      [ ProductList.tsx ]       [ Sidebar.tsx ] (Server Component)
      (Server Component)                 │
               │                         ▼
               ▼                [ FilterTabs.tsx ] ('use client')
      [ LikeButton.tsx ]         (Interactive Leaf Node)
      ('use client')
      (Interactive Leaf Node)
```

<Callout type="tip" title="Keep 'use client' at the Leaves">
Avoid placing `'use client'` at the root of a page or layout. Instead, fetch data in parent Server Components and extract interactive widgets (buttons, dropdowns, inputs) into separate Client Component leaves.
</Callout>

## 4. Code Examples

### 1. Using `'use client'` for Interactive UI

```tsx
// components/Counter.tsx
'use client'; // Required for useState, useEffect, onClick

import { useState } from 'react';

export function Counter() {
  const [count, setCount] = useState(0);

  return (
    <div className="flex gap-2 items-center">
      <span>Count: {count}</span>
      <button onClick={() => setCount((c) => c + 1)}>+</button>
    </div>
  );
}
```

### 2. Using `'use server'` for Server Actions

```tsx
// app/actions/subscribe.ts
'use server'; // Defines server-executable functions (Server Actions)

import db from '@/lib/db';
import { revalidatePath } from 'next/cache';

export async function subscribeNewsletter(formData: FormData) {
  const email = formData.get('email') as string;

  if (!email || !email.includes('@')) {
    return { error: 'Invalid email address' };
  }

  await db.subscriber.create({ data: { email } });
  revalidatePath('/newsletter');

  return { success: true };
}
```

```tsx
// components/NewsletterForm.tsx ('use client')
'use client';

import { subscribeNewsletter } from '@/app/actions/subscribe';

export function NewsletterForm() {
  return (
    <form action={subscribeNewsletter}>
      <input type="email" name="email" required placeholder="Enter email" />
      <button type="submit">Subscribe</button>
    </form>
  );
}
```

## 5. Security Warning: Server Actions are Public RPC Endpoints

<Callout type="warning" title="Server Actions are Public HTTP Endpoints">
When an async function is marked with `'use server'`, Next.js creates an HTTP POST endpoint for it. Always authenticate user sessions and validate inputs using libraries like **Zod** inside Server Actions:
```typescript
'use server';

export async function deleteUser(userId: string) {
  const session = await auth(); // Verify session
  if (!session || session.role !== 'ADMIN') {
    throw new Error('Unauthorized');
  }
  await db.user.delete({ where: { id: userId } });
}
```
</Callout>
