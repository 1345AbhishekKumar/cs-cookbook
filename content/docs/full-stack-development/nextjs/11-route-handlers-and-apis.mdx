Route Handlers allow you to create custom HTTP request handlers for a given route using the Web Standard `Request` and `Response` APIs. They live inside `route.ts` files within the `app` directory.

---

## 1. Supported HTTP Methods

Next.js supports standard HTTP verbs by exporting uppercase functions:

```typescript
// app/api/items/route.ts
import { NextRequest, NextResponse } from 'next/server';
import db from '@/lib/db';

// GET: Retrieve a list
export async function GET(request: NextRequest) {
  const items = await db.item.findMany();
  return NextResponse.json(items);
}

// POST: Create a resource
export async function POST(request: NextRequest) {
  const body = await request.json();
  const newItem = await db.item.create({ data: body });
  return NextResponse.json(newItem, { status: 201 });
}
```

<Callout type="warning" title="No Colocation with page.tsx">
A `route.ts` file cannot exist at the same URL segment level as a `page.tsx` file. Doing so causes a route conflict during build time.
</Callout>

## 2. Dynamic Route Handlers with Async Params

Dynamic segments work identical to pages, with `params` being an asynchronous `Promise`:

```typescript
// app/api/items/[id]/route.ts
import { NextRequest, NextResponse } from 'next/server';
import db from '@/lib/db';

type Context = {
  params: Promise<{ id: string }>;
};

export async function GET(request: NextRequest, { params }: Context) {
  const { id } = await params;
  const item = await db.item.findUnique({ where: { id } });

  if (!item) {
    return NextResponse.json({ error: 'Item not found' }, { status: 404 });
  }

  return NextResponse.json(item);
}

export async function DELETE(request: NextRequest, { params }: Context) {
  const { id } = await params;
  await db.item.delete({ where: { id } });
  return new NextResponse(null, { status: 204 });
}
```

## 3. Webhook Integration (Stripe Example)

Route Handlers are the standard way to accept external third-party webhooks (Stripe, GitHub, Clerk) that require raw body access for cryptographic signature verification:

```typescript
// app/api/webhooks/stripe/route.ts
import { NextRequest, NextResponse } from 'next/server';
import Stripe from 'stripe';

const stripe = new Stripe(process.env.STRIPE_SECRET_KEY!);

export async function POST(req: NextRequest) {
  const payload = await req.text(); // Raw payload string
  const signature = req.headers.get('stripe-signature')!;

  try {
    const event = stripe.webhooks.constructEvent(
      payload,
      signature,
      process.env.STRIPE_WEBHOOK_SECRET!
    );

    if (event.type === 'checkout.session.completed') {
      // Fulfill user purchase in database
    }

    return NextResponse.json({ received: true });
  } catch (err: any) {
    return NextResponse.json({ error: err.message }, { status: 400 });
  }
}
```

## 4. Route Handlers vs. Server Actions

| Capability | Route Handlers (`route.ts`) | Server Actions (`'use server'`) |
| :--- | :---: | :---: |
| Primary Use Case | Public REST APIs, Webhooks, Mobile Apps | UI Form submissions, direct mutations |
| Protocol | Standard HTTP REST endpoints | RPC over HTTP POST |
| Revalidation Integration | Manual cache revalidation | Native (`revalidatePath`, `revalidateTag`) |
| Progressive Enhancement | Requires manual client JavaScript | Works natively with HTML `<form>` |
| CORS Configuration | Highly customizable | Internal to application |
