In the App Router, data fetching is **server-first**. Because Server Components run strictly on the server, you can query databases and internal services directly without building intermediary API routes.

---

## 1. Direct Database & ORM Access

You do not need to call `fetch('http://localhost:3000/api/users')` from a Server Component. Call your database client (Prisma, Drizzle, MongoDB, Supabase) directly:

```tsx
// app/users/page.tsx
import db from '@/lib/db';

export default async function UsersPage() {
  // Direct ORM query running on the server
  const users = await db.user.findMany({
    orderBy: { createdAt: 'desc' },
  });

  return (
    <div>
      <h1>Registered Users</h1>
      <ul>
        {users.map((user) => (
          <li key={user.id}>{user.name} ({user.email})</li>
        ))}
      </ul>
    </div>
  );
}
```

## 2. Next.js 15+ Async Request APIs

<Callout type="warning" title="Breaking Change in Next.js 15 & 16">
Request-time properties—including `cookies()`, `headers()`, `params`, and `searchParams`—are now asynchronous Promises and **must be awaited**.
</Callout>

### 1. Reading Cookies & Headers

```tsx
// app/account/page.tsx
import { cookies, headers } from 'next/headers';

export default async function AccountPage() {
  const cookieStore = await cookies();
  const token = cookieStore.get('auth_token')?.value;

  const headerList = await headers();
  const userAgent = headerList.get('user-agent');

  return (
    <div>
      <p>Session: {token ? 'Active' : 'Unauthenticated'}</p>
      <p>Client: {userAgent}</p>
    </div>
  );
}
```

### 2. Awaiting Dynamic Parameters

```tsx
// app/products/[id]/page.tsx
type Props = {
  params: Promise<{ id: string }>;
  searchParams: Promise<{ sort?: string }>;
};

export default async function ProductPage({ params, searchParams }: Props) {
  const { id } = await params;
  const { sort } = await searchParams;

  return <div>Product ID: {id} (Sort: {sort ?? 'default'})</div>;
}
```

## 3. The Extended Web `fetch` API

Next.js patches the native Web `fetch` function to provide per-request caching and revalidation controls:

```tsx
// 1. Uncached fetch (Default in Next.js 15+)
const dynamicData = await fetch('https://api.example.com/prices', {
  cache: 'no-store',
});

// 2. Cached fetch (Persisted in Data Cache)
const staticData = await fetch('https://api.example.com/categories', {
  cache: 'force-cache',
});

// 3. Time-based revalidation (Incremental Static Regeneration)
const timedData = await fetch('https://api.example.com/news', {
  next: { revalidate: 3600 }, // Revalidate every hour
});

// 4. Tagged fetch for on-demand revalidation
const taggedData = await fetch('https://api.example.com/inventory', {
  next: { tags: ['inventory'] },
});
```

## 4. Preventing Network Waterfalls with `Promise.all`

A waterfall occurs when sequential `await` calls block parallel data retrieval. Initiate independent fetches simultaneously:

```tsx
// ❌ Sequential Waterfall (Slow: 2s + 2s = 4s total)
const user = await fetchUser(userId);
const posts = await fetchPosts(userId);

// ✅ Parallel Execution (Fast: max(2s, 2s) = 2s total)
const userPromise = fetchUser(userId);
const postsPromise = fetchPosts(userId);

const [user, posts] = await Promise.all([userPromise, postsPromise]);
```
