Caching is often the most misunderstood part of Next.js. Next.js operates a multi-layered caching architecture designed to maximize performance, but developers must understand which layer controls which data.

---

## 1. The 4 Caching Mechanisms

| Cache Layer | Where It Lives | What It Caches | Lifecycle | How to Invalidate |
| :--- | :--- | :--- | :--- | :--- |
| **Request Memoization** | Server (Memory) | Return values of identical `fetch` requests | Single render pass per incoming request | Automatic (cleared when render finishes) |
| **Data Cache** | Server (Disk / Store) | HTTP `fetch` responses across users | Persistent across requests and deployments | `revalidateTag()` or `revalidatePath()` |
| **Full Route Cache** | Server (Disk / CDN) | HTML and RSC Payload for static routes | Persistent until revalidation | Triggered when Data Cache revalidates |
| **Router Cache** | Client (Browser Memory) | Visited and prefetched route segments | User session / browser tab navigation | `router.refresh()` or navigation |

---

## 2. Next.js 15 Caching Shift: Uncached by Default

In Next.js 14, `fetch` cached aggressively (`force-cache`). Starting in **Next.js 15 and 16**:
- `fetch` defaults to **`no-store`** (uncached).
- `GET` Route Handlers are uncached by default.
- Client page router cache has a `staleTime` of 0.

---

## 3. Next.js 16 Cache Components: The `'use cache'` Directive

Next.js 16 replaced legacy `unstable_cache()` with the native **`'use cache'`** directive. Instead of configuring caching solely via `fetch`, you can now cache entire components or asynchronous helper functions.

### 1. Function-Level Caching

```typescript
// lib/products.ts
import { cacheLife, cacheTag } from 'next/cache';
import db from '@/lib/db';

export async function getTopProducts() {
  'use cache'; // Marks this function's output as cached!

  cacheLife('hours'); // Built-in profiles: 'seconds', 'minutes', 'hours', 'days', 'max'
  cacheTag('products', 'top-products');

  return db.product.findMany({
    where: { featured: true },
  });
}
```

### 2. Component-Level Caching

You can cache an entire Server Component render tree:

```tsx
// components/FeaturedGrid.tsx
import { cacheLife } from 'next/cache';

export async function FeaturedGrid() {
  'use cache';
  cacheLife('days');

  const items = await fetchCatalog();

  return (
    <div className="grid grid-cols-3">
      {items.map((item) => (
        <div key={item.id}>{item.name}</div>
      ))}
    </div>
  );
}
```

## 4. Cache Invalidation & Revalidation

### 1. Background Revalidation (`revalidateTag` & `revalidatePath`)

Marks cache entries as stale; subsequent visitors receive fresh data once recomputed (Stale-While-Revalidate):

```typescript
'use server';

import { revalidateTag, revalidatePath } from 'next/cache';

export async function refreshProductCatalog() {
  revalidateTag('products');       // Invalidate by cache tag
  revalidatePath('/dashboard');    // Invalidate full route
}
```

### 2. Same-Request Consistency (`updateTag` in Next.js 16)

When a user mutates data and immediately views the updated value (read-your-writes consistency), use `updateTag()` inside Server Actions:

```typescript
'use server';

import { updateTag } from 'next/cache';

export async function updateUsername(formData: FormData) {
  const newName = formData.get('name') as string;
  await db.user.update({ data: { name: newName } });

  // Guarantees immediate cache refresh for this exact request!
  updateTag('user-profile');
}
```
