Middleware allows you to intercept and modify incoming HTTP requests before they resolve to any route handler or page component. It executes at the network layer, making it ideal for authentication checks, geolocation, and internationalization redirects.

---

## 1. File Location & Matcher Configuration

Middleware is defined in a file named `middleware.ts` (or `proxy.ts` in Next.js 16) at the root of the project (or inside `src/`):

```typescript
// middleware.ts
import { NextResponse } from 'next/server';
import type { NextRequest } from 'next/server';

export function middleware(request: NextRequest) {
  // Logic runs for matched routes
  return NextResponse.next();
}

// Configure which paths trigger Middleware
export const config = {
  matcher: [
    /*
     * Match all request paths except:
     * - _next/static (static files)
     * - _next/image (image optimization files)
     * - favicon.ico, sitemap.xml, robots.txt
     */
    '/((?!_next/static|_next/image|favicon.ico|sitemap.xml|robots.txt).*)',
  ],
};
```

## 2. Common Middleware Use Cases

### 1. Conditional Authentication Redirect

Check session cookies and redirect unauthorized traffic to the login page:

```typescript
// middleware.ts
import { NextResponse } from 'next/server';
import type { NextRequest } from 'next/server';

export function middleware(request: NextRequest) {
  const sessionToken = request.cookies.get('session_token')?.value;
  const isDashboardRoute = request.nextUrl.pathname.startsWith('/dashboard');

  if (isDashboardRoute && !sessionToken) {
    const loginUrl = new URL('/login', request.url);
    loginUrl.searchParams.set('redirect', request.nextUrl.pathname);
    return NextResponse.redirect(loginUrl);
  }

  return NextResponse.next();
}
```

### 2. URL Rewriting (Multi-Tenant / Subdomain Routing)

Rewrite the internal path without changing the URL displayed in the browser:

```typescript
export function middleware(request: NextRequest) {
  const hostname = request.headers.get('host')!;
  const subdomain = hostname.split('.')[0]; // e.g. "acme" from "acme.platform.com"

  if (subdomain && subdomain !== 'www') {
    // Internally rewrites /feed to /tenants/acme/feed
    return NextResponse.rewrite(
      new URL(`/tenants/${subdomain}${request.nextUrl.pathname}`, request.url)
    );
  }

  return NextResponse.next();
}
```

### 3. Setting Cookies & Custom Response Headers

```typescript
export function middleware(request: NextRequest) {
  const response = NextResponse.next();

  // Inject secure session cookie
  response.cookies.set('visited_region', 'eu-west', {
    httpOnly: true,
    sameSite: 'lax',
  });

  // Inject security headers
  response.headers.set('X-Frame-Options', 'DENY');
  response.headers.set('X-Content-Type-Options', 'nosniff');

  return response;
}
```

## 3. Important Architectural Limitation

<Callout type="warning" title="Do Not Rely on Middleware Alone for Security">
Middleware acts as an **optimistic gatekeeper**. Because attackers could circumvent edge proxy rules or invoke Server Actions via crafted RPC POST requests, **definitive data authorization must always be enforced in the Data Access Layer (DAL) and inside Server Actions**.
</Callout>
