Regular expressions (**RegExp**) are patterns used to match character combinations within strings. In JavaScript, regular expressions are first-class objects used extensively for form validation, string searching, token parsing, and data sanitization.

---

## 1. Creating Regular Expressions

JavaScript provides two distinct syntaxes for creating a `RegExp`:

<Tabs items={['Literal Notation (Preferred)', 'Constructor Function']}>
  <Tab value="Literal Notation (Preferred)">
    Regex literals are compiled when the script is loaded and offer better performance when the pattern remains static:

    ```javascript
    const regex = /pattern/flags;
    const emailRegex = /^[^\s@]+@[^\s@]+\.[^\s@]+$/i;
    ```
  </Tab>
  <Tab value="Constructor Function">
    Use the `RegExp` constructor when the pattern is dynamic or constructed at runtime (e.g. from user input):

    ```javascript
    const searchTerm = "javascript";
    const dynamicRegex = new RegExp(searchTerm, "gi");
    ```
    <Callout type="warn" title="Escape Backslashes in Strings">
    When passing string literals to `new RegExp()`, remember that the backslash `\` is an escape character in strings, so you must double-escape it: `new RegExp("\\d+", "g")`.
    </Callout>
  </Tab>
</Tabs>

## 2. Core Evaluation Methods: `.test()` vs `.match()`

JavaScript splits regex operations across `RegExp` prototype methods and `String` prototype methods:

| Method | Target | Return Value | Common Use Case |
| :--- | :--- | :--- | :--- |
| `regex.test(str)` | `RegExp` | `boolean` (`true` / `false`) | Fast validation (e.g., checking if email or phone is valid) |
| `regex.exec(str)` | `RegExp` | Match array with capture groups, or `null` | Detailed search with indices and captures |
| `str.match(regex)` | `String` | Array of matches or `null` | Extracting matching substrings |
| `str.matchAll(regex)` | `String` | Iterator of match objects | Capturing multiple groups across global searches |
| `str.replace(regex, sub)` | `String` | Replaced new string | Data cleaning, masking, formatting |
| `str.split(regex)` | `String` | Array of substrings | Splitting by complex delimiters (commas, spaces) |

### Testing with `.test()`
```javascript
const wordRegex = /code/i;
console.log(wordRegex.test("freeCodeCamp")); // true
console.log(wordRegex.test("JavaScript"));   // false

// Matching multiple alternatives with pipe (|)
const petRegex = /cat|dog|bird|fish/i;
console.log(petRegex.test("James has a pet cat.")); // true
```

### Extracting Matches with `.match()`
```javascript
const phrase = "The five boxing wizards jump quickly.";
// Extract all occurrences of alphanumeric words
const words = phrase.match(/\w+/g);
console.log(words); 
// ['The', 'five', 'boxing', 'wizards', 'jump', 'quickly']
```

## 3. Flags

Flags modify how pattern matching behaves:

```javascript
// Case-insensitive ('i') and Global ('g')
const greeting = "Hello hello HeLLo";
const matches = greeting.match(/hello/gi);
console.log(matches); // ['Hello', 'hello', 'HeLLo']
```

| Flag | Name | Behavior |
| :--- | :--- | :--- |
| `g` | Global | Finds all matches rather than stopping after the first match |
| `i` | Ignore Case | Case-insensitive matching (`/a/i` matches `'a'` and `'A'`) |
| `m` | Multiline | `^` and `$` match start/end of each line, not just the whole string |
| `s` | dotAll | Allows the dot `.` wildcard to match newline characters `\n` |
| `u` | Unicode | Enables full Unicode support (e.g. emojis and surrogates) |
| `y` | Sticky | Matches only from the index indicated by `lastIndex` |

## 4. Character Classes & Sets

Character classes let you match specific sets or categories of characters:

### Character Sets `[...]` & Negation `[^...]`
```javascript
// Matches 'bag', 'big', 'bug', but NOT 'bog'
const vowelRegex = /b[aiu]g/;
console.log(vowelRegex.test("big")); // true
console.log(vowelRegex.test("bog")); // false

// Ranges: letters a-z and numbers 0-5
const alphanumericRegex = /[a-z0-5]/i;

// Negated set: Match anything EXCEPT digits and vowels
const negatedRegex = /[^0-9aeiou]/gi;
const sample = "3 blind mice.";
console.log(sample.match(negatedRegex)); 
// [' ', 'b', 'l', 'n', 'd', ' ', 'm', 'c', '.']
```

### Shorthand Character Classes
```javascript
// \w: Alphanumeric + underscore [a-zA-Z0-9_]
// \W: Negation of \w (symbols, whitespace)
// \d: Digits [0-9]
// \D: Non-digits
// \s: Whitespace (spaces, tabs, newlines [\r\t\f\n\v])
// \S: Non-whitespace

const licensePlate = "MH-12-AB-1234";
const digitsOnly = licensePlate.match(/\d/g);
console.log(digitsOnly.join("")); // "121234"
```

## 5. Quantifiers & Match Modifiers

Quantifiers determine how many times an element may repeat:

| Quantifier | Meaning | Example |
| :--- | :--- | :--- |
| `*` | 0 or more times | `/go*/` matches `'g'`, `'go'`, `'goooo'` |
| `+` | 1 or more times | `/s+/` matches `'s'`, `'ss'`, `'sss'` |
| `?` | 0 or 1 time (optional) | `/colou?r/` matches `'color'` and `'colour'` |
| `{n}` | Exactly `n` times | `/\d{4}/` matches 4 digits |
| `{n,}` | At least `n` times | `/\w{3,}/` matches 3 or more alphanumeric characters |
| `{n,m}` | Between `n` and `m` times | `/Oh{3,6}\sno/` matches `'Ohhh no'` to `'Ohhhhhh no'` |

### Greedy vs Lazy Matching

By default, quantifiers in regular expressions are **greedy** — they consume the longest possible matching substring. Appending a `?` after a quantifier makes it **lazy** (reluctant), matching the smallest sequence possible:

```javascript
const html = "<h1>Title</h1><p>Paragraph</p>";

// Greedy: consumes up to the LAST '>'
const greedyMatch = html.match(/<.*>/);
console.log(greedyMatch[0]); 
// "<h1>Title</h1><p>Paragraph</p>"

// Lazy: stops at the FIRST '>'
const lazyMatch = html.match(/<.*?>/g);
console.log(lazyMatch); 
// ['<h1>', '</h1>', '<p>', '</p>']
```

## 6. Anchors & Boundaries

Anchors assert positions rather than matching characters:

```javascript
// ^: Start of string
// $: End of string
// \b: Word boundary

const startRegex = /^Ricky/;
console.log(startRegex.test("Ricky is here"));  // true
console.log(startRegex.test("Where is Ricky?")); // false

const endRegex = /found$/;
console.log(endRegex.test("All lost items were found")); // true
```

### Production Pattern: Username Validation
A classic constraint requirement:
1. Must start with a letter (`^[a-zA-Z]`).
2. Followed by letters or numbers.
3. Length between 3 and 16 characters (`{2,15}$`).

```javascript
function isValidUsername(username) {
  const usernameRegex = /^[a-zA-Z][a-zA-Z0-9_]{2,15}$/;
  return usernameRegex.test(username);
}

console.log(isValidUsername("alice_99")); // true
console.log(isValidUsername("99alice"));   // false (starts with digit)
console.log(isValidUsername("al"));       // false (too short)
```

<Callout type="tip" title="Catastrophic Backtracking Warning">
Avoid nesting quantifiers like `(a+)+` or `([a-zA-Z0-9]+)*$` when validating user input. Malicious input strings can trigger exponential regex backtracking (ReDoS attacks) that freeze the JavaScript event loop.
</Callout>
