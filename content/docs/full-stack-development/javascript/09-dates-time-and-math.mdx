In JavaScript, date and time calculations are driven by the built-in `Date` object, which represents time as a millisecond integer offset from the **ECMAScript Epoch** (**midnight January 1, 1970, UTC**). Mathematical calculations are provided through the static `Math` namespace.

---

## 1. Creating Date Objects

JavaScript offers four distinct ways to construct a `Date` instance:

```javascript
// 1. Current timestamp
const now = new Date();

// 2. Milliseconds since Jan 1, 1970 UTC
const epochOffset = new Date(1_000_000_000_000); 

// 3. Date string (ISO 8601 recommended)
const isoDate = new Date("2026-10-04T22:30:00Z");

// 4. Component arguments: (year, monthIndex, day, hours, minutes, seconds, ms)
const scheduled = new Date(2026, 9, 4, 15, 30); // Note: Month is 0-indexed!
```

<Callout type="warn" title="The 0-Indexed Month Gotcha">
In JavaScript, **months are 0-indexed** (January is `0`, December is `11`). However, days of the month (`getDate()`) are **1-indexed** (1 to 31), and days of the week (`getDay()`) are **0-indexed** (Sunday is `0`, Saturday is `6`).
</Callout>

## 2. ISO 8601 Standard & UTC vs Local Time

The ISO 8601 format (`YYYY-MM-DDTHH:mm:ss.sssZ`) is the industry standard for serializing dates in APIs and databases:
- **`T`** separates the calendar date from the time.
- **`Z`** specifies zero UTC offset (Zulu time). If omitted or replaced by an offset like `+05:30`, local timezone parsing occurs.

```javascript
const utcDate = new Date("2026-07-01T12:00:00Z");

// Returns hours in the browser/server's local timezone
console.log(utcDate.getHours());

// Returns hours in UTC (Universal Time Coordinated)
console.log(utcDate.getUTCHours()); // Always 12
```

## 3. Core Date Methods Reference

The `Date` object exposes both local and UTC accessor methods:

| Task | Local Time Method | UTC Equivalent | Output Range |
| :--- | :--- | :--- | :--- |
| **Current Epoch Time** | `Date.now()` | `Date.now()` | Milliseconds (`number`) |
| **Year** | `date.getFullYear()` | `date.getUTCFullYear()` | 4-digit year (e.g. `2026`) |
| **Month** | `date.getMonth()` | `date.getUTCMonth()` | `0` – `11` |
| **Day of Month** | `date.getDate()` | `date.getUTCDate()` | `1` – `31` |
| **Day of Week** | `date.getDay()` | `date.getUTCDay()` | `0` (Sun) – `6` (Sat) |
| **Hours** | `date.getHours()` | `date.getUTCHours()` | `0` – `23` |
| **Minutes** | `date.getMinutes()` | `date.getUTCMinutes()` | `0` – `59` |
| **Seconds** | `date.getSeconds()` | `date.getUTCSeconds()` | `0` – `59` |
| **Time Offset** | `date.getTimezoneOffset()` | *N/A* | Difference in minutes to UTC |

### Auto-Correction Behavior (Date Rollover)

When you supply an out-of-bounds value to date setters, JavaScript automatically rolls over the calendar mathematically:

```javascript
const eventDate = new Date(2026, 1, 15); // February 15, 2026

// Setting day to 35 in February automatically rolls over into March
eventDate.setDate(35); 
console.log(eventDate.toLocaleDateString()); // 3/7/2026 (March 7th)

// Subtracting days via negative offsets:
eventDate.setDate(eventDate.getDate() - 10);
```

## 4. Modern Date Formatting: `Intl.DateTimeFormat`

Instead of fragile manual string slicing (`month + "/" + day + "/" + year`), production applications use the standard **ECMAScript Internationalization API** (`Intl`):

```javascript
const timestamp = new Date("2026-10-04T18:00:00Z");

const formatter = new Intl.DateTimeFormat("en-US", {
  dateStyle: "full",
  timeStyle: "short",
  timeZone: "America/New_York",
});

console.log(formatter.format(timestamp));
// "Sunday, October 4, 2026 at 2:00 PM"
```

## 5. Mathematical Operations & The `Math` Object

The global `Math` object contains static mathematical constants and functions:

### Generating Random Numbers & Ranges
`Math.random()` returns a pseudo-random floating-point number in the range `[0, 1)` (inclusive of 0, but strictly less than 1).

```javascript
// Generating an integer between min and max (inclusive)
function getRandomInt(min, max) {
  min = Math.ceil(min);
  max = Math.floor(max);
  return Math.floor(Math.random() * (max - min + 1)) + min;
}

console.log(getRandomInt(1, 10)); // Integer from 1 to 10
```

### Picking Random Elements from Arrays
```javascript
const frameworks = ["React", "Vue", "Angular", "Svelte", "Solid"];

function getRandomItem(arr) {
  const randomIndex = Math.floor(Math.random() * arr.length);
  return arr[randomIndex];
}

console.log(getRandomItem(frameworks)); // e.g. "React"
```

### Rounding Comparison

| Method | Behavior | Example (`x = 4.7`) | Example (`x = -4.7`) |
| :--- | :--- | :--- | :--- |
| `Math.floor(x)` | Rounds **down** to nearest integer | `4` | `-5` |
| `Math.ceil(x)` | Rounds **up** to nearest integer | `5` | `-4` |
| `Math.round(x)` | Rounds to **nearest** integer | `5` | `-5` |
| `Math.trunc(x)` | Truncates decimal part towards zero | `4` | `-4` |

## 6. Floating Point Precision Caveat

JavaScript represents all numbers as IEEE 754 double-precision floats. This introduces rounding inaccuracies when dealing with base-10 decimals:

```javascript
console.log(0.1 + 0.2 === 0.3); // false!
console.log(0.1 + 0.2);         // 0.30000000000000004
```

### Production Workaround:
For financial calculations, perform arithmetic in integer cents (e.g., `$19.99` represented as `1999`) or use `Number.EPSILON`:

```javascript
function numbersAreEqual(a, b) {
  return Math.abs(a - b) < Number.EPSILON;
}

console.log(numbersAreEqual(0.1 + 0.2, 0.3)); // true
```
