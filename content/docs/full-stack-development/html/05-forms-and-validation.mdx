Forms are the primary interactive channel for data collection in web applications. Whether building user authentication, payment processing, or admin dashboards, properly structured forms are critical for usability, accessibility, and security.

---

## 1. The `<form>` Element Architecture

```html
<form action="/api/v1/auth/register" method="POST" enctype="application/x-www-form-urlencoded">
  <!-- Form controls go here -->
  <button type="submit">Submit</button>
</form>
```

### Essential Form Attributes:
- **`action`**: The server-side endpoint URL that processes the submitted form data.
- **`method`**:
  - `GET`: Appends form data to the URL as query parameters (`?query=books&page=2`). Use for searches or filters. Never use for sensitive data (passwords, tokens).
  - `POST`: Packages form data inside the HTTP request body. Use for mutating state, creating records, and authentication.
- **`enctype`**:
  - `application/x-www-form-urlencoded` (Default): Encodes values as URL key-value pairs.
  - `multipart/form-data`: **Mandatory** when the form includes file uploads (`<input type="file">`).
- **`novalidate`**: Disables browser default validation popups when implementing custom JavaScript/React validation libraries.

## 2. Accessible Label Binding (`<label>`)

Every interactive form control **must** have an associated label.

### Explicit Association (Recommended):
Match the `<label>`'s `for` attribute with the input's `id`:

```html
<div class="form-field">
  <label for="user-email">Email Address <span aria-hidden="true">*</span></label>
  <input type="email" id="user-email" name="email" required />
</div>
```

<Callout type="warn" title="Placeholders are Not Labels">
Do not rely on the `placeholder` attribute in place of a `<label>`. Placeholders:
1. Disappear the moment the user types a single character.
2. Have low contrast, failing WCAG compliance.
3. Are often ignored or misread by screen readers.
Always provide a visible, persistent `<label>`.
</Callout>

## 3. Comprehensive Input Types

HTML5 provides specialized input types that activate native mobile keyboards (e.g. numeric pads, email keys):

```html
<!-- Text & Identification -->
<input type="text" name="fullName" autocomplete="name" />
<input type="email" name="userEmail" autocomplete="email" />
<input type="password" name="userPassword" autocomplete="new-password" />

<!-- Numbers & Communication -->
<input type="number" name="quantity" min="1" max="100" step="1" />
<input type="tel" name="phone" autocomplete="tel" />
<input type="url" name="portfolio" placeholder="https://..." />

<!-- Dates & Pickers -->
<input type="date" name="birthDate" />
<input type="time" name="appointmentTime" />
<input type="color" name="themeColor" value="#3b82f6" />
<input type="range" name="volume" min="0" max="100" value="75" />

<!-- File Upload (requires method="POST" enctype="multipart/form-data") -->
<input type="file" name="avatar" accept="image/png, image/jpeg, image/webp" />

<!-- Hidden input for CSRF tokens or internal state -->
<input type="hidden" name="csrf_token" value="abc123xyz" />
```

## 4. Selection Controls: Radios, Checkboxes & Dropdowns

<Tabs items={['Radio Buttons', 'Checkboxes', 'Dropdown Select', 'Datalist Autocomplete']}>
  <Tab value="Radio Buttons">
    Use radio buttons when the user must select **exactly one** option from a short list. All options must share the same `name` attribute:

    ```html
    <fieldset>
      <legend>Select Subscription Tier</legend>
      <div>
        <input type="radio" id="tier-free" name="subscription" value="free" checked />
        <label for="tier-free">Free ($0/mo)</label>
      </div>
      <div>
        <input type="radio" id="tier-pro" name="subscription" value="pro" />
        <label for="tier-pro">Pro ($29/mo)</label>
      </div>
    </fieldset>
    ```
  </Tab>
  <Tab value="Checkboxes">
    Use checkboxes for binary toggles (true/false) or multiple selectable choices:

    ```html
    <div>
      <input type="checkbox" id="terms" name="agree_terms" required />
      <label for="terms">I accept the terms and conditions</label>
    </div>
    ```
  </Tab>
  <Tab value="Dropdown Select">
    Use `<select>` for picking from large sets of options:

    ```html
    <label for="country">Country:</label>
    <select id="country" name="country" required>
      <option value="" disabled selected>Choose a country...</option>
      <optgroup label="North America">
        <option value="us">United States</option>
        <option value="ca">Canada</option>
      </optgroup>
      <optgroup label="Europe">
        <option value="de">Germany</option>
        <option value="uk">United Kingdom</option>
      </optgroup>
    </select>
    ```
  </Tab>
  <Tab value="Datalist Autocomplete">
    Provides autocomplete suggestions to a text input while still allowing custom entries:

    ```html
    <label for="framework">Preferred Framework:</label>
    <input list="framework-options" id="framework" name="framework" />

    <datalist id="framework-options">
      <option value="React" />
      <option value="Next.js" />
      <option value="Vue" />
      <option value="Astro" />
      <option value="FastAPI" />
    </datalist>
    ```
  </Tab>
</Tabs>

## 5. Multi-line Text with `<textarea>`

Unlike `<input>`, `<textarea>` is a paired tag and supports multi-line text input:

```html
<label for="user-bio">Professional Biography:</label>
<textarea
  id="user-bio"
  name="bio"
  rows="4"
  cols="50"
  maxlength="500"
  placeholder="Brief summary of your development experience..."
></textarea>
```

## 6. Native HTML5 Constraint Validation

HTML5 includes built-in client-side validation that runs before the form submits:

| Attribute | Valid On | Description |
| :--- | :--- | :--- |
| `required` | Almost all inputs | Value cannot be blank. |
| `minlength` / `maxlength` | Text, password, search, textarea | Character count boundaries. |
| `min` / `max` | Number, range, date | Numeric or chronological boundaries. |
| `step` | Number, range | Valid interval stepping. |
| `pattern` | Text, search, url, tel, email | Regular expression the value must match. |

```html
<!-- Example: Enforcing a strong password pattern via regex -->
<label for="secure-pass">Password:</label>
<input 
  type="password" 
  id="secure-pass" 
  name="password"
  required 
  minlength="8"
  pattern="(?=.*\d)(?=.*[a-z])(?=.*[A-Z]).{8,}"
  title="Must contain at least one number, one uppercase letter, and 8+ characters"
/>
```

## 7. Production-Ready Accessible Registration Form

```html
<form action="/api/register" method="POST" novalidate>
  <fieldset>
    <legend>Account Credentials</legend>

    <div class="form-group">
      <label for="reg-email">Email Address <span aria-hidden="true">*</span></label>
      <input
        type="email"
        id="reg-email"
        name="email"
        required
        autocomplete="email"
        placeholder="alex@domain.com"
        aria-describedby="email-hint"
      />
      <small id="email-hint">We will never sell or share your personal data.</small>
    </div>

    <div class="form-group">
      <label for="reg-password">Password <span aria-hidden="true">*</span></label>
      <input
        type="password"
        id="reg-password"
        name="password"
        required
        minlength="8"
        autocomplete="new-password"
      />
    </div>
  </fieldset>

  <div class="form-group">
    <input type="checkbox" id="terms-agree" name="terms" required />
    <label for="terms-agree">I agree to the <a href="/terms">Terms of Service</a></label>
  </div>

  <button type="submit">Create Account</button>
  <button type="reset">Clear Form</button>
</form>
```
