HTML (HyperText Markup Language) is the foundational language of the World Wide Web. It provides structure and context to digital content by annotating text with elements and tags.

---

## 1. Anatomy of an HTML Element

An HTML element typically consists of an opening tag, optional attributes, the inner text or child nodes, and a closing tag:

```html
<p class="intro-text" id="lead-paragraph">Welcome to modern web development.</p>
```

```
<tag attribute="value"> Inner Content </tag>
 │         │                  │          │
 ├─────────┴──────────────────┼──────────┤
 │ Opening Tag with Attribute │  Content │ Closing Tag
 └────────────────────────────┴──────────┘
```

### Void Elements (Self-Closing)
Some elements cannot contain inner text or child elements. These are known as **void elements**:
- `<img />`: Embeds an image
- `<input />`: User input control
- `<br />`: Line break
- `<hr />`: Thematic break
- `<meta />`: Document metadata
- `<link />`: External resource link

<Callout type="info" title="Self-closing slashes in HTML5">
In modern HTML5, writing `<img src="..." alt="...">` and `<img src="..." alt="..." />` are both valid. The trailing slash `/` is optional, though commonly seen in JSX/React workflows.
</Callout>

## 2. The Standard Document Boilerplate

Every valid HTML5 document begins with the following standardized structure:

```html
<!DOCTYPE html>
<html lang="en">
  <head>
    <meta charset="UTF-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <title>My First Web Page</title>
  </head>
  <body>
    <h1>Hello, World!</h1>
    <p>This is a paragraph of text on our web page.</p>
  </body>
</html>
```

### Breakdown of the Document Nodes:

<Steps>
  <Step>
    #### `<!DOCTYPE html>`
    Informs the browser engine to render the document in modern standards-compliant mode. Without this declaration, browsers fall back into legacy "Quirks Mode", causing layout discrepancies.
  </Step>
  <Step>
    #### `<html lang="en">`
    The root element of the document. Setting the `lang` attribute is critical for screen readers (to load the correct pronunciation library) and search engines.
  </Step>
  <Step>
    #### `<head>`
    Contains machine-readable metadata about the page (character encoding, mobile viewport settings, stylesheets, scripts, page title). None of this is directly rendered in the visible viewport.
  </Step>
  <Step>
    #### `<meta charset="UTF-8">`
    Configures standard UTF-8 character encoding, ensuring emojis, accented characters, and international alphabets display correctly without corruption.
  </Step>
  <Step>
    #### `<meta name="viewport" content="width=device-width, initial-scale=1.0">`
    Instructs mobile browser viewports to render at the physical device screen width at a 1:1 scale rather than simulating a 980px desktop screen.
  </Step>
  <Step>
    #### `<body>`
    The container for all visible elements, text, images, and interactive controls rendered to the user.
  </Step>
</Steps>

## 3. Heading Hierarchy (`<h1>` to `<h6>`)

HTML provides six levels of section headings:

```html
<h1>Main Document Title (Level 1)</h1>
<h2>Major Topic Section (Level 2)</h2>
<h3>Sub-topic Section (Level 3)</h3>
<h4>Detailed Component Header (Level 4)</h4>
<h5>Minor Subsection (Level 5)</h5>
<h6>Deep Detail (Level 6)</h6>
```

<Callout type="warn" title="The Single <h1> Rule">
Never use more than one `<h1>` per page. Search engines and screen readers use `<h1>` as the primary topic outline of your page. Additionally, **never skip heading levels** (e.g. jumping from `<h2>` directly to `<h4>`) just to make text visually smaller—use CSS font sizes for visual adjustments instead.
</Callout>

## 4. Text Content & Semantic Formatting

Use semantic text elements to convey emotional weight, importance, or technical formatting:

| Element | Semantic Purpose | Typical Visual Style |
| :--- | :--- | :--- |
| `<p>` | Standard text paragraph | Block text with margin |
| `<strong>` | High importance, seriousness, or urgency | Bold text |
| `<em>` | Stress emphasis that alters spoken meaning | Italic text |
| `<mark>` | Highlighted text for relevance or reference | Yellow background |
| `<code>` | Inline code, variable, or command | Monospace font |
| `<pre>` | Preformatted text preserving whitespace and newlines | Monospace block |
| `<blockquote>` | Quoted content from an external source | Indented block |
| `<small>` | Side comments, copyright, disclaimer | Reduced font size |

```html
<p>
  <strong>Warning:</strong> Ensure your database credentials are stored in 
  <code>.env.local</code> and <em>never</em> committed to a public repository.
</p>

<blockquote cite="https://www.w3.org/WAI/">
  "The power of the Web is in its universality. Access by everyone regardless 
  of disability is an essential aspect."
  <cite>— Tim Berners-Lee</cite>
</blockquote>
```

## 5. Lists: Unordered, Ordered & Description

Lists organize items sequentially or as related groups:

<Tabs items={['Unordered List (ul)', 'Ordered List (ol)', 'Description List (dl)']}>
  <Tab value="Unordered List (ul)">
    ```html
    <!-- Bulleted list of items where order does not matter -->
    <ul>
      <li>Frontend (HTML, CSS, JS)</li>
      <li>Backend (Node.js, Python, Go)</li>
      <li>Database (PostgreSQL, Redis)</li>
    </ul>
    ```
  </Tab>
  <Tab value="Ordered List (ol)">
    ```html
    <!-- Numbered list where order is strictly sequential -->
    <ol>
      <li>Initialize Git repository</li>
      <li>Install project dependencies</li>
      <li>Start the local development server</li>
    </ol>
    ```
  </Tab>
  <Tab value="Description List (dl)">
    ```html
    <!-- Key-value terms and definitions -->
    <dl>
      <dt>DOM</dt>
      <dd>Document Object Model: In-memory tree representation of HTML.</dd>
      <dt>CSSOM</dt>
      <dd>CSS Object Model: In-memory tree representation of styles.</dd>
    </dl>
    ```
  </Tab>
</Tabs>

## 6. Hyperlinks & Navigation (`<a>`)

The anchor tag `<a>` connects pages across the internet or navigates within the same document using the `href` attribute:

### Link Types & Best Practices

```html
<!-- 1. Absolute URL (External site) -->
<a href="https://developer.mozilla.org" target="_blank" rel="noopener noreferrer">
  Read MDN Web Docs
</a>

<!-- 2. Relative URL (Internal project page) -->
<a href="/docs/guide.html">View Guide</a>
<a href="../contact.html">Contact Us</a>

<!-- 3. In-page Fragment Anchor (Jumps to an element with id="features") -->
<a href="#features">Jump to Features Section</a>

<!-- 4. Communication Links -->
<a href="mailto:support@company.com?subject=Help">Send an Email</a>
<a href="tel:+15550192834">Call Customer Support</a>
```

<Callout type="warn" title="Security Requirement for target='_blank'">
When opening external links in a new window with `target="_blank"`, always add `rel="noopener noreferrer"`. This prevents the opened window from accessing your origin window via `window.opener` (a security attack known as reverse tabnabbing).
</Callout>

## 7. Practical Hands-On Exercise

Create an `index.html` file on your machine and build a simple **Developer Profile Card**:

```html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Jane Doe - Full-Stack Developer</title>
</head>
<body>
  <h1>Jane Doe</h1>
  <p>Software Engineer specializing in <strong>TypeScript</strong> and <strong>distributed backend systems</strong>.</p>

  <h2>Technical Stack</h2>
  <ul>
    <li>TypeScript / React / Next.js</li>
    <li>Python / FastAPI</li>
    <li>PostgreSQL / Redis</li>
  </ul>

  <h2>Contact & Profiles</h2>
  <p>Reach me via email at <a href="mailto:jane@example.com">jane@example.com</a> or visit my <a href="https://github.com" target="_blank" rel="noopener noreferrer">GitHub Profile</a>.</p>
</body>
</html>
```
