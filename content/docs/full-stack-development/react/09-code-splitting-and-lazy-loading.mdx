By default, bundlers like Vite, Webpack, and Rollup package an entire application into a single monolithic JavaScript bundle. As an app grows, users must download megabytes of code for pages they haven't visited yet, degrading mobile performance and delaying **Time to Interactive (TTI)**.

**Code Splitting** divides the application into isolated chunks that are fetched on demand over the network.

---

## 1. Dynamic Imports: `import()`

Modern JavaScript supports dynamic imports as a language-level feature. Unlike static `import ... from '...'` statements at the top of a file, `import()` returns a **Promise** and can be executed conditionally inside functions or event handlers:

```tsx title="src/utils/exportToExcel.ts"
export async function handleDownloadReport(data: ReportData[]) {
  // The heavy xlsx library (500KB+) is only fetched when the user clicks 'Download'
  const xlsx = await import('xlsx');
  
  const worksheet = xlsx.utils.json_to_sheet(data);
  const workbook = xlsx.utils.book_new();
  xlsx.utils.book_append_sheet(workbook, worksheet, "Report");
  xlsx.writeFile(workbook, "Report.xlsx");
}
```

## 2. Component Lazy Loading: `React.lazy` & `<Suspense>`

`React.lazy()` lets you render a dynamically imported component as a regular component:

```tsx
import { lazy, Suspense } from 'react';

// 1. Lazy component declaration outside the render cycle
// Must be an export default from the target module
const HeavyChart = lazy(() => import('./components/HeavyChart'));

export function AnalyticsDashboard() {
  return (
    <div>
      <h2>Monthly Analytics</h2>
      
      {/* 2. Wrap the lazy component in a Suspense boundary */}
      <Suspense fallback={<div className="skeleton-loader">Loading chart...</div>}>
        <HeavyChart />
      </Suspense>
    </div>
  );
}
```

<Callout type="warn" title="Always Declare React.lazy at Module Scope">
Never call `React.lazy(() => import(...))` inside a component function. Declaring it inside the render loop causes the component to be re-created on every single render pass, resetting state and causing continuous remounting.
</Callout>

## 3. Route-Based Code Splitting

The most impactful place to implement code splitting is at the **route level**. When a user visits `/home`, they should not download the code for `/admin` or `/checkout`.

Combining `React.lazy` with **React Router**:

```tsx title="src/App.tsx"
import { lazy, Suspense } from 'react';
import { Routes, Route, Link } from 'react-router-dom';

// Separate chunks created for each page
const Home = lazy(() => import('./pages/Home'));
const Products = lazy(() => import('./pages/Products'));
const Checkout = lazy(() => import('./pages/Checkout'));
const Admin = lazy(() => import('./pages/Admin'));

function PageLoader() {
  return <div style={{ padding: '2rem', textAlign: 'center' }}>Loading page...</div>;
}

export default function App() {
  return (
    <div>
      <nav style={{ display: 'flex', gap: '1rem', padding: '1rem' }}>
        <Link to="/">Home</Link>
        <Link to="/products">Products</Link>
        <Link to="/checkout">Checkout</Link>
        <Link to="/admin">Admin</Link>
      </nav>

      {/* Global Suspense fallback for page transitions */}
      <Suspense fallback={<PageLoader />}>
        <Routes>
          <Route path="/" element={<Home />} />
          <Route path="/products" element={<Products />} />
          <Route path="/checkout" element={<Checkout />} />
          <Route path="/admin" element={<Admin />} />
        </Routes>
      </Suspense>
    </div>
  );
}
```

## 4. Handling Named Exports with `React.lazy`

`React.lazy` only supports **default exports**. If a module uses named exports (`export function HeavyModal()`), transform the Promise resolution:

```tsx title="src/components/ModalWrapper.tsx"
import { lazy, Suspense } from 'react';

// Map named export 'HeavyModal' to default property
const HeavyModal = lazy(() =>
  import('./ModalLibrary').then(module => ({ default: module.HeavyModal }))
);

export function ModalWrapper({ isOpen }: { isOpen: boolean }) {
  if (!isOpen) return null;

  return (
    <Suspense fallback={<p>Opening dialog...</p>}>
      <HeavyModal />
    </Suspense>
  );
}
```

## 5. Preventing Fallback Flickers with `useTransition`

When switching tabs or pages, showing a sudden `<Suspense>` spinner can produce a jarring user experience. `useTransition` allows React to keep the **current screen visible** while the new lazy chunk downloads in the background:

```tsx title="src/components/TabContainer.tsx"
import { useState, useTransition, lazy, Suspense } from 'react';

const ProfileTab = lazy(() => import('./tabs/ProfileTab'));
const BillingTab = lazy(() => import('./tabs/BillingTab'));
const NotificationsTab = lazy(() => import('./tabs/NotificationsTab'));

export function TabContainer() {
  const [tab, setTab] = useState<'profile' | 'billing' | 'notifications'>('profile');
  const [isPending, startTransition] = useTransition();

  function selectTab(nextTab: 'profile' | 'billing' | 'notifications') {
    // Marks the tab switch as non-urgent.
    // The current tab remains active until the new chunk is fully downloaded!
    startTransition(() => {
      setTab(nextTab);
    });
  }

  return (
    <div>
      <div style={{ display: 'flex', gap: '0.5rem' }}>
        <button onClick={() => selectTab('profile')}>Profile</button>
        <button onClick={() => selectTab('billing')}>Billing</button>
        <button onClick={() => selectTab('notifications')}>Notifications</button>
        {isPending && <span style={{ opacity: 0.6 }}> (Updating...)</span>}
      </div>

      <div style={{ marginTop: '1rem', opacity: isPending ? 0.7 : 1 }}>
        <Suspense fallback={<p>Initial load...</p>}>
          {tab === 'profile' && <ProfileTab />}
          {tab === 'billing' && <BillingTab />}
          {tab === 'notifications' && <NotificationsTab />}
        </Suspense>
      </div>
    </div>
  );
}
```

## 6. Catching Failed Chunks with Error Boundaries

If a user loses internet connectivity while navigating to a lazy route, the browser throws a `ChunkLoadError`. Wrap lazy routes in an **Error Boundary** to offer a retry button:

```tsx title="src/components/ChunkErrorBoundary.tsx"
import React, { Component, ReactNode, ErrorInfo } from 'react';

type Props = { children: ReactNode };
type State = { hasError: boolean };

export class ChunkErrorBoundary extends Component<Props, State> {
  state: State = { hasError: false };

  static getDerivedStateFromError(error: Error): State {
    return { hasError: true };
  }

  componentDidCatch(error: Error, errorInfo: ErrorInfo) {
    console.error("Chunk loading failed:", error, errorInfo);
  }

  render() {
    if (this.state.hasError) {
      return (
        <div style={{ padding: '2rem', textAlign: 'center' }}>
          <h3>Failed to load this section.</h3>
          <p>This may happen if a new deployment was released or your connection dropped.</p>
          <button onClick={() => window.location.reload()}>Refresh Page</button>
        </div>
      );
    }

    return this.props.children;
  }
}
```
