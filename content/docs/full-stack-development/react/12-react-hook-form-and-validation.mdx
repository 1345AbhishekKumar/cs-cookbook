Managing forms in React using traditional controlled state (`useState`) introduces severe performance bottlenecks: on every single keystroke, the entire form and its child components re-render.

**React Hook Form (RHF)** embraces **uncontrolled inputs** via native refs, isolating re-renders to only the inputs that require updates. Paired with **Zod**, it provides compile-time and runtime type safety with minimal boilerplate.

---

## 1. Why React Hook Form? (Controlled vs Uncontrolled)

```
Traditional Controlled Form (useState):
Keystroke "a" ──► setState("a") ──► Re-render Form Component ──► Re-evaluate All Child Inputs

React Hook Form (Uncontrolled + Ref Subscription):
Keystroke "a" ──► Native DOM updates instantly ──► Zero Component Re-renders
                                               └── State validated onBlur or onSubmit
```

| Metric | Controlled Forms (`useState`) | React Hook Form (`ref` based) |
|---|---|---|
| **Re-renders on Keystroke** | Every single input re-renders parent | **0** re-renders during typing |
| **Mount Speed** | Slower as form complexity scales | Up to **15× faster** mount time |
| **Boilerplate** | Requires manual `value` and `onChange` | Single spread `{...register('name')}` |
| **Validation Integration** | Manual `if/else` checks or heavy libraries | Native **Zod / Yup / Valibot** schema resolvers |

## 3. Type-Safe Schema Validation with Zod

By combining Zod with `zodResolver`, your form schema becomes the **single source of truth** for both runtime validation rules and TypeScript types.

```tsx title="src/components/RegistrationForm.tsx"
import { useForm } from 'react-hook-form';
import { zodResolver } from '@hookform/resolvers/zod';
import { z } from 'zod';

// 1. Define the declarative validation schema
const registrationSchema = z.object({
  username: z
    .string()
    .min(3, 'Username must be at least 3 characters')
    .max(20, 'Username cannot exceed 20 characters'),
  email: z
    .string()
    .email('Please enter a valid email address'),
  password: z
    .string()
    .min(8, 'Password must be at least 8 characters')
    .regex(/[A-Z]/, 'Password must contain at least one uppercase letter')
    .regex(/[0-9]/, 'Password must contain at least one number'),
  acceptTerms: z
    .boolean()
    .refine((val) => val === true, 'You must accept the terms of service'),
});

// 2. Infer the TypeScript type directly from the schema
type RegistrationFormData = z.infer<typeof registrationSchema>;

export function RegistrationForm() {
  // 3. Initialize useForm with type safety and zodResolver
  const {
    register,
    handleSubmit,
    reset,
    formState: { errors, isSubmitting, isDirty, isValid },
  } = useForm<RegistrationFormData>({
    resolver: zodResolver(registrationSchema),
    mode: 'onBlur', // Validates when an input loses focus
    defaultValues: {
      username: '',
      email: '',
      password: '',
      acceptTerms: false,
    },
  });

  // 4. Submission handler only executes if form is 100% valid
  async function onSubmit(data: RegistrationFormData) {
    try {
      // Simulate backend API call
      await new Promise(resolve => setTimeout(resolve, 1500));
      console.log('Successfully submitted:', data);
      reset(); // Clears form back to defaultValues
    } catch (error) {
      console.error('Submission failed:', error);
    }
  }

  return (
    <form onSubmit={handleSubmit(onSubmit)} noValidate style={{ maxWidth: 400 }}>
      {/* Username Field */}
      <div style={{ marginBottom: '1rem' }}>
        <label htmlFor="username">Username</label>
        <input
          id="username"
          type="text"
          {...register('username')}
          aria-invalid={!!errors.username}
        />
        {errors.username && (
          <p style={{ color: '#ef4444', fontSize: '0.85rem' }}>{errors.username.message}</p>
        )}
      </div>

      {/* Email Field */}
      <div style={{ marginBottom: '1rem' }}>
        <label htmlFor="email">Email</label>
        <input
          id="email"
          type="email"
          {...register('email')}
          aria-invalid={!!errors.email}
        />
        {errors.email && (
          <p style={{ color: '#ef4444', fontSize: '0.85rem' }}>{errors.email.message}</p>
        )}
      </div>

      {/* Password Field */}
      <div style={{ marginBottom: '1rem' }}>
        <label htmlFor="password">Password</label>
        <input
          id="password"
          type="password"
          {...register('password')}
          aria-invalid={!!errors.password}
        />
        {errors.password && (
          <p style={{ color: '#ef4444', fontSize: '0.85rem' }}>{errors.password.message}</p>
        )}
      </div>

      {/* Checkbox Field */}
      <div style={{ marginBottom: '1rem' }}>
        <label style={{ display: 'flex', alignItems: 'center', gap: '0.5rem' }}>
          <input type="checkbox" {...register('acceptTerms')} />
          I agree to the Terms & Conditions
        </label>
        {errors.acceptTerms && (
          <p style={{ color: '#ef4444', fontSize: '0.85rem' }}>{errors.acceptTerms.message}</p>
        )}
      </div>

      {/* Submit Button */}
      <button type="submit" disabled={isSubmitting}>
        {isSubmitting ? 'Creating account...' : 'Register'}
      </button>
    </form>
  );
}
```

## 4. Handling Every Native HTML Input Type

React Hook Form provides built-in type coercion options directly inside `register(name, options)`:

```tsx title="src/components/AllInputTypesForm.tsx"
import { useForm } from 'react-hook-form';

type FullFormInputs = {
  // 1. Text & Textarea
  fullName: string;
  bio: string;
  // 2. Numeric input (coerced from string to number)
  age: number;
  // 3. Date input (coerced from string to Date object)
  birthDate: Date;
  // 4. Boolean Single Checkbox
  subscribeNewsletter: boolean;
  // 5. Multi-Checkbox Array
  hobbies: string[];
  // 6. Radio Group
  gender: 'male' | 'female' | 'other';
  // 7. Select Dropdown
  country: string;
  // 8. File Upload
  avatar: FileList;
};

export function AllInputTypesForm() {
  const { register, handleSubmit } = useForm<FullFormInputs>();

  const onSubmit = (data: FullFormInputs) => {
    console.log("Coerced Form Payload:", data);
  };

  return (
    <form onSubmit={handleSubmit(onSubmit)}>
      {/* 1. Standard Text & Textarea */}
      <input type="text" placeholder="Full Name" {...register("fullName")} />
      <textarea placeholder="Bio" {...register("bio")} />

      {/* 2. Number: valueAsNumber automatically parses input.value to Number */}
      <input
        type="number"
        placeholder="Age"
        {...register("age", { valueAsNumber: true })}
      />

      {/* 3. Date: valueAsDate automatically parses input.value to JavaScript Date */}
      <input
        type="date"
        {...register("birthDate", { valueAsDate: true })}
      />

      {/* 4. Single Checkbox (Boolean) */}
      <label>
        <input type="checkbox" {...register("subscribeNewsletter")} />
        Subscribe to email updates
      </label>

      {/* 5. Multiple Checkboxes (Array of Strings) */}
      <div>
        <label><input type="checkbox" value="reading" {...register("hobbies")} /> Reading</label>
        <label><input type="checkbox" value="coding" {...register("hobbies")} /> Coding</label>
        <label><input type="checkbox" value="gaming" {...register("hobbies")} /> Gaming</label>
      </div>

      {/* 6. Radio Group (Mutually Exclusive) */}
      <div>
        <label><input type="radio" value="male" {...register("gender")} /> Male</label>
        <label><input type="radio" value="female" {...register("gender")} /> Female</label>
        <label><input type="radio" value="other" {...register("gender")} /> Other</label>
      </div>

      {/* 7. Native Select Dropdown */}
      <select {...register("country")}>
        <option value="">Select country...</option>
        <option value="US">United States</option>
        <option value="UK">United Kingdom</option>
        <option value="IN">India</option>
      </select>

      {/* 8. File Upload (FileList) */}
      <input type="file" {...register("avatar")} accept="image/*" />

      <button type="submit">Submit All Types</button>
    </form>
  );
}
```

## 5. The `<Controller>` Component for Custom UI Libraries

Standard HTML inputs (`<input>`, `<textarea>`) expose native DOM refs, allowing `register` to wire them up seamlessly. However, custom UI components—such as **shadcn/ui**, **Radix UI**, **Material UI**, or **React-Select**—are controlled and do not expose standard HTML input event targets.

RHF solves this with the `<Controller>` component:

```tsx title="src/components/CustomSelectForm.tsx"
import { useForm, Controller } from 'react-hook-form';
import { z } from 'zod';
import { zodResolver } from '@hookform/resolvers/zod';

const profileSchema = z.object({
  role: z.enum(['developer', 'designer', 'manager'], {
    errorMap: () => ({ message: 'Please select a valid role' }),
  }),
});

type ProfileFormData = z.infer<typeof profileSchema>;

// Mock controlled custom UI component (e.g. Radix UI or shadcn/ui Select)
function CustomSelect({
  value,
  onChange,
  options,
}: {
  value: string;
  onChange: (val: string) => void;
  options: { label: string; value: string }[];
}) {
  return (
    <div className="custom-select">
      {options.map((opt) => (
        <button
          key={opt.value}
          type="button"
          onClick={() => onChange(opt.value)}
          style={{
            fontWeight: value === opt.value ? 'bold' : 'normal',
            border: value === opt.value ? '2px solid #3b82f6' : '1px solid #ccc',
            marginRight: 6,
          }}
        >
          {opt.label}
        </button>
      ))}
    </div>
  );
}

export function ProfileForm() {
  const { control, handleSubmit, formState: { errors } } = useForm<ProfileFormData>({
    resolver: zodResolver(profileSchema),
    defaultValues: { role: 'developer' },
  });

  return (
    <form onSubmit={handleSubmit((d) => console.log(d))}>
      <label>Job Title</label>
      
      {/* Controller bridges RHF state with the custom controlled component */}
      <Controller
        name="role"
        control={control}
        render={({ field, fieldState }) => (
          <div>
            <CustomSelect
              value={field.value}
              onChange={field.onChange}
              options={[
                { label: 'Developer', value: 'developer' },
                { label: 'Designer', value: 'designer' },
                { label: 'Manager', value: 'manager' },
              ]}
            />
            {fieldState.error && (
              <p style={{ color: '#ef4444' }}>{fieldState.error.message}</p>
            )}
          </div>
        )}
      />

      <button type="submit" style={{ marginTop: 12 }}>Save Profile</button>
    </form>
  );
}
```

<Callout type="tip" title="The shadcn/ui Form Pattern">
In `shadcn/ui`, the `<FormField>` component is simply a pre-configured wrapper around React Hook Form's `<Controller>`. It automatically hooks into field status, generates accessibility IDs via `useId`, and handles `<FormMessage>` error presentation.
</Callout>

## 6. Deep Component Trees: `FormProvider` & `useFormContext`

When forms span across complex multi-step wizards or deeply nested sub-components, passing `register` and `control` as props down through every layer re-introduces prop drilling.

Use `<FormProvider>` to broadcast the form context:

```tsx title="src/components/WizardStep.tsx"
import { useForm, FormProvider, useFormContext } from 'react-hook-form';

// Child component 5 levels deep inside the form tree
function NestedUserBioField() {
  // Retrieves register, errors, and control directly from context
  const { register, formState: { errors } } = useFormContext();

  return (
    <div>
      <label>User Biography</label>
      <textarea {...register("bio", { required: "Bio is required" })} />
      {errors.bio && <span style={{ color: 'red' }}>{String(errors.bio.message)}</span>}
    </div>
  );
}

export function WizardForm() {
  const methods = useForm({ defaultValues: { bio: '' } });

  return (
    <FormProvider {...methods}>
      <form onSubmit={methods.handleSubmit((data) => console.log(data))}>
        {/* Deeply nested component needs no prop forwarding */}
        <NestedUserBioField />
        <button type="submit">Submit Step</button>
      </form>
    </FormProvider>
  );
}
```

## 7. Dynamic Lists with `useFieldArray`

When forms require dynamic additions, removals, or re-ordering of rows (such as line items in an invoice, education history, or tags), use the `useFieldArray` hook:

```tsx title="src/components/DynamicTeamForm.tsx"
import { useForm, useFieldArray } from 'react-hook-form';
import { z } from 'zod';
import { zodResolver } from '@hookform/resolvers/zod';

const teamSchema = z.object({
  teamName: z.string().min(2, 'Team name is required'),
  members: z
    .array(
      z.object({
        name: z.string().min(1, 'Member name is required'),
        email: z.string().email('Invalid email'),
      })
    )
    .min(1, 'At least one team member is required'),
});

type TeamFormData = z.infer<typeof teamSchema>;

export function DynamicTeamForm() {
  const {
    register,
    control,
    handleSubmit,
    formState: { errors },
  } = useForm<TeamFormData>({
    resolver: zodResolver(teamSchema),
    defaultValues: {
      teamName: '',
      members: [{ name: '', email: '' }],
    },
  });

  // useFieldArray manages the nested array state
  const { fields, append, remove } = useFieldArray({
    control,
    name: 'members',
  });

  return (
    <form onSubmit={handleSubmit((data) => console.log(data))}>
      <div>
        <label>Team Name</label>
        <input {...register('teamName')} />
        {errors.teamName && <p style={{ color: '#ef4444' }}>{errors.teamName.message}</p>}
      </div>

      <h4>Team Members</h4>
      {errors.members?.root && (
        <p style={{ color: '#ef4444' }}>{errors.members.root.message}</p>
      )}

      {fields.map((field, index) => (
        <div key={field.id} style={{ display: 'flex', gap: '0.5rem', marginBottom: '0.5rem' }}>
          {/* ALWAYS use field.id as the React key, NEVER index! */}
          <div>
            <input
              placeholder="Full Name"
              {...register(`members.${index}.name` as const)}
            />
            {errors.members?.[index]?.name && (
              <p style={{ color: '#ef4444' }}>{errors.members[index]?.name?.message}</p>
            )}
          </div>

          <div>
            <input
              placeholder="Email"
              {...register(`members.${index}.email` as const)}
            />
            {errors.members?.[index]?.email && (
              <p style={{ color: '#ef4444' }}>{errors.members[index]?.email?.message}</p>
            )}
          </div>

          <button type="button" onClick={() => remove(index)}>
            Remove
          </button>
        </div>
      ))}

      <button
        type="button"
        onClick={() => append({ name: '', email: '' })}
        style={{ marginRight: '1rem' }}
      >
        + Add Member
      </button>

      <button type="submit">Submit Team</button>
    </form>
  );
}
```

<Callout type="warn" title="Critical Rule: Never use index as key in useFieldArray">
Always use `key={field.id}` generated by RHF. If you use `key={index}`, removing or reordering items will leave native DOM input values attached to the wrong inputs!
</Callout>

## 8. Real-Time Field Subscriptions: `watch` vs `useWatch`

If you need to display live previews or conditionally show fields based on another field's value:

- **`watch('fieldName')`**: Calling this inside the main component causes the **entire form component** to re-render whenever the field changes.
- **`useWatch({ control, name })`**: Isolates the re-render strictly to the individual component or preview badge that calls it:

```tsx title="src/components/LivePriceBadge.tsx"
import { useWatch, Control } from 'react-hook-form';

// Isolated sub-component that only re-renders when "plan" changes
export function LivePriceBadge({ control }: { control: Control<any> }) {
  const selectedPlan = useWatch({
    control,
    name: 'plan',
    defaultValue: 'monthly',
  });

  return (
    <div className="badge">
      Plan Selected: <strong>{selectedPlan.toUpperCase()}</strong> ({selectedPlan === 'annual' ? '$120/yr' : '$12/mo'})
    </div>
  );
}
```

## 9. Pre-Populating & Resetting Forms from API Data

When building an "Edit Profile" or "Edit Document" form where initial values arrive asynchronously from an API:

```tsx title="src/components/EditProfileForm.tsx"
import { useEffect } from 'react';
import { useForm } from 'react-hook-form';

export function EditProfileForm({ userId }: { userId: string }) {
  const { register, handleSubmit, reset } = useForm<UserProfile>();

  useEffect(() => {
    async function loadUserData() {
      const response = await fetch(`/api/users/${userId}`);
      const userData = await response.json();
      
      // reset() synchronously updates all form values and clears dirty state
      reset(userData);
    }

    loadUserData();
  }, [userId, reset]);

  return (
    <form onSubmit={handleSubmit((data) => updateProfile(data))}>
      <input {...register('displayName')} />
      <input {...register('bio')} />
      <button type="submit">Save Changes</button>
    </form>
  );
}
```

## 10. Comprehensive React Hook Form Glossary & API Reference

An exhaustive technical reference of every key concept, element, hook, method, and state flag in React Hook Form:

### A. Core Hooks & Components
| Primitive / Component | Description | Syntax / Usage |
|:---|:---|:---|
| **`useForm`** | Root hook that creates the form instance, registers fields, and manages validation state. | `const methods = useForm({ defaultValues, resolver })` |
| **`<Controller />`** | Render prop component for binding controlled UI libraries (shadcn/ui, Radix, MUI) into RHF. | `<Controller name="tag" control={control} render={...} />` |
| **`useController`** | Custom hook version of `<Controller />` for creating reusable custom input components. | `const { field, fieldState } = useController({ name, control })` |
| **`<FormProvider />`** | Context provider component to broadcast form methods to deeply nested sub-components. | `<FormProvider {...methods}><ChildForm /></FormProvider>` |
| **`useFormContext`** | Hook used by nested child components to consume methods from `<FormProvider />`. | `const { register } = useFormContext()` |
| **`useFieldArray`** | Hook for managing dynamic array lists (append, prepend, remove, swap, move, insert). | `const { fields, append, remove } = useFieldArray({ control, name })` |
| **`useWatch`** | Hook for subscribing to specific field changes without re-rendering parent form. | `const val = useWatch({ control, name: "role" })` |
| **`useFormState`** | Hook for subscribing strictly to form state changes (isDirty, errors) independently. | `const { isDirty } = useFormState({ control })` |

### B. `useForm` Configuration Options
| Option | Default | Purpose |
|:---|:---|:---|
| **`mode`** | `"onSubmit"` | Validation timing: `"onSubmit"`, `"onBlur"`, `"onChange"`, `"onTouched"`, or `"all"`. |
| **`reValidateMode`** | `"onChange"` | When to re-validate fields that already have errors. |
| **`defaultValues`** | `{}` | Synchronous or async Promise of initial field values. |
| **`values`** | `undefined` | Reactive form values that automatically re-sync when props change. |
| **`resolver`** | `undefined` | Integration bridge for schema validation libraries (`zodResolver`, `yupResolver`). |
| **`shouldFocusError`** | `true` | Automatically focuses the first input element containing a validation error on submit. |
| **`shouldUnregister`** | `false` | When `true`, inputs unmounted from the DOM are automatically unregistered from state. |
| **`delayError`** | `0` | Delay (in ms) before showing validation errors to the user. |

### C. Methods Returned by `useForm`
| Method | Description |
|:---|:---|
| **`register(name, options)`** | Returns `{ onChange, onBlur, name, ref }` to spread onto an input element. |
| **`handleSubmit(onValid, onInvalid)`** | Higher-order function that validates form and passes sanitized data to `onValid`. |
| **`reset(values?, keepStateOptions?)`** | Resets the form state and field values back to default or newly passed values. |
| **`resetField(name, options?)`** | Resets a single specific field back to its default value. |
| **`setValue(name, value, options?)`** | Dynamically sets a field value (`shouldValidate: true`, `shouldDirty: true`). |
| **`getValues(name?)`** | Synchronously reads current field value(s) without triggering a component re-render. |
| **`watch(name?)`** | Subscribes to input changes and triggers a re-render on the host component. |
| **`trigger(name?)`** | Programmatically triggers validation on the whole form or a specific field. |
| **`setError(name, error)`** | Manually injects a custom error (e.g. from an HTTP 422 API response). |
| **`clearErrors(name?)`** | Programmatically clears errors for a single field or all fields. |
| **`setFocus(name)`** | Programmatically shifts browser focus to the specified input. |
| **`getFieldState(name, formState)`** | Returns isolated state flags (`invalid`, `isDirty`, `isTouched`, `error`) for a field. |

### D. `formState` Flags & Metadata
| Property | Type | Meaning |
|:---|:---|:---|
| **`errors`** | `FieldErrors` | Object containing current validation error messages mapped by field name. |
| **`isDirty`** | `boolean` | `true` if the user has modified any field value from its `defaultValues`. |
| **`dirtyFields`** | `object` | Map of specific fields that have been modified. |
| **`touchedFields`** | `object` | Map of specific fields that have received focus and then blur. |
| **`isSubmitting`** | `boolean` | `true` while the asynchronous `handleSubmit` callback is executing. |
| **`isSubmitted`** | `boolean` | `true` if the form has been submitted at least once. |
| **`isSubmitSuccessful`** | `boolean` | `true` if the last submission completed without throwing a runtime error. |
| **`submitCount`** | `number` | Total number of times the user has clicked submit. |
| **`isValid`** | `boolean` | `true` if the form contains zero validation errors. |
| **`isValidating`** | `boolean` | `true` while asynchronous schema validation is running. |
| **`isLoading`** | `boolean` | `true` while an asynchronous `defaultValues` Promise is pending. |

### E. Controller `render` Parameter Shapes
When using `<Controller render={({ field, fieldState, formState }) => ...} />`:

- **`field` Object**:
  - `field.name`: Name of the field.
  - `field.value`: Current field value.
  - `field.onChange`: Callback to update value.
  - `field.onBlur`: Callback to mark field as touched.
  - `field.ref`: Ref callback to link native element.
  - `field.disabled`: Boolean disabled state.
- **`fieldState` Object**:
  - `fieldState.invalid`: Boolean indicating if field has errors.
  - `fieldState.isDirty`: Boolean indicating if field was changed.
  - `fieldState.isTouched`: Boolean indicating if field was blurred.
  - `fieldState.error`: The `FieldError` object containing `{ message, type }`.

### F. shadcn/ui Form Component Equivalents
| shadcn/ui Component | Underlying React Hook Form Role |
|:---|:---|
| **`<Form>`** | Alias for `<FormProvider>` providing global context to children. |
| **`<FormField>`** | Pre-configured wrapper around `<Controller name="..." control={...} />`. |
| **`<FormItem>`** | Container providing unique accessibility IDs via `useId()`. |
| **`<FormLabel>`** | Accessible `<label htmlFor={id}>` automatically connected to the input. |
| **`<FormControl>`** | Clones input child to inject `id`, `ref`, and `aria-invalid`. |
| **`<FormDescription>`** | Accessible help text connected via `aria-describedby`. |
| **`<FormMessage>`** | Error message container reading `fieldState.error?.message`. |
