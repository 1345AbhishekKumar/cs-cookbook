In React, user interfaces are constructed by composing isolated, reusable building blocks called **Components**.

---

## 1. What is JSX?

**JSX** is a syntax extension for JavaScript that looks like HTML. Modern bundlers compile JSX down into lightweight function calls (`_jsx`):

```tsx
// Your code in React:
const badge = <span className="badge">Active</span>;

// What the compiler outputs:
import { jsx as _jsx } from "react/jsx-runtime";
const badge = _jsx("span", { className: "badge", children: "Active" });
```

### Essential JSX Differences from Native HTML:
1. **`className`** instead of `class` (avoids keyword collision with JS `class`).
2. **`htmlFor`** instead of `for` on `<label>` elements.
3. **Inline Styles** take a JavaScript object with camelCase properties: `style={{ backgroundColor: "blue", marginTop: "1rem" }}`.
4. **Self-closing tags are mandatory**: `<img />`, `<input />`, and `<br />` must have closing slashes or matching closing tags.

## 2. Component Composition & Props

Props (properties) are the inputs passed from parent components to child components:

```tsx
interface StatCardProps {
  title: string;
  metric: number;
  isPositive?: boolean;
}

export function StatCard({ title, metric, isPositive = true }: StatCardProps) {
  return (
    <div className="card">
      <h3>{title}</h3>
      <p className={isPositive ? "metric-up" : "metric-down"}>
        {metric.toLocaleString()}
      </p>
    </div>
  );
}
```

<Callout type="warn" title="Props are Strictly Read-Only">
Components must never mutate their incoming props directly (e.g. `props.metric = 50`). Props are immutable snapshots owned by the parent component. To change displayed values, use state.
</Callout>

## 3. The `children` Prop (Containment Pattern)

The `children` prop allows components to accept arbitrary nested JSX, enabling reusable layout wrappers:

```tsx
interface ModalProps {
  isOpen: boolean;
  onClose: () => void;
  children: React.ReactNode;
}

export function Modal({ isOpen, onClose, children }: ModalProps) {
  if (!isOpen) return null;

  return (
    <div className="modal-backdrop" onClick={onClose}>
      <div className="modal-dialog" onClick={(e) => e.stopPropagation()}>
        <button className="close-btn" onClick={onClose}>✕</button>
        <div className="modal-body">{children}</div>
      </div>
    </div>
  );
}
```

## 4. Conditional Rendering Patterns

```tsx
export function UserBadge({ user }: { user: { name: string; isAdmin: boolean; notifications: number } }) {
  return (
    <div>
      <span>Welcome, {user.name}</span>

      {/* 1. Ternary: Choose between two distinct components */}
      {user.isAdmin ? <span className="tag-admin">Admin</span> : <span className="tag-user">Member</span>}

      {/* 2. Logical AND (&&): Render only when true */}
      {user.notifications > 0 && (
        <span className="badge-count">{user.notifications}</span>
      )}
    </div>
  );
}
```

<Callout type="warn" title="The Falsy Number Trap with &&">
Never use `items.length && <List />`. If `items.length` is `0`, JavaScript evaluates `0 && ...` to `0`, which renders a visible `0` on your screen! Instead, use `items.length > 0 && <List />` or a boolean conversion `Boolean(items.length) && <List />`.
</Callout>

## 5. Rendering Lists & The Critical Rule of Keys

When rendering arrays in JSX using `.map()`, every item **must** have a unique, stable `key` prop:

```tsx
interface TodoItem {
  id: string;
  task: string;
}

export function TodoList({ items }: { items: TodoItem[] }) {
  return (
    <ul>
      {items.map((item) => (
        <li key={item.id}>{item.task}</li>
      ))}
    </ul>
  );
}
```

### Why Array Indexes (`key={index}`) Cause Bugs:
If an array is reordered, sorted, or items are inserted/deleted from the middle:
- React uses the `key` to identify which DOM node corresponds to which item.
- If you use `index`, the item at index `0` changes identities, causing React to mismatch component internal state (like inputs and checkboxes), causing severe UI bugs.
- **Rule**: Always use permanent database IDs (`item.id`) or UUIDs.
