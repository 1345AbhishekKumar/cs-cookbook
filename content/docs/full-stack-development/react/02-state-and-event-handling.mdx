While props allow parents to pass data down, **State** is a component's private, internal memory that persists across renders and triggers UI updates when changed.

---

## 1. The `useState` Snapshot Mental Model

When React renders a component, it takes a "snapshot" of state for that specific render pass:

```tsx
export function Counter() {
  const [count, setCount] = useState(0);

  function handleClick() {
    setCount(count + 1);
    console.log(count); // Still prints 0!
  }

  return <button onClick={handleClick}>Count: {count}</button>;
}
```

<Callout type="info" title="Why console.log prints the old value">
Setting state does not mutate the current `count` variable in place. It schedules a new render pass with a new snapshot of `count = 1`. Inside the current execution frame, `count` remains `0`.
</Callout>

### Functional State Updates
If you need to update state multiple times based on the previous state value, pass an updater callback function:

```tsx
function incrementTriple() {
  // Using updater callbacks ensures React uses the latest state queue:
  setCount(prev => prev + 1);
  setCount(prev => prev + 1);
  setCount(prev => prev + 1);
  // Count will increase by 3!
}
```

## 2. Immutable State Updates

In React, state must be treated as **immutable**. Never modify objects or arrays directly:

<Tabs items={['Updating Objects', 'Updating Arrays']}>
  <Tab value="Updating Objects">
    Use the spread operator (`...`) to create a new object reference:

    ```tsx
    const [user, setUser] = useState({ name: "Alex", role: "Developer" });

    // BAD (Never do this: No re-render triggered!):
    // user.role = "Admin";

    // GOOD:
    setUser(prev => ({
      ...prev,
      role: "Admin"
    }));
    ```
  </Tab>
  <Tab value="Updating Arrays">
    Use non-mutating array methods (`map`, `filter`, spread):

    ```tsx
    const [todos, setTodos] = useState(["Learn HTML", "Learn CSS"]);

    // 1. Add item (Spread)
    setTodos(prev => [...prev, "Learn React"]);

    // 2. Remove item (Filter)
    setTodos(prev => prev.filter(item => item !== "Learn HTML"));

    // 3. Update item (Map)
    setTodos(prev => prev.map(item => item === "Learn CSS" ? "Master CSS" : item));
    ```
  </Tab>
</Tabs>

## 3. Automatic Batching (React 18 & 19)

React automatically groups multiple state updates together into a single render pass, regardless of whether they occur inside click handlers, asynchronous promises, or timers:

```tsx
async function handleSubmission() {
  setIsSubmitting(true);
  await saveToDatabase();

  // Both state updates are automatically batched into ONE single re-render!
  setIsSubmitting(false);
  setSuccessMessage("Saved successfully!");
}
```

## 4. Synthetic Event Handling

React wraps native browser events in a cross-browser **`SyntheticEvent`** wrapper:

```tsx
export function SearchBox() {
  function handleInput(event: React.ChangeEvent<HTMLInputElement>) {
    console.log("Current value:", event.target.value);
  }

  function handleFormSubmit(event: React.FormEvent<HTMLFormElement>) {
    event.preventDefault(); // Prevents full page reload
  }

  return (
    <form onSubmit={handleFormSubmit}>
      <input type="text" onChange={handleInput} placeholder="Search..." />
      <button type="submit">Submit</button>
    </form>
  );
}
```

## 5. The Golden Rule of Derived State

**Don't put values in state if you can compute them from existing state or props during render!**

```tsx
// BAD: Redundant state variables that can get out of sync
const [firstName, setFirstName] = useState("Jane");
const [lastName, setLastName] = useState("Doe");
const [fullName, setFullName] = useState("Jane Doe"); // Antipattern!

// GOOD: Compute directly during render (Derived State)
const [firstName, setFirstName] = useState("Jane");
const [lastName, setLastName] = useState("Doe");
const fullName = `${firstName} ${lastName}`; // Zero state synchronization bugs!
```
