In traditional multi-page web applications, clicking an `<a>` link prompts the browser to fetch a brand-new HTML page from the server, causing a blank screen flash and discarding all in-memory client state.

**Client-Side Routing** intercepts browser URL changes using the HTML5 History API (`pushState` and `replaceState`), conditionally swapping active UI components without reloading the page.

---

## 1. Installation & Basic Setup

In a React web application, routing is provided by `react-router-dom`:

```bash
npm install react-router-dom
```

Wrap your top-level component tree in `<BrowserRouter>`:

```tsx title="src/main.tsx"
import React from 'react';
import ReactDOM from 'react-dom/client';
import { BrowserRouter } from 'react-router-dom';
import App from './App';

ReactDOM.createRoot(document.getElementById('root')!).render(
  <React.StrictMode>
    <BrowserRouter>
      <App />
    </BrowserRouter>
  </React.StrictMode>
);
```

## 2. Declaring Routes & Links

React Router v6 replaces the legacy `<Switch>` component with `<Routes>`. Inside `<Routes>`, each `<Route>` maps a URL `path` to a JSX `element`:

```tsx title="src/App.tsx"
import { Routes, Route, Link, NavLink } from 'react-router-dom';

function Home() {
  return <h1>Welcome Home</h1>;
}

function About() {
  return <h1>About Us</h1>;
}

function NotFound() {
  return <h1>404: Page Not Found</h1>;
}

export default function App() {
  return (
    <div>
      <nav style={{ display: 'flex', gap: '1rem', padding: '1rem' }}>
        {/* Basic Link: Updates URL without refreshing page */}
        <Link to="/">Home</Link>

        {/* NavLink: Adds styling based on active state */}
        <NavLink
          to="/about"
          className={({ isActive }) => (isActive ? 'active-link' : 'inactive-link')}
          style={({ isActive }) => ({ color: isActive ? '#3b82f6' : '#6b7280' })}
        >
          About
        </NavLink>
      </nav>

      <main style={{ padding: '1rem' }}>
        <Routes>
          <Route path="/" element={<Home />} />
          <Route path="/about" element={<About />} />
          {/* Catch-all 404 route */}
          <Route path="*" element={<NotFound />} />
        </Routes>
      </main>
    </div>
  );
}
```

### `<Link>` vs `<NavLink>`
- `<Link to="...">`: Standard declarative client navigation. Replaces standard `<a href="...">`.
- `<NavLink to="...">`: Specialized link that knows whether its target URL is currently active. Provides an `({ isActive, isPending })` callback to dynamically format classes or styles.
- **`end` prop**: In `<NavLink to="/books" end>`, `end` prevents the link from staying active on child sub-routes like `/books/123`.

## 3. Dynamic Routes & `useParams`

To handle variable path segments (e.g. database IDs, usernames, slugs), prefix the segment with a colon `:param`:

```tsx title="src/pages/BookDetail.tsx"
import { useParams, Link } from 'react-router-dom';

type RouteParams = {
  bookId: string;
};

export function BookDetail() {
  // Reads dynamic parameters from current matched URL
  const { bookId } = useParams<RouteParams>();

  return (
    <div>
      <h2>Viewing Book ID: {bookId}</h2>
      <Link to="/books">Back to Library</Link>
    </div>
  );
}
```

Registered inside `<Routes>`:
```tsx
<Route path="/books/:bookId" element={<BookDetail />} />
```

## 4. Nested Routes, `<Outlet>` & Shared Layouts

Nested routing allows parent components (such as dashboards or sidebars) to remain mounted while swapping only inner sub-views. The parent renders an `<Outlet />` placeholder where child routes are projected:

```tsx title="src/layouts/DashboardLayout.tsx"
import { Outlet, Link, useOutletContext } from 'react-router-dom';

type UserContextType = {
  username: string;
};

export function DashboardLayout() {
  const currentUser = { username: "alex_dev" };

  return (
    <div style={{ display: 'flex', minHeight: '100vh' }}>
      <aside style={{ width: '220px', borderRight: '1px solid #e5e7eb', padding: '1rem' }}>
        <h3>Dashboard</h3>
        <ul>
          <li><Link to="/dashboard">Overview</Link></li>
          <li><Link to="/dashboard/analytics">Analytics</Link></li>
          <li><Link to="/dashboard/settings">Settings</Link></li>
        </ul>
      </aside>

      <main style={{ flex: 1, padding: '2rem' }}>
        {/* Child routes render right here */}
        {/* Pass shared layout state downward via context prop */}
        <Outlet context={currentUser satisfies UserContextType} />
      </main>
    </div>
  );
}
```

### Route Nesting Hierarchy:
```tsx title="src/App.tsx"
<Routes>
  {/* Parent Layout Route */}
  <Route path="/dashboard" element={<DashboardLayout />}>
    {/* Index route: Matches exactly /dashboard */}
    <Route index element={<DashboardOverview />} />
    {/* Nested child routes: /dashboard/analytics */}
    <Route path="analytics" element={<DashboardAnalytics />} />
    <Route path="settings" element={<DashboardSettings />} />
  </Route>
</Routes>
```

### Consuming Context in Child:
```tsx title="src/pages/DashboardOverview.tsx"
import { useOutletContext } from 'react-router-dom';

export function DashboardOverview() {
  const { username } = useOutletContext<{ username: string }>();
  return <h2>Welcome back, {username}!</h2>;
}
```

## 5. Query Search Parameters with `useSearchParams`

Search parameters are values stored in the query string after `?` (e.g. `/search?query=react&sort=desc`). `useSearchParams` behaves similarly to `useState`:

```tsx title="src/pages/SearchPage.tsx"
import { useSearchParams } from 'react-router-dom';

export function SearchPage() {
  const [searchParams, setSearchParams] = useSearchParams({ query: '', sort: 'asc' });

  const query = searchParams.get('query') || '';
  const sort = searchParams.get('sort') || 'asc';

  function handleFilterChange(newQuery: string) {
    setSearchParams(prev => {
      prev.set('query', newQuery);
      return prev;
    });
  }

  return (
    <div>
      <input
        type="text"
        value={query}
        placeholder="Filter results..."
        onChange={(e) => handleFilterChange(e.target.value)}
      />
      <p>Current search: <strong>{query}</strong> (Sort: {sort})</p>
    </div>
  );
}
```

## 6. Programmatic Navigation with `useNavigate`

When navigation needs to trigger inside an asynchronous callback (such as submitting a form or completing a checkout), use the `useNavigate` hook:

```tsx title="src/components/LoginForm.tsx"
import { useNavigate } from 'react-router-dom';

export function LoginForm() {
  const navigate = useNavigate();

  async function handleSubmit(event: React.FormEvent) {
    event.preventDefault();
    await authenticateUser();

    // 1. Redirect to dashboard
    // 2. replace: true discards login page from browser back-button history
    navigate('/dashboard', { replace: true });
  }

  return (
    <form onSubmit={handleSubmit}>
      <button type="submit">Sign In</button>
      {/* Navigate back 1 page in history */}
      <button type="button" onClick={() => navigate(-1)}>Go Back</button>
    </form>
  );
}
```

## 7. Protected Routes (Authentication Guard)

To restrict routes to authenticated users, create a wrapper component using `<Navigate>`:

```tsx title="src/components/ProtectedRoute.tsx"
import { ReactNode } from 'react';
import { Navigate, useLocation } from 'react-router-dom';

export function ProtectedRoute({ 
  children, 
  isAuthenticated 
}: { 
  children: ReactNode; 
  isAuthenticated: boolean; 
}) {
  const location = useLocation();

  if (!isAuthenticated) {
    // Redirect unauthenticated users to /login, saving current path for post-login return
    return <Navigate to="/login" state={{ from: location }} replace />;
  }

  return <>{children}</>;
}
```

```tsx title="src/App.tsx"
<Routes>
  <Route path="/login" element={<LoginPage />} />
  <Route
    path="/admin"
    element={
      <ProtectedRoute isAuthenticated={userLoggedIn}>
        <AdminDashboard />
      </ProtectedRoute>
    }
  />
</Routes>
```

## 8. React Router v5 to v6+ Migration Summary

| v5 Concept | v6+ Modern Replacement | Benefit |
|---|---|---|
| `<Switch>` | `<Routes>` | Improved matching specificity algorithm, avoids route definition order bugs. |
| `<Route component={Comp}>` | `<Route element={<Comp />}>` | Direct JSX composition, enables prop passing directly to element. |
| `useHistory()` | `useNavigate()` | Unified API for relative jumps, history replacement, and integer back-forward (`navigate(-1)`). |
| Custom sub-router nesting | `<Outlet />` & Layout Routes | Clean tree architecture with built-in shared context support (`useOutletContext`). |
